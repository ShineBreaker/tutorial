EDITOR MIGRATION GUIDE

从 Zed / VSCode 到 Emacs

你在其他编辑器里的常用操作，这里几乎都有一一对应的键位——而且本配置已经把 C-s 保存、C-p 找文件、C-S-f 查找、C-d 多光标这些现代习惯直接搬了进来。 迁移不是「从头学一套按键」，而是先用手上的肌肉记忆平滑落地，再逐步解锁 Emacs 真正的过人之处。

适用于本机 emacs.org 配置· 键位与配置真理源同步核对· 2026-09· 离线单文件，无外部依赖

这一节的意义

很多人对 Emacs 的恐惧来自「键位全要重学」。这份配置的哲学恰恰相反： 高频操作保留你现在的肌肉记忆，把学习成本留给那些别的编辑器给不了的能力。 上面任何一条不确定时，按 <f1> k 再按那个键，Emacs 会告诉你它是什么。

注：本配置已把 C-h 挪作「左移光标」 （对齐现代编辑器 Home 排的手位），帮助前缀整体住在 <f1> 上——功能与教科书里的 C-h 一模一样，只是换了门牌。

§1三个心智转变：从「记键位」到「会探索」

迁移 Emacs 真正的坎不是键位数量，而是它对「编辑器应该长什么样」的三个不同假设。 理解它们之后，你不再需要背任何速查表——因为编辑器本身会告诉你答案。

1

键位是一棵前缀树，不是一张平面表

VSCode 的快捷键是孤立的组合；Emacs 的键位是树：按下一个前缀键，停顿 0.3 秒， which-key 会弹出这棵子树里所有命令的中文菜单。

例如按 C-c g 停一下，所有 Git 操作尽收眼底。所以你只需要记住 14 个前缀的语义（g = Git、w = 窗口、e = 编辑……）， 不用记每个字母。

2

万物皆命令，帮助永远在手边

界面上每个按钮背后都是一条具名命令，都可以用 M-x 按名字调用、可以问、可以改。

自助体系：<f1> k 按了某键会怎样、 <f1> f 函数是干嘛的、 <f1> v 变量含义、 <f1> b 列出当前所有键、 <f1> ? 本配置的全局中文速查表。 本配置把 C-h 挪作左移光标，帮助前缀住在 <f1>——与各教程里的 C-h 同义。

3

很多功能是「会话」而不是「面板」

isearch、minibuffer 补全、矩形编辑都是临时接管键盘的模式：进去后同一批键有了新含义， 用 C-g 或 ESC 随时退出。

C-g 是万能取消：卡住了、按错了、想反悔了，先按它。

Emacs 的思路：搜索不是输入框，是一条「越查越深」的递进链

isearch 是一个会话：输入的任意时刻，你都可以就地升级这次搜索——按 M-s o 把结果变成可编辑的列表（occur）、按 M-% 直接转入替换（当前搜索串自动预填为被替换串，只需输入新词）、按 C-w 把光标处的单词吞进搜索串、按 M-s h 永久高亮所有匹配。回显行末尾常驻 [M-s 更多 | M-% 替换 | C-w 取词] 提示，不用背。

替换则贯彻「先看 diff 再动手」：C-S-h 会把替换效果渲染成 diff，确认无误才写入——比逐个 y/n 更快，也比一把梭更安全。

;; isearch 会话中的递进（输入搜索词的任意时刻可用）
C-S-f  输入 search-term   ; 开始增量搜索，回显区实时计数 [3/15]
M-s o                    ; 升级为 occur 列表：所有匹配按行铺开，可直接编辑
M-%  new-term RET    ; 升级为逐个替换：搜索词自动预填为被替换串，只输新词即可
;;   循环内：! 全部替换、n 跳过当前、RET 退出——只按一个 RET！
;;   （连按两个 RET 会直接退出且一处不换，echo area 显示 Replaced 0 occurrences）

同一个键在有选区和无选区时做「你显然想要的」那件事： C-S-c 有选区复制选区、无选区复制整行； C-w 无选区时删除整行。 VSCode 里「先 Home 再 Shift+End 再 Ctrl+C」的三步，这里是一步。

—M-<方向>终端聚焦时也能切窗（方向键不透传给 shell）
Emacs 的思路：终端是 Emacs 的「一等公民」，不是外挂面板

按键透传规则（semi-char 模式）：绝大多数按键直接发给 shell，程序自身的快捷键照常工作； 只有一张小小的例外表落回 Emacs——C-c（终端控制前缀： C-c C-c 中断、C-c C-z 挂起、C-c C-d EOF）、C-x、 C-u、M-x、 M-:、C-\， 以及本配置追加的 M-<方向>（切窗）。例外键按下的瞬间 which-key 会弹菜单告诉你接下来能做什么，不用背。

C-h 在终端里被单独重绑为「向 shell 发退格」—— 全局 C-h 已挪作左移光标，而帮助前缀住在 <f1>，两不耽误。

最典型的例子是提交代码：终端里敲 git commit，Emacs 会自动在上方主编辑窗口 打开提交信息缓冲区（完整编辑器能力：折行、拼写、填空模板），写完按 C-x #，终端里的 Git 继续执行。 「编辑器」和「终端里跑的程序」共享同一套界面与剪贴板，边界是透明的。

§3Emacs 独有的提效武器

这些能力在其他编辑器里要么没有、要么残缺。它们才是迁移的「回报」——每一个都值得专门练一周。

前缀参数 C-u：给任何命令加「数量 / 变体」

按住 C-u 再输入数字或直接跟命令，等于给命令传一个参数。 最直观的例子在本配置里： 

C-c i f      ; 插入当前文件名：notes.org
C-u C-c i f  ; 插入相对项目根的路径：docs/notes.org（写文档引用时）

它是通用机制：删 4 个词 C-u 4 M-d、 当前窗口增高 30 行 C-u 30 C-x ^ （内置 enlarge-window）——任何接收参数的命令都吃这一套。

剪贴环 kill-ring：复制过的东西永不丢失

每一次复制 / 删除都进入一个环形历史。粘贴后立刻按 M-y 可换成「上一次复制的内容」，连按逐条向前翻。 典型场景：从 A 处复制、B 处复制、到 C 处粘贴时发现想要的是 A——不用回去重选， C-S-v 后连按 M-y 即可。

矩形与寄存器 C-x r：以「块」和「位置」思考

竖选一列区域（把 mark 和 point 放在不同行不同列即可）后， C-x r t 在每行行首插入同样文字（批量加注释、加引号）、 C-x r d 删掉整列——多光标能干的列编辑它都能干， 而且不占光标。寄存器则用 C-x r SPC 存当前位置、C-x r j 随时跳回， 在大文件里两点往返（已开启选择预览，跳前先看一眼目标）。 （此族为 Emacs 内置原语）

repeat-mode：连续微调不用重按前缀

本配置已开启 repeat-mode：内置的连续型命令（调窗、缩放、翻页等）执行一次后， 直接按后续单键即可连续重复，不必反复按完整前缀。调窗宽度时 C-x } 一次，之后连按 } 逐列加宽，松手即停。

M-/ 词内补全：不用任何语言服务

M-/（dabbrev）在当前缓冲区（及同模式缓冲区）里找 同前缀的单词循环补全——写长变量名、中文文档里重复的术语，比输入法还快， 且完全不依赖 LSP。配置已降噪：不会弹出扫描进度打扰你。

守护进程模型：Emacs 永远「已经开着」

Emacs 以 daemon 常驻后台：图形窗口（emacsclient -c）和终端界面 （emacsclient -t）是同一个会话的两个脸——终端里开着的文件， 回到桌面图形窗口还在原处；启动「新窗口」接近零耗时。这在 Zed / VSCode 里 没有对应物，是 daemon 化 Emacs 的核心红利。

§5建议的学习路径

不要试图一次背下所有键位。按下面的顺序，每阶段只专注一件事。

  1. 第一周：只用手上已有的习惯

    全程用 §0 表里的「同键区」工作：C-s 保存、 C-p 找文件、C-S-f 查找、 C-` 终端。唯一要新学的动作：卡住就按 C-g。

  2. 第二周：养成「停顿看弹窗」的肌肉记忆

    每次想找功能，先按对应前缀（Git 找 C-c g、 窗口找 C-c w）停半秒看 which-key 的中文菜单， 而不是去搜网页。这周结束时你已经「会用」所有功能，只是还不快。

  3. 第三周：把搜索替换升级成递进链

    刻意练习 isearch 会话内的升级动作：M-s o 转列表、 M-% 转替换、C-w 取词。 再用一次 C-c e R 多文件 diff 预览替换， 你会开始理解为什么老用户离不开它。

  4. 第四周：Magit 接管全部 Git 操作

    一周内禁止自己敲 git add：状态页 C-S-g、 目录暂存 C-c g a、提交 c c、 推送 P u。第四天开始你会感觉到「清单式操作」比命令行快。

  5. 之后：读配置，改配置

    C-, 打开 emacs.org， 从你最在意的功能域读起（每个域开头都有设计说明）。改完 herd restart emacs-daemon 即生效——把自己的工作流长进编辑器里， 才是这次迁移的终点，也是 Emacs 的意义。
