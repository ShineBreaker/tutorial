十、实用篇（二）：Tramp 远程编辑与 EWW 浏览器

这一章讲两件看起来不相干、实际都是「把 Emacs 的边界推出去」的事。Tramp（Transparent Remote (file) Access, Multiple Protocol，内置的透明远程文件访问包，中文可译作「透明远程访问」）让你在服务器上直接编辑文件、跑编译、翻目录，用的还是同一个 Emacs、同一套键位、同一个配置；EWW（Emacs Web Wowser，内置的极简网页浏览器）让你不离开 Emacs 就能读一页文档、搜一下午的资料。读完这一节你会得到三样东西：一是 Tramp 那条 /method:user@host:/path 路径语法的完整读法（sudo、多跳、换用户都包含在内）；二是知道 default-directory 这个变量为什么是 Tramp 全部魔法的枢纽——理解它，你就理解了 Emacs 的文件系统抽象；三是关于「Tramp 到底卡在哪、今天怎么调」和「EWW 今天还值不值得学」的诚实答案。这一章还会交代 Emacs 30/31/32 的现状：原书写于 Emacs 26–30 时代，它给的 C-x r l 打开书签列表、M-s M-w 在 EWW 内搜索这两条今天都已经不是原来那回事了，正文里会逐条标出来。

要点

本章涉及的命令是否存在、按键绑定、变量默认值，都是在本机 GNU Emacs 32.0.50（自带 Tramp 2.8.3-pre）上用 emacs --batch -Q 实际查询过的；Magit 相关的说法逐条对着本机装的 Magit 4.7.1 源码核过；EWW 和 Tramp 的引文出自随包安装的 eww.info、tramp.info 与 NEWS.30 / NEWS.31。凡是原书写得不对、或者今天已经变了的，正文会直接说「这里变了」，并给出你可以在自己机器上复核的那一条命令。

一、Tramp 是什么，为什么它值钱

先说说没有 Tramp 的时候有多难受

你要改服务器上的一个 /etc/nginx/nginx.conf。不用 Tramp，你的流程是：开一个终端模拟器，ssh user@server，输密码，sudo vi nginx.conf。然后你面对的是：

  • 一个没有语法高亮、没有括号匹配的编辑器；
  • 一份跟本地完全不同的配置——你在本地 Emacs 里精心调好的主题、缩进、自动补全、小地图、宏、寄存器，一个都用不上；
  • 鼠标滚轮要先选中再复制粘贴这一套笨办法，因为终端里的鼠标转发默认是关的；
  • 改完之后还想顺手 git log -p 看一眼这个文件最近谁改的——得退出 vi，回到 shell，跑 git，再想办法把输出粘回去。

原书作者用一句话概括这种困境：远程编辑「总是伴随各种妥协（trade-offs）」，哪怕技术早就进步了。Emacs 对这个问题的回答就是 Tramp。

Tramp 做的事：接管文件名，不接管界面

Tramp 的核心动作只有一个：当你敲 Cx Cf（find-file，打开文件）并输入一个特殊格式的路径时，Emacs 认出这个路径是「远程的」，于是把读写操作转交给另一台机器执行。除此之外，Emacs 界面上一根汗毛都不动——还是同一个窗口、同一套主题、同一份 init.el、同一套按键。

这就是作者说它是「Emacs 里最酷的功能」的原因：它是透明的（transparent）。你甚至不需要知道它存在——一个远程文件打开之后，缓冲区里的一切（模式、缩进、语法高亮、编译、Git）都跟本地文件一模一样。

技巧

Tramp 是 Emacs 内建的，不需要装任何东西。它随 Emacs 一起发布，作者是 Kai Großjohann，现在的维护者是 Michael Albinus。版本在 Emacs 32.0.50 里是 2.8.3-pre（源码见 lisp/net/trampver.el）。官方主页 https://www.gnu.org/software/tramp/，邮件列表 tramp-devel@gnu.org。

二、核心机制：default-directory 被改写了

这一节是整章最重要的部分。原书写得对：Tramp 的全部魔法都建立在一个变量上——default-directory。如果你只从这一章记住一件事，就记住这件。

先复习：default-directory 是什么

default-directory（默认目录）是每个缓冲区各自一份的变量，用来回答一个问题：「这个缓冲区里，相对路径是相对于哪个目录的？」

在 Elisp 术语里，它是一个 buffer-local（缓冲区局部变量，即每个缓冲区各有一份、而不是全局只有一份的变量）。你新开一个缓冲区，它的 default-directory 通常是你的主目录（~）。一旦你用 Cx Cf 打开了一个文件，这个缓冲区的 default-directory 就自动变成那个文件所在的目录。

所以：在一个 /etc 下的文件里按 Cx Cf，Emacs 会默认去 /etc 找下一个文件——因为这通常正是你想要的（要改配置就改同一目录下的配置）。

Tramp 改的就是它

现在你输入这样一个路径：

C-x C-f /ssh:homer@powerplant:/var/log/reactor.log RET

Tramp 会：

  1. 启动一个到 powerplant 的 SSH 连接，用 homer 这个用户登录；
  2. 在远端读出 /var/log/reactor.log 的内容，填进一个普通的 fundamental-mode 缓冲区；
  3. 把这个缓冲区的 default-directory 设成 /ssh:homer@powerplant:/var/log/。

第 3 步就是全部魔法所在。因为 Cx Cf、Cx s（保存）、Cx d（dired，目录浏览器）、M&（async-shell-command，在 shell 里执行命令）这些命令全都以 default-directory 为出发点：

  • Cx Cf 会以它为默认目录——你再按一次 Cx Cf，补全会去远端列文件，不会去你本机；
  • Cx s 会把文件写回远端；
  • Cx d 会去远端列目录；
  • Mx compile、Mx rgrep 会在远端跑命令，输出回到本地缓冲区。

反过来，你在本地文件的缓冲区里按 Cx Cf，Emacs 就会去本机列文件。这不是 Tramp 干的，这是 default-directory 一直在做的事——Tramp 只是把「目录」这个概念从本地路径扩展成了「远程路径」。

要点

怎么亲眼确认这件事？打开一个远程文件后，按 Ch v（describe-variable，查询变量）然后输入 default-directory 回车，你会看到 /ssh:homer@powerplant:/var/log/。模式行（modeine，显示文件名和模式的那一行）上，远程缓冲区的文件名前面会多一个 @ 符号——这是 Emacs 在提醒你「这个缓冲区指向的不是本地文件」。它来自模式行里的一项 mode-line-remote（源码见 lisp/bindings.el），判断依据是 (file-remote-p default-directory)：为真就显示 @，鼠标悬上去的提示文字会写「Current directory is remote: …」。注意别把它跟文件权限串搞混：像 ls -l 那样先打一串 -rw-r--r-- 再跟文件名的排版，是 Dired 缓冲区才有的，普通文件缓冲区的模式行不这么显示。（顺带说一句：ls-lisp 不是一个能按 Mx 调用的命令，也不是一个模式——它是 ls-lisp.el 这个文件，里面用 advice（advice，给已有函数包一层）改写了 insert-directory，让 Emacs 用纯 Elisp 模拟 ls，好让没有装 ls 的系统（比如 Windows）也能列目录。开关是变量 ls-lisp-use-insert-directory-program：设成 nil 就启用它。）

路径语法：/method:[user@]host[#port]:path

Tramp 的文件名有一套固定语法（官方叫 file name syntax，文件名语法）：

/method:[user@]host[#port]:/path/to/file

逐段拆开看：

  • / 开头的斜杠：这是必须的，表示「这是一个远程文件名的开头」。
  • method：连接方式。常用的有 ssh、scp、sftp、su、su 的各种变体，还有容器类（docker、podman）、adb（安卓手机）、smb（Windows 共享）等。完整列表在 tramp-methods 这个变量里（按 Ch v 查），或者读 M-x info tramp 打开的 Tramp 手册。Emacs 32.0.50 里 tramp-methods 一共有 37 项：36 个真正的方法，再加上伪方法 -（下面「坑一」会讲它）。这个变量是个 alist（关联表），每项写成 (方法名 . 方法参数)，所以取方法名要用 (mapcar #'car tramp-methods)。
  • user@：远端用户名。可以省略，省略时默认用你本机的登录名。
  • host：主机名或 IP。IPv6 地址要写在方括号里：/ssh:[::1]:。
  • #port：端口号，写在主机名后面、冒号前面。IPv6 加端口写成 /ssh:[::1]#42:。
  • 第二个 : 和它后面的路径：从第二个冒号开始，Emacs 才真的需要去连远端。你在 Cx Cf 里敲完 /ssh:powerplant: 先不敲路径，直接按 TAB 补全，Emacs 这时候才去连，然后列出远端文件让你选。
技巧

别死记硬背：直接在 Cx Cf 的提示符里敲路径，让 Emacs 帮你补全。在 Cx Cf 之后输入 /s 再按 TAB，会看到这一串候选（Emacs 32.0.50 自带的 Tramp 里，以 s 开头的方法正好是这 11 个）：scp: scpx: sftp: sg: smb: ssh: sshfs: sshx: su: sudo: sudoedit:。候选里还会混进一些以 s 开头的本地目录（别选错）——具体哪几个取决于你的机器，常见的 Linux 上是 sbin/、srv/、sys/。Tramp 会解析你的 ~/.ssh/config 文件，把里面出现过的所有主机名也一起列进候选。你敲 ssh: 再按 TAB，主机名就出来了。

两个容易踩的坑：默认方法是 scp 不是 ssh；删路径时 // 和 /// 的含义

坑一：默认方法。原书说「现在最可能用的是 ssh 或 scp」，但没告诉你默认是哪个。Emacs 32.0.50 里 tramp-default-method（默认连接方法）这个变量的默认值是按条件算出来的：在 Windows 上如果能找到 pscp 就是 "pscp"，否则如果能找到 scp 就是 "scp"，都没有就退回 "ftp"。在装了 OpenSSH 的普通 Linux 上，它等于 "scp"。这意味着你写 /powerplant:/etc/hosts 这种省略 method 的简写时，实际走的是 scp，不是 ssh。（语法上还有个细节：method 省略时，Tramp 要求你用伪方法 - 显式标出来，比如 /-:powerplant:/etc/hosts；官方文档还专门说明，说外部包不要去读 tramp-file-name-regexp 这个变量，用 file-remote-p 代替。）

坑二：删除路径的快捷键含义很特别。你在 Cx Cf 提示符里用 Cd 或 Ck 删字符时，打两个斜杠 // 会触发 Emacs 的一条特殊规则。Tramp 手册 File name completion 一节的原话是：杀掉双斜杠 //「只杀掉 TRAMP 文件名语法里的文件名部分（kills only the file name part of the TRAMP file name syntax）」，而三斜杠 ///「表示默认行为（stands for the default behavior）」。翻译成大白话：// 删的是「路径」那一段，/ssh:host: 这个远程前缀会保留下来；/// 则回到 Emacs 平常的删除规则上。手册给的两个例子是：

C-x C-f /ssh:melancholia:/usr/local/bin//etc <TAB>
  ⊣ /ssh:melancholia:/etc          ← 只掉了 /usr/local/bin

C-x C-f /ssh:melancholia://etc <TAB>
  ⊣ /ssh:melancholia:/etc

C-x C-f /ssh:melancholia:/usr/local/bin///etc <TAB>
  ⊣ /etc                            ← 整个远程前缀也没了

所以如果你想在 Tramp 路径里删掉一半，得先想清楚你要留的是「哪一半」：打 // 留下远程主机名，打 /// 连主机名一起删干净、打回一个纯本地路径。

进阶：Windows 上要用 PuTTY 的 plink（原书专门讲了一段，今天仍然成立）

如果你在 Windows 上跑 Emacs，情况不一样。原书在这一页明确提醒：「在 Windows 上，你的协议选择不一样。」这段话今天仍然准确，只是背景变了——原书写于 Windows 上还没有好用的 OpenSSH 的年代，那时你多半得去装 PuTTY（一个 Windows 上的 SSH 客户端套件）自带的 plink.exe，然后把协议写成 plink。

Tramp 手册现在的原话是：「TRAMP on MS Windows operating systems is integrated with the PuTTY package, and uses the plink program.」并且给出了完整路径写法：

C-x C-f /plink:user@host:/path/to/file RET

今天你多半不必这么做了。Windows 10 起系统就带有一个可选的 OpenSSH 客户端功能（ssh.exe、scp.exe；Windows 11 默认是启用状态，更早的 Windows 10 需要在「可选功能」里装），如果你的 Emacs 是在 MSYS2、Cygwin 之类的环境下编译的，/ssh: 直接就能用。判断标准很简单：在 Windows 的命令行里敲 ssh -V，能打印版本号就说明有；Tramp 手册也正是把「系统自带 OpenSSH」和「PuTTY」当成两条并列的路来写的。

  • PuTTY 那一族在 tramp-methods 里有四个成员（我实测列表里能看到）：plink（plink -ssh 登录，支持 -P 指定端口）、plinkx（把主机名当成 PuTTY 的会话名来用：plink -load SESSION -t，用户名和端口写在那条会话的 PuTTY 配置里）、pscp（传文件，scp 的 PuTTY 版）、psftp（sftp 的 PuTTY 版）。路径写法跟 ssh 完全一样，只是把方法名换掉。
  • 还有两个专门为「OpenSSH 的怪癖」准备的方法：sshx 和 scpx。手册的原话是 sshx「works like ssh but without the extra authentication prompts」，它用 ssh -t -t -l USER -o RemoteCommand='/bin/sh -i' HOST 打开一条带「标准登录 shell」的连接——注意它并不能跳过认证提问（比如 host key 还没被信任时它照样会问）。Tramp 手册在「Cygwin 与 MS Windows 的 ssh 的问题」一节里明确说：Windows 上自带 OpenSSH 的 ssh 开不出远程 TTY，改用 sshx 或 scpx。

还有一条容易被忽略的：Tramp 手册提到，远端有 mimencode 或 uuencode 这两个工具时，可以用它们做「经由 shell 的编码传输」来加快小文件传输——这属于内部优化，你不用管，知道有这回事即可。

进阶：default-directory 之下的分层——魔法文件名的四层架构

如果你想理解 Tramp 为什么能「透明」，得知道 Emacs 的文件系统抽象是怎么搭的。它是四层的，每一层都可以被包住：

  1. 最内层是实际的系统调用：open、read、write、stat、unlink。
  2. Emacs 的通用文件原语：expand-file-name、file-exists-p、insert-file-contents、write-region、file-attributes、delete-file。这一层不认识任何具体的文件系统，只接受「文件名字符串」。
  3. 文件系统处理函数（file handler）：file-name-handler-alist 这个 alist（关联表，一串「正则表达式 → 处理函数」的配对）决定「哪种格式的文件名交给哪个处理函数」。这一层就是 magic file name（魔法文件名）机制所在：/ssh:host:/path 匹配一条规则，被交给 tramp-handle；/run/foo/bar 这种 file-info 名字被交给 file-info-handler。
  4. default-directory 所在的那一层：各种「找文件」的交互命令，向上要一个目录字符串。

Tramp 的全部工作就在第 3 层：它往 file-name-handler-alist 里加一条规则，说「凡是长这样 /method:...: 的路径，由 tramp-handle 负责」。而 tramp-handle 自己会做一次二次分发（multi-hop，多跳）：它把路径按 | 拆成若干跳，再把「最后一跳」交给一个具体后端——tramp-sh（走远程 shell 的那一类）、tramp-container（容器类）、tramp-smb（Windows 共享）等等。

你在写自己的 Elisp 时，判断一个路径是不是远程的，官方推荐用函数而不是去匹配变量 tramp-file-name-regexp：

(file-remote-p "/ssh:homer@powerplant:/var/log/")   ; ⇒ "/ssh:homer@powerplant:"
(file-remote-p "/su::/etc/passwd")
;; ⇒ #("/su:root@你的主机名:" 4 8 (tramp-default t) 9 27 (tramp-default t))

注意第二条打印出来的那一串：它的类型仍然是字符串，不是向量——我实测 (type-of (file-remote-p "/su::/etc/passwd")) 返回 string，(stringp ...) 返回 t。之所以看起来像向量，是因为这个字符串身上带了 text property（文本属性，可以理解成「粘在字符上的小标签」）：Emacs 打印带属性的字符串时用的就是 #("..." 起始 结尾 (属性名 值)) 这种写法。属性 tramp-default 的意思是「这里的 root 和主机名是我替你猜的，不是你写的」。多跳也一样，比如 (file-remote-p "/ssh:homer@powerplant|su:powerplant:/root/x") 返回的仍然是 字符串 "/su:root@powerplant:"（带 tramp-default 属性）。所以你的代码照常对它调用字符串函数（string-match、concat……）就行，不需要判断「字符串还是向量」。

另外，tramp-file-name-regexp（regexp，正则表达式，用来匹配远程文件名的模式）会随 tramp-change-syntax 一起变，能换成另外两套语法：

  • simplified：/user@host:path/to/file，像 Ange FTP（一个老的 Emacs FTP 客户端）那样，method 省略时用 tramp-default-method；
  • separate：/[method/user@host]path/to/file，源自 XEmacs（Emacs 的分叉项目，后来基本停止维护）。

如果你的 ~/.ssh/config 用了 Include 把主机名分散到多个文件里，默认的主机名补全看不到那些文件，需要额外配一段代码（这是 Tramp 手册 (tramp) Customizing Completion 一节里「Using ssh config include for host name completion」小节给的官方做法）：

;; 前提：~/.ssh/config 里有 Include ~/.ssh/conf.d/*
(tramp-set-completion-function
 "ssh" (append (tramp-get-completion-function "ssh")
                (mapcar (lambda (file) `(tramp-parse-sconfig ,file))
                        (directory-files "~/.ssh/conf.d/"
                                        'full directory-files-no-dot-files-regexp))))

三、换一个用户编辑：su 与那一家

语法：几乎和普通远程连接一样

Tramp 有一族方法专门干「以另一个身份编辑文件」这件事。最常用的是 su（调用系统的 su 程序）：

C-x C-f /su:root@localhost:/etc/fstab RET

或者把主机名整个省掉（Tramp 会猜是本机）：

C-x C-f /su::/etc/fstab RET

语法跟普通远程连接一模一样，只是把 ssh 换成了 su：

C-x C-f /su:root@localhost:/etc/fstab RET
C-x C-f /su::/etc/fstab            RET
易错

su 方法的主机名只能是 localhost 或者 (system-name) 返回的本机名。Tramp 手册对这一点有明确规定（唯一的例外是走多跳）。所以 /su:root@some-remote-box:/etc/shadow 这种写法不是「先 ssh 再提权」的简写——它是想在名叫 some-remote-box 的主机上跑 su，而 su 程序只管切换本机上的用户，压根不联网。要在远端机器上提权，得走「多跳」，写成 /ssh:you@some-remote-box|su:some-remote-box:/etc/shadow，这是下一节的内容。

要点

/su::/etc/fstab 里那个空的 user@ 位置，Tramp 实际会填成 root。Emacs 32.0.50 里我实测 (file-remote-p "/su::/etc/passwd") 返回 #("/su:root@你的主机名:" 4 8 (tramp-default t) 9 27 (tramp-default t))——它连你的本机主机名都替你补上了（原书说「Tramp 聪明到能猜出是 root」，就是这个意思）。这串里 #(...) 的写法容易吓人，其实它是个字符串，只是身上带了 tramp-default 这个 text property（标记「这段是我猜的」），Emacs 打印带属性的字符串就长这样。

今天更省事的两个命令（Emacs 30 和 31 各新增一个）

原书让你自己写 Elisp 命令来做这件事。后来 Emacs 官方把这个能力收进了内核，分两次：tramp-revert-buffer-with-sudo 是 Emacs 30 新增的命令，tramp-dired-find-file-with-sudo 是 Emacs 31 新增的，而 Cx x @ 这个键位绑定是 Emacs 31 才加的。

  • tramp-revert-buffer-with-sudo（Emacs 30 起有，命令本身）——把当前缓冲区重新以 sudo 权限打开。Emacs 31 起默认绑在 Cx x @（注意是三个键：C-x 之后是 x，然后 @）。想换别的方法（比如 su）就按 Cu 前缀：Cu Cx x @——按了会弹提示符让你挑方法（只列出当前已启用的方法）。我实测 (key-binding (kbd "C-x x @")) 确实返回 tramp-revert-buffer-with-sudo。
  • tramp-dired-find-file-with-sudo（Emacs 31 新增）——在 Dired（dired-mode，Emacs 内置的目录浏览器）里，光标停在某一行上按 @，就用提权后的身份打开那个文件或目录。我实测 (lookup-key dired-mode-map (kbd "@")) 返回 tramp-dired-find-file-with-sudo。

它们用的提权方法由用户选项 tramp-file-name-with-method（Emacs 30 新增，默认 "sudo"）决定，Emacs 31 起这个选项可以设成连接局部变量——也就是说你可以让不同的连接用不同的提权方式。

还有个使用上的细节：tramp-revert-buffer-with-sudo 在「当前缓冲区既没有关联文件、又不是 Dired 缓冲区」时会什么都不做（不报错、也不提示），你按了键却像没反应。tramp-dired-find-file-with-sudo 更严格：它带一个 completion predicate（在 Mx TAB 补全时只列在 Dired 缓冲区里才有效的命令），所以你在普通文件缓冲区里 Mx 补全时根本看不到它。

易错

别把 Cx x @ 记成 Cx @。我在 Emacs 32.0.50 上查过，C-x @ 上什么都没有；三个键 C-x x @ 才是。这是 Emacs 31 才有的绑定，在 Emacs 30 及更早的版本上没有。

原书那个自定义命令：值得写，但要改一改

原书建议往 init.el 里加这段：

(defun sudo ()
  "Use TRAMP to `sudo' the current buffer."
  (interactive)
  (when buffer-file-name
    (find-alternate-file
     (concat "/su:root@localhost:" buffer-file-name))))

它的思路是对的：取当前 buffer-file-name（这个缓冲区正在访问的文件名），前面拼上提权前缀，然后用 find-alternate-file（另存为另一个文件，默认在当前缓冲区里问你要新名字，交互式调用时会用 set-visited-file-name 改掉当前缓冲区的文件名）打开。这招确实好使——它能保留你的窗口、光标位置、撤销历史、模式设置。

但原书这段有三个今天该改的地方：

  1. 函数名叫 sudo 太危险。这是个全局名字，跟将来任何可能定义 sudo 的包撞车，而且你在 Mx 里打 sudo 时会和别的候选打架。改成 my-sudo 或 sudo-file 这样的名字（注意别取 sudoedit，那是 Tramp 的一个方法名，容易混）。
  2. 没处理「当前缓冲区没有文件」的情况。原书用 (when buffer-file-name ...)，一旦你在 *scratch* 或某个 *Messages* 缓冲区里按 Mx，什么都不会发生，连个提示都没有。用 user-error 报错更友好。
  3. 今天你可以先试 Cx x @。如果当前缓冲区是 Dired，它会把 Dired 直接改成提权后的目录再 revert-buffer，比手写命令省事。如果当前文件已经是远程的，它调用的内部函数 tramp-file-name-with-sudo（把文件名转成带提权跳的多跳形式）会分情况处理：已经是该方法的文件原样不动；「远程的本机」会变成 /sudo:/etc/x 这种形式；方法支持多跳的会在前面加一跳；其余情况会直接报错（消息形如 Multi-hop with `ssh' not applicable）——所以它不是万能的，原书那个手写版本在远程文件上会拼出 /sudo:root@localhost:/ssh:box:/etc/foo 这种把远程路径当成本地路径的鬼东西，更糟。

所以我的建议版本是这样（放进你的 Emacs 配置文件，Emacs 配置文件一般指 init.el 或 early-init.el；改完存盘，然后在 Emacs 里按 Mx eval-buffer 回车，或者重启 Emacs 让它生效）：

(defun my-sudo ()
  "Re-visit the current file with root privileges, via Tramp."
  (interactive)
  (if buffer-file-name
      (find-alternate-file
       (concat "/su:root@localhost:" buffer-file-name))
    (user-error "这个缓冲区没有关联文件，提权不了")))

原书还有一句很好的话：这段 Elisp 是「学 Elisp 的很好的第一个练手」——它短、效果直观、而且你能立刻看出每一部分在干什么。如果你已经读完了第十二章（Emacs Lisp 编程入门），回头再看这段会有新的体会。

进阶：提权这一族现在有哪些成员，以及一个原书没提的安全限制

提权这一族现在有这些成员（我用 (mapcar #'car tramp-methods) 列出来核对过）：默认就启用的是 su、sudo、doas、sg、sudoedit；下面还列了几个 Emacs 30/31 新增的可选方法，它们默认不在 tramp-methods 里，得先 Mx tramp-enable-method 打开才会出现在这张表里：

  • su——调用系统的 su 程序。主机名只能是 localhost 或者 (system-name) 返回的本机名（除非走多跳）。
  • surs——上面那个的现代变体，底层是 Rust 重写的 su-rs。用法跟 su 完全一样，可以直接替换。但它是一个「可选方法」，默认没启用：要用得先执行 M-x tramp-enable-method 回车，然后输入 surs 再回车；想固定启用，在 Emacs 配置文件里写 (with-eval-after-load 'tramp (tramp-enable-method "surs"))。
  • sudo / sudors——sudors 是用 sudo-rs 的版本，同样是 Emacs 31 起新增的可选方法。sudo 方法要求你的账号必须有足够的权限去启动一个 shell，否则连不上。
  • doas——OpenBSD 的那套提权工具，行为跟 sudo 类似。
  • run0——systemd 体系自带的提权命令（Emacs 30 起新增，可选方法）。
  • sg——「换组」而不是换用户，把 user@ 那个位置写成组名。
  • androidsu——专门对付安卓上那些古怪的 su 实现（Emacs 30 起新增，可选方法；只在 android 系统上默认启用）。
  • ksu——另一个提权命令（ksu）的封装，也是 Emacs 30 起的可选方法（历史上是内置的，Emacs 30 把它改成了可选）。

还有一个今天必须知道的安全限制（原书完全没提）：出于安全考虑，sudo、doas、sudors、run0 这四个方法的连接会在一个预定义的超时之后自动断开（默认 5 分钟），之后你得重新连、重新输密码。这不是 bug，是设计——提权会话长期挂着风险太大。我逐个核对了 lisp/net/tramp-sh.el 里这些方法的定义，它们都带同一行 (tramp-session-timeout 300)。改法是设置连接属性 "session-timeout"（单位秒；设成 nil 表示禁用这个功能）：

;; 让提权连接 1 小时不断（默认 5 分钟就断）
(add-to-list 'tramp-connection-properties
             '("/su:" "session-timeout" (* 60 60)))

手册里还提到，这个超时在多数方法上是不设的（也就是说普通 ssh 连接不会自己断），手册点名有预定义值的是 sudo、doas、run0 三个；我把 lisp/net/tramp-sh.el 里所有 tramp-session-timeout 的出现位置都数了一遍，加上可选方法 sudors 也有同一行，所以源码里一共是四个。

四、多跳（Multi-hop）：穿过跳板机

临时写法：用 | 串起来

原书作者对这一点的判断是对的：他说多跳「通常通过改 tramp-default-proxies-alist 来做」，但他自己也承认「这个变量有点绕，临时写法反而更容易」。临时写法（官方叫 ad-hoc multi-hops）就是用竖线 | 把多段「方法:用户@主机」串起来：

C-x C-f /ssh:homer@powerplant|su:powerplant:/root/salary.txt RET

读法是：先以 homer 的身份 SSH 到 powerplant，然后在那台机器上再执行一次 su 提权，打开 /root/salary.txt。

易错

原书特别强调的那个坑，今天依然成立：第二跳里必须把主机名重复写一遍，也就是 |su:powerplant: 里的 powerplant 不能省。Tramp 手册里把机制说清楚了：su 这一跳要作用在「你刚登上的那台主机」上而不是本机，所以 Tramp 会检查「这一跳的主机名必须和上一跳的主机名相同」，对不上就报错。

还有两点限制：

  • 手册给 ad-hoc multi-hop 定的规则是：每一段都得由 Tramp 的 tramp-sh 后端处理——ssh、scp、su、sudo 这些都算；容器类方法（docker、podman）严格说不是 tramp-sh，但 Tramp 手册举的「同名容器并存」例子 /ssh:user1@host1|docker:name: 确实把 docker 放在了链的末端，所以实际能用。配 tramp-default-proxies-alist 时手册说得更死：PROXY 那个方法必须是 inline 方法——这条限制到今天还在手册里。版本差异：Emacs 31 的 NEWS 补了一条「external 方法现在也能用在多跳连接里了」，实现范围是 tramp-sh 系的方法，官方给的例子是 /scp:user@host|sudo::。所以「多跳里用不了 scp」这类说法只对 Emacs 30 及更早成立；你手上的版本够新就不用管这条。
  • 写完一次之后，Tramp 会把它作为一条临时记录加进 tramp-default-proxies-alist，本次 Emacs 会话里再连同一个主机就可以直接写简写 /ssh:homer@powerplant:/root/salary.txt 了。

Emacs 29 起就有的 tramp-show-ad-hoc-proxies（变量，默认 nil，我实测确认）控制临时定义怎么显示：设成非 nil，Tramp 就不把它折叠成简写，而是把完整的 | 链一直显示在文件名里（这个选项必须在连接建立之前设好才生效）。Emacs 31 在此之上才让「同一台远程主机上有很多个同名容器」的场景真正可用——官方给的例子是 /ssh:user1@host1|docker:name: 和 /ssh:user2@host2|docker:name: 可以并存，NEWS 里明确标注这个特性当时仍是实验性的。

固定写法：tramp-default-proxies-alist

如果这个跳转你天天用，就该写进配置。tramp-default-proxies-alist 是一个 alist，每一项是 (HOST USER PROXY) 三个正则/值：匹配到 HOST 且用户是 USER 的请求，就先走 PROXY 指定的跳板。默认值是 nil（我实测确认）。

手册 Multi-hops 一节给的例子之一是这样的：your.domain 这个域里的所有主机，你想以 root 登录，但 root 不允许从非本地登录：

(add-to-list 'tramp-default-proxies-alist
             '("\\.your\\.domain\\'" "\\`root\\'" "/ssh:%h:"))

于是你打开 /sudo:randomhost.your.domain: 时，Tramp 会先用你自己的账号 SSH 上去，再在那台机器上执行提权。PROXY 里的 %h 代表主机名、%u 代表用户名。

第二个例子更实用：所有非本机的主机，都先 SSH 再提权：

(add-to-list 'tramp-default-proxies-alist '(nil "\\`root\\'" "/ssh:%h:"))
;; 再加一条，把本机排除掉（否则你自己电脑上的提权也变成多跳了）
(add-to-list 'tramp-default-proxies-alist
             `(,(regexp-quote (system-name)) nil nil))

顺序有坑，值得强调：add-to-list 是往列表开头插的，所以源码里最后写的那一行 add-to-list，在列表里排最前、最先被匹配。上面这两行执行完，列表里确实是「本机那条在前（先匹配、豁免本机）、通配那条在后兜底」——这正是想要的效果。反过来如果你把两行调换过来，本机提权就会绕一圈 SSH。Tramp 手册的原话是「add-to-list adds elements at the beginning of a list. Therefore, most relevant rules must come last」，说的就是这个「源码里靠后 = 列表里靠前」的道理。

受限 shell 与跳板机

如果跳板机上跑的是 rbash（restricted bash，受限 shell，只能当跳板不能干别的），Tramp 可以知道这件事，让它只被当作跳板使用：

(add-to-list 'tramp-restricted-shell-hosts-alist
             "\\`bastion\\.your\\.domain\\'")

五、远程上能干的那些事

原书列了一张「我在远程上常用的命令」清单，我逐条在 Emacs 32.0.50 上确认过都还在，并且补上今天的注意事项。

  • Cx d（dired，目录浏览器）：因为 default-directory 是远程的，列出来的就是远端目录。甚至可以在两个 Dired 之间复制文件——一个 dired 缓冲区的 default-directory 是 /ssh:a@h:/x/，另一个是本机 ~/y/，在 dired 里按 m 标记文件、然后在另一个 dired 里按 C（复制），Tramp 会用 scp 或等价方式把文件搬过去，你完全感觉不到中间有个本地临时文件。
  • Mx compile（编译）：命令会在远端跑，输出进本地的 *compilation* 缓冲区。前缀参数在这里有两个完全不同的用法，值得当场说清「为什么同一个键敲两次会变成另一件事」。关键在于：前缀参数不一定是一个数字。本书作者在 Emacs 32.0.50 的 compile.el 里读到了它的 interactive 声明，是这么写的（变量名照抄源码）： 
    (interactive
 (list
  (let ((command (eval compile-command)))
    (if (or compilation-read-command current-prefix-arg)   ; 有前缀就问你
        (compilation-read-command command)
      command))
  (consp current-prefix-arg)))                              ; consp = 是不是「通用前缀」
    • Cu —— 前缀值是一个「有东西」的东西，于是第一个参数非 nil：总是提示你输入命令，不管 compile-command 设没设好。
    • Cu Cu —— 前缀值变成了列表而不是数字。Emacs 内部把这种特殊形态叫「通用前缀参数」（universal argument）。这正是 compile 用 (consp current-prefix-arg) 来认它、也正是它把第二个参数（comint）设成 t 的原因：*compilation* 缓冲区进入 comint 模式，成了可以直接敲命令的 REPL。
    所以「Cu 敲两次就变一件事」不是玄学：前缀参数这个位置能放三种东西——整数（Cu 3 传 3，表示次数）、列表（Cu Cu，表示「我就是要给你一个特殊标记，你自己看」）、符号 -（M-，表示负数方向）。命令用 consp / eq 这类判断就能把三种情况区分开。你只需要记住「Cu Cu 是给命令的一个信号，不是次数」，具体信号什么含义因命令而异——compile 拿它当「开 comint」，别的命令可能拿它当完全另一件事（本书附录那张速查表里还列了几个例子）。跑完按 Cx `（next-error）跳到下一个错误行——跳过去的就是远端文件。你甚至可以在远端跑那种带实时输出的服务，比如 make、python manage.py runserver、npm run dev。
  • Mx rgrep（递归 grep）：grep 命令在远端跑，结果在本地显示，结果里的文件名是可点击的超链接，点一下就在远端打开那个文件。它搜哪个目录，取决于弹出来的提示符：rgrep 会问 Base directory: ，默认值就是当前缓冲区的 default-directory——所以在一个远程缓冲区里按 Mx rgrep，它默认就搜远端，你顺手按回车就行。（没有 rgrep-default-directory 这个变量：我把 Emacs 32.0.50 的整个 lisp 目录 grep 过一遍，rgrep 现在是 grep.el 里的一个函数，(boundp 'rgrep-default-directory) 返回 nil。如果你在网上看到过这个变量名，那是更老的 rgrep.el 时代的说法。）
  • Mx shell：开一个远程登录 shell。补全是 Emacs 自己做的（不是 shell 做的），所以照样能用。
  • Mx eshell：Emacs 自己的 shell（用 Elisp 写的），也能直接 cd 进远程目录。
要点

eshell 走远程需要你手动加一个模块。我实测 (memq 'eshell-tramp eshell-modules-list) 默认是 nil。加上：

(add-to-list 'eshell-modules-list 'eshell-tramp)

加上之后的效果（下面是 Tramp 手册里的原文示例）：

~ $ cd /ssh:user@remotehost:/etc RET
/ssh:user@remotehost:/etc $ find-file shadow RET
File is not readable: /ssh:user@remotehost:/etc/shadow
/ssh:user@remotehost:/etc $ su - RET
/su:root@remotehost:/root $ id RET
uid=0(root) gid=0(root) groups=0(root)

也就是说 eshell 里的 su / sudo 是 Tramp 专门加的命令，会把 *eshell* 缓冲区的 default-directory 一起改掉——这正是这一章开头讲的那个机制在起作用。

进阶：远程进程的其他玩法，以及几个必须知道的坑

1. M&（async-shell-command，在 shell 里执行命令）。它也能在远端跑。手册给的例子：

C-x C-f /su:: RET
M-& tail -f /var/log/syslog.log RET

（版本差异：M& 现在绑的是异步版 async-shell-command；同步版 shell-command 今天只能在 Mx 里调，没有默认键位。手册那一节的标题沿用了 shell-command 这个老名字，但例子用的正是 M&。）输出进一个名字由 shell-command-buffer-name-async（默认 "*Async Shell Command*"）决定的缓冲区。也可以用 Mx auto-revert-tail-mode 看持续输出。

2. 远程调试器。Mx gdb 回车后输入 gdb -i=mi /ssh:host:~/myprog 就能远程调试。注意相对路径是基于远端默认目录的，调试目标必须写成远程路径，写本地路径会失败。会有个 warning: GDB: Failed to set controlling terminal 的警告，可以忽略。

3. 远程程序画本地窗口（X11 转发）。在本地配置文件里：

(add-to-list 'tramp-remote-process-environment
             (format "DISPLAY=%s" (getenv "DISPLAY")))

注意不能用 :0 这种简单名字，远端得能解析。另一条路是在 ~/.ssh/config 里写 ForwardX11 yes 或 ForwardX11Trusted yes；但这时候要把 tramp-use-connection-share 设成 nil，避免意外的副作用。

4. 远程 shell 历史文件会暴涨。Tramp 为了让 ~ 展开生效，会反复触发远程 shell 保存历史，~/.bash_history 可能一天涨几百 MB。设 tramp-histfile-override（默认 "~/.tramp_history"，我实测确认）来治：设成 t 表示关掉远程历史，设成 nil 表示完全不管 HISTFILE 由远程自己决定，设成一个路径就是重定向到那个文件。

5. 两台机器系统不同的时候要指定 shell。比如从 Linux 连 Windows，或者用 ksh 这种登录参数不一样的 shell，需要用连接局部变量（connection-local variable，只对某类连接生效的变量）：

(connection-local-set-profile-variables
 'remote-ksh
 '((explicit-shell-file-name . "/bin/ksh")
   (explicit-ksh-args . ("-i"))))

(connection-local-set-profiles
 '(:application tramp :protocol "ssh" :machine "mybsdhost")
 'remote-ksh)

6. 连接会卡死。网络断了的时候 ssh 会一直挂着，Tramp 无法安全地检测出来。解法在你的 ~/.ssh/config 里：

Host *
     ServerAliveInterval 5
     ServerAliveCountMax 2

PuTTY 用户在 Connection 里把 Seconds between keepalives 设成 5。

7. 连接不上的时候，先怀疑远程 shell 的提示符。Tramp 需要能干净地识别出「命令执行完了」的提示符。如果你远程的 zsh 开了行编辑器（它会同时画左右两个提示符），解析就废了。解法在 ~/.zshrc 里加：

[[ $TERM == "dumb" ]] && unsetopt zle && PS1='$ ' && return

它利用了 tramp-terminal-type（默认 "dumb"，我实测确认）这个值。检查方法：切到 *tramp/…* 那个连接缓冲区，光标放到最顶上，执行

(re-search-forward (concat tramp-shell-prompt-pattern "$"))

如果光标没跳到底部那行提示符，就是没认出来。

六、书签：给远程文件存个快捷方式

书签（bookmark，Emacs 给「一个命名位置」起的记号，比如「项目根目录」「配置文件第 42 行」）对远程文件一样有效。因为 default-directory 里带着完整的 /ssh:user@host: 前缀，重开时会自动重新连上——原书说 Tramp 会自动重连，这个说法今天依然成立。

易错

原书说用 Cx r l 重开书签。这条今天要改：Emacs 32.0.50 里 Cx r l 绑的是 bookmark-bmenu-list（书签菜单，弹出一个列出全部书签的缓冲区，回车选中即跳），不是原书时代的 bookmark-list。我实测确认：bookmark-list 这个函数在 Emacs 32.0.50 里已经不存在了（(fboundp 'bookmark-list) ⇒ nil）。那你今天还能不能敲出一个「书签列表」命令？能，但它是同一个东西的别名：源码 lisp/bookmark.el 里写着 (defalias 'list-bookmarks #'bookmark-bmenu-list)——list-bookmarks 指向的就是这个书签菜单，不是原书当年那种「列一个只读列表然后你去找」的另一个命令。所以键位不用改，只是你对它的期待要调整：它弹出来的是可操作的菜单（能改、能删），比「列一个列表然后你去找」更好用。

对多跳这种复杂路径，书签尤其省事——你不可能每次都手打 /ssh:homer@powerplant|su:powerplant:/root/salary.txt。

七、性能：Tramp 真正会卡的地方，以及今天怎么调

这一节是原书完全没有、但你今天一定会遇到的内容。Tramp 慢不是因为网络，而是因为它在后台做太多事：缓存文件属性、加锁、写自动保存文件、检查符号链接、跑版本控制、追踪连接过程。原话是 Tramp 手册 FAQ 里那句「TRAMP does many things in the background…During these operations, TRAMP's responsiveness slows down」。下面按「你看到的症状 → 对策」组织。

症状 1：打开大文件很慢

Tramp 有两类方法：inline（ssh、su 这些，数据编码成文本再传输）和 external（scp、rsync、rcp 这些，文件传输交给一个外部程序去做）。官方结论是：

  • 大文件用 external 更快，因为 inline 方式要额外做编码解码。例外是 scp：它传文件确实快，但启动时的加密握手开销会把这个优势吃掉，所以小文件用 inline 反而更快。inline 还有一个 external 没有的好处：它只开一条远程连接就一直复用，而 external 方法每次传文件都要新开一条通道。所以「一直编辑同一台机器上的很多小文件」用 ssh 最舒服，「偶尔拉一个几百兆的文件」用 scp / rsync 最舒服。而且这个切换是自动的：变量 tramp-copy-size-limit（默认 10240，即 10 KB，我实测确认）控制「多大的文件才值得启用 external 方法」，比它小的文件 Tramp 照样走 inline（用 external 方法做多跳时也一样，会退回它自带的 inline 方法）。
  • 想在 inline 下加速大文件：把 tramp-inline-compress-start-size（触发压缩的文件大小阈值，单位字节，默认 4096，也就是 4 KB，我实测确认）调小。它依赖远端有 tramp-inline-compress-commands 里列的压缩命令。
  • rsync 是 external 里的大文件利器：当文件两端都存在时它只传差异，比 scp 快得多；但如果文件只在一边存在（也就是第一次传），这个优势就没了。
  • 在两台远程服务器之间直接复制大文件：默认 Tramp 会先落到本地临时目录再传（因为认证问题），这会让你的本地临时目录爆掉。把 tramp-use-scp-direct-remote-copying（默认 nil，我实测确认）设成非 nil，Tramp 就会执行 scp -p -T -R -q -r source:/path target:/path 让两台机器直接对话。这有四个前提：scp 方法、源机器的 ~/.ssh/config 里没用 RemoteCommand、从本地和从源机器看到的目标机器的 host key 相同、以及源机器上的 scp 能免密登录目标机器。
技巧

想让大文件走哪条路，可以按主机配：

(add-to-list 'tramp-default-method-alist '("mybigbox" "" "scp"))
这行的意思是「对名为 mybigbox 的主机、不限用户，使用 scp 方法」。

症状 2：每次都重新输密码，连接复用没生效

这是最常见的一条。tramp-use-connection-share（连接复用开关，默认 t，我实测确认）控制 Tramp 怎么处理 OpenSSH 的 ControlMaster 连接复用。它有三个值：

  • t（默认）——用 ControlMaster=auto，但 Tramp 会覆盖你 ControlPath 的设置，以防「Emacs 外面开着的那个 master 连接已经没了」导致卡死。这就是为什么你明明 ssh 过，Emacs 里还要再输一次密码。
  • nil——完全不管 ControlMaster，你自己在 ~/.ssh/config 里配。如果你已经自己写好了正确的 ControlPath / ControlPersist，就设这个。
  • 就是符号 'suppress——反向：ControlMaster 被关掉。当多个进程并发读同一个 OpenSSH socket 会把 Emacs 卡住时用这个。手册明确说不需要长期设成 'suppress，只在调用 make-process 前临时绑定就行——Tramp 自己给编译进程就是这么做的。

另外两条硬性建议：用了 ProxyCommand 或 ProxyJump 的话，tramp-use-connection-share 一定要设成 nil 或 'suppress；MS Windows 上这个变量默认是 nil，因为 Windows 和 MSYS2 的 OpenSSH 对 ControlMaster 支持有问题（这时可以考虑 sshx / scpx 方法）。

想真正做到「我 ssh 一次，Emacs 里就免密」，需要给 Tramp 一个它认可的 ControlPath。手册给的写法是改 tramp-ssh-controlmaster-options：

(customize-set-variable
 'tramp-ssh-controlmaster-options
 (concat
  "-o ControlPath=/tmp/ssh-ControlPath-%%r@%%h:%%p "
  "-o ControlMaster=auto -o ControlPersist=yes"))

症状 2b：密码记不住——这一条和操作系统无关

上面那三条都在讲「连接复用」（能不能复用同一条 TCP 连接）。但「每次都要重输密码」还有另一半原因，跟 Windows、跟 PuTTY、跟 ControlMaster 都没关系——它是 Emacs 自己把密码忘了。所以你在任何系统上用 Mx tramp 都会遇到：输过的密码隔几十秒就要再输一次。

为什么会这样？看 Emacs 内置密码缓存的默认值就知道了。本书作者在本机 Emacs 32.0.50 的 password-cache.el 和 auth-source.el 源码里查到的三个默认值是：

三个密码缓存相关的变量，取值含义各不相同

按键命令作用
—password-cache-expiry（默认 16 秒）Emacs 内置的密码缓存只留 16 秒。文档字符串是 “How many seconds passwords are cached, or nil to disable expiring.”——设成 nil = 永不过期。16 秒这个默认值就是「Tramp 每次都问密码」的直接原因
—auth-source-do-cache（默认 t）Tramp 的密码走 auth-source 这一套。它是 布尔量，文档字符串是 “Whether auth-source should cache information with password-cache.”——设成 nil = 干脆不缓存，一次都不记。注意它和上面那个 nil 的含义正好相反：一个「永不过期」，一个「根本不缓存」。
—auth-source-cache-expiry（默认 7200 秒 = 2 小时）只对 auth-source 生效的时长覆盖，文档字符串是 “How many seconds passwords are cached, or nil to disable expiring. Overrides password-cache-expiry through a let-binding.”——设成 nil = 永不过期。这是你平时该调的那一个
易错

三个变量里有两个的 nil 表示「永不过期」，只有 auth-source-do-cache 的 nil 表示「不缓存」。同一个 token 在两个变量里意思相反，这是最容易配错的地方——所以照下面这张对照表记，不要凭直觉。

  • auth-source-cache-expiry：7200（默认，2 小时）／ 86400（1 天）／ nil（永不过期）。
  • password-cache-expiry：16（默认）／ nil（永不过期）。
  • auth-source-do-cache：t（默认，缓存）／ nil（完全不缓存）。只有两种取值，没有时长概念。

所以你要改的是 auth-source-cache-expiry，一行就够：

;; 密码记一整天（单位是秒，86400 = 24 小时）
(setq auth-source-cache-expiry 86400)

;; 或者：这一会话里永不过期（关掉 Emacs 就失效，比设成
;; 全局变量安全，所以更推荐临时这么用）
(let ((auth-source-cache-expiry nil))
  ;; 在这个作用域里做的 Tramp 操作都不再问密码
  (tramp "/ssh:you@host:/etc/hosts"))
要点

「延长密码记忆」和「免密登录」是两件事，别指望调这个就等于配好了密钥。上面这一段只解决「Emacs 忘了刚才输过的密码」；如果你想让下次开机、换个 Emacs 进程也完全不用输，那要配 SSH 密钥（ssh-keygen 生成 → ~/.ssh/config 里写 IdentityFile → ssh-copy-id 把公钥推上去）。两件事一起做才是你想要的体验：密钥解决「跨进程免密」，这一段解决「同一进程里别反复问」。

安全代价要说清楚：密码被 Emacs 缓存着，就等于以明文形式留在内存里。设成 86400 意味着一整天都这样；nil 意味着直到你退出 Emacs。共享机器上别这么设。

易错

注意上面那串里的百分号是两个：%%r、%%h、%%p。因为 Tramp 会用 format 处理这个字符串，单个 % 会被吃掉。这是官方文档里特意标注的。还有一条前提容易被忽略：这套写法只有 tramp-use-connection-share 是 t 时才生效（它的默认值在非 Windows 上就是 t，所以照抄能生效）。如果你已经把 tramp-use-connection-share 改成了 nil，那这段配置会被 Tramp 完全跳过，改了等于没改。

症状 3：跑远程命令（编译、测试、Magit）慢得离谱

这是「异步 Tramp」要解决的问题，也是这一节最值得你花时间的一条。

Tramp 实现 make-process 和 start-file-process（启动异步进程的两个底层函数）的方式很重：每启动一个进程，都要先开一个远程 shell、初始化环境、处理可能出现的密码/认证交互。但很多时候这些根本不需要——直接把命令跑起来就完事了。

Emacs 30 起提供了「直接异步进程」：把连接局部变量 tramp-direct-async-process 设成非 nil 就会启用。官方给的配置：

(connection-local-set-profile-variables
 'remote-direct-async-process
 '((tramp-direct-async-process . t)))

;; 只对 remotehost 这台机器生效：
(connection-local-set-profiles
 '(:application tramp :machine "remotehost")
 'remote-direct-async-process)

;; 或者对所有 ssh 连接都生效：
;; (connection-local-set-profiles
;;  '(:application tramp :protocol "ssh")
;;  'remote-direct-async-process)
要点

这是一个版本差异，务必注意。Emacs 30 之前，这个开关是一个叫 "direct-async-process" 的连接属性（connection property）；Emacs 30 起改成了连接局部变量 tramp-direct-async-process。旧写法仍然被支持，但已标记为废弃将来会删掉。网上（包括 Stack Overflow 上大量回答）讲的还是老写法，照抄会不生效。

它的限制（官方列的，抄下来免得你踩）：

  • 只对 tramp-adb.el、tramp-container.el、tramp-sh.el、tramp-sshfs.el 这几个文件里定义的方法有效。
  • 不支持交互式认证。所以你必须配好免密登录：ssh-agent、公钥认证，或者 ControlMaster。一次性密码、安全钥匙确认这类交互它处理不了。
  • 用了 RemoteCommand 选项的 ssh 方法不行。
  • 不能被 interrupt-process（中断进程）杀掉。
  • 不报告远程终端名（process-tty-name），也不设置 remote-pid 进程属性——所以没法给它发信号，信号会发给本地那个负责建连接的进程。
  • 命令太长时会失败（目录名很长、或远程 PATH 太长时可能触发）。
  • 多跳连接用不了这个，Tramp 会退回老实现。

要再快一点，官方建议调这两条：跑 make-process / start-file-process 期间把 tramp-verbose 绑到 0（tramp-verbose 是 Tramp 的日志详细度，官方文档列到 0 到 11，默认 3，我实测确认；只要 >= 4 就会额外往 *debug tramp/…* 缓冲区里写东西，那是给报 bug 用的，平时纯属浪费——再往上还有 10 = 报错时加 Lisp 回溯、11 = 写函数调用轨迹，都是维护者才需要的）；把 tramp-use-connection-share 设成 nil，绕开 Tramp 对 ControlMaster 的处理，自己在 ~/.ssh/config 里配。

症状 4：一开远程就感觉 Emacs 变「黏」了

这一堆都是后台开销，能关就关。下面每一条都注明了 Emacs 32.0.50 的实际默认值——都是我用 emacs --batch -Q 加载相应模块后查出来的（比如 auto-revert-remote-files 要 (require 'autorevert) 之后才 boundp 才为真，这一点新手很容易被坑到：-Q 下一大批用户选项显示成「void」不代表它不存在，只代表那个包还没被加载）：

变量（做什么的）今天默认值什么时候关
remote-file-name-inhibit-cache（远程文件属性缓存）10（秒）设成 nil 表示永不过期（最快，但远端被 Emacs 之外的东西改了也看不出来）。设成 t 是完全不用缓存（最安全，但慢）。设成数字 N 就是「缓存值只用 N 秒」，这是默认值。
remote-file-name-inhibit-locks（远端锁文件）nil（会建）确定不会有第二个 Emacs 同时改同一个远端文件时，设 t 省掉建锁的开销。
remote-file-name-inhibit-auto-save（远端自动保存）nil（会存）「保留自动保存文件在本地」本来就是默认行为，别改。真要关（比如安全考虑）设 t，但想清楚后果。只想对某类连接关，用连接局部变量改 buffer-auto-save-file-name。
auto-revert-remote-files（自动回读远端文件）nil（不检查）Emacs 的 auto-revert 模式默认不检查远端文件，因为太慢。这已经是推荐值，别动。
enable-remote-dir-locals（远端目录局部变量）nil（不加载）同上，已经是推荐值。想开的话记得同时改 safe-local-variable-directories，这是安全相关的，不建议随手开。
dired-check-symlinks（Dired 里检查符号链接有效性）t（会检查）Emacs 31 起可以关，而且官方推荐用连接局部变量只对慢的机器关：
(connection-local-set-profile-variables
 'my-dired-profile '((dired-check-symlinks . nil)))
(connection-local-set-profiles
 '(:application tramp :machine "slowbox") 'my-dired-profile)
tramp-verbose（日志详细度）3平时别高于 3。报 bug 时才调到 6（官方要求），然后看 *debug tramp/…* 缓冲区。
shell-history-file-name（shell 读哪个历史文件）nil（读环境的 HISTFILE）设成 t 表示「不读任何历史文件」，可以让 Mx shell 启动时不去读远端那个可能很大的文件。设成字符串就是指定读哪个文件（源码见 lisp/shell.el：字符串=用这个文件，nil=用 HISTFILE，t=不用）。

还有两条跟版本控制有关：如果你完全不用远端版本控制，把 vc-ignore-dir-regexp 扩成也匹配 Tramp 路径，能省掉每个文件都去问一遍「这是不是个仓库」的代价：

(setq vc-ignore-dir-regexp
      (format "\\(%s\\)\\|\\(%s\\)"
              vc-ignore-dir-regexp
              tramp-file-name-regexp))

但这太粗暴了（会连远端 Git 一起关掉）。想保留远端 Git 的话，官方建议改成只留你关心的后端：

(setq vc-handled-backends '(Git))

最后一条：GNU ELPA 上有个叫 tramp-hlo 的第三方包（包描述原文是「High level operations as Tramp handlers」，不是 Emacs 自带的；我在 2026-10-02 拉取了 elpa.gnu.org 的 archive-contents 确认它确实在列，同一份列表里 Tramp 相关的包共四个：tramp、tramp-hlo、tramp-nspawn、tramp-theme）。它把一批「本来要跟远端来回问好几次」的 Emacs 标准库函数改成一次往返的 Tramp 操作，按它的 README 明确针对的就是 locate-dominating-file（找项目根目录）和 dir-locals（目录局部变量）——这两个在打开远程文件时会被反复调用。装完别忘了启用：Mx tramp-hlo-setup 回车（或者在配置文件里加 (tramp-hlo-setup)）；Mx tramp-hlo-remove 是关掉。

技巧

如果你的 Emacs根本不用远程文件（比如只写本地代码），Emacs 30 新增了两个东西能把「每次拼文件名都要先问一遍 Tramp 要不要接管」这个开销彻底去掉：Mx inhibit-remote-files（命令，关掉魔法文件名处理）以及 without-remote-files（宏，把一段代码包起来，在里面临时关掉）。官方描述是「slightly improved performance of file name handling」。对纯本地用户来说这是白捡的。

症状 5：Magit 在远程仓库上卡住

如果你在远程仓库里用 Magit（Magit 是最常用的 Emacs Git 界面，第三方包，MELPA 和 ELPA 都有，官方文档 https://magit.vc.gnu.org/），有一个非常具体、非常容易撞上的坑。我读了本机装的 Magit 4.7.1 的源码（(defvar magit-version "4.7.1") 见 magit.el；magit-tramp-pipe-stty-settings 定义在 magit-process.el，下面那三个则定义在 magit-git.el），magit-tramp-pipe-stty-settings 这个变量的文档字符串把整件事讲清楚了：

  • Tramp 变量 tramp-pipe-stty-settings（管道进程的终端设置，默认值 "-icanon min 1 time 0"，Emacs 29.3 起引入，我核对了 lisp/net/tramp-sh.el 的 defcustom）会让 stage hunk（把某个 diff 片段加入暂存区，也就是 Magit 里按 s 或在 *magit* 缓冲区里暂存修改）挂住不动。
  • Magit 用 magit-tramp-pipe-stty-settings（默认 ""）覆盖了 Tramp 的这个默认值来绕开它。
  • 但是：如果你给连接开了 tramp-direct-async-process，就必须把 magit-tramp-pipe-stty-settings 设成 'pty，否则 stage hunk 一样会挂（Magit 源码里引用了 issue #5220）。
;; 配了 tramp-direct-async-process 之后，Magit 这行是必须的：
(setq magit-tramp-pipe-stty-settings 'pty)

Magit 跟 Tramp 有关的另外三个设置（同样来自源码）：

  • magit-remote-git-executable（默认 "git"，Magit 3.2.0 起有）——远端机器上的 git 可执行文件名。它的文档字符串明确说：优先考虑改 tramp-remote-path 而不是改这个变量。tramp-remote-path 是 Tramp 搜索远端可执行文件的路径清单：它的第一项是特殊值 tramp-default-remote-path（代表远端 getconf PATH 给出的那批默认目录，远端没有 getconf 时就是 /bin:/usr/bin），后面跟着你系统特有的那些 /usr/local/bin、/opt/homebrew/bin 之类的目录。
  • magit-git-global-arguments（Magit 4.3.2 起有）——Magit 每次调 git 都加的参数，当前默认值是 ("--no-pager" "--literal-pathspecs" "-c" "core.preloadIndex=true" "-c" "log.showSignature=false" "-c" "color.ui=false" "-c" "color.diff=false" "-c" "diff.noPrefix=false")。它的文档字符串里有一句专门给 Tramp 用户的警告：如果你用 Tramp 连的服务器 git 版本很老，加参数要极其小心，永远不要删掉默认值里的任何东西。
  • Git hooks 不走 Tramp。magit-run-hooks-from-githooks（Magit 4.6.0 起有，默认 t）的文档字符串说：Git hook 只能在「Magit 在本机异步调 Git」且 git 至少 2.54.0 时才回跑到 Emacs。也就是说你在远程仓库上用 Magit 提交时，Magit 的 git hook 回调不会触发。这不是配错了，是架构决定的。
要点

你可能在别处看到过「Magit 跑在 Tramp 上要加 git --no-optional-locks」的说法。我把本机装的 Magit 4.7.1 里每一个 .el 源码文件都 grep 过，没有任何一个文件里出现过 --no-optional-locks 或 OPTIONAL_LOCKS。当前 Magit 默认没加这个参数（我 grep 的是本机装的 4.7.1 全部 .el 文件；文档字符串、NEWS 与默认值都逐条对过）。你当然可以通过 magit-git-global-arguments 自己加（用 add-to-list 追加），但那是你自己的取舍，不是 Magit 的官方要求——而且它自己的文档明确警告过通过 Tramp 时不要随便动这一项。真要解决远程 Magit 慢的问题，杠杆最大的仍然是 Tramp 那边：tramp-direct-async-process 加上 magit-tramp-pipe-stty-settings 设成 'pty。

八、EWW：Emacs 内置的那个网页浏览器

它是什么，以及为什么它存在

原书开头引了一条 Zawinski 定律（Jacob Zawinski 提的程序员定律）：「每个程序都在不断膨胀，直到它能读邮件为止；不能读邮件的那些程序，会被能读邮件的替代掉。」Emacs 当年为了不输，内置了好几个邮件客户端。EWW 是在这个传统上继续膨胀的产物——既然都要读邮件了，那顺便把网页也读了。

EWW = Emacs Web Wowser。它是 Emacs 内建的包（eww.el，随 Emacs 一起发布，不需要装）。它的工作方式是：用 shr.el（另一个内建包，文件头写的是 Simple HTML Renderer）把网页下载下来、解析成文本，再塞进一个普通的 Emacs 缓冲区显示出来。图片能内联显示（如果你的 Emacs 编译时带图像支持的话）。

要点

EWW 的渲染器有两个硬性天花板，这是理解它今天定位的关键：

  • 不支持 CSS，也不支持 JavaScript。官方 EWW 手册的原话：「It can display images inline… but there is no support for CSS or JavaScript.」2010 年代的网站排版靠 CSS，交互靠 JavaScript——这两样都没有，意味着今天的大多数网站在 EWW 里会显示成「一堆没样式的链接列表」。
  • 需要 Emacs 编译时带 libxml2 支持。官方 EWW 手册明确写了 「you need to use an Emacs built with 'libxml2' support」。怎么查？按 M-（eval-expression，就是求值一行 Elisp）然后输入这一行回车：
    (fboundp 'libxml-parse-html-region)
    返回 t 就说明你的 Emacs 带 libxml2，返回 nil 就是编译时没带（fboundp 是 Elisp 内置函数，问「这个名字背后有没有函数定义」）。我用它在 emacs --batch -Q 里实测过这台机器的 Emacs 32.0.50，返回 t，所以 EWW 在这台机器上能用。不要用 Mx f（find-function）去查这个符号：它是 Emacs 用 C 写的内置函数，没有对应的 Elisp 源码文件可跳。我实测 (symbol-file 'libxml-parse-html-region) 返回 nil。如果你打开 EWW 报 This function requires Emacs to be compiled with libxml2 之类的错（源码 lisp/net/eww.el 里那句 (error …) 就是它抛的），就是编译时没带，只能换 Emacs 安装包的人补上，跟你的配置无关。

怎么用：三个入口

  • Mx eww 回车，然后输入一个 URL 或者一个搜索词。如果输入的东西看起来不像 URL 或域名，Emacs 会当成搜索词，去 eww-search-prefix（搜索前缀，我实测当前值是 "https://duckduckgo.com/html/?q="，也就是默认搜索引擎 DuckDuckGo）指定的引擎搜。想换引擎就 Ch v 查 eww-search-prefix 改掉。这个提示符还带 TAB 补全（Emacs 30 加的），会从 eww-suggest-uris 建议的历史 URL 和书签里补。
  • Cu Mx eww 回车——Emacs 27 起，即使已经有一个 EWW 缓冲区了也新开一个。原书说的就是这个（它写的是「Starting with Emacs 27」），今天依然成立。Emacs 30 起 eww-open-file 也支持前缀参数了。
  • Mx eww-open-file 回车——用 EWW 打开一个本地文件（也支持 file:// 前缀）。

打开之后：q 退出；g 重新加载当前页。

要点

q 退出这件事有个今天才知道的细节：q 并不是绑在 EWW 自己的 eww-mode-map 上的（我 dump 过这个 keymap，里面没有 q）。它是从 special-mode 继承来的 quit-window——eww-mode 是用 define-derived-mode 从 special-mode 派生的。

而 EWW 官方手册里那句「or exit the browser by calling 'eww-quit'」提到的 eww-quit 命令，在 Emacs 32.0.50 的 eww.el 里已经彻底找不到了（我实测 (fboundp 'eww-quit) 返回 nil，并且在整个 lisp/net/ 目录里 grep 不到这个名字）。这是随包文档比代码超前的例子——所以你要退出 EWW，就按 q，别去 Mx 里找 eww-quit。

易错

原书关于 EWW 的两处错误，今天要改。

  1. Ms Mw 不是「在 EWW 里搜索选区」。原书说 M-s M-w 是 isearch-eww，而 isearch-eww 这个命令在 Emacs 32.0.50 里已经完全不存在了（我实测 (fboundp 'isearch-eww) 返回 nil，并且在整个 lisp 目录里 grep 不到任何定义）。现在 M-s M-w 绑的是 eww-search-words：它把选中的文字拼到 eww-search-prefix 后面丢给搜索引擎，是一个全局命令（在 EWW 缓冲区外面也能用），跟「搜索当前页面」毫无关系。在 EWW 页面里搜东西，用 Cs。顺便说，EWW 现在还支持「多缓冲区连续搜索」：如果你开了多个 EWW 页面，C-s 在当前页找不到时会自动跳到下一页继续找，机制是 EWW 把 eww-isearch-next-buffer 挂到了 multi-isearch-next-buffer-function 这个变量上。
  2. Ms 本身也不再是「开始增量搜索」。原书写这本书的时候，M-s 是 isearch-forward 的全局绑定。今天（Emacs 31/32）M-s 是一个前缀键（search-map），启动增量搜索只用 Cs（向前）和 Cr（向后）。我做了三重核对：(key-binding (kbd "M-s")) 返回的是一个 keymap；(where-is-internal 'isearch-forward) 只返回 C-s 和菜单栏；随包安装的 Emacs 32.0.50 手册 (emacs) Incremental Search 一节里也只列了 Cs 和 Cr。所以 M-s 现在是 M-s w（按词搜）、M-s .（搜光标附近的东西）、M-s h r（高亮正则）这类命令的前缀。

今天的诚实评估：EWW 值得投入多少？

我按「它今天能干什么、不能干什么、替代品是什么」来说，不吹也不贬。

EWW 至今仍在维护。我翻了随 Emacs 一起安装的 NEWS.30 和 NEWS.31，里面都有 EWW 的条目（Emacs 30 给它加了鼠标可点的表单按钮、eww-open-file 的新缓冲区参数、提示符补全、eww-copy-alternate-url、以及历史导航行为的修正；Emacs 31 继续加）。EWW 官方手册的版权年份是 2026。所以它不是被弃用的东西。

但它的定位确实变了。因为没有 CSS 和 JavaScript，EWW 今天不适合当通用浏览器——你用它开 GitHub、开现代文档站，看到的都是一堆散乱的文字和链接。对这类页面，正确做法是让 Emacs 把它交给外部浏览器。

Emacs 里「交给外部浏览器」这件事该由谁做？答案是 browse-url 这一套（Browse-URL，Emacs 内置的 URL 分发器）。原书说 Mx browse-url 会用 browse-url-default-browser 这个变量来「猜」该用哪个浏览器——这个说法今天要精确一点：

  • browse-url-browser-function（主浏览器分发函数）才是控制开关，它的默认值就是 browse-url-default-browser——也就是原书说的那个「按操作系统和已装浏览器猜一个」的内建函数（我实测确认了这个默认值关系：(symbol-value 'browse-url-browser-function) 就是符号 browse-url-default-browser）。原书说 Mx customize-option 然后输 browse-url-default-browser，这一步今天做不到了：它不是一个用户选项，而是一个普通函数（源码 lisp/net/browse-url.el 里的 (defun browse-url-default-browser (url &rest args) …)），所以你在 Customize 里根本找不到它。要改的是下面那两个变量。想定制「URL 怎么打开」的整体策略（比如按域名分流），该改 browse-url-browser-function 和 browse-url-handlers。
  • browse-url-secondary-browser-function（第二选择）默认值也是 browse-url-default-browser；EWW 里那个 & 键用的就是它。
  • browse-url-at-point / browse-url-at-mouse（打开光标处 / 鼠标处的链接）——这两个才是你真正常用的，值得绑键。
技巧

如果你今天只从 EWW 这节里带走一样东西，就带走这个：把「打开链接」绑个键。鼠标党绑 (global-set-key (kbd "C-c C-o") #'browse-url-at-mouse)（按键前把鼠标指针放到链接上就行）；键盘党绑 (global-set-key (kbd "C-c C-o") #'browse-url-at-point)（把光标移到 URL 上）。这样在 Emacs 里看到任何 URL，两下就开了，Emacs 只负责启动浏览器。这才是 2020 年以后 Emacs 处理网页的正确姿势；EWW 留给「纯文本内容」和「快速搜一下」。

EWW 今天还剩哪些真正好用的场景？

  1. 看纯文本和结构简单的 HTML。Emacs 官方手册、手册的 HTML 版本、很多技术文档站的老页面、纯文本邮件的 web 版——这些在 EWW 里读起来意外地舒服，因为没有 CSS 意味着没有花里胡哨的干扰。
  2. 按 R 的阅读模式。eww-readable 会自动判断页面里哪部分是正文、把导航菜单之类全去掉，只留正文。对长文章挺好用。你还可以用 eww-readable-urls 规定「哪些站点默认就用阅读模式打开」。
  3. PDF 直接内联看。EWW 默认用 doc-view-mode（Doc-view 模式，也就是第九章讲过的那种 PDF 阅读模式）显示 PDF。这个配合很顺手。
  4. 把 EWW 设成某些内容类型的专用浏览器。eww-use-external-browser-for-content-type（默认值 "\\`\\(video/\\|audio/\\|application/ogg\\)"，我实测确认）是匹配内容类型的正则，命中的直接甩给外部浏览器。视频音频在 Emacs 里本来就没意义。
  5. 隐私场景（要打折听）。原书半开玩笑说 EWW 适合看「你不想让老板看见的网站」。「不留痕」这半句今天不能打包票：EWW 走的是 HTTP 请求，照样会带 cookie（C 列出来的就是 url 包存下的那些，通常很少；真正落盘的位置由用户选项 url-cookie-file 决定，默认值是 nil，也就是不落盘，但你自己设过就会留痕），eww-history 里也留着访问过的 URL（缓冲区一关就没了，但 Emacs 的 recentf 之类的机制另说）。EWW 真正省掉的是 JavaScript 那一整套追踪机制——没有 JS 就没有指纹脚本、没有追踪像素、没有 navigator 可读。这一点是真的，也确实是它比 WebKit 干净的地方。
  6. 从 Dired 里用浏览器看文件。dired-do-eww（Emacs 29 新增，见 NEWS.29；它是 内建于 dired.el 本身的，不是 dired-x.el——我实测 (fboundp 'dired-do-eww) 在只 (require 'dired) 之后就返回 t）在 Dired 里对当前行的文件用 EWW 打开。

如果你想要「在 Emacs 里看真·网页」，那要看 xwidget。Emacs 25.1 就内建了 xwidget.el（NEWS.25 里明写「Xwidgets: a new feature for embedding native widgets inside Emacs buffers」），可以在 Emacs 缓冲区里嵌一个真的浏览器控件。命令是 Mx xwidget-webkit-browse-url（它默认用光标附近或选区里的 URL）。但它有硬前提：Emacs 编译时必须带 WebKit2GTK——注意这个门槛是 Emacs 26.1 才抬起来的（NEWS.26：--with-xwidgets 从此要求 WebKit2，之前只要 WebKitGTK）。能不能用，取决于你的 Emacs 怎么编译的，不是你能在配置里打开的。判断方法有两个。一是看那个变量：system-configuration-features（从 Emacs 25 起就有的一个变量，NEWS.25 原话是「listing some of the main features that Emacs was compiled with」）里列出编译时的特性，按 Ch v 输入它回车，看里面有没有 WEBKIT；或者在 Mx eval-expression 里执行 system-configuration-features（它是变量，所以要用 C-h v 查或用 eval-expression 求值，Mx 直接敲不行——那是在调命令）。二是直接试：按 Mx xwidget-webkit-browse-url，能弹出一个真的网页窗口就说明带了。（注意 (fboundp 'xwidget-webkit-browse-url) 这个命令本身永远是 t——xwidget.el 不管有没有 WebKit2GTK 都会把函数定义加载进来，所以用 fboundp 判断这个是判断不出来的，必须真的去调用它、看它报不报错。）

要点

用 xwidget 有个安全默认值要知道：WebKit 缓冲区里 JavaScript 默认是开的，而网站常用它来追踪你。Emacs 提供了 xwidget-webkit-disable-javascript 变量来关掉它（改完要杀掉所有 WebKit 缓冲区才生效）。我核对了随包的 cus-start.el，这个选项是 Emacs 30.1 起新增的。经验上，开了 xwidget 之后第一件事就是把它设成 t。

  • w xwidget-webkit-current-url、+ / - 缩放
  • e xwidget-webkit-edit-mode（让普通按键原样传给网页，你就能在网页输入框里打字了）
  • Cs / Cr xwidget-webkit-isearch-mode（专门在网页内容里搜索的增量搜索，Cs 下一页、Cr 上一页，Cg 退出）
  • H xwidget-webkit-browse-history（浏览历史）、SPC 向上滚、S-SPC 和 DEL 向下滚

注意 Cs 在这里是网页内搜索，而不是缓冲区文本搜索——这正好和 EWW 里 Cs 搜的是 EWW 渲染出来的文本一样。两者的心智模型是一致的：Cs 搜「你看到的东西」。

EWW 的几个进阶变量（都在 eww.el 里，我逐个实测过默认值）：

  • eww-history-limit（默认 50）——历史里最多留多少页。EWW 会把每页的渲染结果和源码都留在内存里，所以这个值调大内存吃得很快。设成 nil 表示不限制（不建议）。注意历史在退出 EWW 后就丢了。
  • eww-auto-rename-buffer（默认 nil）+ eww-buffer-name-length（默认 40）——让 EWW 缓冲区自动改名成网页标题而不是 *eww*。
  • eww-download-directory——d 下载的落地目录，默认优先 ~/Downloads/，没有就用 XDG 的 DOWNLOAD 目录。
  • eww-url-transformers（Emacs 29 新增）——改写页面里 URL 的函数列表。
  • eww-before-browse-history-function——Emacs 30 改了历史行为：从一个「历史页面」跳去新页面时会先删掉比它新的历史项（和主流浏览器一致）。设成 'ignore 可以改成不删、直接插到最前面。
  • eww-use-browse-url（默认正则 "\\`mailto:"）——匹配这个正则的链接不交给 EWW 自己处理，走 browse-url（比如点 mailto: 邮件链接会打开写信界面）。
  • eww-search-confirm-send-region——Ms Mw 把选区发去搜索引擎之前要不要问一声。

PDF 与 mailcap：EWW 默认用 doc-view-mode 看 PDF，但这是可以用 mailcap（mailcap-mime-data，Emacs 用来决定「这种 MIME 类型的文件交给谁处理」的机制）改的。如果你已经配置了 mailcap，EWW 会尊重它。

九、练习

练习 1　你要以 root 身份编辑本机的 /etc/fstab。敲出完整的 Cx Cf 路径。接着，这个缓冲区的 default-directory 会变成什么？（提示：实际值比你写的字符串更完整，Tramp 会替你把 root@ 和本机主机名都补上。）

敲 Cx Cf 然后输入 /su::/etc/fstab 回车。打开后按 Ch v 输入 default-directory，你会看到形如 /su:root@你的主机名:/etc/ 的值——su 方法把空的 user@ 补成 root，把空的主机名补成 (system-name)。实测：(file-remote-p "/su::/etc/passwd") ⇒ #("/su:root@你的主机名:" 4 8 (tramp-default t) 9 27 (tramp-default t))。别被 #(...) 骗了：它的类型是字符串（(type-of ...) ⇒ string），Emacs 只是因为它带了 tramp-default 这个 text property 才用向量式的打印法显示。

练习 2　你要 SSH 到 powerplant（用户 homer），然后在那台机器上提权打开 /root/salary.txt。写出这个临时多跳路径。注意原书在这里专门点了一个坑。

/ssh:homer@powerplant|su:powerplant:/root/salary.txt。用竖线 | 分隔每一跳，第二跳里必须把主机名 powerplant 再写一遍——Tramp 会检查这一跳的主机名和上一跳是否一致，为的是保证提权作用在「你刚登上的那台机器」上而不是本机。

练习 3　原书说可以用 Cx r l 重开一个书签。在 Emacs 32.0.50 上这个键实际绑的是什么命令？原来的那个命令名还存在吗？

实测 (key-binding (kbd "C-x r l")) ⇒ bookmark-bmenu-list（书签菜单，弹出一个列出全部书签的缓冲区）。(fboundp 'bookmark-list) ⇒ nil，这个命令已经不存在。今天的替代品 list-bookmarks 并不是另一个命令——lisp/bookmark.el 里写的是 (defalias 'list-bookmarks #'bookmark-bmenu-list)，它就是同一个书签菜单的别名。要按名字跳到某个书签用 Cx r b（bookmark-jump）。

练习 4　原书说在 EWW 里 Ms Mw 可以在页面上搜索选区。今天在 Emacs 32.0.50 上按 Ms Mw 会发生什么？Ms Mw 之外，想在 EWW 页面里搜东西该按什么？

实测 (key-binding (kbd "M-s M-w")) ⇒ eww-search-words，它是一个全局命令，作用是把选区（或提示你输入的词）拼到 eww-search-prefix 后面丢给搜索引擎，跟「搜索当前页面」毫无关系。原来的 isearch-eww 已经被删除（(fboundp 'isearch-eww) ⇒ nil）。在 EWW 页面里搜索要用 Cs（isearch-forward）；开了多个 EWW 页面时它还能自动跨页继续找。

练习 5　你已经在一个远程缓冲区里了（比如 /ssh:box:/etc/），现在想改用 root 身份编辑当前文件。Emacs 31 起有一个专门的命令，它绑在哪个键上？如果想用 su 而不是默认的提权方式，该怎么按？

绑在 Cx x @（三个键），命令是 tramp-revert-buffer-with-sudo。实测 (key-binding (kbd "C-x x @")) ⇒ tramp-revert-buffer-with-sudo。换方法就按前缀 Cu：Cu Cx x @。这个绑定是 Emacs 31 才有的，Emacs 30 及更早没有。

练习 6　remote-file-name-inhibit-cache 这个变量在 Emacs 32.0.50 上的默认值是什么？把它设成 nil 是什么含义（很多人会理解反）？

实测默认值是 10（数字，单位秒），含义是「缓存的文件属性只用 10 秒，之后重新问远端」。设成 nil 是「永不过期」——不是「不用缓存」，而是「一直信缓存」，最快，但远端被 Emacs 之外的东西改了 Emacs 也发现不了。设成 t 才是「完全不用缓存」，最安全但最慢。

练习 7　你在远程仓库里用 Magit，发现按 s 暂存 hunk 一直挂着没反应。你查了 Magit 源码，发现这和 Tramp 的 tramp-pipe-stty-settings 有关。Magit 提供了哪个变量来绕开它？而如果你同时又给连接开了 tramp-direct-async-process，还需要额外做什么？

Magit 提供了 magit-tramp-pipe-stty-settings，默认 ""，用来在 magit-start-process 里覆盖 Tramp 的 tramp-pipe-stty-settings（Tramp 那个默认是 "-icanon min 1 time 0"）。但如果你同时开了 tramp-direct-async-process，这个绕法会失效，必须改成 'pty：

(setq magit-tramp-pipe-stty-settings 'pty)
Magit 源码里引用了它的 issue #5220 说的就是这件事。

练习 8　EWW 里按 & 会用外部浏览器打开当前页。它用的是哪个变量？而你如果想控制 Emacs 里「所有 URL 都怎么打开」，该改的又是哪个变量？

& 用的（经由 EWW 的 eww-browse-with-external-browser）是 browse-url-secondary-browser-function，实测它的默认值也是 browse-url-default-browser。控制全局策略该改的是 browse-url-browser-function（主分发函数，实测它的默认值就是 browse-url-default-browser）以及 browse-url-handlers。日常真正该绑键的是 browse-url-at-point。

练习 9　在 Emacs 32.0.50 上，怎么用一条命令列出 Tramp 当前支持的所有连接方法名？本机一共有多少个？（提示：一个变量，在 Emacs 启动时就已经有值了，不需要 require 任何东西。）

变量是 tramp-methods。它是个 alist（关联表，一串「键 . 值」的配对列表）：每一项都是 (方法名 . 方法参数) 的 cons 单元，car 拿到方法名、cdr 拿到一串 plist（属性列表，即「属性名 . 属性值」两两成对的列表，比如 (tramp-login-program "ssh")）。要说清楚一点：外层是 alist，只有每一项的 cdr 才是 plist——这一条我实测打印过这个变量的开头几百个字符确认过（形如 ((adb (tramp-login-program adb) (tramp-login-args ((-s %d) (shell))) …) (kubernetes …) …)）。命令是在 Mx eval-expression 里执行这一句——car 之所以正好能取到方法名，正是因为外层是 alist 而不是 plist：

(sort (mapcar #'car tramp-methods) #'string<)

我实测结果是 37 项，其中 36 个是真正的方法，另有 1 个伪方法 -（表示「这一段不写方法名」，见正文「坑一」）：- adb afp dav davs doas docker dockercp ftp gdrive kubernetes mtp nextcloud plink plinkx podman podmancp pscp psftp rclone rcp remcp remsh rsh rsync scp scpx sftp sg smb ssh sshfs sshx su sudo sudoedit telnet。另外几个（surs、sudors、run0、androidsu、ksu 等）是默认没启用的可选方法，列不进这张表，用 Mx tramp-enable-method 打开之后才会出现。注意这是 Emacs 32.0.50 自带的 Tramp 2.8.3-pre；你从 ELPA 装的新版 Tramp 可能更多。

练习 10　在 Cx Cf 提示符里删字符时，打两个斜杠 // 和打一个斜杠 / 行为一样吗？在 Tramp 路径里 // 到底删掉的是哪一段？

不一样。Emacs 的 minibuffer 文件名补全里，// 有特殊含义：Tramp 手册的原话是它「只杀掉 TRAMP 文件名语法里的文件名部分」——也就是说，被删掉的是 /ssh:user@host: 后面那一段路径，/ssh:user@host: 这个远程前缀会被保留下来。三个斜杠 /// 则「表示默认行为」，按平常的删除规则走，连远程前缀也一起删掉。手册给的对照：/ssh:melancholia:/usr/local/bin//etc 补全后是 /ssh:melancholia:/etc（只掉了 /usr/local/bin），而 /ssh:melancholia:/usr/local/bin///etc 补全后是 /etc（整个远程前缀连路径一起没了）。

本章要点回顾

  1. Tramp 的机制就一句话：default-directory 被改写成远程路径，所有文件操作从它出发，于是全部落到远端。按 Ch v 查这个变量是理解一切的钥匙。
  2. 路径语法 /method:[user@]host[#port]:path，第二个冒号之后才真的开始连线。默认方法是 scp（不是 ssh）。
  3. 提权：路径写法 /su::/etc/fstab；更省事的是 tramp-revert-buffer-with-sudo（命令 Emacs 30 起有，Emacs 31 起绑在 Cx x @）和 Dired 里的 @（tramp-dired-find-file-with-sudo，Emacs 31 新增）。提权连接 5 分钟后会自动断开，可用连接属性 "session-timeout" 改。
  4. 多跳：临时用 | 串（第二跳必须重复主机名），固定用 tramp-default-proxies-alist（最一般的那条要最后 add-to-list，因为它是往列表头插的；本机要单独加一条豁免掉）。
  5. 性能：大文件用 external 方法或调小 tramp-inline-compress-start-size（默认 4096）；连接复用用 tramp-use-connection-share（t / nil / 'suppress）；跑远程命令开 连接局部变量 tramp-direct-async-process（Emacs 30 起的写法，旧的连接属性已废弃）；Magit 要配 (setq magit-tramp-pipe-stty-settings 'pty)；关掉锁、符号链接检查、版本控制探测等一堆后台开销；用完记得 tramp-cleanup-bufferless-connections。
  6. EWW 是内建的纯文本浏览器，没有 CSS 和 JavaScript，需要 libxml2。今天它适合读纯文本/简单 HTML、按 R 阅读模式、快速搜索；通用网页请用 browse-url 交给外部浏览器，值得绑键的是 browse-url-at-point。想要 Emacs 里的真浏览器看 xwidget（需要 Emacs 编译时带 WebKit2GTK，且记得关 JavaScript）。原书关于 Ms Mw 和 Cx r l 的两处说法今天都不成立了。
