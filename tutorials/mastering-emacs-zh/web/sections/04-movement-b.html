四、移动理论（二）：基本移动、书签寄存器、选区

这一章把 Emacs 的移动命令按「语法单元」重新排了一遍：字符、词、行、句、段、S 表达式。你会弄清方向键为什么不值得停在上面、前缀参数（数字前缀，敲在命令前面表示「做 n 次」的按键）怎么让任何一个移动命令都变成「可重复」的，以及最反直觉的那件事——Emacs 没有独立的「选区模式」，选区是 point 和 mark 两点之间那一段，所以必须「先设 mark，再移动」。最后是书签（bookmark，跨会话保存的跳转点）、寄存器（register，一个字符名的小仓库）和矩形选择。

要点

Emacs 里「移动」是密度最高的操作，没有之一。一个熟练用户 80% 的按键是在移动和删除，全是本节这一套键。所以这一节值得你读慢一点、抄一遍速查表。

一、为什么 Emacs 的移动要按「语法单元」组织

任何编辑器都能让你把光标往右挪一格。但 Emacs 的设计前提是：你几乎永远不应该用鼠标。这不是宗教，是算术——在键盘上，从主键区（asdf jkl; 这排，两只手的默认落点）挪到方向键区，路上要花的时间乘以每天几千次，是一笔很大的账。所以 Emacs 把所有移动都改写成「主键区就能敲的组合键 + 数字前缀」，代价是初学者要背，回报是后期速度碾压鼠标流。

为了能用数字前缀，命令就必须能被参数化。所以 Emacs 不提供「右移一格」这种命令，而是提供一个通用的语法单元（syntactic unit，指一组有结构的字符，比如一个词、一行、一个括号对），再让前缀参数去数它：

  • 字符（character）——最小单位，只在「需要精确偏一两个字」时用。
  • 词（word）——由语法表（syntax table，一张「每个字符属于哪一类」的表）在当前 buffer 里现算出来的，不是固定规则。
  • 行（line）——分逻辑行和屏幕行两套，Emacs 23.1 起默认按屏幕行走。
  • 句（sentence）、段（paragraph）——给中文、英文散文用的。
  • S 表达式（sexp，Lisp 里平衡表达式的简称）——程序员的主力。

读到这里只要记住一件事：Emacs 的移动命令几乎全部接受数字前缀，而且负数前缀会反过来。敲 C-3 Mf 就是「往前跳三个词的反方向」——即往后三个词。这条规则对字符、词、行、句、段、括号全都成立（少数命令例外，下面会逐个标出来），所以你只需要学一次。

易错

终端里的 Delete 键行为不一定是删后面的字符。Emacs 靠 normal-erase-is-backspace-mode 这个次模式来区分 Backspace 和 Delete：正常情况下 Delete 删后面、Backspace 删前面；但如果 Emacs 判断你的键盘/终端发过来的键位编码不对，两个键可能都变成删前面。查 Emacs 的说法：Mx normal-erase-is-backspace-mode（手册节点 If <DEL> Fails to Delete），切换一下就对了。写进配置文件永久生效：(normal-erase-is-backspace-mode 1)。

第二处，Prior（Page Up）绑的是 scroll-down-command，Next（Page Down）绑的是 scroll-up-command。原因是 Emacs 的「向上/向下滚动」指的是文字在窗口里移动的方向，不是你在看什么方向。这是老术语，Emacs 沿用了，改不动了（手册 Scrolling 一节专门解释了这个约定）。

技巧

翻页时窗口会保留 next-screen-context-lines 行重叠内容（默认值 2，我用 emacs --batch -Q --eval 实测确认），这样你翻回去还能看到上一屏的最后两行。觉得两行太少就 Mx customize-option 然后输 next-screen-context-lines 改成 3 或 4。

技巧

如果你在终端里用 bash、python 交互解释器、psql、任何基于 GNU readline 的程序，那些程序的默认键位就是 Emacs 键位：Mf 前进一词，Mb 后退一词，Ca 行首，Ce 行尾，Ck 杀到行尾。也就是说这一章的肌肉有一半你已经在用了——只是 shell 里没有 mark 和 region，所以感觉不到完整版。

三、按字符移动：C-f C-b C-p C-n

第一次看到 Emacs 用 Cf 表示「前进一个字符」，多数人会觉得别扭——为什么不直接用 Cd（delete）或者某个不冲突的键？答案是留位：这套键位是一整族，每个修饰键管一档粒度，你只要认得 C- = 字符、M- = 词、C-M- = 结构，整张表就自洽了：

  • C- 这一档：字符、句、行（Ca / Ce / Ck）
  • M- 这一档：词、句、段（Md / M-DEL / Mt）
  • C-M- 这一档：结构（CMf / CMb / CMk / CMt）
  • 字母本身取首字母：forward、backward、previous、next。

字符移动（character movement）本身是最慢的移动方式，因为它的速度上限是键盘的重复键速度。它只在一种情况下是最高效：你想在词里偏一两个字的时候。除此之外一律不要用。

四、行、屏幕行与折行：三个容易混的名词

Emacs 默认把过长的行按窗口宽度折断显示。一行长文本会占屏幕上好几行。这时候「一行」到底是哪一行？三个名字，三个意思：

  • 逻辑行（logical line）——buffer 里真实的、由换行符结尾的一行。
  • 视觉行 / 屏幕行（visual line / screen line）——屏幕上你看到的一行。手册说这两个词可以互换，区别只在「有没有折行」。
  • 历史包袱：早期 Emacs 的 Cp/Cn 按逻辑行走，导致光标上下跳时会跳过折行的中间部分。当年这引发了大量争议，结果是几乎所有人都改了。

结论很简单：Emacs 23.1 起，Cp 和 Cn 默认按屏幕行走。我查了 Emacs 32.0.50 上 line-move-visual 的默认值，确实是 t。要恢复老行为，把 line-move-visual 设成 nil（Mx customize-option 然后输这个变量名）。

但 Ca、Ce 这些仍然按逻辑行工作——手动册里明确写了这点：Unlike C-n and C-p, most of the Emacs commands that work on lines work on logical lines.

如果你希望 Ca 也认屏幕行，就要开 Visual Line mode（visual-line-mode，按词边界折行的次模式）。我实测它开了之后改写了三个键：

C-a  →  beginning-of-visual-line
C-e  →  end-of-visual-line
C-k  →  kill-visual-line

同时它会关掉截断，模式行上会显示 wrap 字样。开启方式：Mx global-visual-line-mode（全局）或 Mx visual-line-mode（只对当前 buffer）。写进配置文件则是 (global-visual-line-mode 1)。不想要折行、想看到完整的长行，就用 Mx toggle-truncate-lines 切换截断（truncation）——这个词有点误导：它不是「砍掉文本」，只是屏幕上用右边框截断，文本还在 buffer 里。

行号与列号

Emacs 默认不开行号（display-line-numbers-mode 默认 nil，我实测确认）。今天要开就敲 Mx display-line-numbers-mode——它是一个全局次模式（global minor mode，一个小写单词，开关一次影响所有 buffer），所以 Mx 直接调用就是全局效果。写进配置：(display-line-numbers-mode 1)。行号的样式（绝对 / 相对 / 两者混合）用 Mx customize-group 输 display-line-numbers 调，核心变量是 display-line-numbers-type。

只想在模式行（mode line，屏幕最下面那行状态栏）看当前行号，就开 line-number-mode（默认已开）和 column-number-mode（默认关闭）。列号从 0 开始数，行号从 1 开始——这是历史遗留，习惯就好。

Emacs 自带两个更好的方案，都不用装包。

  • word-wrap-whitespace-mode（次模式）——在「空白字符」之外，再加上一批可以折行的字符。加哪几个由选项 word-wrap-whitespace-characters 决定，它的默认值是一串 Unicode 空白（含全角空格 U+3000）和零宽空格。中文里全角空格本来就常被当分隔用，这个模式通常就够。
  • word-wrap-by-category——按字符的语法类别决定能不能折行，而不是只看空白。默认值是 nil（关着）；设成非 nil 后 Emacs 可以在任意类别边界折行，汉字友好得多。它有三个取值：set 是标准禁则处理（遵守「行首不出现 ，。，行尾不出现 《」」的中文排版规则），raw 跳过禁则（写代码时用这个，免得格式化长行时缩进被折断），variable 则由变量 kinsoku-justify 决定要不要做禁则。

标准禁则处理由 Emacs 自带的 kinsoku.el 提供。想改禁则规则：Mx customize-group 输 kinsoku。想看某个字符属于哪一类：Cu Cx =，看报告里的 category 段（Emacs 手册 Visual Line Mode 一节举的就是这个用法）。

「词」到底是什么？语法表说了算

多数人以为词就是「用空白隔开的一串字符」。在 Emacs 里不完全对。每个 主模式（major mode，一种语言/文件类型对应的编辑模式，如 python-mode）都有一张 语法表（syntax table），它给每一个字符（包括 Unicode 码点）标一个「语法类」：词构成字符（?w）、标点（?.）、括号（?( ?)）、引号（?\"）、注释起始符（<）等等。词移动完全按这张表算。

所以同一个字符串在不同主模式里，「词」的切法可以完全不同。最干净的例子是 a.b.c：在 fundamental-mode（最基础的文本模式）里，. 的语法类是标点（?.），而 Emacs 跳过标点，所以 Mf 一次跳过整个 a.b.c——它算一个词；到了 python-mode 里，主模式把 . 标成了表达式的一部分，Mf 就只走 a、b、c 三步。我用 (char-syntax ?.) 和逐步 forward-word 在 Emacs 32.0.50 上分别试过 fundamental-mode、python-mode 和 emacs-lisp-mode，结果确实如此。这就是为什么同一个键在不同文件里感觉不一样——不是你记错了，是模式改写了语法表。

想看你当前 buffer 的语法表，敲 Ch s（describe-syntax），会开一个帮助 buffer 列出所有字符的类别。这是 Emacs 少有的、其他编辑器做不到的事：你可以直接看到并修改 Emacs 判断「词」和「注释」的依据。移动不灵时先查这里。

技巧

中日韩读者注意两件事。

第一，Emacs 默认把汉字判为词构成字符——我实测 (char-syntax ?这) 返回 ?w。所以 Mf 在中文里是按「连续汉字串」跳的。顺便，汉字之间的全角空格（U+3000）在语法上是空白，所以「汉字　空格　汉字」会被切成两个词——写中文时如果想让它连成一个词，把全角空格换成普通空格或者直接去掉。

第二，词移动还看字符所属的文字体系（char-script-table，判定一个字符属于汉字、拉丁、假名、阿拉伯等哪一「文字」），不同文字体系之间也构成词边界。这不是新加的功能，手册 Motion by Words 一节就是这么描述 forward-word 的。我在 Emacs 32.0.50 上实测 中文abc混排：Mf 先停在 中文 之后，再停在 abc 之后，最后停在 混排 之后——汉字和拉丁字母分开成词，正是你想要的效果。全角句号 。 的语法类是 ?.（标点），不是词字符。

词移动是不对称的

这是新手最容易被绊倒的一点，务必理解而不是死记。规则是：Emacs 会跳过移动方向上紧跟在 point 后面、但不属于词的字符（标点、符号），直到遇见真正的词字符为止。结果是 Mf 之后接 Mb，不会回到原位。

我用 buffer 内容 Hello, World. 在 Emacs 32.0.50 上实测了每一步（下面的 │ 表示 point）：

起点在 position 1（Hello 的 H 之前）
  M-f  →  Hello,│ World.        落在 position 6，即 o 之后、逗号之前
  M-f  →  Hello, World│.        落在 position 13，跳过了逗号和空格
  M-b  →  Hello, │World.        落在 position 8，跳过了句点，停在 W 之前
  M-f  →  Hello, World│.        落在 position 13 —— 没有回到 8

从行尾（position 14）出发：
  M-b  →  Hello, │World.        落在 position 8
  M-f  →  Hello, World│.        落在 position 13，也不是行尾

为什么 Emacs 要这么设计？因为如果不这样，代码里的每个符号都会变成一个「词」，Mf 就变成了一个没有任何用处的逐字符移动。规则的实际效果是：你连续敲 Mb，会一个一个退过文本里的词，顺手跳过沿途的括号、逗号、下划线。代码里到处都是这种东西，这是唯一合理的行为。

再看一个你真会在源码里遇到的例子，buffer 内容 print(add_two(num_table[10]))，point 在行尾：

  print(add_two(num_table[10]))▌
  M-b → print(add_two(num_table[▌10]))
  M-b → print(add_two(num_▌table[10]))    ← 停在 table 前，不是 num_table 前

往回走一步再往前：
  M-f → print(add_two(num_table▌[10]))

看到不对称在这里怎么帮你：Mb 之后紧接 Md（kill-word，杀到词尾），你会干净地杀掉 10，不会碰到后面的 ]))。移动和编辑共用同一套不对称规则，这正是它能用的原因。

易错

别指望 Mb 和 Mf 互为逆操作。要精确回到某个位置，用 Cx Cx 交换 point 和 mark（见第十一节），或者干脆记一个位置用寄存器。

CamelCase 与 snake_case

如果你写 Java、C#、Objective-C 这类用 CamelCase 命名的语言，Emacs 自带两个次模式（minor mode，叠加在主模式之上的行为开关）来调整词的定义：

  • subword-mode——把 GtkWidget 当成 Gtk 和 Widget 两个词，手册叫这种混合大小写的符号为 nomenclature。开了之后 Mf、Md、Mt（transpose-words，交换两个词）都会在驼峰边界停下。
  • superword-mode——反过来，把 this_is_a_symbol 当成一个词，因为它把符号类字符（symbol syntax，通常包括下划线）算作词的一部分。

两者都是 Emacs 自带的（不用装包），但默认关闭（我实测 Emacs 32.0.50 上 subword-mode、superword-mode、glasses-mode 默认都是 nil），而且都是 buffer 局部的。要全局打开：

(global-subword-mode 1)
;; 如果你还常写 snake_case：
(global-superword-mode 1)

superword-mode 有个坑：它依赖主模式把 _ 判成符号类字符（?_），有些模式没设，就不起作用。另外知道它们的来历有助于你判断新版本行为：superword-mode 是 Emacs 24 新增的（NEWS.24 明确记录）；subword-mode 在 Emacs 25 被重写过——重写后它不再靠语法表，而是给词移动装了一层钩子，Mf、Md 这些直接依赖 forward-word 的命令全都跟着按驼峰边界走。如果你的 Elisp 代码需要「不受 Subword mode 影响」的严格词移动，Emacs 25 起请改用新提供的 forward-word-strictly / backward-word-strictly（这是 NEWS.25 的迁移建议）。

还有个小玩意 glasses-mode：它只在显示上给 CamelCase 中间插一道虚拟下划线（Camel_Case），不改动 buffer 里的任何字符。原文作者个人很喜欢，但这属于口味问题。

六、按平衡表达式移动：C-M 这一族

如果你写代码，这可能整章最有价值的一节。

S 表达式（sexp）是 Lisp 术语，指「平衡表达式」（balanced expression）：一个从头到尾配对的结构。Emacs 认为这些是平衡的：

  • 字符串——以 " 或 ' 开始并结束，可以跨行。
  • 括号类字符——( )、[ ]、{ }、< >。具体哪几个算，由主模式在语法表里定义。
  • 单个符号、单个数字。

键位还是那套助记法，修饰键换成 C-M-：

四个方向：前、后、下、上、左右

C-Mf 跳过一个完整的平衡表达式。在 Python 字典里按一次，光标会从 { 前面直接飞到 } 后面——因为 Emacs 知道 {} 是配对的。

想「钻进」括号里逐层处理，就用下面这四个。它们的设计是：C-Md 往下钻一层，C-Mu 往回退一层，C-Mn 和 C-Mp 在同一层左右横移。

下面是我在 emacs-lisp-mode 里对 buffer (+ (* 5 2) (- 10 10)) 逐步实测的结果（`│` 是 point）：

起点（第二个字符）      (+│ (* 5 2) (- 10 10))
C-M-d  向下钻一层        (+ (│* 5 2) (- 10 10))
C-M-u  退回上一层        (+ (│* 5 2) (- 10 10))   ← 停在左括号上，不是括号里
C-M-n  右移一个括号组    (+ (* 5 2)│ (- 10 10))
C-M-n  再右移一个        (+ (* 5 2) (- 10 10)│)
C-M-n  再来一次          报错：这一层已经没有更多括号组了
C-M-u  退出外层          │(+ (* 5 2) (- 10 10))
C-M-n  进入外层          (+ (* 5 2) (- 10 10))│

两点要注意：（1） 括号命令在字符串和注释里结果不可靠，手册明说了；（2） 它和词命令一样不对称——C-Mu 退出去时会把 point 留在左括号上，不是括号内部的第一个位置。

要点

这些命令不是 Lisp 专属。在 Python 里，字典、列表、函数调用的参数、元组全是大括号小括号；括号命令照样工作。原文作者的说法是：大多数语言里你都会频繁遇到平衡表达式，所以这套命令在所有语言里都值得学。唯一的前提是你的主模式在语法表里正确标了括号——如果某个语言的 C-M-f 跳不过去，那是那个模式的问题，不是你命令敲错了。

技巧

C-Mu 现在也能从字符串里跳到开头的引号（手册确认：move out of enclosing strings as well）。

真正让它值回票价的是和 C-Mk（kill-sexp）的组合。C-Mu 回到上一层，C-Mk 删掉刚钻出来的那个表达式。实测 buffer (+ (* 5 2) (- 10 10))，point 在 5 上：

起点（point 在 5 上）
  (+ (* █5 2) (- 10 10))
C-M-u 后（point 停在 4，即左括号之前）
  (+ █(* 5 2) (- 10 10))
C-M-k 后（point 仍在 4，buffer 里 (+) 后面有两个空格）
  (+ █ (- 10 10))

两键删掉一整个嵌套调用，而且不会碰到外层括号（我实测：kill-sexp 从 4 开始删掉 4–10 这七个字符 (* 5 2)，留下的 (+ 和 (- 10 10)) 各自拼接，所以 + 后面有两个空格）。大范围重构代码时这是最高效的一招。

易错

有些终端发不出 CM 这个组合。最可靠的绕法是用 Mx 调命令名：Mx 然后输入 forward-sexp 回车，功能完全一样，只是慢一点。这是我的经验性做法，不是官方文档里的说法——遇到发不出去的组合键，先想到这招。

句子：Emacs 假设你句号后打两个空格

句子的定义由三个变量决定，手册的措辞很直白：The sentence commands assume that you follow the American typographers' convention of putting two spaces at the end of a sentence. 这样 Emacs 才能区分「句号结束句子」和「句号是缩写的一部分」。

  • sentence-end-double-space（默认 t）——非 nil 表示一个空格不结束句子。设成 nil 则单空格即断句，但就没法识别缩写了。手册明确建议保留双空格习惯。
  • sentence-end-without-period（默认 nil）——设成 t 表示句子可以没有句号就结束（泰语等）。
  • sentence-end-without-space——「后面不跟空格也能断句的字符集合」。这个默认值对中文读者很重要：我实测 Emacs 32.0.50 的值是 。．？！，也就是全角句号、全角点、问号、叹号。也就是说在中文文本里，Me 遇到 。 就能正确断句，不需要你打任何空格。

另外句子的边界就是段的边界——段落开始或结束的地方必然也是句子开始或结束的地方。句命令在编程模式里同样有用，因为主模式可以重定义「句子」：在 C 模式里一个「句子」就是一个完整语句（int x = 5;），在 JS 模式里可以是一条完整语句。它比 sexp 大、比 defun 小，正好填上中间那层。

段落：定义在一堆正则里

段落的精确边界由两个正则变量控制。我实测了 Emacs 32.0.50 在基础模式下的默认值：

paragraph-start     "\\|[ \t]*$"   ; 开启或分隔段落
paragraph-separate  "[ \t]*$"     ; 只作分隔（本身不算段落内容）

用 Ch v（describe-variable）输变量名可以随时看真实值和说明。实用结论：

  • 默认把空行当段落分隔。在编程模式里程序员也常用空行把逻辑块分开，所以 M{ / M} 在代码里同样好用——沿着空行跳，一跳一块。
  • 缩进行在 text-mode 里不是段落分隔。想要缩进也算分隔，开 paragraph-indent-minor-mode（Mx 调用）。
  • 这两个正则匹配的是左边距处的文本，不一定在行首，所以别用 ^ 锚定，否则遇上带 margin 的文件就失效。

定义（defun）：跳到函数边界

defun 是 LISP 缩写，意思是「定义函数」。在 Emacs 里它是个泛称：编程模式里通常指函数、类，或两者；在别的模式里可能是章节（比如 reStructuredText 模式里 C-Ma 跳到小节开头）。

C-Ma 的用处很实在：想改函数名或参数列表，一键跳到定义行。反复按 C-Ma 会一路往上跳到外层块，直到文件最外层。注意它和 C-Me 不是严格互逆：函数尾和下一个函数头之间常有注释和空行，两者位置不一定重合。

要点

新版 Emacs 补上了这块的老缺口。Emacs 29 起陆续内置了一批基于 tree-sitter 解析的主模式（NEWS.29 的「New major modes based on the tree-sitter library」是起点，Emacs 30 又加了 Elixir、HEEx 等），这些模式多了一个变量 treesit-defun-tactic。默认 nested 表示找最内层的定义；设成 top-level 就找最外层的（更适合在大文件里跳）；设成 parent-first 则总是先试着往外跳，没有外层才去找前后相邻的定义。C 模式里 C-Mh 会被替换成 c-mark-function，它会额外把参数表、函数名、返回类型一起包进去——这是主模式按语言调整键位行为的典型例子。

页：Emacs 的「页」和打印意义的页无关

Emacs 的页就是被 page-delimiter（默认正则 ^\f，即行首的换页控制符 ^L；我实测 Emacs 32.0.50 的默认值确实是这个）隔开的两段文本。文本文件里几乎没有 ^L，所以这几条命令基本用不上。但它们值得知道存在，因为个别格式（PostScript 片段、LaTeX 中间文件、某些日志）会真的用到。想手动插一个 ^L：Cq Cl。搬整页的标准做法是 Cx Cp 把当前页设成 region，再 Cx Cw 杀掉它，然后到别处 Cy 粘上。

易错

这组键不是 C-[ / C-]。我在 Emacs 32.0.50 上查过：backward-page 和 forward-page 绑的是 Cx [ 和 Cx ]（(where-is-internal 'backward-page) 返回 (C-x [)）；而 C-[ 在 Emacs 里是个 ESC-prefix 嵌套键表，C-] 绑的是 abort-recursive-edit，都跟翻页无关。手册 Pages 一节列的也是 Cx [ / Cx ]。

另一个实用技巧：不知道某个命令叫什么的时候，Ch a（apropos-command，按名字片段搜命令）输 page 会列出所有含 page 的命令（原文作者当年输的是 page$，只留以 page 结尾的）。掌握「怎么向 Emacs 提问」比记住具体命令更重要——Ch f 查函数、Ch v 查变量、Ch m 查当前模式、Ch s 查语法表、Ch k 查按键绑定，这六个是 Emacs 自助能力的全部。我用 (key-binding (kbd "…")) 逐条查过它们在 Emacs 32.0.50 上确实都还绑着。

C-Mv（scroll-other-window）是别的编辑器基本都没有的能力：你在一边写代码，一边开着一个 help buffer 或编译日志，不用切窗口就能把那边滚上去。原文作者说他几乎为此放弃了 C-MSv，因为那个键要同时按住三个修饰键，手指姿势太别扭，他改用 C-M-（负参数）加 C-Mv 来反向滚动。

顺带解释「维持节奏」这件事：负参数键 C-M- 和滚动键 C-Mv 用的修饰键是同一组，所以你的手不用在两套姿势之间挪。这是 Emacs 键位设计里很典型的一层考虑——不是每个键都最合理，但成族设计的键位更省手。

Cl 这一族我单独说一句，因为它的命令名变过：现在 Cl 绑的是 recenter-top-bottom，不是老书里写的 recenter。我在 Emacs 32.0.50 上查 (key-binding (kbd "C-l")) 返回 recenter-top-bottom，而 (where-is-internal 'recenter) 返回 nil——也就是说 recenter 这个函数还在，但已经没有默认绑定了，Mx 调它也只会把当前行居中一次，没有「反复按变最上/最下」的效果。你要的是现代行为就用 recenter-top-bottom。

横向滚动（Cx < / Cx >）只在长行不折行时有用，比如 CSV、日志。鼠标滚轮在图形界面里当然能用；在终端里能不能用取决于你的终端支不支持鼠标事件上报（Emacs 26 起终端也支持滚轮了，但要看终端和 Emacs 的具体组合），所以这两条键盘键位仍然值得记住。自动横向滚动由 auto-hscroll-mode 控制：t 时整个窗口一起滚（这样窗口里每一行的左右部分都对齐，好看），current-line（有意思的取值）时只有光标那一行滚，设成 nil 则完全关掉自动横向滚动。我实测 Emacs 32.0.50 的默认值是 t。

易错

按住 Cv 让键盘自动重复时，Emacs 有时会来不及重绘：画面卡住不动，输入也像没反应。原因是滚动时要做语法着色（fontification）。两个解法：(setq fast-but-imprecise-scrolling t) 让它跳过着色；或者更推荐的 (setq jit-lock-defer-time 0.2)，让着色延迟一点点做，效果平滑而且颜色是对的。

九、跳到缓冲区首尾，以及它顺手留下的面包屑

最后两个最基本的移动：M<（beginning-of-buffer）和 M>（end-of-buffer）。图形界面里 C<Home 和 C<End 也能用（我实测确实绑到了同样的命令），但终端里这两个键常常不发出来，还是用 M< / M> 保险。

关键细节在这里：这两个命令会自动在你来的位置留下一个 mark。我查了 Emacs 32.0.50 上 beginning-of-buffer 和 end-of-buffer 的文档字符串，原话是 Push mark at previous position（例外：带 Cu 前缀时不推，或者 Transient Mark mode 开着且 mark 已激活时不推）。

所以你按 M< 冲到文件头之后，敲 Cu C<SPC 就能弹回刚才的位置。Cu 在这里是「把这个命令变个味」——普通 C<SPC 是「设 mark」，带 Cu 是「跳到 mark」。

这就是下一节的伏笔：mark 不是一个单纯的「选区锚点」，它是 Emacs 的面包屑系统。

十、书签与寄存器：一个管持久，一个管临时

这两个机制经常被一起讲，但它们的设计意图正好相反：

  • 书签（bookmark）——永久。有名字，自动保存到磁盘，下次启动还在。用来标记「我常去的地方」：常开的文件、常看的文档位置。
  • 寄存器（register）——临时。只有一个字符的名字，Emacs 关闭就没了。用来在一件事当中临时存一段文本、一个位置、一个窗口布局。

易错

原书写这本书时，书签文件在 ~/.emacs.d/bookmarks。今天默认路径不一样了。我在本机 Emacs 32.0.50 上实测 bookmark-default-file 的值是 ~/.config/emacs/bookmarks.eld——多了一个 .eld 后缀，而且目录从 ~/.emacs.d/ 挪到了 ~/.config/emacs/（跟随 XDG 规范）。

变的是哪一步：我查了 Emacs 的源码。Emacs 30 及更早，bookmark-default-file 的默认值是 (locate-user-emacs-file "bookmarks" ".emacs.bmk")；Emacs 31.1 起改成了 (locate-user-emacs-file '("bookmarks.eld" "bookmarks") ".emacs.bmk")——先试带 .eld 的新名字，找不到才退回旧名字，这样升级后老书签不会丢。对应地，这个变量的 :version 标记写着 31.1。所以你在 Emacs 30 上看到的是 ~/.config/emacs/bookmarks（XDG 目录迁移是更早的事，和 .eld 无关），在 31.1 及以后看到的是 bookmarks.eld。

值可能随你的系统（有无 XDG_CONFIG_HOME）不同。要确认自己机器上的实际值，敲 Ch v 然后输 bookmark-default-file。书签文件是纯文本（Elisp 的 s-表达式列表），实在要手动编辑或从另一台机器合并也不是不行——但多数情况下你只需要知道它在哪。

另外两个值得知道的机制。其一，bookmark-save-flag 决定什么时候自动写盘，它的默认值是 t，不是 nil（我实测 Emacs 32.0.50 就是 t，并核对了源码里的说明）——t 的含义是「Emacs 退出时保存」。所以如果你崩溃过、丢过书签，想让它每次改动都立刻落盘，把这个变量设成 1（nil 才是彻底不自动保存，只在你显式 Mx bookmark-save 时才写）。

其二，书签会连同上下文一起存——bookmark-search-size（默认 16，源码里的说明是「记录在书签两侧的上下文字符串长度」）控制每侧存多少字符。文件被小改过之后，跳回来仍然能靠这段上下文重新定位。

寄存器

寄存器是一个单字符的存储格。名字可以是字母、区分大小写（a 和 A 是两个寄存器）、数字，甚至 C-d 这种（用 Cq 再敲 Cd 输出来）。这几点是官方手册 Registers 一节明写的。

Emacs 提示你输寄存器名时会弹一个预览窗口，列出现有寄存器及其内容。这个弹窗的行为由两个变量控制：

  • register-preview-delay——延迟多少秒弹出来，默认 1（我实测确认）。设成 nil 就完全不自动弹，但提示时按 Ch 或 F1 还是能手动叫出来。
  • register-use-preview——预览风格，默认 traditional，也就是「延迟弹、不能导航、敲个字母就选中」的老行为。想要那套立即弹出、可用 Cn / Cp 或上下键在寄存器之间导航、选中了要按回车才确认的新界面，把它设成 t；设成 insist 是 t 的加强版（再按一次同名字母就能退出 minibuffer，不用按回车）；设成 never 则彻底关掉预览。
要点

register-use-preview 是 Emacs 30.1 才有的新变量（NEWS.30.1 的原话是「A new mode of prompting for register names and showing preview」，并说明默认值 traditional 保留了 Emacs 29 及更早的行为）。手册里把 traditional 描述成「Emacs 29 and before」的形态——所以如果你在 29 上找不到这个变量，不是你记错了，是它那时还不存在。另一个新界面带来的好处：t 模式下预览会按命令过滤，比如 Cx r i 的预览里只显示「能插入 buffer 的」寄存器，窗口布局、位置这类塞不进来的就不显示了。

用法上最实用的两条是 Cx r s 和 Cx r i：先把一段模板或代码块存进寄存器（比如 a），之后在任何地方敲 Cx r i a 就能插入。相比 kill ring（杀死环，最近杀死内容的循环队列），寄存器的好处是它不会被下一次 kill 冲掉——它是你明确指定要长期留着的东西。

Cx r i 插完之后 point 停在插入文本之后；给它一个 Cu 前缀则停在之前，这个细节在连续插入多段时很有用。

存位置用 Cx r SPC，回来用 Cx r j。注意这里有个历史遗留的不对称：Cx r i 碰上存位置的寄存器不会跳过去，而是把内部位置编号插进文本，毫无意义。记住用 Cx r j 就好。

数字寄存器配合键盘宏（keyboard macro，录制回放一串按键，见第 13 章）很顺手：Cu 100 Cx r n a 存 100，Cx r + a 加一，Cx r i a 插回 buffer。反复编号的场合（改带编号的条目、批量重编号）这招很直接。

十一、选区与 region：先设 mark，再移动

这一节是全章最反直觉的地方，也是 Emacs 与所有其他编辑器分歧最大的地方。

region（区域）是 point 和 mark 之间的那段文本，就这么多。Emacs 里没有一个「选择模式」，也没有「光标锚点 vs 活动端」这种概念。point 和 mark 都是位置，region 就是它们之间，谁在前谁在后都无所谓。这和按住 S（Shift）再按方向键的模型是不同的——Emacs 也有 Shift 选择（见下一节），但那只是建在 point/mark 之上的一个便利层。

所以流程永远是三步，没有例外：

  1. 把光标移到选区的一端。
  2. 设 mark（C<SPC）。回显区（echo area，屏幕底部弹消息的那一行）会显示 Mark set。
  3. 用任意移动命令走到另一端，region 跟着 point 实时增长、高亮。

然后跑你要的命令。做完之后 region 自动失效，高亮消失。

动手试一遍，记住手感：打开任意文件，光标停在某个词中间，按 C<SPC（你会看到 Mark set），然后连按几下 Mf 和 Mb，看着高亮一块一块地长长短短。再按一次 C<SPC，高亮消失。

易错

要「只记一个位置，以后回来」时，得按两次 C<SPC：第一下设 mark 并激活 region，第二下取消激活。第一次取消激活会顺带把原来的 mark 压进 mark ring（面包屑环），所以这个位置不会丢，之后 Cu C<SPC 照样能弹回来。

只想取消 region 的话，按 Cg（keyboard-quit，那个万能的「算了」键）也完全可以，效果和再按一次 C<SPC 一样。

mark ring：可以一直往回退的面包屑

每个 buffer 都有一个 mark ring（面包屑环，mark-ring-max 默认 16 条，我实测确认）。任何设 mark 的动作——不管是你手按的 C<SPC，还是命令顺手留下的（比如 M<、Cx h，还有 Cy 插入文本后把 mark 放在插入起点）——都会把旧位置压进这个环。

Cu C<SPC 就是顺着这个环往回走：第一次跳到 mark 所在位置，再按一次跳到环里的上一条，再按跳更前一条。走过的位置不会被丢，而是被重新放到环尾，所以你可以在两个地方之间来回弹。

要点

另有一个全局 mark ring，专门记跨 buffer 的位置。Cx C@（pop-global-mark，我实测过这个绑定）跳到全局环的最新一条并把环轮转，连续按可以一路退回你之前待过的那些 buffer 的那些位置。这比 mark ring 强的地方是它跨 buffer——普通 Cu C<SPC 永远在当前 buffer 里走。两条路都值得按一按。

Emacs 提供三个开关，让它的选择行为贴近别的编辑器。原文作者的建议是：先用着，慢慢戒。我的建议是：delete-selection-mode 值得开着，另外两个看你。

delete-selection-mode

默认情况下，Emacs 里你在激活的 region 上直接打字，是把字插在 point 前面，然后取消高亮，选中内容还在。很多人第一反应是「这是 Emacs 有 bug」，其实只是原生行为。其他编辑器都是「直接输入替换选中」。这个次模式补上这个差别，代价几乎没有：写进配置 (delete-selection-mode 1)。

Emacs 29 之后还有个更细的旋钮 delete-selection-temporary-region（默认 nil，我实测确认）：设成 t 就只对「临时 region」——鼠标拖出来的、或 Shift 选择出来的、或在关掉 transient-mark-mode 时用 Cu Cx Cx 弄出来的——才替换；设成 selection 则连 Cu Cx Cx 那种也不替换，只剩鼠标和 Shift。默认 nil 意味着全都不限，最接近别的编辑器。

shift-select-mode

按住 Shift 移动会自动设 mark 并扩展 region——这就是你在 VS Code 里熟悉的那一套。它默认就是开的（shift-select-mode 默认 t，我从 Emacs 23.1 起就是这个默认值，NEWS.23 有明确记录）。我实测 shift-select-mode 不是一个命令，只是个变量——所以 Mx shift-select-mode 会报错，要改得用 Mx customize-option，或者在配置里写 (setq shift-select-mode nil)。

Shift 选择出来的 mark 行为略有不同：之后任何不带 Shift 的移动命令都会取消 region。所以你 Shift 选到一半，觉得方向不对按了个 Cf，高亮就没了。（Emacs 28 起把 shift-select-mode 扩展出了第三种取值 permanent：设成它以后，不带 Shift 的移动也会扩展而不是取消 region，想脱身得先按 Cg。喜欢连续选的人可以试。）

另外注意，Shift 选择只在那个键本身没被绑到别的命令时才生效。你要是把 S-Cf 重新绑了东西，它就不再做选择——C<SPC（即 C@）在 Emacs 32 里就默认绑给了 set-mark-command，所以 Emacs 的 C-@ 是设 mark 而不是「移到行首」（那是 Unix readline 的老约定，两者不同）。

cua-mode

CUA 是 IBM 的 Common User Access，一套老式终端交互规范。CUA 模式把 Emacs 改成那套键：Cz 撤销、Cx 剪切、Cc 复制、Cv 粘贴。

默认关闭，因为它和 Emacs 自己的 Cx、Cc 前缀键直接冲突。开启后（我实测 cua-mode 默认 nil）有个明确规则：Cx 和 Cc 只有在 region 激活时才执行剪切/复制，否则仍然当普通前缀键。但代价有三个，手册明说：

  1. region 激活时想发前缀键 Cx，必须快速连按两下（比如 Cx Cx）。
  2. 想敲 Cx 加别的键时，两个键必须极快地连着敲，否则会被当成剪切。
  3. 或者干脆用 CSx 代替 Cx、CSc 代替 Cc。

CUA 模式还会顺手开 delete-selection-mode，并提供一套带可见矩形高亮的矩形支持（C<RET 开始画矩形，RET 跳到下一个角）。如果你只想要矩形、不要改 Cx 系列，有单独的 cua-rectangle-mark-mode，或者用下一节的 Cx <SPC。想只要 CUA 的其他特性但保留标准绑定，把 cua-enable-cua-keys 设成 nil。

进阶：关掉 Transient Mark Mode 之后

Transient Mark mode（TMM）是「设 mark 就点亮高亮」这个行为的正式名字。它是交互式 Emacs 里默认开启的次模式，可以用 Mx transient-mark-mode 切换。

TMM 出现得很晚。在它之前 Emacs 根本没有选区高亮——你设了 mark 也看不出来，得自己记着位置在哪。这本书第 32–34 页讲的正是那段历史：Emacs 早期连 region 概念都没有，像 replace-string 这种命令一律从 point 处理到 buffer 末尾；你只能先用 narrowing（shrink-window 类命令，临时把 buffer 缩到只剩要改的那一段）来限制命令的作用范围——今天除了专门用途很少再用 narrowing，但知道这段历史能解释 Emacs 里一些「怎么这么绕」的设计。

关掉 TMM 之后：C<SPC 不再高亮；M-% 之类的命令不再认 region，一律处理到 buffer 末尾。补救办法是临时开启 TMM：连按两次 C<SPC，或者 Cu Cx Cx。我实测 Emacs 32 里 transient-mark-mode 的默认值是 nil，但那只是因为 batch 模式不算「交互式会话」；在 GUI 或终端里正常启动 Emacs 它是开的，模式行上会显示 Transient Mark。

技巧

「选一块然后杀掉」这件事，在 Emacs 里往往不需要先选——直接用 kill 命令（按语法单元删除，第 6、7 章详讲）更快：C-Mk 杀表达式、C-Mu 退回一层再 C-Mk 杀外层，比「设 mark + 移动 + 杀」少两次按键。先学会 kill，mark 主要用在「选一块做非破坏性操作」上（转大写、缩进、替换、保存到寄存器）。

十五、六条规则

  1. region 就是 point 和 mark 之间的那段文本，谁在前谁在后都算。矩形 mode 会换掉它的边界，你可以 Cx <SPC 来回切着看差别。
  2. C<SPC 激活 region（设 mark 并点亮），再按一次取消。
  3. 激活的 region 跟着 point 走，但你一旦执行了非移动命令（比如打了字、杀了东西），它就自动失效。
  4. mark 有双重身份：既是选区锚点，也是可以用 Cu C<SPC 回去的面包屑。很多命令会顺手帮你设 mark，连按 Cu C<SPC 就在 mark ring 里一路后退。
  5. Cx Cx 交换 point 和 mark 并重新点亮，是你找回上一块选区的快捷方式。
  6. 有些命令根本不看 region 是不是激活的，照样动手（小心）。根源是 Transient Mark mode 是后加的，而老命令的行为必须保持不变。

练习

练习 1　你已经用 Mf 往前走了一个词，想退回一个词。Emacs 里前缀参数怎么帮你不用换键？命令名是什么？

敲 M-（negative-argument）再 Mf，即 M- Mf，等于 Mb。命令名 forward-word——forward-word 的文档字符串明确写了「COUNT 为负则向后移动」。M- 也可以写成 C-M-，两者等价（M-- 与 C-M-- 都绑到 negative-argument，我实测确认）。

练习 2　在 buffer (+ (* 5 2) (- 10 10)) 里，point 在第二个字符 + 上。你按 C-Mu 之后 point 会停在哪？再按一次 C-Mn 呢？

C-Mu（backward-up-list）会退到最外层左括号上，也就是 position 1，光标在 ( 之前。然后 C-Mn 会横向走到这一层唯一的那个括号组之后，也就是最后一个 ) 的后面（position 22）。注意 C-Mu 不会把 point 放在括号内部，而是放在左括号上——这是「不对称」的又一处体现。我在 Emacs 32.0.50 的 emacs-lisp-mode 里逐步实测过这个序列。

练习 3　buffer 内容是 Hello, World.，point 在行尾（position 14）。先按一次 Mb，再按一次 Mf。两次之后 point 在哪？为什么不是回到行尾？

我在 Emacs 32.0.50 上逐步实测过：Mb 从 14 跳到 position 8（W 之前），再 Mf 跳到 position 13（d 之后）。没有回到 14。

原因是不对称。第一步往回走时，point 后面紧挨着的 13 号字符是句点 .，不是词字符，Emacs 跳过它继续回退，直到 W 前才停。第二步往前走时，从 8 出发遇到的是 World 这个词，落在最后一个字母之后就不再往前了——句点不会再被当作「词尾之后要处理的东西」。两次移动用的是同一套「跳过非词字符」规则，但起点不同，落点自然不同。

反例更能说明问题：如果 point 一开始在 position 8，按 Mb 会一路退到 position 1（Hello 之前，因为往回路上 7 号是空格、6 号是逗号，都被跳过），再按 Mf 只到 position 6（Hello 之后），离原来的 8 还差得远。结论不变：Mf 和 Mb 互不为逆操作，要精确回去请用 Cx Cx。

练习 4　你要把当前这一个单词转成大写。完整的三步分别是什么？做完之后 region 状态如何？

第一步：M@（mark-word）一步把整个词框起来——它把 mark 放到词尾，point 不动。第二步：跑命令 Cx Cu（upcase-region）。第三步：什么都不用做——命令执行完 mark 自动失效，高亮消失。

如果用经典三段式也可以：C<SPC → Mf → Cx Cu。两种写法都要会，第二种是理解 region 怎么工作的基础。

练习 5　你在文件里跳来跳去，忘了刚才读到哪了。按 M< 之前那个位置是怎么被记住的？「那串面包屑」叫什么？Cu C<SPC 之后还能退回上一个 buffer 的位置吗？该按什么？

M<（beginning-of-buffer）会自动 push mark——beginning-of-buffer 和 end-of-buffer 的文档字符串都写着 Push mark at previous position，我用 (documentation 'beginning-of-buffer) 查过。同样会顺手压 mark 的还有 Cx h、Cy 等一大批命令。那串面包屑叫 mark ring，每个 buffer 各有一个，默认存 16 条（mark-ring-max）。

普通 Cu C<SPC 不能跨 buffer——手动册明说它「永远留在同一个 buffer 里」。要跨 buffer 得用全局 mark ring，按 Cx C@（pop-global-mark），它会跳到全局环最新的一条并把环轮转，连按就能一路退回你待过的那些 buffer（我实测过这个绑定确实是 pop-global-mark）。

练习 6　你选中了一段 SQL 模板，想存起来以后到处插。用哪两个键？delete-selection-mode 和 shift-select-mode 这两个「兼容性模式」，哪一个默认开着？

存用 Cx r s（copy-to-register，会问你「存进哪个寄存器」，输个单字符如 a），插用 Cx r i a（insert-register）。存之前必须有激活的 region。用寄存器而不是 kill ring 的好处是它不会被下一次 kill 覆盖掉。

默认开的是 shift-select-mode（Emacs 23.1 起默认为 t，我实测确认）。delete-selection-mode 默认关闭，需要你写 (delete-selection-mode 1) 或 Mx 手动开。

补充一个常见困惑：shift-select-mode 只是个变量，不是命令——我实测 (fboundp 'shift-select-mode) 返回 nil，所以 Mx shift-select-mode 会报错，要改得用 Mx customize-option 或者在配置里 (setq shift-select-mode nil)。delete-selection-mode 则确实是命令，Mx 直接调。

练习 7　你想把当前精心排好的窗口布局存下来，之后一条命令恢复。存和恢复分别是哪两个键？原文作者为什么说这个功能不太值得记？

存：Cx r w（window-configuration-to-register）。恢复：Cx r j（jump-to-register）。frame 层面还有 Cx r f（frameset-to-register，我实测过绑定），Cx r i 就是「插入」专用，恢复布局要用 j。

原文作者说不值得记的理由是：窗口布局有更好的工具——winner-mode（记住你的窗口操作并让你「赢回来」）和 Tab Bar Mode（标签页栏）。寄存器里存布局是一次性的快照，不追踪你之后做了什么。这条属于「知道了就好」的知识。

练习 8　你已经用 C<SPC 选好了一块区域，想改成矩形选择。按哪个键？改完之后按同一个键会怎样？

Cx <SPC（rectangle-mark-mode）。高亮会从连续的一条变成矩形，mark 是左上角、point 是右下角；此时 Cf、Cn 这些扩展 region 的命令也按矩形走，普通 kill/yank 也作用于矩形。

再按一次 Cx <SPC 就切回连续模式。另外两个要点：这个模式只在 region 激活期间有效，region 一失效自动回连续；矩形模式下按 Cx Cx 会在矩形四个角之间轮转（命令是 rectangle-exchange-point-and-mark，我查过 Emacs 32 手册确认），这样不用重拖就能改矩形尺寸。

练习 9　一个长行折成三屏行。Emacs 23.1 之后（含 30、31、32） Cp Cn 默认按哪种行走？Ca Ce 呢？想让它们全部按屏幕行走，该开什么？

Cp Cn 默认按屏幕行（visual line）走——变量 line-move-visual 默认值是 t，我从 Emacs 23.1 起就是这个默认（NEWS.23 明确记录了这次改动），我也实测确认了 Emacs 32.0.50 的默认值。要恢复老的逻辑行行为，把 line-move-visual 设成 nil。

Ca 和 Ce 仍然按逻辑行走——手动册原文：Unlike C-n and C-p, most of the Emacs commands that work on lines work on logical lines.

想让它们也认屏幕行，开 visual-line-mode（Mx visual-line-mode，或全局版 global-visual-line-mode，配置里写 (global-visual-line-mode 1)）。我实测它会把 Ca、Ce、Ck 分别改绑成 beginning-of-visual-line、end-of-visual-line、kill-visual-line，同时关掉截断、模式行显示 wrap。

练习 10　光标在 Python 的 result = foo(bar(1, 2), 3) 里 bar 后面那层括号内部。想删掉 bar(1, 2) 这个调用但保留外层的 foo(...)，用哪两个键？

C-Mu（backward-up-list）先退回一层，C-Mk（kill-sexp）再把这一层的平衡表达式杀掉。我实测过这个组合：buffer (+ (* 5 2) (- 10 10))，point 在 5 上，C-Mu C-Mk 之后变成 (+ █ (- 10 10))（█ 处的 point 位置编号是 4，+ 后面因此有两个空格）——正好删掉 (* 5 2)，外层括号完好。

原理是：C-Mu 把 point 退到当前这一层的左括号上，C-Mk 杀掉「C-Mf 会经过的那一段」，也就是刚钻出来的那整个表达式。破坏性操作建议先 C/（undo）。
