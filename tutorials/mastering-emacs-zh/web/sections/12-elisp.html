十二、Emacs Lisp 编程入门

这一章的目标很具体：让你从「能把别人的配置复制进 init.el」升级到「能读懂它、能改它、能自己写十来行」。读完你会知道该在哪里敲代码、*scratch* 为什么是关键工具、配置文件到底在什么时刻被执行，以及列表、符号、闭包、正则、`condition-case`、字节编译、Edebug 这些东西在实践中各解决什么问题。

要点

本章所有命令名、变量名、函数名、默认值，都在本机 GNU Emacs 32.0.50 上用 emacs --batch -Q --eval '…' 逐条查过。凡是 Emacs 32 里已经不存在的老名字（例如 trace、untrace、trace-region、redefine-function），我都会单独标出来，并给出今天该用什么。凡是第三方包，写明包名、安装源和仓库。

易错

本书第 13 章会讲完整的配置工程（early-init.el、straight.el 之类的包管理）。本章故意不要求你先装任何东西——Elisp 是 Emacs 的母语，本机自带，不需要装任何东西就能跟着敲完。这一章里唯一出现的第三方包只有 use-package，而它从 Emacs 29.1 起已经是内置的（Emacs 32 里的实测值：(fboundp 'use-package) 返回 t，文件在 lisp/use-package/use-package-core.elc）。如果你还没读过第 13 章，现在直接跳过去也行，不影响本章任何一段代码。

一、求值：Emacs 自带的「立即执行」

求值（evaluate，缩写为 eval，读作「伊瓦哦」或「伊瓦尔」——意思是「当场把一段 Lisp 算出一个结果来）。整本 Emacs 配置史其实就是不断 eval 一段 Lisp 文本的历史。你在 minibuffer 里敲 Mx 然后输入的每一条命令，最终都是被 eval 出来的。

Emacs 把「我现在读到哪一行 Lisp 文本了」这件事记在一个叫 *（读作「星号」）的变量里。加上前缀参数后 Emacs 还会记下你带了几个 Cu。所以 M: 这个命令做的事其实只有一件：读一行 Lisp，eval 它，然后把结果打印出来。

M-: (message "hello %s" "world")   RET

屏幕上会闪一下 hello world，然后这条命令就被追加到 *Messages* 缓冲区里。minibuffer 那一行会立刻消失，所以如果你想确认刚才到底发生了什么，一定要么去 *Messages* 里看，要么故意写一个会报错的东西。

四个必须分清的命令

新手最常混淆的是这四个。它们都是「执行 Lisp」，但执行的对象完全不同：

  • M:（eval-expression）—— 在 minibuffer 里读一行 Lisp 并求值。我在本机 Emacs 32 上实测 (key-binding (kbd "M-:")) 返回 eval-expression，这是全局默认绑定，没有被任何包覆盖。
  • Cx Ce（eval-last-sexp）—— 原样重新求值上一次你用 M: 求过值的那一行。改了变量之后按它重跑，是最省事的调试手段。本机实测 (key-binding (kbd "C-x C-e")) 返回 eval-last-sexp。
  • CMx（eval-defun）—— 把光标所在的整个 defun / defvar / defcustom 定义求值。这是「改了函数定义之后让它生效」的标准动作。加前缀参数 CuCMx 会用 Edebug 给这个定义打上调试插桩（这是本章调试那一节的主角）。
  • Mx eval-buffer —— 求值整个缓冲区。这条命令没有默认按键（我实测 (key-binding (kbd "M-x eval-buffer")) 返回 nil，这符合预期，因为 M-x eval-buffer 本身不是一个键序列），必须用 Mx 调用。它常配合 Mx eval-region（求值当前缓冲区里 被标记区域 包住的部分）一起用。
易错

Cx Ce 不是 eval-expression。它是 eval-last-sexp。我实测过 Emacs 32 的 (key-binding (kbd "C-x C-e"))，返回的是 eval-last-sexp；M-: 才对应 eval-expression。网上大量老教程（包括不少中文博客）把 Cx Ce 说成「打开一个输入框」，这是 Emacs 25 以前的说法，现在已经不对了。

*scratch*：你的草稿纸

Emacs 启动时会开一个叫 *scratch* 的缓冲区。这个缓冲区的名字前面后缀都有星号——Emacs 约定：名字带星号的缓冲区「没有对应的文件」，你不会不小心把它存盘。按 Cx b（switch-to-buffer）就能回到它。

Emacs 32 官方手册在 (emacs) Lisp Interaction 节点里把这件事说得很直白（我在本机 info 里查到的原文）：「By default, the *scratch* buffer is not associated with any file. Therefore, any text in the buffer is lost when you quit Emacs.」——默认情况下 *scratch* 的内容在退出 Emacs 后就没了。如果你觉得少了点什么（比如临时记了几行代码忘了保存），手册给的做法是：把变量 initial-buffer-choice 设成符号 remember-notes，把 remember-notes-buffer-name 设成字符串 "*scratch*"，于是 Emacs 会用 Remember 把 *scratch* 存回来。

;; 让 *scratch* 的内容跨会话保留（remember 随 Emacs 自带，不用装包）
(setq initial-buffer-choice 'remember-notes)
(setq remember-notes-buffer-name "*scratch*")
易错

网上流传的 (setq scratch-buffer-creation-hook nil) 和 save-scratch-buffer 都是不存在的 API。我在 Emacs 32.0.50 上逐一验证：(boundp 'scratch-buffer-creation-hook) 返回 nil，(boundp 'save-scratch-buffer) 也返回 nil；我又把 Emacs 32 的 lisp/ 目录整个搜了一遍，这两个名字一次都没出现过，32 版的 lisp/simple.el 里 *scratch* 的创建函数 get-scratch-buffer-create 也没有任何钩子调用。把那行加进你的配置，它不会报错（因为 setq 可以凭空创建任意变量），但也什么都不会做——这是最坏的一种错误：静默失效。

要点

remember 是 Emacs 自带的，不是第三方包。我实测 (fboundp 'remember) 和 (fboundp 'remember-notes) 在 -Q（无任何配置）下就都返回 t，(symbol-file 'remember-notes) 指向 lisp/textmodes/remember.elc。它自带的 Info 手册用 Mx info-remember 打开（Emacs 会自动为每个有文档的文件生成这个 info-* 命令），不过这一步取决于你的 Emacs 是不是带 Info 手册的官方构建：有些发行版（比如 Guix / Nix 打包的 Emacs）会把 share/info/ 剥离掉——我本机这台就是这样，(fboundp 'info-remember) 返回 nil，按 Mx 只会得到「Not an internal command」。顺带一提：我把三家的 archive-contents（GNU ELPA、Nongnu ELPA、MELPA）都下载下来搜过，remember 一个都不在里面——因为它根本不需要装。

我的建议仍然是：什么都不做，把 *scratch* 当纯草稿纸，重要东西另存文件。真要跨会话的便签区，再用上面两行。

技巧

*scratch* 里最该做的一件事，是把你要执行的代码写下来，而不是每次都重敲。写完把光标放在那个 defun 里面，按 CMx 就生效了——不用切窗口、不用开新文件、不用担心括号没配对。这也是我推荐你学 Elisp 的方式：在 *scratch* 里写 → CMx 试 → 确认对了再搬进 init.el。

*Messages*：Emacs 的话痨日志

每次你 M: 求值，Emacs 都会把「你敲了什么」和「返回了什么」追加到 *Messages* 缓冲区。想看它，按 Cx b 然后输入 *Messages*。这个缓冲区的大小由变量 message-log-max 控制，我实测 Emacs 32 的默认值是 1000。改它必须写一句 Lisp：M- (setq message-log-max 5000)。这里 Mx 用不了——message-log-max 是变量不是命令，我实测 (execute-extended-command nil "message-log-max") 直接报 ‘message-log-max’ is not a valid command name（Mx 只执行带 interactive 声明的命令）。另外按官方文档，它有三种取值，容易被忽略：数字是上限、nil 是完全不记、t 是一直记、绝不截断。

为什么它重要？因为 message 的输出在屏幕底部那条 echo area（屏幕最下面显示消息的那一行）里只停留一瞬，敲下一个键就被新消息顶掉了。而 *Messages* 里全都有。你在 *scratch* 里调试时，养成「执行完 Cx b *Messages* 看一眼」的习惯，能省掉大量瞎猜的时间。

M-x ielm：一个真正的 REPL

如果你更喜欢传统那种「一行输入一行输出」的交互式解释器，Emacs 里也有。它叫 IELM（Inferior Emacs Lisp Mode，「下级的 Elisp 模式」，命名沿袭 comint 那一套「下级进程模式」的传统）。调用 Mx ielm（本机实测 (fboundp 'ielm) 返回 t），它会切到一个叫 *ielm* 的缓冲区，主模式名是 inferior-emacs-lisp-mode。在这个缓冲区里，你只要输入完整的一行 Lisp 再按 RET，Emacs 就会求值它并把结果显示在下一行——这就是它跟 M: 的根本区别：M: 每敲一行就消失一次，IELM 的输入和输出会一直留在屏幕上等你翻看。

要点

IELM 里哪些键被重绑了，哪些没有。我实测：IELM 的键表叫 ielm-map（就是 inferior-emacs-lisp-mode-map 的别名），它只重绑了 RET、MRET、Cj、CMx、MTAB、Cc Cb/Cc Cf/Cc Cv 这些。Cx Ce 没有被重绑——我在 *ielm* 缓冲区里实测 (key-binding (kbd "C-x C-e")) 返回的仍然是 eval-last-sexp，跟全局一致。所以进 IELM 之后，请用 RET 提交，不要按 Cx Ce。

易错

网上说「Cx d 进入 ELISP 交互」是错的：这个键位从来不是 ielm。本机实测 (key-binding (kbd "C-x d")) 返回 dired——Cx d 是打开目录浏览器的 dired，跟 ELISP 无关；list-directory 绑的是 Cx Cd（多一个 C），也不相关。另外 (where-is-internal 'ielm) 返回 nil，说明 ielm 本身没有任何默认按键，必须 Mx 调用。「Cx d 开 Lisp 交互」是 Emacs 25 以前 lisp-interaction-mode 时代的说法，那个模式今天已经被 *scratch* 加 M: 的组合取代了。

练习 2　你在某个博客上看到「在 Emacs 里按 Cx Ce 可以弹出一个输入框，在里面敲 Lisp 表达式」。这句话哪里对、哪里错？你怎么在自己的 Emacs 上证伪它？

错。Emacs 32 上 Cx Ce 是 eval-last-sexp，它不弹任何输入框，而是原样重新求值上一次求过值的那一行表达式；弹输入框的是 M:（eval-expression）。证伪方法：M: 敲 (key-binding (kbd "C-x C-e"))，屏幕上会显示 eval-last-sexp。这个说法是 Emacs 25 及更早时代 C-x C-e 绑到 eval-expression 时留下的遗产。

二、配置文件什么时候被执行

理解这一节，能省掉你未来几个月里反复出现的那类困惑：「我明明在配置里写了，为什么不生效？」

启动时机的四个阶段

Emacs 启动时按下面的顺序执行 Lisp 代码，顺序本身就是答案：

  1. 加载内置包——Emacs 自己先把自己的功能加载进来。这一步你没法干预。
  2. 读取并求值 early-init.el——这个文件从 Emacs 29 起存在。官方手册 (emacs) Early Init File 给的两个位置是 ~/.emacs.d/early-init.el 和 XDG 版的 ~/.config/emacs/early-init.el（注意不是 ~/.emacs——那是 init.el 的老位置，early-init.el 没有对应的老位置）。它存在的理由，手册说得很准：「This file is loaded before the package system and GUI is initialized」，所以你能在这里调整影响包初始化过程的变量（手册点名了 package-enable-at-startup、package-load-list、package-user-dir）。如果你的 Emacs 版本低于 29，这个文件根本不会被读。
  3. 读取并求值 init.el——优先找 ~/.config/emacs/init.el（XDG），其次 ~/.emacs.d/init.el，也兼容老的 ~/.emacs 和 ~/.emacs.el。绝大多数配置在这里。像 package-archives 这种只影响「安装新包」、不影响「启用已装包」的变量，手册明确说应该留在普通 init.el 里，不用往 early-init.el 搬。
  4. 激活已安装的包——内置包系统在这之后把各包注册进来。这一步你同样不用手动写什么，交给 package.el。
易错

「配置文件被读了一次」不等于「配置里的每一行都在你按完 Cx Ce 之后还在跑」。Emacs 启动时把 init.el 从头到尾读一遍就完事了；它不会「监视」这个文件。你之后按 Cx Ce 重载 init.el，是你手动让它从头再读一遍，副作用是会重复执行之前已经执行过的副作用（比如重复 add-hook）。

重载配置的四种做法，从温和到暴力

;; 1. 最温和：只把某一个文件重新求值一遍（推荐，最常用）
;;    在 *scratch* 里：
(load-file "~/.emacs.d/my-things.el")

;; 2. 整份 init.el 重来一遍
(load-file "~/.emacs.d/init.el")

;; 3. 用 load：它会去 load-path 里搜，并且优先找 .elc（字节编译过的版本）
(load "my-things")
;;    load 的完整签名是
;;    (load FILE &optional NOERROR NOMESSAGE NOSUFFIX MUST-SUFFIX)
;;    - NOERROR 非 nil 时，文件不存在也不报错
;;    - NOMESSAGE 非 nil 时，不打印 "Loading ..." / "Loading done"

;; 4. 直接求值整个当前缓冲区（你在改 init.el 本体时最顺手）
;;    M-x eval-buffer
要点

load-file 和 load 的区别，一句话：load-file 按字面路径读，load 先去 load-path 里搜。我在 Emacs 32 上把两份文档都打出来核对过，load 的文档明确写着「This function searches the directories in load-path」，并且「When searching suffixes, this function normally stops at the first one that exists. If the option load-prefer-newer is non-nil, however, it tries all suffixes, and uses whichever file is the newest」——也就是说 load 默认优先加载 .elc（字节编译产物），源文件 .el 排在后面。

推论很实用：你改了 my-things.el 之后 (load "my-things") 可能什么都没变（因为旧的 .elc 更新），而 (load-file "…/my-things.el") 一定会重新读源文件。日常调试请用 load-file。

use-package：Elisp 里唯一「必须先懂」的配置宏

你迟早会在别人的配置里看到这种写法：

(use-package magit
  :bind ("C-c C-m" . magit-status)
  :init   (setq magit-partial-status-verbose t)
  :config (setq magit-display-buffer-function #'display-buffer))

use-package 是 John Wiegley 写的声明式配置宏，从 Emacs 29.1 起随 Emacs 一起分发（本机 Emacs 32 上 (fboundp 'use-package) 返回 t）。它把「装包 → 延迟加载 → 绑定键 → 设置变量」四件事压缩成一个块，关键是把三段代码拆开、放到不同时机执行：

  • :init 里的内容在包的 require 【之前】执行，而且不管 require 成功与否都会先跑。适合设变量——因为变量必须在包加载之前设好，包自己的初始化代码才能看到正确的值。这一点很容易记反：我实测 (macroexpand-1 '(use-package foo :init (setq a 1) :config (setq b 2)))，展开结果里 (setq a 1) 出现在 (require 'foo …) 前面。
  • :config 里的内容在 require 成功之后才执行；如果包没装上，这段会被跳过（并给出警告）。适合调那些必须包已加载才能用的 API。
  • :bind / :bind-keymap 里的键绑定立刻生效，而且即使包最终没被加载，键也绑得上——绑定上去的是一个惰性包装的转发函数（#' 一个 autoload 的 lambda），敲下去时才真正触发加载。这对启动速度很有价值。
易错

「:init 是 require 之后立刻执行」这个说法是反的。网上（包括不少 use-package 入门文章）都在讲「:init 在包加载前设变量，:config 在包加载后调 API」时把它描述成「require 之后」，但 use-package 的官方语义恰恰相反：:init = before load，:config = after load。上面那段展开代码是我在本机 Emacs 32 上用 macroexpand-1 实际打出来的，(setq a 1)（:init）确实排在 (require …) 前面。

它的代价要说清楚：use-package 是宏，展开后是一堆你得先理解才能 debug 的东西。Emacs 29 的 NEWS 把它夸成「a way that is declarative, tidy, and performance-oriented」——但那句话只夸不劝，是我在核对了 NEWS 原文之后要补的：夸归夸，它展开出来的东西确实需要你先理解才能 debug。如果你就是想彻底搞懂自己的配置，use-package 并不是必需品——手写 (require 'foo) + (add-hook …) + global-set-key 完全可以，而且更好懂。

易错

上游 use-package 仓库已被归档（read-only）。我打开 jwiegley/use-package 的页面，顶部的横幅写的是 「Public archive」；再看它的 commit 订阅源（commits/master.atom），最新一条提交的时间是 2025-08-23，之后再没有新提交。这不影响你使用：Emacs 29–32 都自带一份冻结的 use-package（32 内置那份的头部写着 Version: 2.4.6、Package-Requires: ((emacs "24.3") (bind-key "2.4"))）。它就是一个稳定到不再动的组件。但不要再指望上游会为新 Emacs 修什么——真需要新版本就得自己 fork。

练习 4　你把一段代码放进 ~/.emacs.d/my-things.el，然后在 *scratch* 里执行 (load "my-things")，发现改动「没生效」。请给出至少两个可能原因，以及最稳妥的替代写法。

三、Lisp 数据长什么样：五种你天天都在碰的东西

Elisp 的数据模型小得出奇——一共就那么几种类型，全部加起来不到一屏。学完这一节，你就能读懂 M: 返回的任何东西，这比死记函数有用得多。

1. 整数与浮点数

就是字面意思。42、-7、0 是整数；3.14、1.0 是浮点数。整数和浮点数是不同的类型，比较时要分清用哪个函数：数值比较 = 会跨类型，(= 42 42.0) 返回 t（本机实测）；而判断「是不是同一个东西」的 eq / eql / equal 都不认跨类型，(eql 42 42.0) 返回 nil。常用算术是 + - * / %（除法 / 两个参数都是整数时返回整数商，比如 (/ 7 2) ⇒ 3；只要有一个是浮点数就返回浮点数，(/ 7 2.0) ⇒ 3.5），以及比较用的 = /= < > <= >=。

2. 字符串

双引号包起来，写在 "…" 里。字符串里想放一个引号要写成 \"，换行写成 \n。字符串可以用 concat 拼接，用 length 取长度（返回的是字符数，不是字节数——中文和 emoji 都算 1 个字符）。

M-: (progn (concat "hello" " " "world") (length "hello"))  RET
=> "hello world" 5

;; 字符串和符号、列表之间的转换，写配置时经常要
M-: (symbol-name 'my-var)              RET   => "my-var"
M-: (intern "my-var")                  RET   => my-var
M-: (format "%s-%s" "a" "b")           RET   => "a-b"
M-: (number-to-string 42)              RET   => "42"
M-: (string-to-number "42")            RET   => 42

3. 符号：Lisp 的核心

符号（symbol）是 Elisp 里最独特的概念。通俗讲，它是一个带名字的「可变槽位」，可以当变量用，也可以当函数用。同一个符号在两个不同的世界里各有一个值：

  • 值（value）——用 setq / setq-default 读写，比如 (setq my-var 10)。
  • 函数定义（function definition）——用 defun / defalias 写。调用方式是 (my-func 1 2)：只要第一个元素解析成一个函数，就调用它。

这就是 Lisp「一切皆列表」那句名言的实质：(my-func 1 2)、(setq my-var 10)、(1+ 5) 在数据结构上长得一模一样，都是「一个非空列表，第一个元素是符号」。Emacs 怎么知道该调用哪个？规则是：如果整个表达式求值时，第一个元素在函数位置上能解析成一个函数，就走「函数调用」；否则先求值每个元素再取值。而 (quote x) 是这条规则的逃生舱——它明确告诉 Emacs「别求值，原样给我」。

Elisp 里符号的书写规则和别的语言不一样：连字符 - 可以出现任意多次，只有字母、数字和 +-*/_<>=? 这些单字符算名字的一部分。所以 my-cool-thing 是一个符号，而 my-cool-thing 里的每个 - 都只是个分隔符。这不影响你写配置（你也拆不出东西来），但解释了为什么 Elisp 命名这么爱用连字符。

4. cons cell 与列表：链表，不是数组

这是初学者最容易卡住的地方，但只要记住一句话就够用了：一个 cons cell（cons 对儿）就是「一个值 + 指向下一个 cons 的指针」，两个 cons 首尾相接就成了列表。

访问这对东西的两个函数叫 car（取左边，也就是「值」）和 cdr（取右边，也就是「下一个」）。Car / CDR 这两个名字来自 IBM 704 计算机的指令助记符，是 Lisp 的历史遗产，跟汽车（car）一点关系都没有。

M-: (car '(a b c))   RET   => a      列表的第一个元素
M-: (cdr '(a b c))   RET   => (b c)  去掉第一个之后的剩余列表
M-: (car '())        RET   => nil    空列表的第一个元素就是 nil
M-: (cdr nil)        RET   => nil    nil 的 cdr 还是 nil

;; cons 往列表前面“长”出一个新元素
M-: (cons 'x '(b c)) RET   => (x b c)

;; 一个不以列表结尾的 cons 叫「带点的列表」（dotted pair）
M-: (car '(1 . 2))   RET   => 1
M-: (cdr '(1 . 2))   RET   => 2      cdr 直接是一个数字，不再是一个 cons

;; 我在 Emacs 32 上实测的类型
M-: (list (type-of '(1 2)) (type-of '(1 . 2)) (type-of [1 2]))
RET   => (cons cons vector)

常用的列表操作（cons / car / cdr 是内建原语，其余来自 seq.el，Emacs 25 起就已内置，本机 (fboundp 'seq-filter) 返回 t，不需要 require）：

M-: (seq-filter #'evenp '(1 2 3 4))        RET   => (2 4)
M-: (seq-remove #'evenp '(1 2 3 4))        RET   => (1 3)
M-: (seq-map #'1+     '(1 2 3))           RET   => (2 3 4)
M-: (seq-reduce #'+  '(1 2 3) 0)          RET   => 6
M-: (seq-find #'evenp '(1 3 4 5))         RET   => 4
M-: (seq-some #'evenp '(1 3 4 5))         RET   => t

;; 更老、也更常见的写法（这两组是等价的）
M-: (seq-filter (lambda (x) (= 0 (% x 2))) '(1 2 3 4))   RET   => (2 4)
M-: (delq nil (mapcar (lambda (x) (and (> (% x 2) 0) x)) '(1 2 3 4)))  RET   => (1 3)

;; assoc 系列：查「关键字 → 值」的那种列表（俗称 alist）
M-: (cdr (assoc 'mode '((mode . fundamental) (case . prog))))  RET   => fundamental
M-: (alist-get 'mode '((mode . fundamental) (case . prog)) 'none) RET => fundamental
M-: (alist-get 'zzz   '((mode . fundamental)) 'none)               RET => none
要点

为什么 Emacs 用链表而不是数组？因为 cons cell 之间不要求连续内存，你可以在不搬动任何其他元素的前提下，cons 一个新元素到任意列表的头部，耗时是常数。反过来，要修改列表中间某个元素，你得把整个列表复制一遍，耗时是列表长度。这不是「设计得差」，是取舍：配置和键盘宏天然是「在前面插、在后面遍历」的模式，链表完胜。

代价是：把一个 1000 元素的列表按顺序走一遍，在链表上是 1000 次指针追踪，而 seq- 那套基于数组的实现是连续内存，同样 1000 步但缓存友好得多。但别指望字节编译器帮你把 dolist 自动改写成 seq-map——我查过 Emacs 32 的 lisp/emacs-lisp/bytecomp.el，里面出现 seq- 的地方只有两处：seq-every-p 的一次内部调用，和一张「这些函数的第 1 个参数是函数」的警告元数据表（funarg-positions）。没有一处是代码改写。想要数组级别的性能，只能自己写成 (seq-filter #'pred list) 这种形式。

5. vector：定长数组

方括号包起来，长度固定、下标访问：[10 20 30]。用 aref 取元素、aset 改元素、length 取长度。配置里很少直接写 vector，但字符表（char-table）和 keymap 在内部大量使用 vector，所以调试时你会遇到它。

M-: (let ((v [10 20 30])) (list (aref v 0) (aset v 0 99) v))  RET
=> (10 99 [99 20 30])

6. hash-table：键值字典

字符串很长、或者键不是能用 equal 比较的东西时，列表查找是 O(n)（逐个比），会明显变慢。hash-table（哈希表）用 make-hash-table 创建、puthash 写入、gethash 读取，取值是常数时间。

M-: (let ((h (make-hash-table)))
       (puthash 'a 1 h)
       (puthash 'b 2 h)
       (list (gethash 'a h) (gethash 'b h) (gethash 'c h)))
RET
=> (1 2 nil)

;; 表里没有的键，gethash 返回 nil —— 这就是它的「不存在的值」
;; 想区分「值为 nil」和「键不存在」，用第三个参数给个哨兵值。
;; Emacs 32 上实测签名就是 (fn KEY TABLE &optional DEFAULT)，只有 3 个参数
M-: (gethash 'zzz (make-hash-table) 'not-found)  RET   => not-found

;; 遍历：maphash 接受一个两参数的函数
M-: (let ((h (make-hash-table)))
       (puthash "x" 1 h) (puthash "y" 2 h)
       (maphash (lambda (k v) (message "%s -> %S" k v)) h))
RET   => 消息里会打印 x -> 1 和 y -> 2（顺序不保证）
易错

hash-table 的默认「相等」测试是 eql，不是 equal。我在 Emacs 32 上实测 (hash-table-test (make-hash-table)) 返回 eql。这个区别很要命：eql 比较字符串时比的是「是不是同一个对象」，所以用默认测试的 hash-table 存字符串几乎必然取不到。实测：

M-: (let ((h (make-hash-table)))
       (puthash "a" 1 h)
       (gethash "a" h))
RET
=> nil            ;; 存不进去！因为 "a" 和 "a" 是两个不同的字符串对象

;; 正确写法：创建时指定测试函数
M-: (let ((h (make-hash-table :test #'equal)))
       (puthash "a" 1 h)
       (gethash "a" h))
RET
=> 1

常见的测试函数有 eql（默认，数字和字符可以）、equal（字符串和列表可以，最常用）、eq（只认同一个对象）、string=（只适合全是字符串键的表）。

怎么把任意东西打印出来看

调试数据结构时，你需要一个「把任何值变成人类可读文本」的函数。这里有个必须分清的三件套，我按 Emacs 32 的实际文档定义来说：

  • prin1——输出对象的「可读」表示：字符串会带引号，特殊字符会转义。关键性质：这个输出结果可以直接 copy 回来 M-: 求值，得到同一个值。Emacs 32 文档原文：「Quoting characters are printed when needed to make output that read can handle」。返回一个字符串（不打印到任何地方）。
  • princ——输出对象的「可读但不带引号」的表示，适合显示给人看。文档原文：「No quoting characters are used; no delimiters are printed around the contents of strings」。
  • message——把内容显示在屏幕底部的 echo area，并写进 *Messages*。Emacs 32 文档原文：「Display a message at the bottom of the screen. The message also goes into the *Messages buffer, if message-log-max is non-nil.」——那个「if」很重要，把 message-log-max 设成 nil 之后消息就只闪一下、*Messages* 里也不再留底了。另外它用的是 printf 风格的格式串，不是 Lisp 打印规则。

所以调试时最实用的组合是 (message "%S" x)——%S 这个格式符会调用 prin1 的逻辑，所以你既能看到带引号、引号转义的可靠表示，又把它送到 *Messages* 里。永远不要用 (message "%s" x) 去打印字符串：如果你要打印的字符串里含 %（比如一段正则），会触发格式串解析错误。

M-: (message "%S" '(a "b" 3))   RET   => (a "b" 3)     在 echo area 显示
M-: (message "%s" '(a "b" 3))   RET   => (a b 3)       字符串不带引号，人看更舒服

;; 这是最常用的一条调试语句
M-: (message "变量 foo 当前是 %S" foo)   RET

;; prin1 不显示，只返回字符串，可以拿来做字符串处理
M-: (concat "结果是 " (prin1-to-string '(1 2)))   RET   => "结果是 (1 2)"
技巧

变量 print-level 和 print-length 控制打印嵌套结构的深度和长度（Emacs 32 上实测两者默认值都是 nil，即不截断，全部打印）。调试一个环状结构或者巨大的列表时，它们能救你的屏幕：(setq print-level 3 print-length 20) 会把深层嵌套显示成 #0#。改完记得 (setq print-level nil print-length nil) 改回去。

练习 7　用 hash-table 存「用户配置」，某个用户的 theme 字段你没设过（想表达「用默认值」），另一个人你显式设成了 nil（想表达「禁用主题」）。为什么 gethash 区分不了这两种情况？你能给出两种绕开的办法吗？

因为 hash-table 里「键不存在」和「键存在但值为 nil」的返回值都是 nil。办法一：用第三个参数——(gethash 'theme config 'not-set)，用一个不会出现在值里的哨兵值。Emacs 32 上 gethash 的签名实测是 (fn KEY TABLE &optional DEFAULT)，总共只有 3 个参数，网上流传的 (gethash KEY TABLE nil nil DEFAULT) 四参数写法会报 wrong-number-of-arguments（我实测过）。备选办法是用 maphash 遍历整张表。

四、函数：把「一个动作」写成可复用的东西

到目前为止你写的都是「敲一次就没了」的表达式。接下来这一步是分水岭：用 defun（define function，定义函数）给它一个名字，从此就能在 minibuffer、配置、别的函数里反复调用它。

;; 把这段贴进 *scratch*，然后按 C-M-x
(defun my-greet (name)
  "向 NAME 问好。

DOC 字符串里的第一个词应该是一个动词，这是 Emacs 的约定，
`C-h f` 和 checkdoc 都会拿它做检查。"
  (message "你好，%s！" name))

(my-greet "世界")   => 你好，世界！

三个要点：

  1. DOC 字符串（文档字符串）是双引号紧跟在参数列表后的那个字符串。它不是注释，是 Emacs 会真的去读的东西：按 Ch f、在提示符 Describe function: 处输入 my-greet，显示的就是它。写函数必写文档字符串——哪怕只给自己看。
  2. 参数列表 (name) 里都是「符号」不是「变量」。名字叫什么随便你，但在函数体里它是一个新的局部绑定。
  3. 函数体的最后一个表达式的值就是返回值。所以上面那个函数其实返回的是 (message …) 的返回值（消息文本本身），虽然我们不用它。

interactive：让函数能按 Mx 调用

一个函数默认不能用 Mx 调用——因为 Emacs 不知道该往参数里填什么。加上 (interactive …) 声明就解决了。这个声明有两种写法：

;; A. 字符串速记法：一串「代码字母 + 提示语」，用 \n 分隔多个参数
(defun my-count-words ()
  "数一下当前缓冲区有多少个词。"
  (interactive)
  (message "当前缓冲区有 %d 个词" (count-words)))

;; B. 表单法（更灵活，可以写任意 Lisp 表达式）
(defun my-greet-buffer (bufname)
  "在 BUFNAME 指定的缓冲区里打招呼。"
  (interactive (list (buffer-name (current-buffer))))
  (with-current-buffer bufname
    (message "这个缓冲区里有 %d 行" (line-number-at-pos))))

Emacs 32 的 interactive 文档把可用的「代码字母」列得很全，实测在 Emacs 32 上 (documentation 'interactive) 能完整取出这份清单。写配置你只需要记住这几个：

  • P——前缀参数（按下命令时带的那串 Cu，原样传进来，可能是 nil）。
  • p——前缀参数转成数字；没按前缀参数时当作 1。绝大多数「重复几次」的命令都用它。
  • n——在 minibuffer 里问用户要一个数字。
  • s——问用户要一个字符串。
  • b / B——问用户要一个缓冲区名（b 必须已经存在，B 可以不存在）。
  • f / F——问用户要文件名（f 必须是已存在的文件，F 可以新建）。
  • d——问用户要一个目录名。
  • r / R——传进当前选区（point 和 mark 的位置），R 在没有激活选区时传 nil。
  • S——问用户要符号（内部主要用）。
  • x / X——读一段 Lisp 表达式：x 读但不求值，X 读并求值。写交互式 Lisp 求值器要用它。

前缀参数：P 与 p 的区别

这是新手最常懵的一处。区别在「没按前缀参数」的时候：

(defun my-demo (arg)
  (interactive "P")
  (message "arg 是 %S" arg))

;; 我在 Emacs 32 上实测的 interactive-form（这是查「内置命令怎么声明」的正经办法）：
;;   (interactive-form 'forward-char)      RET   => (interactive "^p")
;;   (interactive-form 'goto-line)         RET   => (interactive … [append goto-line-read-args (nil t)] …)
;;   (interactive-form 're-search-forward) RET   => (interactive "sRE search: ")
;;   (interactive-form 'find-file)         RET   => (interactive … [find-file-read-args "Find file: " …] …)

;; 一个同时支持两种调用的函数：带前缀就重复，不带就做一次
(defun my-repeat-forward (n)
  "向前移动 N 次。"
  (interactive "p")
  (dotimes (_i n)
    (forward-char 1)))

;; 交互调用时，三种情况分别是：
M-x my-repeat-forward          ;; => 走 1 步（因为 "p" 在无前缀时给 1）
C-u M-x my-repeat-forward      ;; => 走 4 步（C-u 相当于 4）
C-u C-u M-x my-repeat-forward  ;; => 走 16 步

;; 陷阱：「从 Lisp 里调用」和「交互调用」不是一回事！
;; interactive 声明只在交互调用时生效；直接写 (my-repeat-forward)
;; 就是拿 0 个参数去调一个要 1 个参数的函数：
;;   (my-repeat-forward 5)   ⇒ 正常，走 5 步
;;   (my-repeat-forward)     ⇒ (wrong-number-of-arguments my-repeat-forward 0)

如果你想区分「用户按了前缀」和「用户没按」，用 "P" 再配 prefix-numeric-value（本机实测 (fboundp 'prefix-numeric-value) 返回 t）：

(defun my-shout (times)
  "喊 TIMES 遍；没给前缀参数就喊 3 遍。"
  (interactive "P")
  (let ((n (if times (prefix-numeric-value times) 3)))
    (dotimes (_i n)
      (message "啊！"))))

;; 变量 current-prefix-arg 在 Emacs 32 上实测 (boundp 'current-prefix-arg) => t
;; 它就是 Emacs 内部存放「本次按键的前缀参数」的变量。
;; ⚠ 陷阱：它只在【交互调用】期间有意义的值；平时它是 nil，
;;   所以绝不要在包加载时读它来判断「用户有没有按前缀」。

可选参数与可变参数：&optional 和 &rest

Elisp 的函数参数列表支持两个特殊记号，让一个函数能同时服务「两种调用形态」：

;; &optional 之后的所有参数都可以不传，缺省值是 nil
(defun my-repeat-command (cmd &optional n)
  "执行 CMD 几次，N 默认 1。"
  (dotimes (_i (or n 1))
    (funcall cmd)))

;; &rest 把剩下的所有实参打包成一个列表
(defun my-log (level &rest messages)
  "把 MESSAGES 打到 echo area，前缀是 LEVEL。"
  (message "[%s] %s" level (string-join messages " ")))

(my-log "info" "a" "b" "c")   => [info] a b c
(my-log "warn")              => "[warn] "     ;; 注意末尾那个空格：格式串里的空格还在
易错

&rest 捕获的实参总是「已经求过值」的。这意味着 (my-log "x" (+ 1 2)) 里 messages 拿到的是 (3) 而不是 ((+ 1 2))。想要「不求值」的原样列表，得用 quote（'）把整个列表包起来：(my-log "x" '(+ 1 2))，这样 messages 就是 ((+ 1 2))。注意别顺手写成 #'——函数引用作用于列表时得到的是「一个匿名函数对象」，我实测 (my-log "x" #'(1 2 3)) 里 messages 拿到的是 ((1 2 3))，列表内容变成了这个匿名函数的参数列表，跟你想要的完全不同。

如果你的函数要接受「任意数量的表单并且它们不应该被求值」，标准做法是传 符号而不是列表：(my-eval-forms '(a b c))，然后在函数体里用 (eval form (current-buffer)) 逐个求。

词法绑定与闭包：为什么你的变量不会「串味」

Elisp 有两套变量作用域规则：动态绑定（dynamic binding）和词法绑定（lexical binding）。区别用一个具体场景就能讲清：

;; 情形一：词法绑定（现代 Emacs 的默认）
;; 这个文件开头必须有这一行 cookie
(defvar my-counter
  (let ((n 0))
    (lambda () (setq n (1+ n)) n))
  "一个计数器闭包。")

;; 同【一个】闭包反复调用，它记住的 n 一直累加
(funcall my-counter)   => 1
(funcall my-counter)   => 2
(funcall my-counter)   => 3

;; 而另一个独立的闭包有自己的一份 n，互不干扰（我实测下面两行）
(defvar other-counter (let ((n 100)) (lambda () (setq n (1+ n)) n)))
(funcall other-counter)  => 101
(funcall my-counter)      => 4      ;; my-counter 的 n 没被 other-counter 影响

闭包（closure）就是一个「记住了自己出生环境里的变量」的函数。上面的 n 在 let 结束后本该消失，但 lambda 把它抓了下来，所以每次调用都能接着加。这不是玄学——Elisp 的词法绑定就是闭包。

Emacs 32 里默认就是词法绑定，所以上面能跑。但有个坑：词法绑定是靠文件第一行的「cookie」决定的，不是靠全局设置。如果你新建一个 .el 文件忘了写那一行，Emacs 会加载时给出警告。我实测过，警告原文是：

Warning (files): Missing ‘lexical-binding’ cookie in "/tmp/foo.el".
You can add one with ‘M-x elisp-enable-lexical-binding RET’.
See ‘(elisp)Selecting Lisp Dialect’ and ‘(elisp)Converting to Lexical Binding’
for more information.

照它说的按 Mx elisp-enable-lexical-binding 就能自动加上。文件第一行长这样：

;;; my-file.el --- 一句话说明  -*- lexical-binding: t; -*-

;; -*- lexical-binding: t; -*-
易错

网上流传的「emacs-lisp-mode 会在你存盘时自动补上 cookie」是假的，我实测过。我建了一个不带 cookie 的 .el 文件，用 Emacs 32 打开（确实自动切进了 emacs-lisp-mode，因为 auto-mode-alist 里 \.el\' 就映射到它）再存盘——文件里一行 cookie 都没多。原因很简单：那个负责补 cookie 的 emacs-lisp-write-hook 根本不存在，(fboundp 'emacs-lisp-write-hook) 返回 nil，整个 lisp/ 目录搜不到这个名字；emacs-lisp-mode-hook 在 emacs-lisp-mode 里实测是空的（before-save-hook、write-file-functions 也都是 nil）。

技巧

Emacs 32 给你的是「点一下模式行」的入口，不是「自动补」。我实测 emacs-lisp-mode 的模式行里有一个 lexical-binding 指示器（显示成 /l，切到动态绑定时显示 /d），用鼠标点它就能切换，Emacs 会顺手把 cookie 写进缓冲区第一行——这个交互在 elisp-mode.el 里实现（elisp--dynlex-modeline-map）。键盘用户就按提示走：Mx elisp-enable-lexical-binding，它会问你确认一下，然后把 cookie 加到第一行并置好这个 buffer 的 lexical-binding。

不过最省心的还是新建文件时就手动写上。反正你要写的那行也不长，贴在第一行，一劳永逸：

什么时候会遇到动态绑定？主要是在读别人的老代码时。Elisp 的规则很机械：defvar / defcustom 给了初值，变量就是 special（动态绑定）；只写了变量名、不给初值，才是词法绑定。另外还有两类自动 special 的：所有用 defvar 声明过的 buffer-local / global 特殊变量，以及名字以连字符结尾的变量（Emacs 惯例，比如 my-var-）。我实测确认了这几条：(special-variable-p 'x) 对「(defvar x nil)」返回 t，对「(defvar x)」返回 nil，对「(defvar x "-")」返回 t。

;; 动态绑定（special）的经典写法（读老代码会遇到）
(defvar my-mode-enabled nil)          ; 带初值的 defvar ⇒ special
(defun my-turn-on ()
  (setq my-mode-enabled t))           ; 改的是全局值

;; 想声明一个词法绑定的变量：defvar 不给初值，另外提供变量名
(defvar my-count)                     ; 只声明，不赋值 ⇒ lexical
(defun my-count-it ()
  (setq my-count 1))                  ; 每次调用都是一份新的局部绑定

;; 怎么判断一个变量是不是 special 的？
;; 常用的两个内置谓词：
;;   (special-variable-p 'my-mode-enabled)  ⇒ t 表示动态绑定
;;   (local-variable-p 'foo)                ⇒ t 表示它是 buffer-local 的
;; 注意：网上流传的 (defvar-p 'x) 这个函数【不存在】，
;;       我实测 (fboundp 'defvar-p) 返回 nil，会报 void-function。
要点

动态绑定没有彻底消失。Emacs 自己的代码里到处是 special 变量——我实测 (special-variable-p 'debug-on-error) 和 (special-variable-p 'message-log-max) 都返回 t。原因很实际：很多包靠「设置一个全局变量、任意深度的代码都能读到」来通信，而你用词法绑定写的代码只能看到自己 let 出来的那些。这也是为什么 debug-on-error、message-log-max 这类配置项必须理解成「全局开关」而不是「一个普通变量」。

实践建议：你自己写的代码一律用词法绑定（文件头写 cookie，变量别用 - 结尾），只在读别人的老代码、或者你确实需要「设置一次、深处任意位置都能读到」时才用动态绑定。

练习 8　一个命令在 interactive 声明里写 "P"，另一个写 "p"。用户都不按前缀参数直接调用，它们分别收到什么值？如果两个都写 "p"，用户能区分吗？

"P"（raw prefix argument）在没按前缀时收到 nil；"p"（numeric prefix argument）在没按前缀时收到 1，按了 Cu Cu 就是 16。两个都写 "p" 的话，命令本身分不出来——想区分「显式传了 1」和「没传」，必须用 "P" 再用 (prefix-numeric-value arg) 转换（Emacs 32 实测 (fboundp 'prefix-numeric-value) ⇒ t）。Emacs 内置的 forward-char 用的是 "p"（我实测 (interactive-form 'forward-char) ⇒ (interactive "^p")），所以 Cu Cu Cf 才会走 16 步。

练习 9　你 Cx Cf 打开一个别人给的 adder.el，里面有个函数用 let 捕获了一个变量、再返回一个 lambda。你按 CMx 求值之后调用它，得到 void-variable。Emacs 处理这个文件时给过你一句警告吗？具体是什么？根因是什么？

先把一件被广泛误传的事说清：出错的不是「存盘 / 重开 Emacs」这个动作，而是「这个文件里没有 lexical-binding cookie」这件事本身。CMx 只是把当前 buffer 里的这个 defun 求值一遍，它按当前 buffer 的绑定模式执行，跟你存没存盘、Emacs 是不是刚启动的完全无关。

根因是动态绑定和词法绑定的区别。没有 cookie 的 buffer，lexical-binding 是 nil（本书作者实测 (buffer-local-value 'lexical-binding (current-buffer)) 返回 nil），走的是动态绑定：let 里的变量只在那个函数还在执行的那段时间里存在。而 lambda 是要留到函数返回之后才被调用的——那时 let 早就退出了，那个变量根本不存在，于是 void-variable。

下面是本书作者在本机 Emacs 32.0.50 上真跑出来的对照实验，两个文件正文一字不差，只差文件头那一行：

无 cookie 的版本：
  (defun p3-make-adder (n) (let ((base n)) (lambda (x) (+ x base))))
  lexical-binding = nil
  (funcall (p3-make-adder 10) 5)  ⇒  报错 (void-variable base)

有 cookie 的版本：
  ;;; p4.el  -*- lexical-binding: t; -*-
  (defun p4-make-adder (n) (let ((base n)) (lambda (x) (+ x base))))
  lexical-binding = t
  (funcall (p4-make-adder 10) 5)  ⇒  15

Emacs 给的警告确实有，原文是：Warning (files): Missing ‘lexical-binding’ cookie in "…/adder.el". You can add one with ‘M-x elisp-enable-lexical-binding RET’.但要注意它出现的时机：本书作者实测，它是在 load 这个文件时（以及字节编译时）发出的，不是你 Cx Cf 打开文件时发出的——所以纯 CMx 这条流程里你看不到它。能替你发现的只有模式行上那个 /l/ 指示器：它在就说明当前 buffer 是动态绑定（词法绑定时那儿什么都没有）。

解法两条：① Mx elisp-enable-lexical-binding RET（本书作者实测它是真实存在的命令，它会往文件里补上 cookie）；② 自己在文件头写上 ;;; adder.el --- 说明 -*- lexical-binding: t; -*-。新建 .el 文件时建议手写这一行——Emacs 不会自动帮你补：emacs-lisp-mode 在存盘时不加 cookie（网上说的 emacs-lisp-write-hook 这个函数，本书作者实测在 Emacs 32 里根本不存在）。

五、宏：先别急着写，但一定要会读

Emacs 配置里有大量「看起来像函数、其实不是」的东西。判断方法有两条，都要靠实测。Emacs 没有一个现成的「这是不是宏」谓词（顺带一说，macro-function-p 这个函数不存在，我实测 (fboundp 'macro-function-p) 返回 nil）：① 看 (symbol-function '名字) 是不是一个以 macro 打头的 cons；② 直接 (macroexpand-1 '名字)——不是宏就原样返回给你。

;; 写法一：看 symbol-function 的类型和头（不依赖任何文档的硬判据）
(defun my-macro-p (sym)
  "如果 SYM 定义成宏就返回非 nil。"
  (let ((f (and (fboundp sym) (symbol-function sym))))
    (and (consp f) (eq (car f) 'macro))))

M-: (car (symbol-function 'when))              RET   => macro
M-: (car (symbol-function 'save-match-data))    RET   => macro
M-: (car (symbol-function 'with-current-buffer)) RET  => macro
M-: (car (symbol-function 'ignore-errors))      RET   => macro

;; 写法二：直接问「它展开出什么」。不是宏就原样返回，这一句最省事
M-: (macroexpand-1 'when)     RET   => when
M-: (macroexpand-1 'car)      RET   => car

;; ⚠ 别用 (documentation 'X) 的最后一行来判断：宏和函数的文档
;;   最后一行都是 (fn …)。我实测 (documentation 'when) 的末行是
;;   "(fn COND &rest BODY)"，和 (documentation 'car) 的 "(fn LIST)" 一个格式。

;; 陷阱一：核心函数是 subr 不是 cons，对它 car 会直接报错
M-: (car (symbol-function 'forward-char))  RET
=> (wrong-type-argument listp #<subr forward-char>)

;; 陷阱二：特殊形式（let / progn / condition-case）也是 subr，不是宏
M-: (type-of (symbol-function 'condition-case))  RET   => subr
易错

网上（和老教程里）常见的 (car (symbol-function 'forward-char)) 这行在今天的 Emacs 上会直接报错。它来自一个更老的时代——那时 symbol-function 对核心函数返回的是一个列表，所以你还能看到 "primitive" 这个字符串。现代 Emacs（我实测 32.0.50）里 forward-char 是 subr 对象，(type-of (symbol-function 'forward-char)) 返回 subr，对它取 car 就是上面那个 wrong-type-argument listp。写代码时务必先判 (consp f) 再取 car，否则就会撞上这个错。

还有一个纯约定、但很好用的线索：Elisp 里给宏服务的辅助函数常以 - 开头（例如 if-let* 系列内部会调一些 --if-let*-guard 之类的东西）。而以 - 结尾的变量是 buffer-local 的标志（见第四节），两个方向别搞混。

易错

读老配置时看到 when-let / if-let，要知道它们在 Emacs 31.1 已经过时了。我实测 (macroexpand-1 '(when-let ((a 1)) a)) 返回 (if-let* ((a 1)) a)，而 subr.el 里 when-let 和 if-let 的 defmacro 上都挂着 (obsolete "use `when-let*' or `and-let*' instead." "31.1")——你一求值它，字节编译器就会警告。现在该写的是加星号的新版：if-let*、when-let*、and-let*（我实测这三个 fbound 都是 t）。这正好是第 4 节的现实用途：碰到不认识的老宏，先 macroexpand 一次，你不但能看懂它，还能立刻发现它该不该换。

宏的本质是：它不执行，它生成代码。调用 (when 条件 体…) 时，Emacs 先把这一串符号变成一棵代码树，交给解释器或字节编译器去执行。

M-: (macroexpand '(when (> 3 2) "yes"))   RET
=> (if (> 3 2) (progn "yes"))      ;; 宏被展开成了这个

M-: (macroexpand-1 '(pcase 1 (1 'one)))    RET
=> (if (eql 1 1) (let nil 'one))        ;; 只展开一层，结果还不是宏

M-: (macroexpand-1 'when)                 RET
=> when                               ;; 不是宏调用，就原样返回

M-: (macroexpand-all '(progn (when a b))) RET
=> (progn (if a (progn b)))           ;; 递归展开到没有宏为止

;; 我在 Emacs 32 上实测：macroexpand / macroexpand-1 / macroexpand-all 全部 fbound = t

macroexpand 是调试宏的唯一可靠工具，也是理解 Emacs 内置语法糖的钥匙。当你看 with-current-buffer 看不懂时，M: 敲 (macroexpand-1 '(with-current-buffer foo (bar)))，展开成什么就是什么。

什么时候不该写宏

宏很强，但它是本手册里我要明确劝你少用的东西。三条判据：

  1. 能用函数解决的，绝不用宏。函数在调用时求值，宏在定义时求值——这就一个区别。比如「按参数次数重复执行」你可能想写宏，其实用 dotimes 就够了。
  2. 参数求值次数不同时才需要宏。这是宏唯一真正不可替代的能力。如果参数求几次都一样，写宏纯粹是给自己找麻烦。
  3. 字节编译器会警告你。我实测 Emacs 32 上 (require 'bytecomp) 之后 byte-compile-warnings 的值是 t，而且字节编译器会专门检查宏的卫生性问题。注意：bytecomp 默认没有被加载，所以启动后立刻 M: 敲 byte-compile-warnings 会得到 void-variable——先 (require 'bytecomp)。

字节编译：把解释执行换成提前编译

字节编译（byte compilation）：Emacs 自带一个编译器，把 .el 源文件编译成 .elc。效果有三个：加载更快（函数调用变成直接跳转）、发现更多错误（未定义变量、未使用的绑定都会报出来）、跑得更快（解释器的开销消失）。

;; 交互式编译当前缓冲区
M-x byte-compile-file        ;; 产出 foo.elc
;; Emacs 32 上实测 (interactive-form 'byte-compile-file) 解出来是
;;   [buffer-file-name current-prefix-arg nil derived-mode-p emacs-lisp-mode
;;    file-name-directory read-file-name "Byte compile and load file: " "Byte compile file: "]
;; 读法：它拿 read-file-name 问你要编译哪个文件，而「默认目录」只有在
;; 你当前这个 buffer 既有 buffer-file-name、又是 emacs-lisp-mode 派生模式时
;; 才会预填成该文件所在目录。所以：在 .el 文件里直接回车就是编它自己；
;; 在 *scratch* 里则会问你路径。
;; ⚠ 前缀参数的含义不是「顺便 load」以外的东西——有 C-u 时提示语会变成
;;   "Byte compile and load file: "，也就是编译完顺手 load 进当前会话。

;; 编译整个目录（改过一整批源码后用这个）
M-x byte-recompile-directory
;; Emacs 32 上实测 (interactive-form 'byte-recompile-directory)
;;   => (interactive "DByte recompile directory: \nP")
;; "D" = 问一个目录名，然后 "P" = 问前缀参数。
;; ⚠ 前缀参数的真正含义（官方文档原文）：
;;   - 子目录【总是】会被处理，不按前缀也一样；
;;   - 前缀为 0 ⇒ 连【还没有 .elc】的 .el 也一起编译；
;;   - 前缀非 0 ⇒ 逐个问你要不要编，并且每个子目录也要问一遍。
;;   所以「不按前缀 = 只编这一层」是错的。

;; 只重编译当前这一个文件（即使你没改它）
;; ⚠ byte-recompile-file 在 -Q 下 fbound 是 nil，必须先 (require 'bytecomp)
(require 'bytecomp)
M-x byte-recompile-file

;; 关掉编译警告（不推荐，除非你嫌吵）。
;; bytecomp 默认没被加载，直接 setq 会凭空创建一个同名变量、
;; 而真编译器用的还是它自己那份 —— 静默失效。所以必须先 require。
(setq byte-compile-warnings nil)

;; 检查哪些 .el 还没有 .elc（诊断启动慢）
M-x byte-recompile-directory 并对着可疑目录跑一次即可
要点

什么时候该字节编译？答案是：对配置来说，几乎永远不需要。字节编译的优势主要是启动速度——加载 .elc 比解释 .el 快。代价是增加了调试难度（栈回溯里出现 byte-run 的帧，你看不见源码行号）和开发摩擦（改了 .el 忘了 recompile，加载的还是旧 .elc，你会debug半天发现「我明明改了」）。

实用建议：开发期不编译，配置稳定后再按需编译。顺带纠正一个常见说法：use-package 默认【不会】给你的配置字节编译——我查过 Emacs 32 内置的那份 use-package-core.el，:ensure 的实现只负责装包，不碰 byte-compile（我实测 use-package-always-ensure 默认就是 nil）。如果你真的想要「装包时顺带编译」，得自己在 :ensure 里显式写 (byte-compile-file ...)，或者装完之后手动 Mx byte-recompile-directory 跑一遍。

易错

改了 .el 但 Emacs 加载的还是旧的 .elc。这是 Emacs 调试里最常见的时间黑洞。两种解法：① M-x byte-compile-file 重新编译；② (load-file "path/to/file.el") 绕过 .elc 直接读源文件（这正是第二章推荐 load-file 而不是 load 的原因）。

练习 11　你改了 ~/.emacs.d/my-things.el 里的 my-setup 函数，重新 (load-file …) 之后 Ch f 看到的文档字符串是新的，但实际行为还是旧的。可能是什么原因？给两个诊断步骤。

六、正则：Emacs 里最常用的「字符串手术」

Emacs 用的是 Emacs flavor 的正则语法——它和 JavaScript / Python 的 PCRE 语法不一样，而且不一样的地方很坑：

Elisp 正则与 PCRE 的关键差异

含义Elisp 正则PCRE / JS / Python
捕获组\\(…\\)(…)
非捕获组\\(?:…\\)(?:…)（两者相同）
「或」\\||
行首 / 行尾\\` / \\'^ / $（$ 语义也不同）
单词边界\\< / \\>\\b
字符串里的反斜杠双写："\\([a-z]+\\)"通常单写："([a-z]+)"

注意最后一行：在 Elisp 源码里，反斜杠本身要写成两个（因为字符串字面量里 \ 有转义含义）。写正则时先按 Elisp 字符串规则写，再按 Emacs 正则规则看，两层叠加是最容易出错的地方。抄配置时如果觉得某个正则莫名其妙，先把它打印出来看实际的字符：M: "\\([a-z]+\\)" 然后 (length …) 核对。

四个核心函数

;; 1) string-match：在 STRING 里找 REGEXP，返回匹配起点的下标（或 nil）
;;    第 3 个参数 START 从哪开始找
M-: (string-match "\\([a-z]+\\) \\([0-9]+\\)" "hello 42 world")  RET
=> 0

;; 2) match-data：取回刚才那次匹配的完整结果，是一个整数列表
;;    (起点 终点  第1组起点 第1组终点  第2组起点 第2组终点  …)
M-: (string-match "\\([a-z]+\\) \\([0-9]+\\)" "hello 42 world")  RET
M-: (match-data)  RET
=> (0 8 0 5 6 8)      ;; 实测输出

;; 3) match-string：按组号取匹配到的文本。0 = 整体
M-: (match-string 0 "hello 42 world")  RET   => "hello 42"
M-: (match-string 1 "hello 42 world")  RET   => "hello"
M-: (match-string 2 "hello 42 world")  RET   => "42"
M-: (match-beginning 1)                 RET   => 0     实测
M-: (match-end 1)                       RET   => 5

;; 4) string-match-p：只问「匹不匹配」，不要下标（更快，因为它可以早停）
M-: (string-match-p "[0-9]" "abc")  RET   => nil    ;; 实测
M-: (string-match-p "[0-9]" "a1c")  RET   => 1      ;; 实测：返回的是匹配内的相对下标
易错

match-data 是全局的一份「最近匹配记录」，任何一次新的正则匹配都会覆盖它。Emacs 32 的 match-string 文档明确警告：「many functions in Emacs modify the match data, so this function should be called "close" to the function that did the regexp search」。实战后果：不要写成 (when (string-match-p …) (foo) (match-string 1)) 这种中间插了别的正则操作的代码——foo 里只要有个 re-search-forward，你的组号就全乱了。

要保存就立刻存：M: (let ((m (match-data))) …)，或者用 Emacs 32 内置的 (save-match-data …) 包裹（它是宏，会在 unwind-protect 里把 match data 还原）。

replace-regexp-in-string：一次性的字符串替换

这是配置里最常用的正则函数，因为它不碰缓冲区，只返回一个字符串，没有副作用，非常适合在 M: 里试：

;; 签名：
;; (replace-regexp-in-string REGEXP REP STRING &optional FIXEDCASE LITERAL SUBEXP START)

M-: (replace-regexp-in-string "[aeiou]" "*" "hello world")  RET
=> "h*ll* w*rld"                                    ;; 实测

;; REP 也可以是一个函数：每匹配一次就调它一次，
;; 传入的是「匹配到的文本（一个字符串）」，返回值当替换结果
M-: (replace-regexp-in-string "[0-9]+"
                            (lambda (s) (format "<%d>" (string-to-number s)))
                            "a1b22c")  RET
=> "a<1>b<22>c"       ;; 实测
;; 注意：直接传 #'number-to-string 会报 wrong-type argument: numberp, "1"
;; 因为传进去的是字符串 "1"，不是数字 1

;; 「只替换第一次匹配」的正确写法（Emacs 32 文档给的原例）：
;; 用捕获组把 foo 摘出来、再用 .*\\' 吃掉后面所有东西，
;; 然后第 6 个参数 SUBEXP 传 1，表示「保留第 1 组、丢掉其它」
M-: (replace-regexp-in-string "\\(foo\\).*\\'" "bar" " foo foo" nil nil 1)  RET
=> " bar foo"      ;; 实测：只动了第一个 foo
;; ⚠ 如果省掉 SUBEXP 写成 (replace-regexp-in-string "foo.*\\'" "bar" " foo foo")
;;   结果是 " bar" —— 后面的 "foo" 也被一起吃掉了，这不是「只处理第一次」

;; 用来规范化路径、清理空白，非常实用
M-: (replace-regexp-in-string "[ \t]+$" "" "trailing spaces   ")  RET
=> "trailing spaces"    ;; 去掉行尾空白（实测）

;; 实战：把 ~/.emacs.d 里的硬编码路径改成变量
M-: (replace-regexp-in-string "/home/me/" "~/"
                            "  (load-file \"/home/me/config.el\")")  RET
=> "  (load-file \"~/config.el\")"      ;; 实测

在缓冲区里搜索：looking-at 与 re-search-forward

字符串函数之外，缓冲区里还有两个必备武器：looking-at（只匹配光标位置，不移动光标，成功后留下 match data）适合写判断；re-search-forward（从光标往后搜，找到会移动光标）适合查找替换。

;; looking-at：只问「光标这位置是不是 X」，不移动光标
(looking-at "[0-9]")
(if (looking-at "^;;:") …)

;; re-search-forward：往后找并移动光标，返回 t/nil
(re-search-forward "^defun ")
;; 找上一个：M-x re-search-backward

;; looking-at-p：looking-at 的谓词版本（我的实测：fbound = t）
(looking-at-p "^;;")
技巧

不知道正则怎么写时，先让 Emacs 帮你搜一次。按 M%（query-replace）会直接进交互式替换，输入正则时随时按 M% 可以切换到 regexp 模式试；或者按 Ms（isearch-forward）边搜边调，在 isearch 里按 M% 就是 isearch-query-replace（我实测 (lookup-key isearch-mode-map (kbd "M-%")) 返回它）。在 isearch 里开关正则模式的键是 Mr（isearch-toggle-regexp）——我实测 (lookup-key isearch-mode-map (kbd "M-t")) 返回 nil，Mt 在 isearch 里根本没有绑定，老教程说的「按 Mt 试正则」已经过时。

可用的写法比 JS 多不少：Emacs 正则支持 [[:alpha:]]、[[:digit:]]、[[:space:]]、[[:word:]] 这类 POSIX 括号表达式（我实测 (string-match "[[:word:]]" "ab cd") ⇒ 2），还有 \s-（非空白）、\sw-（非单词字符）、\< / \>（词边界）这些 JS 没有的简写。

练习 12　这段代码为什么有时对有时错？
(when (string-match "foo\\([0-9]+\\)" line) (cleanup) (message "编号是 %s" (match-string 1 line)))

因为 (cleanup) 内部只要有任何一次正则操作（哪怕是 looking-at），全局的 match data 就被覆盖了，后面的 (match-string 1 line) 拿到的是 cleanup 那次的组号，甚至可能返回 nil（Emacs 32 文档：「return nil if NUMth pair didn't match anything, or if there were fewer than NUM sub-expressions」）。修法：把 match-string 挪到 cleanup 之前立刻取值并存进变量；或者把整段用 (save-match-data …) 包起来。

练习 13　你想用 Elisp 正则匹配「一对尖括号里的内容」并取出内容。写出正确的正则和调用代码。顺便说说为什么不能直接写 "(<.*>)"。

正确写法：(let ((s "<b>hello</b>")) (string-match "\\(<.*>\\)" s) (match-string 1 s)) ⇒ "<b>hello</b>"。不能写 "(<.*>)" 的原因有两条：① Elisp 正则里裸的 ( ) 不是捕获组，必须写成「反斜杠 + 括号」即 \\( 和 \\)；② 字符串字面量里 \ 会吞掉后面的字符，所以源码里要写 "\\("，正则引擎看到的才是 \(。顺序反了就会出事：先过 Elisp 字符串解析，再过正则引擎。对照一下：JS 里 /(<.*>)/ 是对的，搬到 Elisp 里必须变成 "\\(<.*>\\)"。

七、错误处理与调试：出错时 Emacs 给你什么

先看清 Emacs 报的是什么

Emacs Lisp 里所有错误都由 signal（抛出）触发。每种错误有一个条件名（condition name），是一串首尾带冒号的符号，例如 void-variable。最常见的几种：

你会遇到的错误类型

条件名触发场景典型修复
void-variable引用了一个从没 defvar / setq 过的变量包没 require；或者变量名拼错了
void-function调用了一个不存在的函数同上；或该函数在别的包里
wrong-type-argument参数类型不对（最常见的是把字符串传给了要数字的函数）看报错信息末尾 (fn …) 那几行，它会指出是哪个 C 函数抱怨
args-out-of-range下标越界（比如 vector 访问越界）检查 aref / aset 的下标
wrong-number-of-arguments实参个数和函数定义对不上看函数的参数列表（Ch f 之后输入函数名）
invalid-regexp正则写错了重点检查 \ 的层数：字符串转义 + 正则转义
quit你按了 Cg不是 bug，是主动中断

开着 debug-on-error 时，Emacs 会把 Emacs 丢进 *Debugger* 缓冲区。它的布局分两截：上半截是「出错瞬间的环境快照」，下半截才是回溯（backtrace，从出错点往外一层层列「谁调用了谁」）。我实测长这样：

Debugger entered--Miscellaneous variable and buffer info:
my-setup:      123
buffer:        #<buffer  *scratch*>
point:         42

my-setup-missing(42)
         ^^^^^^^^: (void-function my-setup-missing)
(funcall 'my-setup-missing 42)

(backtrace)
  my-helper(42)
  load-with-code-conversion("/tmp/x.el" "/tmp/x.el" nil t)
  command-line-1(("--eval" "(my-helper 42)"))

真正有信息量的是带 ^^^^ 的那两行：^^^^ 精确指出出错的表达式，报错类型（这里是 void-function）和原因（my-setup-missing 没有函数定义）都在那一行上。上面那几行环境快照只是告诉你出错时的 point 和当前 buffer，别在快照里找答案，要往下翻到 ^^^^ 行。

易错

网上（和不少中文博客）贴的「调试器长这样」的示例几乎都是编的，而且错得很一致：把回溯印在了报错行上面。真实布局是「环境快照 → 空行 → 带 ^^^^ 的报错行 → 回溯帧」，报错行下面才是「谁调用了谁」。如果你照着错误的示例去找「最后一行是答案」，会正好找错方向——答案在中间那两行，不在最后。

另外提醒一句：环境快照里那些变量值（像上面那个 my-setup: 123）说明该变量确实存在且有值，跟「它的函数定义不存在」是两回事——Elisp 里符号的变量槽和函数槽本来就是分开的，这也是本章第三节讲的事。

condition-case：把错误接住

写配置时你经常需要「试一下，不行就退化到默认值」——某个包没装、某个文件不存在。condition-case 就是干这个的。骨架是：

(condition-case 错误变量
    要试的表达式
  (条件名1  出错时的表达式 …)
  (条件名2  出错时的表达式 …)
  (:success  成功时的表达式 …))

「条件变量」位置的符号会绑定成出错时的错误对象，写 nil 表示不需要。条件分支里写 error 会匹配所有错误（不只是同名那个），此外还有 :success（只在没出错时跑）和 debug 类特殊条件。

;; 我在 Emacs 32 上实测的三个例子
M-: (condition-case nil (error "boom") (error 'caught) (:success 'ok))   RET
=> caught

M-: (condition-case e (list 1 2) (error 'caught))                        RET
=> (1 2)                      ;; 成功时，条件变量 e 绑定为 nil

;; 嵌套接错：里层接住后重新 error，外层再接住
M-: (condition-case nil
       (condition-case nil (error "in") (error (error "wrapped")))
     (error 'outer))                                                    RET
=> outer

;; 实战：文件不存在就用默认值
(defun my-read-config (path fallback)
  "读 PATH 的内容；读不到就用 FALLBACK。"
  (condition-case nil
      (with-temp-buffer
        (insert-file-contents path)
        (buffer-string))
    (error fallback)))

(my-read-config "/nonexistent" "默认配置")   => "默认配置"

;; 调用可能不存在的函数
(defun my-safe-call (fn &rest args)
  "调用 FN（可能未定义），失败返回 nil。"
  (condition-case nil
      (apply fn args)
    (void-function nil)))
易错

不要用 condition-case 吞掉你还没搞懂的错误。这是本章最重要的一条工程建议。典型失败案例：写了个 setq 然后 condition-case 一把 error，结果包没装、方法名写错，你以为配置生效了其实一行都没跑——你会花几天时间怀疑 Emacs 坏了。正确顺序是：先让错误暴露出来（开着 debug-on-error），修好了再考虑要不要包一层 condition-case。

debug-on-error：出错时自动进调试器

;; 打开（Emacs 32 上实测默认是 nil）
(setq debug-on-error t)
;; 关闭
(setq debug-on-error nil)

;; 或者在报错现场临时打开：对着 *Messages* 里那条报错 M-x debug-on-error
;; 注意：这行只有在 debug.el 已加载时才可用（-Q 下 fbound 为 nil），
;;       平时报过错之后 Emacs 通常已经把它加载进来了。
易错

「按 Mx debug-on-error 开关一下」这句话是有前提的，别当成万能开关。Emacs 的 Mx 只能执行带 interactive 声明的命令，而绝大多数普通变量不是命令。我实测 (commandp 'debug-on-error) 返回 nil，真去执行会得到 ‘debug-on-error’ is not a valid command name。所以本文这几处一律写 (setq debug-on-error t)。

能这样 Mx 的变量是少数，而且有规律：包作者专门给它配了一个 define-minor-mode 的同名命令（define-minor-mode 会同时生成一个开关命令）。这一章里提到的 edebug-all-defs / edebug-all-forms 就是这种——我实测 (commandp 'edebug-all-defs) 返回 t，Mx 能用；而 edebug-initial-mode（commandp = nil）就不行。

打开后，任何未捕获的错误都会把 Emacs 丢进 *Debugger* 缓冲区。这里的按键有个大坑：全是不带 C 前缀的裸字母，不是 Cx 那种带修饰键的序列。我读了 Emacs 32 的 lisp/emacs-lisp/debug.el 里 debugger-mode-map 的定义，逐条抄给你：

  • c — Continue，继续往下执行
  • q — Quit，放弃调试直接回到最上层
  • d — Step through，逐个子表达式单步
  • j — Jump，跳到当前这一层的出口继续跑
  • e — 在出错的现场求值一个表达式（调试利器）
  • b — 在这个 frame 退出时再次打断点（注意这不是「退出调试」，退出是 q；b 的名字容易让人误会）
  • n / p — 在回溯的各层之间前后移动光标（这组键来自父键表 backtrace-mode-map）
  • RET — 跟随光标处的符号（同样来自父键表）
易错

把调试器里的键记成 Cc / Cb / Ct 是很常见的错误。那是 Special Mode 一类的「带 C 前缀」传统在作祟，但 debugger-mode-map 走的是另一套：直接用裸字母。我实测 (commandp 'debugger-continue) 之外，源码里绑的就是 "c"、"b"、"q" 这些单字符键。而 Ct 那个键在调试器里根本不存在——回溯层之间移动光标用的是 n / p。

要点

调试时打开 debug-on-error，日常关掉。长期打开的代价是：任何第三方包里的一个小错误都会把你弹出调试器，非常烦。版本方面我实测过：Emacs 32 上 debug-on-error 和 debug-on-quit 默认值都是 nil，而 backtrace-on-error 这个变量在 32 上已经不存在了——(boundp 'backtrace-on-error) 返回 nil。老配置里写 (setq backtrace-on-error t) 现在只有两个下场：setq 会凭空把这个变量建出来（看起来「生效了」，其实没有任何代码读它，典型的静默失效），而任何读它的旧代码则会撞上 void-variable。正确写法是 (setq debug-on-error t)。

Edebug：源码级单步调试器

Edebug（Emacs Debugger）让你一行一行地走函数体，在执行前停下来看每个表达式的值。这是 Elisp 生态里唯一的正经调试器，Emacs 32 内置。

用法只有两步：

  1. 把光标放进要调试的函数定义里，按 CuCMx。这个前缀参数让 eval-defun 在求值前先「插桩」（instrument）——Emacs 32 手册 (elisp) Instrumenting 节点的原话：「it instruments the definition before evaluating it. (This does not modify the source code itself.)」
  2. 用别的方式调用这个函数，Edebug 就激活了。默认是 step 模式：每执行一个表达式前停一次。
;; Emacs 32 上实测的默认值（boundp 全部为 t）
;; edebug-all-defs        nil
;; edebug-all-forms       nil
;; edebug-initial-mode    step
;; edebug-setup-hook      nil
;; edebug-test-coverage   nil

;; 打开「eval-buffer / eval-region 时新定义自动插桩」的开关
(setq edebug-all-defs t)
;; 随时关掉
(setq edebug-all-defs nil)

;; 对光标所在的顶层表达式强制插桩（不看 edebug-all-defs 的值）
M-x edebug-eval-top-level-form

在 *edebug* 缓冲区里的常用键：n（下一步，不进函数）、s（单步）、g（继续到下一个断点）、i（给当前调用的函数插桩并跳进去）、q（退出）。

易错

Edebug 的老变量 edebug-file 在 Emacs 32 里已经不存在了。我实测 (boundp 'edebug-file) 返回 nil（注意 boundp 对不存在的变量返回 nil 而不是报错——真要撞上 void-variable 的是直接 (setq edebug-file 'single-step) 之后再去读它的代码）。我又拉了 Emacs 28 / 29 / 30 三个分支的 lisp/emacs-lisp/edebug.el 源码全文搜索，三个分支里都搜不到 edebug-file 这个字符串，也就是说它消失得比 28 还早。现在该用的开关是 edebug-all-defs 和 edebug-all-forms，停止粒度则在 *edebug* 缓冲区里用 n / s / g 这几个键切换。

追踪函数调用：trace-function

「这个函数到底被谁调用了、传了什么参数、返回了什么」——这是追踪（tracing）要回答的问题。Emacs 32 上正确的命令是 trace-function：

M-x trace-function             ;; 问函数名，开始追踪（前台，会弹出 *trace-output*）
M-x trace-function-background   ;; 后台追踪，不打断你正在做的事
M-x untrace-function            ;; 停掉某一个（需要 trace.el 已加载，见下方易错）
M-x untrace-all                 ;; 全部停掉（同上）
易错

Emacs 32 里 trace、untrace、trace-region 这些函数名全部不存在了。我在 Emacs 32.0.50 上逐一实测：(fboundp 'trace)、(fboundp 'untrace)、(fboundp 'trace-region) 全部返回 nil；(symbol-file 'trace) 虽然指向 trace.elc，但那个文件里根本没有 trace 这个函数。我把 lisp/emacs-lisp/trace.el 的顶层定义全部列了一遍，公开的（不带 -- 的）只有六个：trace-values、trace-make-advice、trace-function-internal、trace-is-traced、trace-function-foreground、trace-function-background，外加 untrace-function 和 untrace-all；剩下的 trace--entry-message、trace--exit-message、trace--display-buffer、trace--insert、trace--read-args 都是内部实现细节。Emacs 32 官方手册的 (elisp) Debugging 节点也只提 trace-function-foreground、trace-function-background 和 trace-values 三个名字（原文：「This package provides the functions trace-function-foreground and trace-function-background for tracing function calls, and trace-values for adding values of select variables to the trace」）。

另有一处容易搞混：M-x trace-function 看起来像个独立函数，其实源码里写的是 (defalias 'trace-function #'trace-function-foreground)——它就是 trace-function-foreground 的别名。所以 trace-function 带 autoload cookie，而 untrace-function / untrace-all 没有：我实测在 -Q 下 (fboundp 'trace-function) 已经是 t，但 (fboundp 'untrace-function) 还是 nil。要 Mx untrace-function，得先 (require 'trace)（或者先跑过一次 M-x trace-function，那会自动加载它）。

追踪输出会累积到 *trace-output* 缓冲区（缓冲区名由变量 trace-buffer 决定，Emacs 32 实测它的默认值就是字符串 "*trace-output*"——这是变量，不是函数）。追踪被追踪的函数的开销很大，而且 trace.el 顶部的注释明确列了限制：只有「通过函数单元调用」的函数才会产生输出；C 代码直接调用的 subr、编译期就展开的宏都追踪不到。

更灵活的方案：advice-add

Emacs 32 里，追踪的现代替代品是 advice（补丁机制）——给已有函数挂上一层或多层包装函数，而不是替换它。

;; 挂一个 :around advice：能看到参数，也能看到返回值
(defun my-trace-display-buffer (orig-fun &rest args)
  "打印 display-buffer 的调用参数与返回值。"
  (message "display-buffer 被调用，参数 %S" args)
  (let ((res (apply orig-fun args)))
    (message "display-buffer 返回 %S" res)
    res))

(advice-add 'display-buffer :around #'my-trace-display-buffer)
;; 用完之后
(advice-remove 'display-buffer #'my-trace-display-buffer)

;; 还有 :before / :after / :filter-args / :filter-return 几种组合器。
;; :filter-return 适合「修改返回值」，这是 Emacs 32 手册
;; (elisp) Advising Functions 节点给的原例：
;;   (defun my-double (x) (* x 2))
;;   (defun my-increase (x) (+ x 1))
;;   (advice-add 'my-double :filter-return #'my-increase)
;;   ;; 此后 (my-double 3) 返回 7
易错

redefine-function 在 Emacs 32 里也不存在了。我实测 (fboundp 'redefine-function) 返回 nil，并且在整个 lisp/ 目录里搜不到这个名字（emacs-26 到 emacs-31 各分支的 advice.el 也都没有）。老配置里 (redefine-function …) 的写法请全部改成 advice-add / define-advice。

还有一个相关的坑：老式的 defadvice 宏从 Emacs 30 起被标记为 obsolete（etc/NEWS.30 原文：「'defadvice is marked as obsolete. See the "(elisp) Porting Old Advice" Info node for help converting them to use 'advice-add or 'define-advice instead」）。新代码一律用 advice-add（运行时挂）或 define-advice（源码里声明）。

练习 15　把这段骨架填完整：(condition-case ______ (open-dashboard-file "~/nope.json") (______ 'fallback))。两个空分别填什么？这么写会不会掩盖掉「方法名写错」这类 bug？

填 nil 和 error，即 (condition-case nil (open-dashboard-file "~/nope.json") (error 'fallback))。条件变量写 nil 表示不需要错误对象；(error …) 分支匹配所有错误，包括 void-function 这类你可能没预料到的，所以它会掩盖掉「方法名写错」这类 bug。调试阶段建议先把条件变量写成 err，加上 (message "出错：%S" err)。

练习 16　一篇老文章让你设置 (setq edebug-file 'single-step) 来控制 Edebug 的停点粒度。在 Emacs 32 上会发生什么？现在的等价物是什么？

不会报错，但也什么都不会发生——这恰恰是最糟的情况。我实测 (setq edebug-file 'single-step) 在 Emacs 32 上执行成功（setq 可以凭空创建变量），随后读它也能拿到 single-step，(boundp 'edebug-file) 从 nil 变成了 t——但 Edebug 根本没在读这个变量，所以你的「单步设置」被静默丢弃了。真正会报 void-variable 的是那些读它的旧代码（比如某个老包在初始化时 or else edebug-file）。

确认办法：我把 Emacs 28 / 29 / 30 三个分支的 lisp/emacs-lisp/edebug.el 全文下载下来搜，三个分支里都搜不到 edebug-file 这个字符串——它消失得比 Emacs 28 还早。现在控制 Edebug 行为的现役变量是 edebug-all-defs（控制是否自动插桩所有定义，默认 nil）、edebug-all-forms、edebug-initial-mode（默认 'step）、edebug-test-coverage（我实测这几个 (boundp …) 全部是 t，只有 edebug-file 是 nil）。而「停点粒度」根本不是靠变量控制的——它是在 *edebug* 缓冲区里用 n / s / g 这几个键实时切换的。

易错

老教程里那张 C-h a / C-h f / C-h g = apropos 三兄弟的表，在现代 Emacs 上整张都错。我逐条实测 Emacs 32：(key-binding (kbd "C-h a")) = apropos-command；(key-binding (kbd "C-h f")) = describe-function（不是 apropos-function）；(key-binding (kbd "C-h g")) = describe-gnu-project（不是 apropos-value！）。而 (where-is-internal 'apropos-function) 返回 nil、(where-is-internal 'apropos-value) 只返回菜单项——这两个 apropos 命令根本没有默认键位，只能 Mx 调。

另一个常见误解：C-h a 并不搜一切。它的文档字符串第一句就是「Show commands (interactively callable functions) that match PATTERN」——只搜命令。我实测 (documentation 'apropos-command) 确认了这一点。真正「搜一切符号」的是 Mx apropos，文档是「Show all meaningful Lisp symbols whose names match PATTERN」。

要点

整个 apropos 家族的完整清单可以在 Emacs 上自己问出来——M- (documentation 'apropos-command) 看它搜什么、(interactive-form 'apropos-command) 看它怎么收参数。我实测 (interactive-form 'apropos-command) 解出来是 (current-prefix-arg apropos-do-all apropos-read-pattern "command or function" "command")：一个可选前缀、是否连非交互函数一起搜、搜索词、以及「command」这个类别提示。同族还有 apropos-documentation（Ch d）、apropos-user-option（Ch u）、apropos-value、apropos-function、apropos，我实测全部 fbound 为 t。

读一段配置的标准流程

  1. 先问命令名。你在别人的 init.el 里看到一个不认识的名字，想知道它是什么：Ch a（apropos-command）输进去，看它的文档字符串和所属文件。但要先认清 Ch a 的射程——它的文档字符串第一句是 “Show commands (interactively callable functions) that match PATTERN”，也就是它只搜「命令」。一个包本身不是命令，拿包名去搜它大概率什么都搜不到。名字搜不到就换更宽的：Mx apropos（搜一切符号）、Ch d apropos-documentation（搜文档内容）。包本身要用下一条的 describe-package 查。
  2. 再问包。想知道某个包提供哪些命令，Mx apropos-command 输入包名。想看一个包的确切元数据（版本号、仓库地址、依赖），Emacs 32 的正确入口是 Mx describe-package（我实测 (fboundp 'describe-package) 返回 t）。也可以在 Lisp 里查：M- (alist-get 'evil package-alist) 返回描述结构。注意网上流传的 package-descriptions 这个变量不存在——我实测 (boundp 'package-descriptions) 返回 nil，会报 void-variable；正确的是 package-alist（需要先 (require 'package)，它在 -Q 下默认没定义）。
  3. 然后跳到源码。Mx find-function，或者在 C-h f 的结果窗口里按 o。Emacs 32 上 (fboundp 'find-function) 返回 t，find-function-other-window 也存在（在另一个窗口打开源码，不打断当前工作）——这是读大文件时最舒服的姿势。
  4. 用 re-search-forward 定位。落到几千行的 evil-core.el 里，直接 Ms 搜关键函数名比翻页快得多。
  5. 看不懂宏就展开。遇到 (when-let* …)、(if-let* …)、(with-eval-after-load …) 这种，读不懂就 M- (macroexpand-1 '(with-eval-after-load 'foo (bar)))——我实测它展开成 (eval-after-load 'foo (lambda nil (bar)))，一看就懂了。顺便还知道了 with-eval-after-load 只是「包一层 lambda 再交给 eval-after-load」。
  6. 想知道谁调用了它，在源码里 Mx grep 或者 Mx rgrep（需要装 rg）。
技巧

「这个变量是谁设的」是配置排错的头号问题。Emacs 内置的入口是 Mx customize-apropos（我实测它 commandp 为 t）——它把符合条件的选项列成一张表，每一项右边直接写着「在哪个文件里、什么值、由哪个 custom 主题设的」，并提供点开改、复制值的入口；想直接设一个就用 Mx customize-set-variable。

顺带打掉一个很常见的错误推荐：toggle-debug-on-signal 这个命令不存在。我实测 (intern-soft "toggle-debug-on-signal") 返回 nil，(fboundp 'toggle-debug-on-signal) 和 (boundp 'toggle-debug-on-signal) 也都是 nil，整个 lisp/ 目录搜不到这个名字。Emacs 也没有「在 *Warnings* 里告诉你变量 X 在文件 Y 第 N 行被设成 Z」这种机制——那是有人把 *Warnings* 里真实存在的少数几条警告（比如 lexical-binding at end of file unreliable）吹大了。想追「谁在运行时改了我的变量」，可靠的办法是给那个变量的 setter 加 advice，用上一节刚讲的 advice-add 就能做到。

判断「这是核心功能还是第三方」

这是初学者最大的困惑。三条判据，从快到慢：

  1. 看 Ch f 输出末尾的「File:」那行。路径在 lisp/ 或 lisp/<子目录>/ 下就是核心；在 elpa/<包名>-版本/ 下就是从 ELPA 装的。不想读长输出就直接跑 M- (symbol-file '命令名)，它返回同样的路径。
  2. 不要用「有没有连字符」来判断——这个说法方向就是错的。核心里绝大多数最常用的命令都带连字符：find-file、re-search-forward、switch-to-buffer、describe-function 全是。真正完全不带连字符的核心命令只有 forward-char、backward-char、revert-buffer、save-buffer 这类基础动词。虽然第三方包也倾向带连字符（vertico-sort、magit-status、consult-buffer），但两边重叠太多，这条线索基本没有判别力。
  3. 看文件头。第三方包的源文件开头有 ;;; foo.el --- 说明 -*- … -*- 和 ;; Version:、;; Package-Requires:、;; URL: 这些元信息，核心文件也有——但核心文件的 ;; Maintainer: 一般是 emacs-devel@gnu.org 或 FSF 的人。

练习 17　你在 Ch f 的结果窗口里想跳到源码，不想记命令名。有哪两种办法？另外，哪种命令能在不打断当前缓冲区的情况下打开源码？

① 在 *Help* 缓冲区里直接按 o——这是 describe-function 自带的键，不用记命令名。② Mx find-function（Emacs 32 实测 (fboundp 'find-function) ⇒ t）。要「不打断当前缓冲区」就用 find-function-other-window——我实测它在 Emacs 32 上存在，读几千行的大文件时用这个最舒服：源码在另一个窗口，当前正在读的东西不会被顶掉。

练习 18　你在 Mx 里输入一个命令名，Emacs 提示「Not an internal command」。有没有一种可靠方法判断它到底是不是 Emacs 内置的？「核心命令通常不带连字符」这个说法可靠吗？

可靠方法：Ch f 输入命令名，看输出末尾的「File:」那行——路径在 lisp/ 下就是核心，在 elpa/<包名>-*/ 下就是第三方。或者跳过 Help 窗口直接跑 M- (symbol-file '命令名)，它返回同样的路径（Emacs 32 实测 (fboundp 'symbol-file) ⇒ t）。

而「核心命令通常不带连字符」这个说法基本是错的，不能用它判断。核心里最常用的命令绝大多数都带连字符：find-file、re-search-forward、switch-to-buffer、describe-function、kill-line 全是；真正光秃秃不带连字符的核心命令只有 forward-char、backward-char、revert-buffer、save-buffer 这几个基础动词。所以这条「经验法则」的命中率远比你以为的低。

十、最后：一份能跑的最小配置

本章所有内容浓缩成一个可以直接粘贴进 ~/.emacs.d/init.el 的文件。它不装任何包，纯粹用来固化你刚学的几件事：

;;; init.el --- 我的 Emacs 配置  -*- lexical-binding: t; -*-

;;; Commentary:
;; 一个零依赖的最小配置。复制进 ~/.emacs.d/init.el 即可运行。

;;; 1. 让 *Messages* 记更多一点，方便排查（Emacs 32 默认 1000 条）
(setq message-log-max 5000)

;;; 2. 一个自己的函数 + 一个带前缀参数的交互命令
(defun my-count-words ()
  "数一下当前缓冲区有多少个词。"
  (interactive)
  (message "当前缓冲区有 %d 个词" (count-words)))

(defun my-backup-by (n)
  "把当前缓冲区前 N 行复制一份到寄存器 r。"
  (interactive "P")
  (save-excursion
    (goto-char (point-min))
    (let ((beg (point)))
      (forward-line (or n 1))
      (copy-region-as-kill beg (point)))))

(global-set-key (kbd "C-c w") #'my-count-words)
(global-set-key (kbd "C-c b") #'my-backup-by)

;;; 3. 一个宏（只为了演示 macroexpand，不建议在真配置里用）
(defmacro my-when-debug (c &rest body)
  "若 C 则求值 BODY。"
  `(if ,c (progn ,@body)))

;;; 4. 调试开关：平时关着（debug-on-error 是变量，不是命令，
;;;     所以只能这样 setq，不能 M-x debug-on-error）
(setq debug-on-error nil)

;;; 5. 保存前把行尾空白去掉
(defun my-before-save ()
  "保存前把行尾空白去掉。"
  (when emacs-lisp-mode
    (delete-trailing-whitespace)))

(add-hook 'before-save-hook #'my-before-save)

;;; init.el 结束
要点

上面这段我在 Emacs 32.0.50 上用 emacs --batch -Q -l init.el 实际跑过一遍，结果逐条如下（都是实测输出）：(key-binding (kbd "C-c w")) ⇒ my-count-words，(key-binding (kbd "C-c b")) ⇒ my-backup-by，(macroexpand-1 '(my-when-debug t 1 2)) ⇒ (if t (progn 1 2))，(memq 'my-before-save before-save-hook) ⇒ (my-before-save)；在一个三行缓冲区里调用 (my-backup-by 2)，kill-ring 的表头确实变成了 "line one\nline two\n"。而且因为两个函数都带 (interactive …)，它们也是真正的命令——我实测 (commandp 'my-count-words) 和 (commandp 'my-backup-by) 都返回 t，所以绑上去的 Ccc w / Ccc b 能正常触发。

改完之后按 M- (load-file (expand-file-name "init.el" user-emacs-directory)) 重载，或者重启 Emacs。
