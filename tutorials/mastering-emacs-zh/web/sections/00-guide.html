导读：怎样用这本书

这一章不教你按键，它教你两件事：Emacs 究竟是个什么东西、它要你付出什么；以及这本书该怎么读。读完你会有一个 2026 年的版本坐标、一张「内置还是第三方」的分界表、一份可以直接抄进 init.el 跑起来的最小配置、三种安装路线各自的代价、十八章的顺序与依赖、四个学习阶段的时间投入、一张章节导读表，外加十条常见误区。你不需要任何 Emacs 基础。

0.1 Emacs 到底是什么：一个用 Lisp 写出来的编辑器

先说一个能让你省下三个月的事实：Emacs 不是一个编辑器加上一堆插件。Emacs 本身就是一段运行在编辑器里的 Lisp 程序。你启动 Emacs，启动的其实是它的 Lisp 解释器；屏幕上那块文本区域，是这个解释器的输出。你的每一次击键，都是在调用一个用 Lisp 定义的函数。

这决定了 Emacs 和其他工具的根本区别。VS Code 的界面逻辑写在 TypeScript 里，你只能通过它公开的 API 之一部分去改动；Neovim 的界面逻辑是 C 写的，配置只能填参数。而 Emacs 的界面逻辑就是 Lisp 本身，没有「内部」和「扩展点」之分。所谓「可编程」，在这个语境下不是修辞，是字面意思。

要理解后面十六章的全部内容，你必须先装下四个词。它们是 Emacs 的基本词汇表，本书从第一章到最后一章都在用：

  • buffer（缓冲区）：你正在编辑的那份文本。注意不是「文件」——文件在磁盘上，buffer 在内存里。同一个文件可以同时有两个 buffer，一个在左边一个在右边，两边的光标各自独立。「这个文件没保存」这句话在 Emacs 里其实是「这个 buffer 被改过」。
  • window（窗口）：屏幕上的一块矩形区域，显示一个 buffer。注意不是「窗口」那种系统窗口——Emacs 里窗口可以任意切分，一个 frame（帧，也就是操作系统意义上的窗口）里可以有十几个 window。
  • frame（帧）：操作系统意义上的一个窗口。Emacs 是多帧程序，你可以开两个独立的 Emacs 窗口，它们共享同一套配置。
  • mode（模式）：一段绑定好的行为约定。major mode（主模式）决定「这份文本是什么类型、编辑时用哪套按键」，比如写 Python 时是 python-mode，写 C 时是 c-ts-mode。minor mode（辅模式）是可叠加的小开关，随时能开能关，比如显示行号的 display-line-numbers-mode。一个 buffer 同一时刻只有一个主模式，可以有任意多个辅模式。

还有一件事必须现在讲清楚，否则你后面会一直困惑：Emacs 自带一本完整的说明书，而且它就在编辑器里。它的入口是 Mx（按名字调用任何命令）和 Ch 这一族查询键——后面跟 f（function）、v（variable）、k（key）、m（mode）分别是查函数、查变量、查按键、查当前模式。这套命名是 1980 年代的遗产，但你要记的不是这四个字母，而是这句：Emacs 里任何东西都能查，而且查的方式是统一的。

上表里 Cx Cq 是「只读模式」，不是很多人在网上看到的「保存全部」。「保存全部」是 Cx s，命令名 save-some-buffers（Emacs 30 起就是这个绑定，本书作者在 30.2、31.0.91、32.0.50 上都实测过）。至于网上流传的 Cx s a 和命令名 save-all——那是更老版本 Emacs 的写法，Emacs 30 之后已经不存在，敲 Mx save-all 只会得到「没有这个命令」。

要点

按键记号现在就记住：C 是 Ctrl，M 是 Alt（Mac 上是 Option），S 是 Shift。写成一个键序列时中间用空格分开表示先后，比如 Cx Cf 就是先按住 Ctrl 按 X 松开，再按住 Ctrl 按 F。

那它值得学吗？回报集中在一句话上：你学会的那一套按键、编辑思路、配置手段，在所有场景里都通用，而且都能被你改造。一旦你用 Emacs 写代码，你会发现读邮件、跑 shell、编译、查手册、记笔记、写文档，用的都是同一套肌肉记忆、同一个快捷键体系、同一个配置入口。这在别的编辑器身上做不到——它们各自是一个独立应用。

代价同样是真的。这一章先把账摊开，后面就不含糊了：

  • 配置门槛高。一个「什么都不改」的 Emacs 用起来相当难受。键位自成一套，很多日常功能默认没有，开箱体验远不如 VS Code。这是 Emacs 用户配置量大、人均会写 Elisp 的根本原因。
  • 离 Vim 的肌肉记忆很远。Vim 的 hjkl 加计数前缀这套东西，在 Emacs 里默认完全没有。想要得自己装 evil（Vim 模拟层），但装了等于放弃了一部分 Emacs 自己的设计。
  • 包的来源质量参差不齐。Emacs 允许任何人发布包，好处是选择多，坏处是你得自己判断：这个包还在维护吗？它和你已有的包冲突吗？本书凡是引入第三方包都会写明来源和仓库，不让你猜。
  • 启动要调优。配置臃肿的 Emacs 启动几秒钟很常见，而且不调会越来越慢。第十三章整章讲这件事。
  • Lisp 解释器是单线程的。一个跑很久的 Elisp 任务会把界面卡住。Emacs 靠原生编译（native compilation，把 Elisp 编译成机器码）缓解了一部分，但没有完全解决。
易错

不要指望「装完 Emacs 就有现代编辑器体验」。如果你要的是一个开箱即用、不折腾就够用的工具，Emacs 不是它。如果你要的是一个能被改造成你自己形状的工具，并且愿意为此花两三个月，那么你读完了这本书大概还想要更多。

要点

本书写配置时会用 if (fboundp '某函数) 这种写法把版本差异吸收掉，这样你在 29、30、31 上读到的同一段代码行为一致，不需要自己判断版本。第十三章会详细讲这个技巧。

顺便纠正一个在中文 Emacs 圈流传很广的说法：有人告诉你「Emacs 29 引入了 use-completion 新式补全开关」。这个说法是错的。本书作者在本机实测过：use-completion 这个变量在 Emacs 30.2、31.1、32.0.50 上都不存在，Emacs 29 到 32 的官方 NEWS 里也从来没有出现过这个名字，源码树里同样搜不到。想要现代补全体验，走的是另一条路（vertico + orderless 那套，见 0.5 节），本书第十四章会讲。

三个包仓库分别是什么

Emacs 内置一个叫 package 的包管理器（Emacs 25 起）。你在 Emacs 里按 Mx 输入 package-install 回车，它会去网上下载并安装第三方包。下载的来源叫 包仓库（package archive）。Emacs 自带两个：

  • GNU ELPA，地址 https://elpa.gnu.org/packages/。FSF 审核过的包，质量有底线。截至 2026 年 10 月有 508 个包。
  • NonGNU ELPA，地址 https://elpa.nongnu.org/nongnu/。审核标准宽松一些的官方仓库，290 个包。magit、evil、flycheck、slime、lua-mode 都在这里。

这两个地址是 Emacs 的默认值，本书作者在本机 Emacs 32.0.50 上实测确认过（注意仓库名是字符串，所以打印出来带引号）：

$ emacs --batch -Q --eval '(progn (require (quote package))
                                       (prin1 package-archives))'
(("gnu" . "https://elpa.gnu.org/packages/") ("nongnu" . "https://elpa.nongnu.org/nongnu/"))

注意 MELPA 不在默认值里。MELPA（https://melpa.org/packages/）是社区包仓库，不做审核，任何人都能发。它有 6324 个包，特点是滚动发布：包名后面跟日期戳（比如 vertico-20260913），几乎每天都有新版本。好处是最新，坏处是没有稳定承诺——作者某天推送一个坏版本，你的 Emacs 第二天就起不来了。

易错

如果你要用 MELPA 又不想追新，就把它换成稳定镜像 https://stable.melpa.org/packages/：它有 3482 个包，用语义化版本号而不是日期戳（Emacs 的 package 两种都认——MELPA 上 vertico 是 20260913，stable.melpa 上同一个包是 2.15），只在版本变化时通知你。代价是稳定镜像里的包会比 MELPA 主线旧几个月。本书默认不引入 MELPA，因为上表里那些你真正需要的包现在都在官方仓库里。

最后说一个安全默认值。变量 package-check-signature（包签名检查）控制 Emacs 怎么对待下载下来的包：它本身在 Emacs 24 就有了，而 allow-unsigned 这个取值、以及把它设成默认值的做法，是 Emacs 27.1 引入的——含义是「如果包有签名就验签名，没有签名也放行」。想要严格模式，把它设成 t，这样只接受至少有一个已验证签名的包。代价是很多第三方包没签名，你会装不上。（本机 32.0.50 实测：(default-value 'package-check-signature) 的值是 allow-unsigned。）

0.4 三种安装路线：发行版包、官方预编译、源码与容器

装 Emacs 有三条路。它们没有优劣之分，只有「谁在什么场景下更省事」的区别。这一节把每条路的真实代价和什么时候不该用都写出来。

路线 A：用发行版的包管理器装

最省事的一条。包管理器替你解决依赖、编译、打包。

# Debian / Ubuntu
$ sudo apt install emacs            # 装 GTK 版（有图形界面）
$ sudo apt install emacs-nox        # 装终端版（无图形界面，启动快）

# Fedora / RHEL
$ sudo dnf install emacs

# Arch
$ sudo pacman -S emacs

# 先查清楚它到底会给哪个版本
$ apt policy emacs
$ dnf info emacs

代价是版本滞后。这不是猜测，是可以查到的实情。下表是本书写作时（2026-10）几个发行版的实际情况，数据来自 Debian 包追踪站与各发行版软件仓库页面：

  • Debian 13（trixie，正式版）：Emacs 30.1；Debian 12（bookworm）：28.2；Debian 11（bullseye）：27.1
  • Arch Linux 官方仓库：Emacs 31.1（滚动发行，跟得紧）；Guix：Emacs 31.1

滞后一两个大版本意味着什么？意味着 0.3 节表里那些「Emacs 30 起内置」「Emacs 31 起内置」的东西你可能没有：which-key、EditorConfig 支持、compat 在 28.2 上都没有；lua-mode 在 30.2 上还得自己装。本书的配置片段都用 if (fboundp '……) 做了保护，在老版本上会跳过而不是报错，所以照抄仍然安全。

滞后还有一个更实际的问题：安全补丁。Debian 追踪站上就明确列着 trixie（30.1）有未修安全问题，例如 CVE-2026-77219（PBM/PPM/PGM 图像加载器的整数溢出，攻击者可以用构造的图片越界读出堆内存里的像素值；官方说明写的是「Emacs 31.0.91 之前受影响」）。发行版通常会反向移植补丁而不改版本号，做得好的话你不用管；但如果你用的是无人维护的旧版，那就等于在跑有已知漏洞的代码。

要点

路线 A 适合：公司发的开发机、离线环境、你不想折腾系统的人。路线 A 不适合：需要用到 30/31 新特性的人；以及打算长期用 Emacs 的人——因为你会需要换版本，而系统包一旦装上就很难干净地换掉。

路线 B：用官方发布的预编译版本

这条路的意思是：不经过发行版，直接从 GNU 官方拿已经编译好的二进制。

Windows 上这条路是通畅的。GNU FTP 站 gnu/emacs/windows/emacs-31/ 目录下有官方安装程序：emacs-31.1-installer.exe（标准版，自带依赖，官方 README 说「Mostly, this is the best one to install」）、emacs-31.1-installer-UCRT64.exe（用 Windows 的 UCRT 运行库，在较新的 Windows 10/11 上兼容性更好），以及免安装的 emacs-31.1-nodeps.zip 和 emacs-31.1.zip（前者不带依赖，后者自带依赖）。每个文件旁边都有一个 .sig 签名文件，用来验证下载没被篡改。这个目录里还有一组文件名带 31.1_1 的更新构建，下载前先看清你要的是哪一组。

Linux 上这条路基本不通。本书作者检查了 GNU FTP 的 gnu/emacs/ 目录，里面只有源码包（emacs-31.1.tar.xz、emacs-31.1.tar.gz），没有任何 Linux 预编译二进制。GNU 已经停止发布 Linux 预编译包，官方下载页现在只提供源码包和 Windows 安装程序。如果你看到某个教程说「去 GNU 官网下 Linux 预编译包」，那个链接多半已经失效了。

Android 上官方倒是提供了 APK，在 gnu/emacs/android/ 目录下，形如 emacs-31.1-35-arm64-v8a.apk（arm64-v8a 是绝大多数现代安卓手机）。这个 APK 是给 Termux 用的，见第十五章。

易错

Windows 上还有一个常见的陷阱：装完 Emacs，C- 键位和 M（Alt）跟别的程序冲突，或者字体渲染发虚。Emacs 官方文档里有一节专门讲 Windows 的特殊情况，你装好之后应该去读一遍。

路线 C：从源码编译，或用 Nix / Guix / 容器

C1：从源码编译。步骤是下载 emacs-31.1.tar.xz，解包，./configure --with-x，make，make install。得到的版本一定是 31.1，还能自己加编译选项。代价你要知道：从 tar 包到能跑，中位数是二十到四十分钟，依赖 GTK 开发库、字体库、图像库，缺一个就 configure 失败。调试 configure 失败会占掉你整个下午。

C2：用 Nix 或 Guix。这条路解决了编译问题，同时给你「可重现」和「随时切换版本」两件事。比如在 Guix 上，本书写作时的 emacs 包是 31.1，可以用一次性的方式跑起来，不污染系统：

$ guix shell emacs@31.1 -- emacs --version
GNU Emacs 31.1

Nix 的对应写法是 nix run nixpkgs#emacs。这两条路的前提是你已经装好了 Nix 或 Guix，并且习惯用声明式的方式管理工具。如果你从没碰过它们，为了装一个编辑器先学一套包管理工具，是本末倒置——先走路线 A。

C3：容器。适合两类人：一是需要在一台机器上同时跑多个 Emacs 版本做兼容性测试的；二是团队里想把 Emacs 环境固化成镜像、新人拉下来就能用的。代价是容器里配 X11 转发、中文字体、以及编辑宿主机上的文件都要额外折腾。日常用 Emacs 的人几乎从不需要容器。

要点

怎么选：先用路线 A 装一个能用起来的版本（十分钟），照着本书学。当你第一次因为版本太老而缺功能时（比如发现 lua-mode 要自己装、或者 which-key 没自带），那时候再换路线 B/C。用「换版本」当理由，比用「听说编译版更快」当理由靠谱得多。

0.5 第一次打开 Emacs：先验证它能用

装完之后，Emacs 会问你要不要把默认配置写进配置文件。选 yes。它到底写哪个文件，因机器而异，所以第一件事是查出来，不要凭猜。按 Mx 输入 user-init-file 回车，Emacs 会在回显区显示这一台机器真正使用的配置文件路径——那就是要粘配置的那个文件。

查出来的结果通常是下面两种之一，取决于你的机器上已经存在什么目录：

Emacs 会用哪个配置文件

按键命令作用
~/.emacs.d/ 里没有任何东西全新机器上最常见的情况Emacs 用 ~/.emacs.d/init.el
~/.config/emacs/ 已经存在装过别的 Emacs 发行版、或者你手动建过这个目录Emacs 用 ~/.config/emacs/init.el
~/.emacs 这个旧文件存在很老的安装留下的Emacs 不读它，但会因为它存在而改用 ~/.emacs.d/，并把那个目录建出来
 
$ emacs --batch -Q --eval '(prin1 user-emacs-directory)'
"~/.emacs.d/"

这一条本书作者在本机实测过两次，结论是「全新机器上得到 ~/.emacs.d/」：在 HOME 下没有任何 Emacs 目录时，它就是 ~/.emacs.d/；把 ~/.config/emacs/ 预先建出来，它才变成 ~/.config/emacs/。所以别照抄别的教程里的路径，用上面那个 Mx 查询的结果。

易错

贴错文件是最容易犯、也最难自查的错误：你把七行配置粘进 A 文件，Emacs 重启后读的是 B 文件，于是配置一条都不生效，而屏幕上没有任何报错。如果贴完发现「什么都没变」，第一件事不是检查配置内容对不对，而是回到 user-init-file 确认你粘的是不是它指的那个文件。

这个文件叫 init 文件（初始化文件）。你的所有配置都写在这里，每次启动 Emacs 时它会被读一遍。这一章能让你把这段代码原样贴进去，然后重启 Emacs 看到效果。去掉注释，它只有七行，做三件事，每件都能在本书后面找到对应的章节。

;;; init.el —— 这本书的起点配置
;;;  -*- lexical-binding: t; -*-

;; ① 装包并声明式配置 --------------------------------------------
;; use-package 是 Emacs 29 起自带的宏，不用另外装。
;; :ensure t 表示「这个包没装就自动装」。
(require 'use-package)
(setq use-package-always-ensure t)

(use-package vertico
  :init (vertico-mode))

;; ② 官方配色主题（Emacs 28 起自带 Modus）---------------------
;; modus-operandi = 浅色，modus-vivendi = 深色，
;; 加 -tinted 后缀是「同色系加一点区分度」的变体。
(load-theme 'modus-operandi-tinted t)

;; ③ 几个「人人都想要」的设置 ---------------------------------
;; 用空格缩进而不是制表符
(setq-default indent-tabs-mode nil)
;; 显示行号（buffer-local，只在当前 buffer 生效）
(add-hook 'emacs-startup-hook #'display-line-numbers-mode)
;; 输入 ( 会自动补出 )。注意没有 global-electric-pair-mode
;; 这个命令——30.2 / 31.1 / 32.0.50 上实测都没有，正确的是挂在 prog-mode-hook 上
(add-hook 'prog-mode-hook #'electric-pair-mode)

把上面这段贴进 init.el，重启 Emacs。第一次启动时它会去 elpa.gnu.org 下载 vertico，屏幕底部 echo area（回显区，最下面那一行）会显示进度。这是正常的，等它跑完。

下面这段命令本书作者在本机 Emacs 32.0.50 上实际跑过。它把上面那份配置原样执行了一遍（vertico 那一段单独省掉了，因为它要联网下载包），然后把四项结果打出来：

$ emacs --batch -Q --eval "(progn (require 'use-package)
  (setq use-package-always-ensure t) (load-theme 'modus-operandi-tinted t)
  (setq-default indent-tabs-mode nil)
  (add-hook 'emacs-startup-hook #'display-line-numbers-mode)
  (add-hook 'prog-mode-hook #'electric-pair-mode)
  (python-mode) (display-line-numbers-mode 1)
  (princ (format \"RESULT tabs=%S line-numbers=%S pair=%S theme=%S\"
    (default-value 'indent-tabs-mode) display-line-numbers-mode
    electric-pair-mode (car custom-enabled-themes))))"
RESULT tabs=nil line-numbers=t pair=t theme=modus-operandi-tinted

四个值分别是：indent-tabs-mode 的默认值被设成了 nil（即用空格缩进）、行号已打开、electric-pair-mode 已开启、Modus 主题的名字进了 custom-enabled-themes。(load-theme 'modus-operandi-tinted t) 里那个 t 是「不要弹确认提示」，不是「不要启用」——主题照样会被启用，上面最后一项就是证据。

最后验证一下这台 Emacs 是活的。在回显区输入 Mx，然后键入 version 回车，你会看到一行：

GNU Emacs 31.1

看到版本号，就说明 Emacs 能跑、Info 系统能读手册、你的键盘输入没问题。这一章的动手部分到此结束。

技巧

改了 init.el 怎么让它生效？不用重启 Emacs。打开 init.el，Mx 输入 eval-buffer 回车，作用是「把当前 buffer 当 Lisp 代码执行一遍」。eval-buffer 是个老命令（Emacs 24 系列就有了，本书作者在 31.0.91 和 32.0.50 上实测过）。它跟 M-x load-file 的区别在于不走 load 那条路：不会触发 after-load、after-load-functions 这类加载钩子，也不会去读文件头部的「局部变量」声明。

易错

配置写错了不会毁掉 Emacs。启动时若弹出报错，Emacs 会在警告里直接告诉你这句话：「Start Emacs with the --debug-init option to view a complete error backtrace.」——照做，退出当前 Emacs，用 emacs --debug-init 重新启动，它会停在出错的那一行并进入调试器，你可以逐条展开看是谁出的问题。注意别去敲 Mx debug-init：Emacs 30 之后已经没有这个命令了，那条路只在很老的教程里才出现。实在不想重启用命令行，就先把 init.el 改名（比如 init.el.bak）再启动，Emacs 会回到出厂状态。

易错

不要在 init.el 里写 (load-file "…/other-config.el") 去加载网上抄来的配置。网上配置默认是给你的 Vim/Emacs 换个键，不是教你怎么用。你的肌肉记忆会变成两套按键的混合体，这比不配置更糟。0.10 节会展开讲这个误区。

0.6 这本书的十八章在做什么

本书改编自 Eli Spare 的 Mastering Emacs（第 5 版，英文原书 326 页）。原书的内核讲的是「按键、移动、编辑的肌肉记忆」，这些到今天没过时；但周边生态变了很多（consult、eglot 这些原书成书时都还没有）。所以这本书 = 原书的内核 + 当代 Emacs 的正确做法。

十八章的顺序是刻意排的。关键在于中间三章移动理论的排法：Emacs 的移动命令看似杂乱，其实是分层的——先有「光标放到哪」的通用动作，再在通用动作上叠加「寄存器 / 书签 / 标记」这类跳转原语，最后才是搜索与索引。三章连起来读，才不会觉得命令表是一盘散沙。同理，三章编辑理论从「杀死与粘贴」这个最核心的模型出发，一步步加到键盘宏；三章实用篇按「自己找信息 → 操作外部世界 → 管理文件和进程」排列。

按主题分组，这十八章是这样摆的：

  • 入门（第 0–2 章）：第 0 章是这章导读。第 1 章讲五个核心概念和 Emacs 心智模型与 Vim 的根本差异。第 2 章带你走完「安装 → 界面 → 按键 → 配置」这条链。
  • 基础（第 3–5 章）：三章移动理论。第 3 章讲基础动作、窗口与标签页；第 4 章讲基本移动、书签、寄存器、选区；第 5 章讲搜索与索引。这三章是全书的地基。
  • 进阶（第 6–7、9、11 章）：第 6、7 章是编辑理论（一）（二），讲清 Emacs 最有特色的编辑模型和计数前缀；第 9、11 章是实用篇（一）（三），讲自助探索、项目管理、交叉引用、Dired、编译与 Shell。
  • 精通（第 8、10、12–17 章）：第 8 章编辑理论（三）进入自动化；第 10 章实用篇（二）是 Tramp 远程编辑与 EWW 浏览器；第 12 章 Emacs Lisp；第 13 章安装与配置工程；第 14 章现代工作流实战；第 15 章移动端与特殊场景；第 16 章结语与延伸资源；第 17 章速查表与排障手册（查阅用，不是顺序读的）。
要点

如果你的时间非常紧，最小可用路径是：第 2 章 → 第 4 章 → 第 6 章 → 第 13 章。这四章给你「装好、能动、能改、能装包」四件事。其余章节是把这四件事打磨成肌肉记忆和完整工作流。

易错

不要按「一章一章读完再动手」的顺序学 Emacs。书可以顺序读，练习必须同时做。每一节后面的练习题不是装饰，是这一节真正要你记住的东西。通勤路上读，进了电脑前先做上一节留下的练习，做不动了再回去读一遍解释。

0.9 手机上怎么读，怎么边读边练

本书的主要阅读场景是手机上通勤时读，电脑上精读为辅。这个场景有两个后果，你从现在起就要适应：① 手机上看书时不要指望立刻验证——把「这一节要我做什么操作」记住，看到电脑前再敲；硬要在手机上想清楚「CM f 到底怎么按」，只会让你读不下去。② 本章及各章的按键表在手机上会换行——这是排版问题，不是你看错了。按键那一列永远最短，命令名第二列，作用描述第三列；你只要读懂第三列在说什么就行。

通勤路上具体怎么用

  1. 读（地铁上）。按目录顺序读一到两节。手机读不动 Cc 这类「按住再按另一个键」的时候，记住记号就够了：C 是 Ctrl、M 是 Alt、S 是 Shift、CM 是 Ctrl 加 Alt（Emacs 里这个组合在终端上通常等同于 Meta）。
  2. 标记（随时）。读完一节，把「我想试的三件事」在手机备忘录里敲一行。不用写详细，写「练 4-2」就行。
  3. 敲（到电脑前）。打开 Emacs，按顺序把标记过的东西做一遍。做完才算读完，没做完就是没读。
  4. 答（当天睡前或第二天早上）。把那一节的练习题做完，不看答案先做，做完再点开对答案。答错的那几题，把答案里的为什么读一遍——本书的答案通常不只给命令，还解释为什么是这条命令。

电脑上练的时候，本书每一节后面都有一个「按键速查表」和至少两道练习。建议你用一本真的、项目里的文件来练，不要新建一个空的 buffer 敲 foo bar——练习的目的是建立「看到真实代码 → 想到按键」的条件反射，用空 buffer 练出来的反应迁不到真实场景。还要准备一份乱糟糟的练习材料：一个几百行、行宽乱七八糟、有中文注释的旧文件。Ch k、缩进、批量替换这类操作在整齐的代码上练不出真本事，因为整齐的代码没有「需要收拾的烂摊子」。

技巧

判断一章有没有真学会的标准只有一条：合上书，能不能说出「遇到 X 情况我会用 Y」。如果只能说得出「这一章讲了 Y，但我说不清 Y 用来干什么」，那就是没学会。重读那一节，直到能举出三个具体的 X。

0.10 十个最常见的误区

这一节是全章最实用的部分。每条后面写清了为什么错和该怎么办。

误区 1：把 Emacs 当 Vim 背键位

错在哪：Emacs 的键位是分层设计的。同一前缀下的一堆命令共享语义——Cx 后面跟字母 b（buffer）是切换 buffer、f（file）是打开文件、s（save）是保存。记住「前缀代表操作类别、字母是那个动作的首字母」，二十组键你都能自己推出来；当成背单词表，二十组只能二十组地记。怎么办：读第 4 章时不要只记「Cx Cf 是打开文件」，要问「Cx 是什么类别、f 为什么选 f」。

误区 2：照抄巨型配置而不懂原理

错在哪：网上那些三百行起步的配置，99% 是作者的偏好而不是最佳实践。照抄之后一旦某个包更新导致报错，你完全不知道该动哪一行。更糟的是你会形成「我的 Emacs 能用是因为我抄了个好东西」的错觉。怎么办：本书 0.5 节那份配置去掉注释只有七行，就是刻意的。读完整本书之后你自己加的每一行，都应该能用一句白话说清楚「这行在干什么、为什么需要它」，做不到就别加。

误区 3：装五十个包，却没有一个用熟

错在哪：这是最常见也最隐蔽的坑。Emacs 的包生态奖励「装得多」——别人的 dotfiles 看起来都很长，你很容易觉得「我配置得不够厚」。但边际收益递减极快：第一个补全包给你效率提升，第五个补全包给你的是排查它们谁在抢 completion-at-point-functions 的痛苦。怎么办：一条硬规则——一次只加一个包，用满一周再加下一个。用满一周的意思是「你已经不自觉地用上了它，而且知道它叫什么名字」。第 13 章整章讲怎么有纪律地加包。

误区 4：只会复制粘贴配置，不会写

错在哪：Elisp 是 Lisp。你不会写不代表学不会——它比 Python 简单得多。但只复制粘贴会让你卡在一个非常具体的位置：某个教程让你改一个变量，你不知道该改成什么类型、要不要加引号。怎么办：第 12 章是本书唯一从零教语法的一章，学完你就能读懂 Ch v 看到的默认值「为什么长那样」。任何时候卡住了，都可以先跳到第 12 章。

误区 5：用 Mx 代替形成肌肉记忆

错在哪：新手用 Mx 是对的——它让你在不背按键的前提下开始干活。但一直用它，你就永远不会「想到按键」，宏回放之类场合更是完全想不起来。怎么办：分层。刚学一个命令时用 Mx 确认它存在；练熟后有意识地改成按键。本书每节的练习题就是逼你做这件事。

误区 6：一上手就调启动速度

错在哪：启动慢的头号原因是包太多和配置里塞了同步网络调用。把注意力放在 gc-cons-threshold（垃圾回收阈值）、dumper 之类的调优上是本末倒置。怎么办：先把包数量降到你觉得「确实都需要」，再看还慢不慢。第 13 章给出测量启动耗时的命令和排查方法，但那应该是你把配置整理干净之后的事。

误区 7：照着网上的 Emacs 教程敲

错在哪：Emacs 的默认行为在 26 到 31 之间改过好几次，网上随便一篇 2020 年的文章，它说的「默认行为」对你这版可能根本不成立。怎么办：任何一条「默认是 X」的断言，你都可以花十秒钟验证：Ch v 然后输入那个变量名。如果实测值和文章说的不一样，以你机器上的为准。

误区 8：在 MELPA 主线上追新版本

错在哪：0.3 节说过，MELPA 用日期戳滚动发布。一个包的作者某天推了个有 bug 的 commit，你的 Emacs 当晚就起不来，而你会以为是 Emacs 本身崩了。怎么办：把 MELPA 换成 https://stable.melpa.org/packages/。如果你完全不需要 MELPA（本书的配置默认就不需要），更好：干脆别加它。

误区 9：把 Emacs 当 IDE 用

错在哪：Emacs 有 LSP、有项目管理、有搜索替换，但它没有一个统一的「项目面板」。很多人装一堆包试图造出一个 VS Code 的资源管理器，然后抱怨「为什么 Emacs 这么难用」。怎么办：接受 Emacs 的工作方式是以「项目 + 当前文件」为中心，不是以「文件树」为中心。项目根目录用 project 管理，文件树用 Dired 临时看一眼就行，第 9、11 章讲这套。

误区 10：把 Emacs 和 Vim 当敌人

错在哪：两者源自同一个技术路线：把编辑器做成可编程的。Emacs 用 Lisp，Vim 用 VimScript，Neovim 用 Lua。共同点是「你可以把编辑器改成任何样子」，不是某一边特有的优点。而且两边都能接过来对方的用户。怎么办：如果实在放不下 hjkl，装 evil（仓库 github.com/emacs-evil/evil，NonGNU ELPA 与 MELPA 都有，NonGNU ELPA 里是 1.15.0）。但请给它两周——很多人装完就再也回不去了，原因不是 evil 不好，而是 Emacs 自己的按键体系其实更整齐。

0.11 你现在应该做的事

这一章的信息量不小，下面是压缩成六条的行动清单。读完请照着做，别只是读完。

  1. 装一个 Emacs。用发行版包管理器就行，十分钟。装完先按 Mx version 确认它能跑。
  2. 把 0.5 节那七行配置贴进 init.el，重启。等 vertico 装完。这是本书唯一要求你现在动手做的事。
  3. 记住五个按键：Mx（按名字找命令）、Ch f、Ch v、Ch k、Ch m。这五个是你永远不会忘的，因为它们是 Emacs 教你怎么用自己。
  4. 装一个练手的文件。一个几百行、格式混乱的旧文件。它比任何教程都重要。
  5. 读第 1 章和第 2 章。这两章是全书门槛最低的（只有第 2 章要求你能读得懂一点点 Elisp），读完你就能开始用 Emacs 干活了。
  6. 记住一句话：Emacs 里任何东西都能查，而且查的方式是统一的。Ch 就是那个统一的方式。你不需要记住命令名，你只需要记住怎么找命令名。
要点

最后一条不是安慰话。这是 Emacs 和其他编辑器最大的结构差异：别的编辑器你要「记住功能在哪」，Emacs 你只要「记住怎么问」。第 9 章专门讲怎么把「问」这件事挖到极致。

0.12 练习

建议在 Emacs 真的开着的时候做这些题。答之前先动手试一次——这章考的都是「你知不知道有这个东西」，不是「你能不能背出来」。

练习 1　你刚装好 Emacs，想确认它能跑、安装的是哪个版本。应该敲什么？

M-x version 回车。回显区会显示 GNU Emacs 31.1 这样一行。记住这个命令——本书后面每次要确认「我这台 Emacs 到底有什么功能」都用它。

练习 2　网上文章说「indent-tabs-mode 默认是 nil」。你不信，要在你这台 Emacs 上核实默认值。敲什么？

Ch v，输入 indent-tabs-mode 回车。屏幕上会出现这个变量的当前值、说明文档，以及「这个变量在哪个版本引入的」。注意以你机器上的实测值为准——本书作者在 Emacs 32.0.50 上实测的结果是：它的默认值是 t（用制表符），而 python-mode 之类的编程主模式会在进入时把它局部设成 nil。同一个变量在不同 buffer 里可能是不同的值，C-h v 显示的只是当前 buffer 的。

练习 3　你看到有人说 Emacs 的包管理器叫 elpaca。按 Mx 输入 package-install RET elpaca RET，能装上吗？

不能。本书作者核对过三大仓库的包清单：elpaca 在 GNU ELPA、MELPA、NonGNU ELPA 里都不存在，它只能通过别的方式获取。这道题考的是 0.3 节那条规则：装不上包时，先确认这个包到底在哪个仓库里，别在一个仓库里反复重试。

练习 4　你想让输入 ( 时自动补出配对的 )。查一下 Emacs 有没有 global-electric-pair-mode 这个命令。

没有。本书作者在本机可实测的 Emacs 30.2、31.1、32.0.50 三个版本上逐一查过，这个命令都不存在（Emacs 18 到 32 的官方 NEWS 里也从未出现过这个名字）。正确写法是 (add-hook 'prog-mode-hook #'electric-pair-mode)。这道题考的是 0.10 节误区 7：网上（含 AI 生成的博客）经常编造看似合理的 Emacs 命令名，而 Ch 查不到的东西就是不存在。

练习 5　你只有两周时间，想跳着读。按 0.8 节的「需要先会什么」列判断：哪三章跳了会直接读不懂？

三处硬约束：第 5 章依赖第 4 章（没有寄存器和标记的基础就讲不懂交叉引用）、第 7 章依赖第 6 章（不先理解杀死与粘贴模型，计数前缀用不起来）、第 13 章依赖第 12 章（没有 Elisp 基础，第 13 章会退化成抄写）。其他章节可以按当下的问题挑读。

要点

五道题做完，这一章就结束了。去读第 1 章吧——它不需要任何前置知识。
