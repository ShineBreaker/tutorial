二、上手：安装、界面、按键、配置

这一章解决三件事：把 Emacs 装上并跑起来、认得屏幕上每一条横栏都是干什么的、看懂 C-x C-f 这种按键记号。读完你能自己装好 Emacs、知道自己的配置放在哪、在忘键时用 C-h 自救。本章不讲移动和编辑技巧，那是后面几章的事。

先查一件事：你机器上已经有 Emacs 吗

很多 Linux 和 macOS 机器出厂就带着 Emacs，但版本往往很旧。旧版本不是不能用，是会让你在网上抄到的配置全部报错。所以第一件事不是安装，是确认版本。

$ emacs --version

输出第一行长这样：GNU Emacs 32.0.50。中间那个数字是主版本号（major version），它决定了你能用上哪些新功能。冒号后面那个是次版本号（minor version），同一主版本内的增量更新。

要点

写本书时（2026 年）的情况是：Emacs 30 和 Emacs 31 都已正式发布，32 正在开发序列中。开发版号长成 32.0.50 这种样子——主版本后面的次版本是 0，说明它还没发布；正式的稳定版会是 31.2、30.2 这种形式。你从系统仓库装到的多半是 29 或 30。

Emacs 有一个值得知道的脾气：它极少在补丁版本里做破坏性改动。原书里说得很准——从废弃一个变量到真正删掉它，中间要隔好几个大版本。所以你在网上看到一篇写于 2018 年的文章，里面的变量名在今天的 Emacs 里大概率还能用。反过来也成立：如果你抄到一篇很新的文章，用的是 30 才引入的功能，而你跑的是 29，那就会报「Symbol's function definition is void」之类的错。

易错

不要为了追新而追新。Emacs 的开发版（32.0.x 这类）可能带 bug，插件作者也未必测过。日常使用请装稳定版；只有当你要写的配置明确需要某个新版本特性时才用开发版。

怎么装

Emacs 官方的 Windows 和 macOS 安装包在 GNU FTP 站上，解压即用，不必编译。下面给的是具体文件名而不是目录名——目录只告诉你去哪，具体文件才告诉你拿哪个。各平台最省事的路子分别是：

  • Linux：发行版的包管理器。Debian/Ubuntu 系是 apt install emacs，Fedora 系是 dnf install emacs，Arch 系是 pacman -S emacs。缺点是仓库里的版本可能偏旧，因为发行版要保证稳定性。GNU 官方的 gnu/emacs/ 目录下只有源码包（emacs-31.1.tar.xz 这类），没有任何 Linux 预编译二进制，所以这条路只能走发行版包管理器，或者按上面路线 C 自己编译。如果你看到某个教程说「去 GNU 官网下 Linux 预编译包」，那个链接多半已经失效了。
  • macOS：Homebrew 的 brew install --cask emacs。它跟 GNU Emacs 本身没有任何绑定关系，只是帮你下载官方构建。装出来的是 Cocoa 图形版（不是终端专用构建），双击图标开窗口，同时也能在终端里当 emacs 命令用；你要是想在终端窗口内跑，加 -nw 参数（emacs -nw）就行，不需要为了这件事另装一个版本。EmacsWiki 上的 EmacsForMacOS 页面是社区汇总的安装攻略，遇到问题先看那里。
  • Windows：目录是 gnu/emacs/windows/emacs-31/，从这几个文件里挑一个：emacs-31.1-installer-UCRT64.exe（推荐，用 Windows 自带的 UCRT 运行库，在较新的 Windows 10/11 上兼容性最好）、emacs-31.1-installer.exe（标准版，自带依赖，官方 README 说「Mostly, this is the best one to install」）、不想装进系统就用免安装包 emacs-31.1.zip（自带依赖）或 emacs-31.1-nodeps.zip（最精简，不带依赖）。装好后双击 bin\runemacs.exe 开图形界面，或在命令行敲 emacs -nw 让它跑在终端窗口里。
易错

Windows 上下载前先看清文件名。那个目录里还有一组文件名带 31.1_1 的更新构建，和不带下划线的那组不是同一批文件，选错了装出来的版本和你预期的不一样。另外每个安装包旁边都配一个 .sig 签名文件，用来验证下载没被篡改，校验命令写在官方 README 里。

易错

Windows 上有大量第三方「Emacs 增强发行版」——它们打包了 GNU Emacs 再塞进一堆自己的插件，常用 C/C++ 编辑模式、终端工具和预置配置。行为会和官方版对不上，本书默认你用的是官方 GNU Emacs。如果你确实装了某个发行版，本章的键位和命令名仍然适用，但默认配置和启动速度会不一样。

从源码编译是另一条路，命令就是最经典的 ./configure、make、make install 三连。Debian 系可以先用 apt build-dep emacs 把编译依赖装齐，再照着官方 INSTALL 文件做。本书不展开——对绝大多数读者，包管理器装出来的版本完全够用。

启动 Emacs：四个必须认识的开关

在命令行敲 emacs 就启动了。Emacs 启动后会占住终端不退出，这是设计如此，不是卡死了——它是个长驻程序，按 Cx Cc（save-buffers-kill-terminal）才能退出。

Emacs 的命令行选项遵循 Unix 惯例：选项用 - 或 -- 开头，文件名跟在后面。你只需要先认识四个。

本节按键：命令行开关

开关命令作用
--version（非交互）打印版本号后退出
-nw（非交互）强制在终端里跑，不开图形窗口
-q（非交互）不加载你的个人配置文件 init.el
-Q（非交互）比 -q 更狠：额外跳过站点级的全局配置文件（site-start.el、site-lisp）以及 X 资源
--help（非交互）打印完整帮助后退出
--daemonserver-start在后台启动 Emacs 并开启服务器，立即返回命令行

-q 和 -Q 的区别值得单独说。Emacs 启动时会读一个站点级配置文件（site-start.el，路径由编译时决定，常见的是 /etc/emacs/site-start.el 或 /usr/local/etc/emacs/site-start.el），那是管理员给全机器写的公共设置。个人电脑上通常没有这个文件，两个开关效果一样；但在有管理员配置的机器上，-Q 才是那个「回到最干净的出厂状态」的开关。

技巧

-q 是初学者最该学会的排错开关。哪天 Emacs 一启动就满屏红字，八成是你的配置文件写错了。这时候在终端里按 Cg 中断掉，然后敲 emacs -q 重来。如果这样就干净了，问题一定在你的 init.el 里——而不是 Emacs 本身出了问题。

要点

GUI 和终端是同一个 Emacs，只是外面那层壳不同。终端版没有独立窗口、没有内置图片查看器、颜色受终端能力限制。功能上几乎完全一致——本书讲的每一条命令，在两种模式下都能用。真遇到差异时本书会单独标出来。

练习 1　你的 Emacs 一启动就报错，满屏红色。想排除是不是自己配置文件的问题，该敲哪条命令？

敲 emacs -q。它跳过你的个人配置文件但保留系统级设置。如果这样启动就干净了，那问题在你的 init.el 里；如果照样报错，那问题更可能在系统配置或安装本身。

练习 2　-q 和 -Q 都能让你「用干净的 Emacs 启动」，两者差在哪？

-q 只跳过你自己的 init.el，站点级的全局配置照读；-Q 连站点级配置和 X 资源一起跳过。个人电脑上通常没有站点级文件，两个效果一样；你需要排除管理员配置的影响时用 -Q。

客户端—服务器模式：只开一个 Emacs

Emacs 的设计前提是「长驻」——开一次，用几个月。想改个配置也开一个新 Emacs，等于每次都重新启动一遍、重新加载一遍包，慢，而且窗口布局全丢。

Emacs 内置了一套 客户端—服务器（client-server）机制来解决这件事：一台机器上跑一个真正的 Emacs 进程当服务器，其他程序通过 emacsclient 把「打开某某文件」的请求递进去。

开启服务器

在一个已经跑起来的 Emacs 里执行 Mx 然后输入 server-start 回车，它就变成服务器了。屏幕上不会有任何提示——没有弹窗、没有消息。这不是失败了，你可以用 emacsclient 试着连一下，连得上就说明成了。

但这样只是让当前这个窗口变成服务器。你一旦关掉它，服务器也就跟着没了。真正想要的是后台常驻的服务器，用命令行开关：

$ emacs --daemon

这个命令会先启动 Emacs、在里面执行 server-start，然后立刻把控制权还给终端，Emacs 在后台等着。

易错

开了服务器之后，emacs 这个命令不会自动连到已有的服务器，它照样会新开一个完整实例。必须改用名字很像的另一个程序：emacsclient（结尾多个 l）。这是初学者最常踩的坑——敲了 emacsclient 却抱怨「怎么还是开新窗口」，八成是敲成了 emacs。

用服务器打开文件

$ emacsclient README.md
$ emacsclient -nw notes.org
$ emacsclient -c report.tex

三个开关的区别值得说清楚，因为它们决定了「谁在等谁」：

  • 不给开关：有图形界面就新开一个窗口，否则开终端窗口。命令会一直挂着，直到你把这个文件编辑完并退出，终端才把控制权还给你。这正是 git commit 想要的——它调你的 $EDITOR 写提交信息，写完关掉，git 才知道可以往下走。
  • -nw：强制开终端窗口，同样挂着等。
  • -c（--create-frame）：新开一个窗口，语义上跟默认一样，但显式指定了「要图形界面」。
  • -n（--no-wait）：不等。把文件丢给 Emacs 就立刻返回终端。适合「顺手开一堆文件丢进去慢慢看」。

易错

Cx # 在刚启动、还没碰过服务器的 Emacs 里是按不动的。这不是 bug：C-x # 这个绑定是在 Server 库被加载时才装上的，而 Server 库是用到才加载的。只要你执行过一次 server-start（或者任何其他服务器命令），它就出现了。反过来说，如果你怀疑自己的 C-x # 失灵了，先确认服务器真的开着。

这个「按 Cx # 切到下一个」的设计，是为了伺候最常见的场景：

$ emacsclient A.md B.md C.md

三个文件都塞进 Emacs 了，但 emacsclient 还在终端里干等着你处理 A.md。你在 Emacs 里存好 Cs 关闭，Emacs 自动跳到 B.md，你再存再关，轮到 C.md——没有下一个了，Emacs 通知客户端「完成」，emacsclient 退出，终端回到你面前。

让命令行工具都走 Emacs

一旦服务器常驻，把环境变量 $EDITOR（或 $VISUAL）设成 emacsclient，很多工具就自动接上了：

$ export EDITOR=emacsclient

git commit（不带 -m）、crontab -e、git rebase -i 的编辑器步骤，都会调起你那个已经在跑、配置齐全、插件都在的 Emacs，而不是冷启动一个。这是 Emacs「长驻」理念最直接的收益。

Linux 用户：交给 systemd 托管

Emacs 自带一个 systemd 用户单元文件 emacs.service，默认安装在 ${prefix}/lib/systemd/user/ 下（/usr 装的话就是 /usr/lib/systemd/user/emacs.service；也可以在编译时用 --with-systemduserunitdir 改）。用它可以让 Emacs 登录后自动以守护进程方式起来：

$ systemctl --user enable emacs
$ systemctl --user start emacs
要点

这一段是 Linux 专有的。macOS 用 brew services，Windows 用服务管理或计划任务。systemd 不是 Emacs 的一部分，是操作系统提供的服务管理器；Emacs 只是附带了一个单元文件。用不用随你，它只是个方便——emacs --daemon 一样能用。

技巧

第一次用 emacsclient 前，先确认服务器活着。直接敲 emacsclient 不带参数，服务器在的话它会开一个新窗口，服务器不在则会报 emacsclient: can't find socket; have you started the server? 之类的错误（终端没有图形界面时措辞会略有不同）。这比猜要快。

练习 3　你已经用 emacs --daemon 开了后台 Emacs。在终端里想用那个实例打开一个文件，该敲哪个命令？敲错了会有什么后果？

敲 emacsclient 文件名。敲成 emacs 的话，Emacs 不会去连已有的服务器，而是再启动一个全新的完整实例——窗口多开一个、启动时间白付一次、配置状态还和原来那个对不上。这是最常见的误操作。

练习 4　用 emacsclient 一次打开三个文件后，命令行还在等着。你在 Emacs 里存好关掉第一个，想切到第二个，用哪个键？另外，这个键在你「刚启动、还没开过服务器」的 Emacs 里能按吗？

用 Cx #，命令是 server-edit。它在你「刚启动、还没开过服务器」的 Emacs 里按不动：C-x # 是在 Server 库被加载时才装上的全局绑定，而 Server 库是用到才加载的。执行过一次 server-start 之后它才出现。

认屏幕：Emacs 的界面分区

Emacs 的窗口自上而下就四块。认全了它们，你以后看截图、别人录屏、书里的插图才不会迷路。

欢迎界面

第一次启动会看到一张欢迎页，上面有介绍和入口。要关掉它，按 Cx Cc，命令是 save-buffers-kill-terminal（退出 Emacs 的常规按键，官方手册里也常笼统称作 quit Emacs）。

很多人第一反应是「把这个讨厌的页面关掉」。原书的作者也这么说，但他的建议反常识：头几个星期先留着。欢迎页、菜单栏、工具栏这些「界面元素」的价值在于——你还没记住某个功能在哪的时候，它们是你唯一能问的地方。等你把 Emacs 用熟了再关，那时你已经不需要它提醒你了。

关掉它的办法是设 inhibit-startup-screen 为 t，这个变量默认是 nil（也就是显示欢迎页）。

模式行

正中间那条横线叫模式行（mode line），是 Emacs 的状态栏。在一个全新的 *scratch* 缓冲区里，它渲染出来大致是这样：

-UUU:--- F1  *scratch*      All L4     (Lisp Interaction ElDoc) ---

从左到右你能读出：

  • 文件编码信息：-UUU:--- 那一段，一共 6 个字符。前 3 个告诉你这个缓冲区用的什么编码方案；第 4 个（: 后面的）告诉你文件有没有换行符；最后 2 个告诉你「读进来的换行符该怎么写回去」和「存盘时结尾要不要补一个换行符」。这一段一次讲不清很正常——它的每个位置都有合法值，本书不在这里展开。第 3 章会把这一段拆成 6 个格子逐个解释，现在你只要知道「最左边这 3 个字符是编码方案（utf-8 会显示成 U），冒号是分隔符，冒号后面 3 个字符分别管换行符的两端和结尾」就够用了。
  • frame 编号：F1。Emacs 把「一个 frame」（可以理解为独立窗口）都编号，服务器模式下同时开着好几个窗口时靠它区分。
  • 缓冲区名：*scratch*。两边带星号是 Emacs 的约定：星号表示「这个缓冲区关联着文件，但文件还没存盘」。名字前有个 % 或者被改写过，说明对应文件在磁盘上被 Emacs 之外的东西改动过，存盘时会问你怎么办。
  • 位置：All L4。L4 是「第 4 行」；All 表示光标在整个缓冲区范围内，按 C-x = 类命令时会作用于全文。这个区域可以设置成显示百分比、行列号或者时间。
  • 模式列表：(Lisp Interaction ElDoc)。括号里第一个是主模式（major mode，决定这个缓冲区怎么编辑、语法怎么高亮），后面跟着的是启用的次模式（minor mode，可以叠加，随时开关的附加行为）。这一段是 Emacs 里信息量最大的地方——遇到「为什么我的 Emacs 行为怪怪的」，八成能在模式列表里找到答案。
技巧

不确定光标在哪，看 Ch w：where-is 会在回显区告诉你当前所在行列的百分比。它绑在 Ch w 上（Ch 家族的一员）。注意别和 M- 混了——后者是 negative-argument，见后面「万能参数」一节。

回显区和小模式行

模式行下面紧贴着的那一行叫回显区（echo area）。Emacs 平时不往那儿写字，所以看着是空的；一旦你敲了半个键、或者执行了一个命令，它就会显示提示和结果。前面讲过的 C-x- 那个带横杠的「等下一个键」提示，就显示在这里。

回显区正下方那条更窄的线叫小模式行（minibuffer）或 迷你缓冲区。它是 Emacs 的命令行输入框。Mx 提示你输命令名、Cs 提示你输搜索词、Cx Cf 提示你输文件名，全在这儿敲。

要点

小模式行几乎总是处于「可用但空闲」状态，所以你根本不会注意到它。它的特点是：敲 Cg 随时能取消，然后焦点自动回到缓冲区，什么事都没发生。忘了当前在问什么，按 Cg 就对了。

菜单栏、工具栏、滚动条

顶部那条写着 File Edit Buffer Tools Help 的是菜单栏（menu bar）。图形界面下鼠标点它就行；终端下要用键盘打开。每个主模式和次模式也可以往菜单栏里加自己的一级菜单，所以有些模式一激活，菜单栏就多出一项来。

菜单栏下面那条图标是工具栏（tool bar），图标是上下文相关的——你在什么模式、什么缓冲区，就显示什么图标，比如 Emacs 里有个内置的 dired（目录浏览器）打开目录时，工具栏会变成文件操作按钮。

右边那条细长的叫滚动条（scroll bar）。变量 scroll-bar-mode 控制它：nil 表示不显示，left 放左边，right 放右边，both 两边都放。默认值随平台和编译方式而变：官方文档写的是，在 GTK+ 版 Emacs（Linux）、MS-Windows 和 macOS 上默认放右边，在不用 GTK+ 的 X11 上默认放左边。官方发行版基本都是右边。

原书写「用 M' 打开纯键盘菜单栏」，这是错的。M' 在 Emacs 里是 abbrev-prefix-mark（给缩写加前缀），跟菜单无关。正确的键是 M`（Meta 加一个反引号，在数字 1 左边那个键），命令是 tmm-menubar。记不住就 Mx tmm-menubar。

要点

终端版能不能用鼠标，分版本。Emacs 30 及以前，终端 Emacs 默认不能点菜单栏和滚动条，需要你手动 Mx xterm-mouse-mode。Emacs 31 起，在「兼容的终端」里这个模式默认就开着，开箱即用鼠标。

但「兼容」是有条件的：你的终端必须支持 Emacs 读写系统剪贴板、以及上报鼠标按下和移动事件。绝大多数现代终端（iTerm2、Windows Terminal、GNOME Terminal、kitty、Alacritty 等）都符合；通过 emacs --daemon 启动、或者挂在某些不完整的终端环境里，就可能不算。实在发现鼠标没反应，手动开一次即可。

不管哪个版本，F10 和 M` 都是纯键盘的路子，在任何终端下都可靠，推荐优先记这个。

练习 5　你在终端版 Emacs 里，想用纯键盘的方式操作菜单栏（左右方向键切换菜单那种）。按哪个键？命令名是什么？另外，M' 行不行？

按 M`（Meta 加反引号），命令是 tmm-menubar。F10（menu-bar-open）也行，它会展开第一个菜单然后你可以用方向键走。M' 不行——它是 abbrev-prefix-mark，给缩写加前缀用的，跟菜单没关系。

练习 6　模式行上 (Lisp Interaction ElDoc) 这一段是什么意思？括号里的第一个和后面的分别代表什么？

括号里第一个是主模式（major mode），决定这个缓冲区怎么编辑、语法怎么高亮、哪些键可用；后面跟的全是次模式（minor mode），是可叠加、随时开关的附加行为。调试配置问题时先看这一段——某个奇怪的次模式开着，就足以解释奇怪行为。

按键记号法：把 C-x C-f 读出来

Emacs 的按键写法是出了名的难认。网上看到 C-M-S-p 你完全不知道该按哪几个键。本节的目标是：看到任何一串记号，你能立刻翻译成手指动作。

进阶：把 Caps Lock 改成 Control，以及自定义键盘

你已经知道 C- 在 Emacs 里有多常用。但对大多数人来说，键盘左下角那个 Ctrl 是个很不舒服的位置——要用无名小指去够，还得把手掌撑开。Emacs 用户的「左小指痛」（作者戏称 Emacs pinky）就是这么来的。

原书给出的头号建议是：把 Caps Lock 这个键重新映射成 Control，然后完全不用左下角那个原始的 Ctrl。大写锁定键离手指更近、发力更顺，改造之后 C- 组合会舒服得多。

这么建议是有历史原因的：当年的 Space Cadet 键盘（大名鼎鼎的 MIT 人工智能实验室键盘）上，Control 键占据的正是今天 Caps Lock 的位置。也就是说 Emacs 最早的键位设计里，Ctrl 本来就在那儿，是后来的 PC 键盘把 Ctrl 挪到了左下角。把它映射回去，等于把 Emacs 还原回它设计时最顺手的布局。这个习惯在 Emacs 之外也有用，所以值得养成。

怎么改

  • Windows：原书推荐用 SharpKeys 这类工具改注册表，把 Caps Lock 映射成左 Ctrl。它改的是注册表，所以不需要进 BIOS，也不需要重启。
  • macOS 和 Ubuntu：系统自带。在「键盘设置」里把 Caps Lock 的行为改成 Control 就行，不装任何额外软件。
  • 其他 Linux 发行版：可能得手工改 xmodmap 映射。

改之前想清楚一件事：你之后就没有 Caps Lock 了，想临时打个大写，得用 Shift 或者 C- u 然后字母。这个过渡期会有点别扭，但通常一两周就适应了，而且省下来的力气会在以后几千次 C- 里还回去。

更进一步：可编程的人体工学键盘

如果你用的是带可编程固件的人体工学机械键盘，还能再往前走一步：让所有修饰键都完全不用小指。这类键盘常见两种能力——拇指键（拇指能碰到的额外按键）和分层（按住某个键之后，这一排键变成另一套功能）。

如果你的键盘有这些能力，就把 Ctrl（至少是它）挪到食指或拇指轻松够到的位置，比如某个拇指键或某个分层上。Emacs 原生支持这种改法，你只要让操作系统或键盘固件把键报成 Ctrl 就行——Emacs 这边不用任何配置，它只关心「你按下的这个键报的是什么修饰键」。

这一步属于硬件投资，不是必需品。但如果你已经在折腾 Emacs 了，这通常是投入产出比最高的一笔：它对每一个命令都有效，而不是只优化某一处。

前缀键与完整键

Emacs 有一套自己的术语，用错了会看不懂文档：

  • 按键（key）：一次键盘或鼠标动作。比如「按下 Ctrl 然后按 x」是一串按键，「按 Ctrl+a 是 Ctrl 再按 a」也是。
  • 完整键（complete key）：一串足以触发一个命令的按键。Cd 就是完整键。
  • 前缀键（prefix key）：一串还没说完的按键，后面还要接。Cx 就是前缀键。
  • 按键映射表（key map，Emacs 里叫 keymap）：一个前缀键后面挂着的一整张表，记录了每个可能的续键对应哪个命令。
  • 无效（invalid）：Emacs 完全不认识的按键序列。按了会在回显区报错。

为什么要搞前缀键这种东西？因为键盘能表达的组合太少了。按键修饰符最多三四层，加上几十个字母，理论上限也就三四百个组合，而 Emacs 光命令就有几千条。前缀键是把有限的按键空间切成树，让每个前缀下面再挂一层子前缀，从而理论上可以无限扩展。

这就是为什么 Emacs 把最核心的东西全挂在 Cx 下面：Cx 后面还有 Cx、Cf、Ck、Cs……两层、三层地铺开。图省事的设计不会这么干，但 Emacs 宁可难记也要保证任何一个功能都能有一个纯键盘的入口。

读三个真实的例子

Cd：按住 Ctrl，按 d。它是完整键，触发命令 delete-char，删掉光标后面那个字符。

Cx Cf：两段。第一段是前缀键 Cx——你按下 x 之后，回显区会显示 C-x-（末尾带个横杠），Emacs 在告诉你「我在等你按下续键」。第二段 Cf 才是完整键，合起来触发 find-file，弹出小模式行问你要打开哪个文件。

敲 Cx Cf 时不用松开 Ctrl。按住 Ctrl 先按 x，再按 f，一气呵成。保持手指不离开修饰键这个习惯，原书作者管它叫保持节奏（tempo），到后面讲编辑技巧时还会再出现。

Cx 8 P：三段前缀键。Cx 是第一层，8 是第二层——按 8 之后 Emacs 仍在等，因为后面还挂着东西。最后的 P 才是完整键，效果是插入一个段落符号 ¶。这个 keymap 里塞满了 Unicode 里的生僻符号：

带 Shift 的组合，和终端打不出来的键

看一个容易卡住新手的例子：CM%，命令是 query-replace-regexp（正则替换）。

难点在于 % 这个字符。在美式键盘上，% 是数字 5 键上的上档字符——按住 Shift 再按 5 才出来。所以想打出 CM%，你得同时按住三个键：Ctrl、Alt（Meta）、Shift，再按 5。

忘了按 Shift 会怎样？你打出来的是 CM5，是完全不同的东西。

易错

CM% 在终端版 Emacs 里很可能打不出来。原因是终端协议本身表达不了「Ctrl+Alt+Shift+字符」这种四层组合——这是终端技术的限制，不是 Emacs 的问题。图形界面版没这个问题（当然，前提是你的系统能把它发给 Emacs）。所以本书强烈建议：能用图形界面就别用终端版。实在只能用终端，正则替换可以改用不带 Shift 的替代路径，例如 M% 对普通文本已经够用。

尖括号写法

有些键没有对应的字母，文档里写成尖括号包着的样子：<tab>、<f1>、<return>、<escape>、<left>、<f12>。它们指的不是字符本身，而是键盘上那个有名字的键。

唯一的坑是：不要把 <tab> 跟字母 T、A、B 搞混。文档里写 C-q 才是「先按 Ctrl 再按 q」；写 <tab> 是指键盘上那个 Tab 键——虽然它在某些键盘上确实挨着 Q。

万能的脱身键

无论你按了半个键、命令卡住了、还是小模式行正问着一个你不想回答的问题，Cg（keyboard-quit）都能把你拽出来。这大概是 Emacs 里最该形成肌肉记忆的一个键。

常见的触发场景：Cx 按下去之后你后悔了（回显区里那个 C-x- 提示会被取消掉）；Cs 的搜索输入了一半不想搜了；某个第三方插件慢得像是死了。

技巧

真的卡死到连 Cg 都没反应时，连按两下 Cg。第一次是打断当前命令；如果还是没反应，第二次会提示你输入 quit 然后回车，Emacs 立刻退出到命令行（有未保存的缓冲区时会先问你，答 y 保存）。

练习 7　想插入一个段落符号 ¶，该按哪串键？它有几层前缀？

Cx 8 P。三层：Cx 是第一层前缀，8 是第二层前缀，只有最后的 P 才是完整键。同一个 keymap 里还有 Cx 8 <（«）、Cx 8 S（§）等等。

练习 8　你按了 Cx 之后发现按错了，正卡在「等下一个键」的状态。按哪个键退出？命令名是什么？

Cg，命令 keyboard-quit。它是 Emacs 的万能取消键：取消半截按键序列、取消正在问你的小模式行、打断卡住的命令。养成随手 Cg 的习惯，你就不怕「我是不是已经搞坏了」。

练习 9　CM% 要同时按住几个键？为什么在终端版 Emacs 里可能按不出来？

要同时按住 Ctrl、Alt（Meta）、Shift 三个修饰键再按数字 5，因为 % 是 5 键上的上档字符。终端版打不出来是因为终端协议表达不了四层组合键，属于终端技术的限制；图形界面版一般没问题。命令是 query-replace-regexp。

练习 10　你觉得老按左下角那个 Ctrl 手很酸。原书给的头号建议是什么？为什么这个位置值得改？

把 Caps Lock 重新映射成 Control，之后完全不用左下角那个原始 Ctrl。值得改是因为 C- 组合在 Emacs 里用得极多，而左下角要靠无名小指发力，够着别扭。历史上这也确实是 Emacs 的原设计——当年 Space Cadet 键盘上 Control 占的正是今天 Caps Lock 的位置，是后来的 PC 键盘把它挪到了左下角。代价是暂时失去 Caps Lock，打大写改用 Shift 或 C- u 加字母。

Mx：没有按键的命令怎么调

Emacs 有几千条命令，但绑了键的只有一小部分。剩下的怎么办？答案是 Mx。

按 Mx，小模式行弹出 M-x: 提示，你输入命令名，回车执行。

M-x lunar-phases RET

Emacs 里真有这么个命令 lunar-phases，它会开一个新窗口显示从今天起的月相表。看完按 Cx 1 回到单窗口。

要点

Emacs 圈子里「跑一下 Mx lunar-phases」是个玩笑，因为它专挑一个没人需要的命令来举例。但笑点恰恰在于：Mx 这个机制的存在，意味着Emacs 的每一个功能你都能拿到，哪怕它既没按键也没出现在菜单里。

什么命令能进 Mx

不是所有东西都能用 Mx 调。命令（command）是 Emacs 的一类特殊函数：它被标记为 interactive（交互式），意思是「能被人直接调用」。标记为 interactive 的函数，Emacs 才知道可以把它挂到按键上、放进 Mx 的候选列表里。

反过来说，没标记 interactive 的函数你既不能用 Mx 调，也不能绑到键上。这类函数是给别的 Elisp 代码调用的内部工具。

技巧

在 Mx 提示符里按 Tab 会列出所有候选命令，而且每敲一个字符就收窄一次。只剩一个候选时，Emacs 直接替你补全；你也可以直接按回车，效果和 Tab 一样，但会顺带把它执行掉。养成「忘了就 Mx 输前几个字母再 Tab」的习惯，你永远不需要背命令表。

更窄的入口：MX

从 Emacs 28 开始，多了一个 MX（大写 X），命令是 execute-extended-command-for-buffer。它和 Mx 的区别是：候选列表只保留跟当前缓冲区有关的命令——也就是当前主模式专用、当前次模式启用的、以及在当前键映射表里绑定了的命令。

在一个写 Python 的缓冲区里按 MX，不会给你列出几百个跟 Python 毫无关系的命令。在 *scratch* 里按，它给你的候选就少得多——因为 *scratch* 用的是 lisp-interaction-mode（就是前面模式行上那个 Lisp Interaction），这是个几乎不绑定任何东西的交互式 Elisp 模式。

易错

这个命令的实际键位绑定在 Emacs 内部记作 M-X（Meta 加大写 X），不是 M-S-x。你如果要在配置文件里写这个绑定，用 (kbd "M-X")。原因很技术：Emacs 的 kbd 函数把 M-S-x 解析成「Meta 加上带 Shift 修饰位的 x」，跟 Meta 加字符 X 是两个不同的键向量，只有后者是真正绑定了的。日常敲键盘不用管这个区别（按住 Meta 再按 Shift+x 出来的就是 X），但写配置时会咬人。

万能参数：给命令加个数字

很多命令有「不同档位」的行为。向下移动一个词和向下移动三个词是同一条命令，只是参数不同。Emacs 用前缀参数（prefix argument，也叫 universal argument）来表达这件事，键是 Cu。

它的规则简单到有点反直觉：

  • 光按一次 Cu，代表数字 4。
  • 再按一次变 16（4 乘 4）。
  • 第三次 64，第四次 256，以此类推。

Emacs 源码里 universal-argument 的文档字符串就是这么写的，它自己的注释是「不带数字和负号时提供 4 作为参数，重复按则每次乘以 4」。

最好记的例子是：Cu 然后按 a，屏幕上出现 4 个 a；Cu Cu 然后 a，出现 16 个 a。

但这些其实都是默认档。想要任意数字，直接打就行：Cu 然后 3 然后 a，就是 3 个 a。

要点

万能参数自己什么都不做。它只是挂在命令前面的一个「数字」，Emacs 读完就等着你敲下一个真正要执行的命令，然后把数字传给它。所以 Cu 之后如果按 Cg，什么都没发生——这完全正常。Mx 也能接受前缀参数：Cu 4 Mx lunar-phases 就是「显示未来 4 天的月相」。

你打的字母其实也是个命令

这里藏着一个很值得知道的设计。你按下 a，屏幕上出现字母 a——这看起来是「键盘直接写字」，但实际上 Emacs 把每个字符都绑定到了同一条命令上：self-insert-command，它的工作就是「把最后按下的那个键插进缓冲区」。

这个设计的好处是：普通字符从此和其他所有命令受同一套规则管辖。它可以被取消绑定、可以被重绑定、可以吃前缀参数。所以 Cu a 能插 4 个 a 才成为可能——前缀参数对 self-insert-command 生效，意思就变成了「插入 N 份」。

文档里写 C--（C-），意思是「Ctrl 加减号键」，不是「先按 Ctrl、松开、再按减号」。后者在 Emacs 里不是合法的按键序列——Emacs 无法区分你打算表达的这两件事，而你松手再按减号的结果是在屏幕上打了个普通减号。Emacs 记法里的连字符永远是「修饰键的连接符」，不是两个独立的按键。

负数让命令反过来

前缀参数是方向性的，这是它最巧的地方。同一条命令，正着和倒着是相反的操作。

在缓冲区末尾的 alpha beta gamma 上试：

  • Md 单独用，命令是 kill-word，向前杀掉一个词。
  • M- Md，backward-kill-word，向后杀掉一个词。

两种写法结果一样，但打字速度差很多。M- Md 全程 Meta 手不松开，是一次连贯的动作；而 C- Md 你得先按 Ctrl 加减号、松开 Ctrl、再按住 Meta 按 d，节奏全断了。

原书作者管这个叫保持节奏（tempo）。这也是为什么 Emacs 要给同一个操作准备 C-、M-、CM- 三种看起来完全冗余的写法——它们各自对应「你另一只手正按着哪个修饰键」。Emacs 把这个冗余当成特性，因为在这里，少一次松手比少记一个键更重要。

练习 11　想用 Emacs 查未来几天的月相，输入什么？

Mx lunar-phases 回车。命令名是 lunar-phases，确实存在。输入命令名时按 Tab 可以补全。

练习 12　Emacs 28 引入了一个「只列出跟当前缓冲区有关的命令」的入口。日常怎么敲？如果要把它写进配置文件，kbd 里该写什么？

日常按 MX（Meta 加大写 X），命令是 execute-extended-command-for-buffer。写配置时用 (kbd "M-X")。不要写 (kbd "M-S-x")——Emacs 会把它解析成「Meta 加带 Shift 修饰位的小写 x」，那是另一个键向量，并没有绑定。

练习 13　Cu 单独按代表数字几？连按两次呢？Cu 之后按 a 屏幕上会出现几个 a？

单独按是 4，连按两次是 16（每次乘 4），三次 64，四次 256。Cu 之后按 a 出现 4 个 a。想要任意数字就 Cu 后面直接打数字，比如 Cu 10 a 是 10 个。

练习 14　在光标处向后删掉前一个词，用 M- Md 和用 C- Md 效果一样吗？打字速度呢？

效果完全一样，都是 backward-kill-word。但速度差很多：M- Md 全程 Meta 手不松开，一气呵成；C- Md 要先按住 Ctrl 加减号、松开 Ctrl、再按住 Meta 按 d。这正是原书说的「保持节奏（tempo）」：Emacs 故意把同一个操作绑到 C-、M-、C-M- 三种前缀上，就是为了让每种手型都能不松手地打出来。

自救系统：Ch 家族

如果这一章只能记住一节，就是这一节。

Emacs 有一个说法叫「自文档化」：它内部的一切——每个命令、每个变量、每个 face（界面元素的配色和字体）、每个模式——都带着一段说明文字，Emacs 随时能把它取出来给你看。这套机制让 Emacs 在某种程度上能自己回答「我是谁、我干了什么、我被谁绑定了」。

要点

为什么这件事值得这么大力气讲？因为你的 Emacs 和别人的不一样。你可能改过键位，装过插件，开过某个奇怪的次模式。上网问只能得到泛泛的回答，只有你机器上这个 Emacs 自己知道确切答案。「我知道我不知道，但我知道去哪儿查」——这个能力比记住任何一个键都重要。

五条最该背下来的命令

全部挂在 Ch 下面。先解决一个会挡住所有人的问题：万一你的键盘发不出 Ch。不少笔记本键盘和精简终端会把 Ch 吃掉（它和 Backspace 发的是同一个字节），Emacs 于是把你的按键当成「退格」。三个都能用的替代入口：

  • Mx help-command——这个永远管用，因为 Mx 只依赖 Meta 键。本节表格里 Ch m 的功能，写成 Mx describe-mode RET 效果完全一样（本章后面所有表格你都可以这样替换）。
  • F1——Emacs 的帮助键表里确实把 F1 也绑成了帮助菜单，但它是否在你的终端里真的绑上了，取决于终端的 terminfo 和你的 Emacs 构建。本书作者在 32.0.50 上实测，Ch 绑的是 help-command，而 F1 在裸 Emacs 里没有全局绑定。结论：别把 F1 当成保底方案，先试一下，敲了没反应就用上面那条。
  • Ch Ch——如果 Ch 能发出来但你不想每次都记具体字母，按两下 Ch（help-for-help）会弹出一个列出全部帮助子命令的菜单，用方向键选、回车执行。

确认一下你这台机器上 Ch 到底通不通：把它按住，按一下 h。屏幕上应该弹出一个 *Help* 缓冲区。什么反应都没有，说明你的终端把它吃掉了，上面三条选一条用。

技巧

Ch k 的最大价值是：它查的是「你现在的 Emacs」，不是「平均的 Emacs」。同一个键在 Python 模式和文本模式可能绑不同的命令——Ch k 会如实告诉你此刻在这个缓冲区里它到底是什么。

describe-mode 的输出比你以为的更全：除了列出该模式绑了键的那些命令（带按键），它末尾还有一段 Other commands for this mode, not bound to any keys，专门列出这个模式定义了但没绑键的命令。所以「一个模式有哪些命令」这个问题，Ch m 基本能一次答完。

忘了某个前缀键下有什么？后面加 Ch

这是 Emacs 最优雅的一个技巧。绝大多数前缀键，后面加 Ch（或 ?、F1），Emacs 就把这个前缀键表里所有绑定列出来——超链接形式，可以鼠标点。少数自己给 Ch 和 ? 派了别的用处的键表不支持这招，但它们都支持 F1。

Emacs 自带一整套完整的用户手册，写在 TeXinfo 格式里（GNU 全生态的文档格式）。按 Ch i 打开它。Emacs 内置的 Info 阅读器带超链接，比命令行里那个 info 工具好用得多。

手册入口有好几个，容易混：

原书写「用 Ch F 查命令的文档」，这条今天仍然有效，但用途窄。Ch F 在 Emacs 里还绑着，指向 Info-goto-emacs-command-node，而它并不显示命令的文档——它是跳到「命令在手册里的那一节」，也就是打开 Info 手册对应节点。官方手册至今仍然推荐它（它认得 Emacs 之外的其他手册）。不过想直接看命令的说明文字，现在更该按 Ch x（describe-command，Emacs 28 起），直接给你文档字符串。

进阶：Info 里另外几个高价值的按键

下面这些同样只在 Info 缓冲区里有效，初学阶段用不上，但知道有它们，以后查手册会省事：

  • g（Info-goto-node）——按名字直接跳到某个节点。手册里某个功能你知道在哪但不知道节点名时，比一层层点快得多。
  • i（Info-index）——打开当前节点的索引条目，按字母排好了全部主题，输入关键词过滤。查「某个功能叫什么」用这个。
  • s（Info-search）——在当前节点里搜字符串；S（Info-search-case-sensitively）区分大小写。
  • f（Info-follow-reference）——跳到光标处提到的那个引用。
  • ?（Info-summary）——打印当前节点的菜单（大纲），迷路时按它回到该去的地方。
  • < / >（Info-top-node / Info-final-node）——直接跳到整本手册的开头或结尾。

原书只列了其中一部分，并把它们描述成「命令的前后节点」这类含糊说法；上面是按 Emacs 32 的 Info-mode-map 逐条核对过的准确含义。

你经常处在这种处境：知道要找什么，但不知道它叫什么。Emacs 为此准备了一整套 apropos（法语，「关于」）命令，作用是按模式搜索。

Emacs 的命名是有规律的，看多了能形成直觉：命令名末尾常常标明它作用的对象，-word 对词、-line 对行、-buffer 对缓冲区、-window 对窗口、-paragraph 对段落。认得这个规律，apropos 的命中率会高很多。

进阶：让 apropos 的结果按相关度排序

apropos 的默认排序方式是按名字字母序。搜 -word$ 时，最相关的命令往往散在长长的列表中间，不太好找。

有个变量专门管这件事：apropos-sort-by-scores，默认是 nil（不按相关度排）。把它设成 t 之后，结果会按「命令名里包含你输入的关键词的比重」重新排序，最像的排最前面；设成 verbose 还会在每条后面显示算出来的分数。

M-x customize-option RET apropos-sort-by-scores RET

它是变量不是命令，所以必须通过 Customize 这类改设置的入口来改，不能直接在 Mx 里敲。这是初学者常踩的一个坑：Mx 只能调用命令，变量得走 Customize 或者 Ch v 查。

还有一个相关的：apropos-documentation-sort-by-scores 控制 Ch d（apropos-documentation）的排序，它的默认值是 t——也就是说，搜文档字符串时默认就已经按相关度排了，不需要你改。

快捷速查：Ch Cq

从 Emacs 29 起多了一个功能：Ch Cq，命令 help-quick-toggle，会在窗口底部弹出一张常用键位速查表。

它就是当年 80 年代人桌上那块盖在键盘上的透明塑料板的电子版——救急用的，不是用来精通 Emacs 的。当你一时想不起来「保存文件是哪个键」，扫一眼就够。按 q 关掉。

练习 15　想查「Cs 到底是干什么的」，按 Ch 然后哪个键？而「当前这个缓冲区是什么模式」，又是哪个键？

查按键用 Ch k（describe-key），它提示你按下按键然后如实报告。查模式用 Ch m（describe-mode），它不用输名字，直接看当前缓冲区。

练习 16　查一个命令的文档，Emacs 28 之后推荐按哪个键？原书教的 Ch F 是什么状态？

推荐 Ch x，命令 describe-command，Emacs 28 新增，直接显示命令的文档字符串。Ch F 也还能按，官方手册仍然推荐，但它做的是另一件事：跳到这条命令在 Info 手册里的对应节点，而不是把文档摆在你面前。

练习 17　你只记得「Cx 8 后面有个键能打段落符号」，但忘了是哪个。敲哪串键能让 Emacs 把整个键表列给你？

练习 18　在 Info 手册里，SPC、]、u、l/r、? 这几个键各自是干什么的？其中哪个适合「从头通读手册」？

SPC 往下翻一屏，读完当前节点会自动接上下一个节点——通读手册用它。] 明确跳到下一个节点（[ 反向），n/p 在兄弟节点间移动。u 回到父节点（上一层）。l/r 是按浏览历史后退和前进，像浏览器一样。? 打印当前节点的菜单（大纲），迷路时按它就能回到该去的地方。

配置 Emacs：文件在哪、怎么改

Emacs 的所有个性化都写在一个文件里，叫初始化文件（init file）。它是一段 Elisp 代码，Emacs 启动时读它、执行它。

先查你自己的文件在哪

不同平台、不同版本、甚至同一台机器的不同 Emacs，初始化文件的位置都可能不一样。所以不要背路径，直接问 Emacs 本身：

M-x customize-option RET user-init-file RET

或者按 Ch v 然后输 user-init-file。Emacs 会把它此刻真正使用的那个路径显示给你。启动时回显区闪过的那行 Loading /home/you/.emacs.d/init.el... 也是同一个答案。

常见的几种情况：

  • 传统路径 ~/.emacs.d/init.el——绝大多数 Linux 和 macOS 用户的配置在这。
  • XDG 路径 ~/.config/emacs/init.el——Emacs 27.1 开始支持（本书作者在 Emacs 32.0.50 自带的 etc/NEWS.27 里查过：那一版第 192 行写着 “Emacs can now use the XDG convention for init files.”，归属的版本小节是 “Startup Changes in Emacs 27.1”），也可以用环境变量 XDG_CONFIG_HOME 改这个位置。规则和很多人的直觉相反：Emacs 优先用传统路径，只有当 ~/.emacs.d/、~/.emacs、~/.emacs.el 全都不存在 时才轮到 XDG 路径。官方文档写得很直白：~/.emacs.d、~/.emacs 和 ~/.emacs.el 只要存在就永远优先，想用 XDG 路径你必须先把它们删掉或改名。另外，如果两条路径都不存在，Emacs 会自己创建 ~/.emacs.d/ 并从此使用它——所以在一台全新机器上，你什么都不用做就会得到 ~/.emacs.d/init.el，而不是 ~/.config/emacs/init.el。
  • Windows——Emacs 在 Windows 上把 ~ 解析到用户的应用数据目录（%APPDATA%）而不是 C:\Users\你，所以配置在 %APPDATA%\.emacs.d\init.el 一带。同样，用 Ch v 查 user-init-file 最稳。
技巧

配置出问题时的标准流程：先用 emacs -q 确认「问题出在我的配置」，然后把 init.el 注释掉一半，再启动一次。反复二分，很快能定位到出问题的那几行。Emacs 报错时通常会在 *Messages* 缓冲区里给出具体是哪一行；按 Cg 之后按 Ch e（view-echo-area-messages）就能把它翻出来。

early-init-file：一个更早加载的文件

从 Emacs 29 起，Emacs 会先读一个 early-init.el，再读普通的 init.el。它就在 init 文件同一个目录里（比如 ~/.emacs.d/early-init.el）。

为什么要多一个？因为有些设置必须在包系统启动之前生效，否则不起作用。典型例子是禁止 Emacs 启动时自动激活已装的包：变量 package-enable-at-startup（默认 t）控制这件事——非 nil 时 Emacs 会在读 init 文件之前把已装的包激活，这个过程可能触发字节编译、联网、甚至报错。把「别自动激活」写进 early-init.el，就能赶在它之前拦下来：

(setq package-enable-at-startup nil)

官方文档明确说了：因为这个变量的值在读普通 init 文件之前就被用到，所以它必须写在 early-init.el 里。哪怕你用 Customize 改它并存了档，Emacs 也会把设置写进 early-init.el。之后想手动激活包，按 Mx package-initialize 就行。

如果你现在还不需要它，完全可以先不建这个文件——Emacs 找不到就跳过，不会报错。

两条改配置的路

Emacs 给了你两种改设置的方式，新手常犯的错是「只用一种然后抱怨另一种很难用」。

路线一：Customize 图形界面。按 Mx customize，出来一棵分组树，每一项都有复选框、下拉框、输入框。改完点 Apply 生效，点 Apply and Save 存进文件。Emacs 会自动帮你写好对应的 Elisp。

它的硬限制是：不是所有变量都支持 Customize。支持的那些，也只暴露其中一部分选项——变量自己声明能 Customize 什么，Customize 就只能显示什么。这是原理性的，不是没做全。

路线二：直接写 Elisp。配置文件的本质就是一段 Elisp，你在 init.el 里写 (setq tab-width 4) 和在 Customize 里把 Tab Width 拖到 4，效果完全一样。强大、无限制，代价是要学一点 Elisp。

要点

原作者的建议很中肯：先用 Customize，等你写顺手了 Elisp 再切过去。它确实笨重，但不会写错。对初学者来说「不会错」比「省事」重要得多。

进阶：Apply、Apply and Save、Revert 这三个按钮的准确区别

Customize 底部那一排按钮，语义比看上去微妙，弄错会留下「改了却不生效」或者「回退不干净」的烂摊子：

  • Apply——只让改动当前这一次会话生效，不写文件。关掉 Emacs 就没了。用来「先试试看，不喜欢就算了」。
  • Apply and Save——当前会话生效，并且写进配置文件，下次启动还在。这才是真正「改了」的那一下。
  • Revert…——回退。它带一个下拉菜单，有几个选项：Revert This Session's Customizations 只撤销你在这个缓冲区里改动过的那些项；Erase Customizations 则是把 Customize 为你做过的改动整块删掉（从文件里移除），适合「我改乱了，想让 Emacs 忘掉我」的情况。

一个要记住的规律：只要你还没点 Save，就还能干净地回退；一旦点了 Save，回退就只能靠 Erase，或者自己去配置文件里手工撤销。这也是为什么「不确定就先 Apply」是个好习惯——Apply 是可以反悔的，Save 不是。

原书这一点讲得准确，值得原样保留：Revert 只影响当前 Customize 缓冲区里显示的那些项，不是全局撤销。你要是改了五个变量但只看得到一个，Revert 就只动那一个。

包管理器：装第三方插件

Emacs 自带包管理器 package.el。它的工作方式类似手机上的应用商店：联网抓取各个仓库的包索引，合并成一张列表，你挑着装。

开箱自带两个官方仓库：GNU ELPA（elpa.gnu.org）和 NonGNU ELPA（elpa.nongnu.org）。这两个是官方维护的，包都经过基本审核。

易错

MELPA 不是 Emacs 自带的。它是一个社区志愿者运营的第三方仓库，收包很杂但数量远超官方 ELPA，几乎所有主流插件都会先发到那里。用它需要在配置里手动加一条仓库地址——Emacs 不会自动配好。另外 MELPA 的服务器由志愿者维护，可能不稳定甚至哪天关掉，所以别把它当成唯一依赖。EmacsWiki 的 ELPA 页面有当前的仓库清单。

主题：换个配色

Emacs 21 之后，界面的配色由主题（theme）控制。默认情况下不启用任何主题（变量 custom-enabled-themes 默认是 nil），走的是 Emacs 自己的经典外观。手动挑一个主题：

M-x customize-themes RET

这个列表里 Emacs 28.1 起就自带一批：modus-operandi（浅色）和 modus-vivendi（深色）是其中的代表——本书作者在 32.0.50 自带的 etc/NEWS.28 第 2843 行读到 “New themes ‘modus-vivendi’ and ‘modus-operandi’”，那一行归属的小节是 “Changes in Specialized Modes and Packages in Emacs 28.1”；同一批里还有 tango／tango-dark、leuven、wheatgrass 等。Emacs 30 又给 Modus 家族补齐了 8 个色觉友好变体（etc/NEWS.30 第 1968 行：“The highly accessible Modus themes collection has eight items”），所以你现在能选到 modus-operandi-tinted、modus-operandi-deuteranopia 这些，是 30 才有的。自己挑一个试。不喜欢就再换，或者干脆禁用主题回到默认。主题本身也是普通包，用 package-install 装，装完出现在这个列表里。

顺带一提：不少主题成对提供「浅色／深色」两个变体，比如 modus-operandi 和 modus-vivendi、tango 和 tango-dark。装了成对的主题之后，用 Mx theme-choose-variant 可以在两者之间切换。注意这个名字有点误导：它切的是主题家族里的变体，不是操作系统那种跟随日落自动切换深浅的模式。

要点

Emacs 可以同时启用多个主题，后启用的覆盖先启用的，面板（panel）、face 的属性是叠加的。所以关掉一个主题，另一个的效果可能还留着——真要干净，回到默认主题。

进阶：终端 Emacs 里颜色不对、或者想让主题配色显示出来

图形界面下主题基本都能正确显示，终端 Emacs 里经常不是——终端能显示多少颜色，由你的终端程序和 Emacs 之间的协商结果决定。下面几招用来排查和修正。

先看清 Emacs 眼里的「可用颜色」

Mx 然后输 list-colors-display 回车，会开一个窗口列出当前环境实际支持的颜色，每种还标上名字。这个名字就是你在 Customize 里填颜色时能用的名字（比如 OrangeRed、DarkGreen）。

图形界面下，Emacs 能用多少颜色只受显示器色深限制，几乎整个 RGB 色彩空间都能取；终端下就受终端限制，这个命令给出的才是真实可用的那一小撮。

24 位真彩色（truecolor）

现在的终端大多不止传统的 16 色或 256 色，而是支持 24 位真彩色——每个颜色分量 8 位，能显示一千六百多万种颜色。主题里那些细腻的颜色过渡要靠它才显示得出来。Emacs 对这件事的支持是逐步加的：

  • Emacs 26 起：Emacs 能识别「有能力的终端」并自动启用 24 位颜色。
  • Emacs 28 起：如果你的终端明明支持真彩色，但系统缺 terminfo 数据库（termcap/terminfo 描述终端能力的数据库），Emacs 判断不出来。这时可以设环境变量 COLORTERM=truecolor 告诉它。Emacs 源码里确实会读这个变量。
  • Emacs 29 起：终端的 terminfo 条目里带 Tc 能力标记的话，Emacs 会自动用 24 位颜色——大多数现代终端不需要你再手工设 COLORTERM 了。

还是不对怎么办？Mx info-apropos 然后输入 Colors on a TTY，会给你一条指向官方手册里那个 FAQ 节点的链接，那里按操作系统分门别类地讲了怎么配终端。注意 info-apropos 是搜手册内容的，和 Ch a 搜命令名是两回事——info-apropos 搜的是 Info 手册里的文字和节点名。

练习 19　你改了 init.el 并存了盘，想立刻知道这批改动有没有语法错误，不必重启 Emacs。该用什么？

Mx eval-buffer，把整个文件当 Elisp 执行一遍。有语法错误会立刻报出来。只想试一小段就选中它按 Mx eval-region。（注意：如果配置已经把 Emacs 弄坏了，这些命令本身可能也执行不了，那就退回 emacs -q 排查。）

练习 20　网上教程说「去改 ~/.emacs.d/init.el」，但你的 Emacs 好像用的不是这个路径。最可靠的办法是什么？

按 Ch v 然后输 user-init-file，Emacs 会显示它此刻真正使用的那个路径。这一步不能省：从 Emacs 27.1 起支持 XDG 路径（~/.config/emacs/），但传统路径优先——~/.emacs.d/ 之类只要存在就用它，两边都没有才会创建 ~/.emacs.d/；Windows 上 ~ 又指向 %APPDATA% 而非 C:\Users\你。没有任何一个默认路径是全局固定的，所以「问一下变量」是唯一稳妥的办法。

练习 21　MELPA 是 Emacs 自带的包仓库吗？

不是。Emacs 开箱自带的只有两个官方仓库：GNU ELPA 和 NonGNU ELPA。MELPA 是社区志愿者运营的第三方仓库，需要在配置里手动加地址才能用，而且因为服务器由志愿者维护，可能不稳定，重要依赖别只压在它上面。

现在的 Emacs：30、31、32 带来了什么

原书写于 Emacs 29 前后。核心的东西（按键、移动、编辑）一个字都没过时，但周边生态确实往前走了不少。这一节把「你今天装的 Emacs 和书里描述的有什么差别」一次说清。

原生编译：从可选变成默认

这是最值得知道的一条。Emacs 30.1 起，原生编译（native compilation）默认开启了——官方 NEWS 里写得很直接。

原生编译做的事，是把你 init.el 和各个包里的 Elisp 代码翻译成机器码并存成缓存，下次启动直接加载编译好的产物。省掉的是「逐行解释 Elisp」的时间。效果因机器和配置而异，但方向是对的：Emacs 启动变快了，而且差距在扩大。

这也是原生编译一直没有被淘汰的原因——它一直存在，但因为各种原因总是默认关闭、文档又少，很多人不知道它是什么。Emacs 30 把它扶正了。

技巧

想知道「我这套配置启动到能干活花了多久」：Emacs 启动时会记下起始时刻，存放在变量 before-init-time 里。在小模式行按 M-，然后输入这行算式回车，就得到从启动到现在的秒数：

(- (float-time) (float-time before-init-time))

刚启动完马上执行，得到的数字就约等于启动耗时。改完配置重启后再看一次，你就知道那几行改动是快了还是慢了。

其他和你有关的版本变化

  • Emacs 28：加入了 MX（execute-extended-command-for-buffer）和 Ch x（describe-command），以及 *Help* 缓冲区里的 i / s / c 快捷键。本章前面都讲过了。
  • Emacs 29：加入了 Ch Cq 快捷速查（help-quick-toggle）；use-package 和 Eglot 进核心；early-init.el 成为标准做法。注意 XDG 配置目录不是 29 才有的——那是 27.1（本书作者在 32.0.50 自带的 etc/NEWS.27 第 192 行查过），见 2.6 节。
  • Emacs 30：原生编译默认开启；Unicode 支持更新到 15.1；内置 Org 升级到 9.7。
  • Emacs 31：在兼容的终端里 xterm-mouse-mode 默认开启，终端版终于开箱支持鼠标；site-start.el 的加载顺序提前到 early-init.el 之前（管理员现在能覆盖更多早期设置）；新增了用户 Lisp 目录机制。
  • Emacs 32：仍在开发序列中（版本号形如 32.0.x）。日常使用请等它正式发布。
要点

这五年的版本变化有个共同点：新东西大多是「默认更聪明」，而不是「键位大改」。Emacs 一直在克制地保持向后兼容——这正是它值得信任的地方，也是你照着几年前的教程敲键仍然有效的原因。真正需要你警惕的只有两类：被移除的废弃变量（Emacs 会隔好几个大版本才动手，但动手就是真删），和少数几个新增的默认绑定（比如 Emacs 31 的终端鼠标）。

本章小结

回头看这一章装进去的东西：

  1. 版本意识：emacs --version 先看一眼。Emacs 极少做破坏性改动，但你得知道自己在哪个版本上，因为少数默认值会跨版本变。
  2. 干净启动：-q 排除个人配置，-Q 再排除站点级配置。配置出错时的第一反应。
  3. 长驻：emacs --daemon 配 emacsclient（注意结尾多个 l），配合 $EDITOR 让命令行工具都接上来。Cx # 是那个「做完一个换下一个」的键，但它要服务器开着才存在。
  4. 认屏幕：欢迎界面、模式行、回显区、小模式行。模式行右侧括号里第一个是主模式，后面是次模式——排查异常行为先看它。
  5. 按键记号：C- 是 Control、M- 是 Alt、S- 是 Shift。理解前缀键和完整键的区别。看不懂就 Cg 取消。
  6. 不背命令：Mx 加 Tab 补全能调出任何 interactive 命令。Cu 是数字 4，每多按一次就乘以 4（4、16、64、256），用它表达「做 N 次」和「反过来做」。
  7. 自救：Ch k 查键、Ch f 查函数、Ch v 查变量、Ch x 查命令、Ch m 查模式。绝大多数前缀键后面加 Ch（或 F1）列出该键表全部绑定。Ch a 模糊搜索，Ch r 开手册。忘了就查，这不是丢人的事，是正确用法。
  8. 配置：Ch v user-init-file 查出你自己的路径（别背网上的路径）。Customize 改完要点 Apply and Save。Mx eval-buffer 试配置。装包用 package.el，官方仓库是 GNU ELPA 和 NonGNU ELPA，MELPA 是第三方要手动加。
技巧

如果这一章你只记住一件事，就记住这个：Emacs 的每一个功能你都能自己查到。你不需要背命令表，不需要记住某个功能在菜单的哪个角落，甚至不需要知道它叫什么名字。知道「按 Ch 然后能问 Emacs 问题」，剩下的都可以现场查。这一条比本章所有具体键位加起来都重要。
