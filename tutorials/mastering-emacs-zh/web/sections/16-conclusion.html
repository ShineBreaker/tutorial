十六、结语与延伸资源

这一章是全书的「下一站地图」。你要学会的不是新的按键，而是向 Emacs 提问的方法——这是唯一能让你脱离本书继续前进的能力。读完你会知道：原书列的那些第三方包在 2026 年还剩哪些、当代 Emacs 生态的标准答案是什么、你的 Emacs 到底是哪个版本以及这几个版本之间改了什么、官方手册怎么查、社区去哪儿问问题，以及一条四周就能走完的学习路线。

要点

这一章的每一条版本结论，都在写稿时在本机跑过：Emacs 32.0.50 用 emacs --batch -Q --eval 直接查函数与变量是否存在、读变量的当前默认值；版本归属逐条对照随 Emacs 安装的 etc/NEWS.* 文件；再拿同机安装的 Emacs 30.2 与 31.1 的文件树做交叉确认。文中凡是「我实测过」的地方都标了具体做法，你自己可以重复一遍。

一、真正的终点：学会向 Emacs 提问

原书作者 Eli Spare 在这一章说了一句整本书最要紧的话：掌握 Emacs 这样的编辑器，办法不是背下所有键位，而是学会向它问正确的问题。他自己举的例子是：忘了 Cx r l 干什么，这根本不是问题——按 Ch k 问一句 Emacs 就告诉你了。

自解释编辑器是一个专有名词，指编辑器能告诉你「我刚才做了什么、这个东西是哪来的」——Emacs 把内置文档、函数说明、变量说明、键位表都做成了运行时可查询的东西，所以它属于这一类。Emacs 用来回答你提问的入口是 Ch 这个前缀键（C 表示 Control 键，M 表示 Alt 键或 Escape 键；前缀键指按下之后还要再按一个键才能确定具体命令的按键）。按 Ch 之后，Emacs 会在回显区（窗口最下面那一行，平时显示文件名和提示信息的地方）列出一长串「Ch 后面跟什么键 = 什么命令」，你可以把这一行当索引随便挑。

四个最该先记住的：

  • Ch k（describe-key，描述按键）：问「我刚按的这个键会做什么」。Emacs 弹出窗口告诉你它调用的命令名、命令的完整说明、以及这个命令定义在哪个文件里。全书出现频率最高的按键。
  • Ch c（describe-key-briefly，简述按键）：同样的问题，但只在回显区给一行短答案，不弹窗口。想快速确认某个键时用它。
  • Ch f（describe-function，描述函数）：按命令名问「它到底是干什么的」。等价于 Mx describe-function 回车。
  • Ch v（describe-variable，描述变量）：问「这个选项当前值是多少、默认值被改成了什么」。Emacs 31 起它还会提醒你「这个变量该用 setopt 设」（setopt 是 Emacs 29 引入的设值宏，比 setq 好，因为它会自动触发变量的钩子）。
技巧

摸黑用 Emacs 的正确姿势是：先按，错了立刻问。别在博客上搜「Emacs 怎么保存文件」——按 Cx s，没反应就 Cg（keyboard-quit，中止正在执行的命令）掐掉，然后 Ch k 按下刚才那个键。三十秒得到答案，而且这个答案永远对应你手上这个版本，不会像网上帖子那样过时。

还有一条是原书特别强调的：给任意前缀键追加 Ch，可以列出这个前缀下的所有键位及其命令。想知道 M- 那一串是什么，就在它后面加 Ch：按 M- 之后紧接着按 Ch，Emacs 就把 M- 下的全部绑定列出来。这一招在你自己改过键位之后尤其有用——Emacs 问的是当前状态，不是出厂状态。

要点

想在一大堆绑定里筛出某个包提供的那些，标准做法是「前缀 + Ch，然后用 Cs 搜」。以 evil- 包为例，不要试图把 e v i l 当成四个键一个一个敲下去（那既不是合法的键序列，也搜不出任何东西），正确做法分两步：

  1. 按 M- Ch，Emacs 打开 *Prefix Bindings* 之类的缓冲区，列出 M- 下的全部绑定。
  2. 在这个缓冲区里按 Cs（isearch-forward），输入 evil- 回车。凡是命令名以 evil- 开头的行都被高亮出来——这一行就是你要找的。

换个包名就换第二步的搜索词：查 consult-、flycheck-、evil- 用的是同一套动作。而如果 M- 下的绑定多到刷屏（装了一堆包时常这样），就直接搜你的包名前缀，比逐行读快得多。

练习 1　你按 Cx Cs 弹出了一个写着「Visit the specified file in a buffer」的窗口。你想立刻知道这个键到底叫什么名字，用哪一组键？

按住 Cx Cs 的时候再按 Ch k，然后松开——等价写法是先按 Cx Ch k 再按 Cs。命令是 describe-key，它会告诉你答案是 save-buffer（保存当前缓冲区）。

练习 2　你想快速确认 Mx 是不是真的能打开命令执行器，但不想被弹窗挡住视线。用哪一组键？

Ch c（describe-key-briefly），然后按下 Mx。答案会是一行「Mx runs the command execute-extended-command」。

练习 3　某个第三方包（假设叫 evil-mode）重定义了你的 Cf。你想搞清楚它把所有键都改成了什么。最直接的办法是什么？

用命令名做前缀查询：按 M- Ch e v i l，Emacs 会列出所有以 evil- 开头的键位。另一种更笨但同样有效的办法是 Ch b（describe-bindings）导出当前模式的完整键位表，粘到别处慢慢读。

二、原书那份资源清单：今天还剩什么

原书在最后给了一张第三方包清单。这张表在 2026 年已经明显过时了——不是「包没了」，而是生态的重心换了位置。我们逐条过一遍，把「内置 / 第三方 / 已被取代」标清楚。

先说判断标准。内置指 Emacs 自带、不用装、跟着 Emacs 一起升级。第三方指要自己从 包归档（package archive，一个打包好的在线包仓库）安装的包；Emacs 官方维护的叫 GNU ELPA（地址 https://elpa.gnu.org/packages/），社区维护的叫 MELPA 和 NonGNU ELPA（https://elpa.nongnu.org/nongnu/）。在 Emacs 32 里，配置归档地址的变量叫 package-archives，它的默认值就是上面这两个 GNU 的地址——这意味着你装包时不用先手工加任何一行配置。

易错

网上（包括本书生态部分的早期版本）大量教程让你写 (setq package-archive-alist '(("melpa" . "https://melpa.org/packages/") …))。这个变量名在当前 Emacs 里已经不存在了——我在 Emacs 32.0.50 上执行 (boundp 'package-archive-alist) 返回 nil。现在要用的是 package-archives，格式相同、名字不同。你照着老教程抄会得到 Symbol's value as variable is void: package-archive-alist。

但这不是 Emacs 32 的新变化。package-archives 这个名字从 Emacs 24.1 就是这样了（Emacs 24.1 用 ELPA 的包管理器替换掉了 23 及更早版本里自带的那个 package.el，那次替换才把变量名换掉）。老名字出现在 2012 年之前的文章和 Emacs 22/23 时代的配置里。要验证某个变量名在不在，别猜，直接问 Emacs：(boundp 'package-archives)。一个坑：这个变量定义在 package.el 里，而 package 特性在启动时并没有被预加载——所以在刚启动的 --batch -Q 会话里 (boundp 'package-archives) 会返回 nil，要先 (require 'package) 才为 t；而 (boundp 'package-archive-alist) 在 require 前后都永远是 nil。这两者不是一回事。

三、当代生态的标准答案（2026 版）

原书写的是 Emacs 26 到 30 的过渡期，那个时期生态的默认选择是 Helm、IDO、Flycheck、LSP mode。这四样在今天都有更好的答案。下面按「你在做什么」组织，而不是按包名。

3.1 补全：内置的 *Completions* 缓冲 vs Corfu + Vertico + Consult

补全（completion）指 Emacs 猜你想输入什么、然后替你补上。Emacs 内置的补全体系在 Emacs 29 和 30 做过一轮大改，先把事实说清楚，因为这直接决定了你的配置该写什么。

  • 命令是 completion-at-point（在光标处补全），默认键是 MTAB。Emacs 30 起，Text mode 也把 MTAB 交给了 completion-at-point，不再默认绑给 ispell-complete-word；想换回去就定制新选项 text-mode-ispell-word-completion（这个选项在 Emacs 32 上的默认值实测就是 completion-at-point）。
  • 补全的匹配规则由变量 completion-styles（补全风格列表）决定，Emacs 32 上的默认值是 (basic partial-completion emacs22)（我用 emacs --batch -Q --eval 读出来的）。还有一个概念叫 capf（completion-at-point-functions，补全函数列表）——它是一串函数，Emacs 挨个问它们「你能补全什么」，谁有答案就用谁的。凡是想接管补全的库——内置的 eglot、GNU ELPA 上的 corfu 与 company——都是通过往这个列表里塞函数来做的。
  • Emacs 29 给 minibuffer 补全加了大量操作：M↑ / M↓ 在 *Completions* 缓冲里上下移动候选，MRET（minibuffer-choose-completion）选中当前高亮的候选，新选项 completion-auto-select 控制 TAB 是否自动切到第一个候选。Emacs 30 又补了 minibuffer-visible-completions（候选在 minibuffer 里就地显示而不是弹 *Completions* 窗口）、completions-sort 的 historical 值（按使用频率排序）等。
要点

另一个常见的误会是 Company。很多人以为 company-mode 是 Emacs 自带的（它确实很「像」内置的），其实不是：我在 Emacs 32.0.50 的整棵 lisp/ 树里找不到 company.el，etc/NEWS.29 到 etc/NEWS（32 的）里对 “Company” 的命中数是 0，Emacs 手册 emacs.info 里也一次都没提到它。它是 GNU ELPA / MELPA 上的第三方包（本机 Guix 配置里装的是 company-1.0.2）。要判断某个功能是不是内置的，办法永远是 (locate-library "名字")：返回 nil 或者返回一个来自 site-lisp 的路径，就说明它不在核心里。

易错

很多中文资料（包括一些 Emacs 29 时期的文章）会说「Emacs 29 引入了 use-completion 这个新选项，打开它就能用新式补全」。这个变量在当前 Emacs 里不存在。我在 Emacs 32.0.50 上实测 (boundp 'use-completion) 和 (fboundp 'use-completion) 都返回 nil；在 NEWS.29、NEWS.30、NEWS.31、NEWS（32 的）里 grep use-completion 全部是零命中，在随 Emacs 安装的 emacs.info 手册里也搜不到。至于名字相近的 use-completion-under-point：实测 (fboundp 'use-completion-under-point) 在 Emacs 32.0.50 上也是 nil，别拿它当挡箭牌。写配置时不要加 (setq use-completion t)，它只会给你一个 void-variable 报错。

那今天该怎么配？两条路，先想清楚你要不要跨过这条线。

  1. 什么都不装。只用内置补全。要做的是挑好 completion-styles。最常用的一条是把 flex（模糊匹配）加进去：输入 mlm 就能补出 message-log-mode。flex 是 Emacs 27.1 起内置的（不是 29——etc/NEWS.27 里有 “New 'flex' completion style.” 这一条；etc/NEWS.29 只是又提到了它）。手册的 “Completion Styles” 一节确实把 substring、flex、initials 列成「额外提供、想用就加进 completion-styles」的风格。这一条路不用装任何包。
  2. 装三个包，换一套完全不同的补全体验。corfu（补全引擎，GNU ELPA，官网 https://github.com/minad/corfu）+ vertico（垂直排列候选，GNU ELPA 与 MELPA 都有）+ consult（把 switch-to-buffer、find-file 这些「搜点什么」的操作统一成同一个弹出界面，GNU ELPA 与 MELPA 都有）。这三样是 2026 年最常见的新配置。装法：Mx package-install，依次输入 corfu、vertico、consult，然后在配置里 (global-corfu-mode 1)。

为什么这一章要专门花笔墨说这件事？因为初学者最大的困惑恰恰是「这功能到底是自带的还是要装包」。Corfu 不是 Emacs 内置的——Emacs 31.1 的 NEWS 里在讲子窗口时用的是「GNU ELPA packages Corfu」这个说法，本身就说明它是 ELPA 包而不是核心代码。

3.2 Git：没有替代品，只有 Magit

Magit（https://magit.vc，MELPA 与 NonGNU ELPA 都有）是原书那份清单里今天地位最高的一个。它把 Git 的状态、暂存区、分支、提交历史都做成一个可以在 Emacs 缓冲区里操作的面板。

易错

原书写于 Magit 3.x 时代，那时默认键位是一套 g 前缀的「和弦键」。Magit 4 改成了单字母键：我读了本机 Magit 4.7.0 的 lisp/magit-mode.el，magit-mode-map 里 "s" 绑 magit-stage-files、"u" 绑 magit-unstage-files、"c" 绑 magit-commit、"l" 绑 magit-log、"b" 绑 magit-branch、"d" 绑 magit-diff、"f" 绑 magit-fetch、"F" 绑 magit-pull、"P" 绑 magit-push、"q" 绑 magit-mode-bury-buffer、"g" 绑 magit-refresh；打开状态面板的键是 j（magit-status-quick）。整个包里没有 g g、g s、g k 这类绑定——根本没有 k 键，取消暂存是 u。按老文章敲 g g，在 Magit 4 上什么也不会发生。

Magit 4 也有子前缀（比如 l l 是 magit-log-current），所以「和弦」这个说法只在子前缀这一层还成立。想学的人从它自己的 Info 手册入手最快，本机装了 magit.info，在 Emacs 里 Ch i 然后输 magit 回车就能打开。

Magit 依赖的 Transient 库从 Emacs 28.1 起就是内置的（早于本书成书年代，也不是 30），所以现在装 Magit 不需要单独处理这条依赖。Magit 本身也是大量其他包（forge、git-grep、org-modern 等）的基础设施，值得优先学。

3.3 语言服务：Eglot（内置）而不是 LSP mode

LSP（Language Server Protocol，语言服务器协议）是一套让编辑器把「跳转定义、查引用、重命名、诊断」外包给独立进程的标准。Emacs 29 起把 Eglot（https://github.com/jojojoe777/eglot）收进了核心，Emacs 自带 eglot.info。我在 Emacs 32.0.50 上实测 (fboundp 'eglot-ensure) 返回 t，不用装包就能用。

原书说 LSP mode「试图复刻别的编辑器里那种完整 IDE 体验」。这话今天仍然描述了它与 Eglot 的分工：lsp-mode（https://github.com/emacs-lsp/lsp-mode）功能更激进、生态更老；Eglot 更薄、更可预测、跟着 Emacs 走。多数新配置选 Eglot，理由是：只有一个 LSP 客户端要操心，遇到 bug 时去 Emacs 的 bug 追踪比去第三方仓库更容易得到响应。

Eglot 之外的诊断用内置的 flymake（Emacs 自带 flymake.info；(fboundp 'flymake-diagnostics) 实测为 t）。它和 Flycheck 的关系就像 Eglot 和 LSP mode：更薄、够用、跟着 Emacs 走。

进阶：capf 是什么，以及它为什么决定你能不能换补全前端

completion-at-point-functions（简称 capf，中文常译「补全函数表」）是一个变量，值是一串函数的列表。Emacs 每次触发补全时，会按顺序挨个调用这些函数，每个函数要么返回 nil（我提供不了候选），要么返回一个「补全表」数据结构。

关键点在于：capf 是一个标准接口，不是某一个包的私有接口。Eglot 会往里塞自己的函数，company 模式会往里塞自己的函数，Corfu 也会往里塞自己的函数。所以换补全前端和换语言服务器这两件事是正交的——你可以用 Corfu 呈现 Eglot 提供的补全候选。

Emacs 29.1 的 NEWS 里专门记了一条：新增 dabbrev-capf 函数专门用来往 capf 里提供「数据缩写」候选。这是 Emacs 自己在用这个接口扩展补全源（定义在 lisp/dabbrev.el）。

想看当前有哪些 capf 在生效：Ch v 然后输入 completion-at-point-functions，Emacs 会显示整个列表以及每个元素是谁加进去的。

3.4 跳转、搜索、片段：大纲

  • 项目内跳转：内置的 project（项目管理库，(fboundp 'project-current) 实测为 t）加 xref（定义/引用查询）。对纯文本项目配 ripgrep，对有 LSP 的语言用 Eglot。dumb-jump 只在「没有任何索引、又没有 LSP」的场景还有价值。
  • 搜索：外部程序 ripgrep（命令行 rg）仍然是最好的搜索工具，但要记住 Emacs 核心没有 M-x rg 这个内置前端（(fboundp 'rg) 实测为 nil）。Emacs 内置的接法是 Emacs 28 引入的选项 xref-search-program，它让 xref / project- 系列命令可以用 ripgrep 而不是 grep。想要弹出式的搜索界面，用 consult 生态的 consult-rg。
  • 片段展开：yasnippet 仍是主力；不想背 yasnippet 的 $ 语法可以试内置 templates 加 tempel。
  • 弹出面板：用内置的 transient，不要再新装 hydra。Magit 已经是 transient 的大用户，跟着它学最快。
  • 大纲与结构化编辑：Org（内置）仍然是首选，原书对它的评价今天完全成立。

练习 6　你想换成目前最流行的补全体验（候选竖排 + 统一弹出界面）。需要装哪几个包？它们分别能在哪些官方归档里找到？

三个：corfu（补全引擎）、vertico（候选竖排）、consult（统一弹出界面）。这三个现在 GNU ELPA 和 MELPA 上都有——常见的老文章只说 corfu 在 GNU ELPA、另两个在 MELPA，那已经过时了。装完在配置里写 (global-corfu-mode 1)。

练习 7　你在 Emacs 29 或更新的版本里，想用 LSP 跳转到一个符号的定义，但不想装任何包。用哪个命令？

Mx eglot-ensure。Eglot 从 Emacs 29 起是内置的，需要对应语言的 eglot-server-programs 配置好（(fboundp 'eglot-ensure) 在 Emacs 32.0.50 上实测为 t）。

四、Emacs 26 到 32：原书没写的版本变化

这一节是这一章最有价值的部分。读者现在手上的 Emacs 很可能和原书写这本书时的版本差了好几个大版本，如果不先对齐事实，后面所有的配置抄来抄去都会踩空。

先给一张时间表。这些日期来自 Emacs 源码树里的 HISTORY 文件（我直接读的本机 Emacs 32.0.50 随附的 etc/HISTORY）：

  • Emacs 26.1 — 2018-05-28
  • Emacs 27.1 — 2020-08-10
  • Emacs 28.1 — 2022-04-04
  • Emacs 29.1 — 2023-07-30（29.4 — 2024-06-22）
  • Emacs 30.1 — 2025-02-23，30.2 — 2025-08-14
  • Emacs 31.1 — 2026-08-24（截至你读这一章时的最新正式版）
  • Emacs 32 —— 开发中（你如果用发行版滚动源或 Git 快照，可能已经拿到 32.0.50 之类的开发版）

然后是逐条变化。写这一节时我反复使用两个手段：一是读 Emacs 源码树里自带的 etc/NEWS.26 到 etc/NEWS（32 的那一份），二是直接在 Emacs 32.0.50 上用 emacs --batch -Q --eval 读变量的实际值。凡是下面写了「实测」的，都是第二种方式跑出来的。

4.1 行号：display-line-numbers 是 Emacs 26.1 引入的，不是 28

网上（包括很多 Emacs 27/28 时期的教程）说行号功能 display-line-numbers 是「Emacs 28 引入的」。这个说法是错的。它出现在 Emacs 26.1 的 NEWS 里——我在本机的 etc/NEWS.26 第 576 行读到：buffer-local variable 'display-line-numbers' to activate this optional display，紧接着是 display-line-numbers-mode 和 global-display-line-numbers-mode。Emacs 27.1 只是给它补了 display-line-numbers-major-tick、display-line-numbers-minor-tick、display-line-numbers-offset 这些选项，Emacs 28 那一版的 NEWS 里关于行号的唯一改动是 mode-line-position-column-format。

它在 Emacs 32.0.50 上的默认是关闭的（实测 (boundp 'display-line-numbers) 为 t、值为 nil），column-number-mode（在模式行显示光标列号）也是关闭的。想要行号，在配置里加一行：

;; 显示行号（display-line-numbers 是 Emacs 26.1 引入的缓冲区局部变量，
;; global-display-line-numbers-mode 是它的全局次模式开关）
(global-display-line-numbers-mode 1)

;; 让光标所在行的行号更醒目
(setq display-line-numbers-major-tick 1)

如果你在较老的资料里看到 (linum-mode 1)，那是 Emacs 26 之前的做法，已经被内置的 display-line-numbers 取代了，新配置不要用。

4.2 补全：Emacs 29 做了什么，Emacs 30 又做了什么

上面 3.1 已经讲了命令和风格层面的变化，这里补版本归属：

  • Emacs 29.1（2023-07-30）：minibuffer 补全大改。新增 M↑ / M↓ 在候选间移动、MRET 选择当前候选；新选项 completion-auto-select、completion-auto-wrap、completions-sort、completions-max-height、completions-header-format、completions-highlight-face。内置 eglot 也是这一版进来的。这一版的 NEWS 里没有 use-completion 这个条目。
  • Emacs 30.1（2025-02-23）：completion-auto-help 现在也管 icomplete-in-buffer；*Completions* 缓冲改为总是伴随 icomplete-in-buffer 出现；新增 minibuffer-visible-completions（候选就地显示）、completions-sort 的 historical 值、completion-auto-deselect、previous-line-completion / next-line-completion。Text mode 把 MTAB 让给了 completion-at-point。这一版 NEWS 里同样没有 use-completion。
要点

所以「Emacs 29 引入 use-completion 新式补全体系」这句话，在当前 Emacs 上没有任何可对应的实物。真实的故事是：Emacs 29 改了 minibuffer 补全的交互，Emacs 30 继续补，并且彻底换掉的是「文本终端上 TAB 补全会乱跳」这个老毛病。如果你读到了这句话的来源，它大概率来自一篇把某个社区包或者某个提案的变量名记混了的文章。

4.3 Emacs 30：原生编译、Android、Modus 家族补齐变体

Emacs 30 最重要的一批变化（全部来自 etc/NEWS.30）：

  • 原生编译默认开启：只要系统有 libgccjit，Emacs 编译时就默认用 Elisp 原生编译器（native compilation，把 Elisp 编成机器码以加快执行）。要关掉得在 configure 时加 --with-native-compilation=no。这是「Emacs 30 启动比 29 快」的来源之一。
  • 移植到 Android：Emacs 30 有了官方的 Android 端口（需要交叉编译）。Emacs 手册从这一版起多了一整章附录 “Emacs and Android”（Ch i 然后输 Android），讲的是在 Android 设备上跑 Emacs 的那些特殊之处：文件系统、应用间文件获取、窗口系统、字体、以及 Termux / BusyBox 之类怎么补上缺失的命令行工具。不是讲用 emacsclient 去连手机。
  • Modus 家族补齐成 8 个变体（这一条才是 Emacs 30 的）。NEWS.30 原文是「The highly accessible Modus themes collection has eight items」，本书作者在 32.0.50 自带的 etc/NEWS.30 第 1968 行查到，并逐条核对了它列出的 modus-operandi-tinted、modus-vivendi-tinted、modus-operandi-deuteranopia、modus-vivendi-deuteranopia 等。但要注意：modus-operandi 和 modus-vivendi 这两个主题本身是 Emacs 28.1 就进核心的（etc/NEWS.28 第 2843 行 “New themes ‘modus-vivendi’ and ‘modus-operandi’”，归属 28.1 小节）。看到「Emacs 30 内置 Modus」这种说法，只能理解成「30 把变体补齐了」，不能理解成「30 才有 Modus」。
  • Transient 不是这一版才进来的（这条放进来是为了纠偏）：Transient（Magit 弹出菜单的实现库）Emacs 28.1 就进了核心，Emacs 30.2 的 lisp/ 目录里有 transient.el、也自带 transient.info 手册——但这不是 30 的新变化。任何说「Emacs 30 才内置 transient」的说法都搞错了两个版本。
  • Tree-sitter 模式**：Emacs 30 开始自带一批基于 Tree-sitter 语法树的模式（NEWS 32 里还有「New major modes based on the tree-sitter library」这一条，说明这条线在 32 仍在推进）。
  • 安全相关：修掉 man.el 的 shell 注入漏洞（CVE-2025-1244），新增用户选项 trusted-content 允许你手动放开某些危险功能。
要点

关于「10 色调色板」：我在 Emacs 32.0.50 的整个 lisp/ 源码树里 grep palette，作为变量或函数定义的只有 macOS 上的 ns-do-show-character-palette（那个字符查看器，跟主题无关）；Emacs 30/31/32 的 NEWS 里也没有「10 色」相关的条目。Emacs 核心并没有一个「10 色调色板」的主题机制。

你可能想说的是 Modus 主题自己的调色板——这个确实存在，而且是 Modus 成为内置主题后最值得学的部分。它的 “Palette overrides” 一节写得很清楚：每个 Modus 主题都声明一个调色板，里面是一串 (名字 . "#rrggbb") 的具名颜色；你可以用 modus-themes-common-palette-overrides 做跨主题的共享覆盖，也可以用 modus-operandi-palette-overrides 这种「主题名 + -palette-overrides」的形式做单个主题的覆盖（主题专属的优先级更高）。想只取调色板里的一个颜色值，用 modus-themes-get-color-value。版本提醒：随 Emacs 30.2 附带的是 modus-themes 4.4.0，31.1 升到 5.2.0，32.0.50 已经是 5.3.0；从 Modus 5.0.0 起（也就是 Emacs 31.1 之后）调色板常量改了名，旧的 modus-operandi-palette 现在只是 modus-themes-operandi-palette 的过时别名（源码里有一行 (define-obsolete-variable-alias 'modus-operandi-palette 'modus-themes-operandi-palette "5.0.0")）。新配置请写新名字，跨版本的配置里加个版本判断。

4.4 Emacs 31：更安静的破坏性变化

Emacs 31.1（2026-08-24）里有几条会让老配置突然不工作的改动，值得单独列出来（来自 etc/NEWS.31）：

  • 老的 ctags 不再随 Emacs 安装。Emacs 31 起请用 Universal Ctags（https://ctags.io/）；要临时获得旧行为可以跑 etags --ctags，或者放一个叫 ctags 的 shell 脚本包一层。这条会打到任何依赖 ctags 的第三方包（比如各种语义跳转插件），是 Emacs 31 最容易踩的坑。
  • unexec dumper 被移除（它从 Emacs 27 起就弃用了）。portable dumper 是唯一剩下的启动加速方式，Emacs 启动脚本里 --dump 那一套在 31 上要重新检查。
  • site-start.el 现在在你的 early init 之前加载。你如果在 site-start.el 和个人配置里都设了同一个东西，加载顺序变了，后者现在赢。
  • describe-variable 会主动告诉你「这个变量该用 setopt 设」。这条对本书读者最有用——你再也不用猜某个变量用 setq 设会不会不生效了，按 Ch v 一问便知。
  • 主题机制终于改好了：对已启用的主题调用 custom-theme-set-faces 或 custom-theme-set-variables，改动会立刻生效，不必重新加载整个主题（Emacs 30 及以前需要重载）。新增命令 copy-theme-options，可以把一个主题里的选项设置复制出来。
  • 新增内置主题 newcomers-presets：它不改变外观，只是把一批「新手友好」的用户选项设成另一套默认值（NEWS 原文：“configures user options and minor modes that might interest new users, but would otherwise be too invasive to enable by default. It is basically a set of alternative defaults.”）。官方手册专门用一个 “Newcomers Theme” 节点讲它，并提醒两件事：这个主题启用的功能集合每个 Emacs 版本都会变；用顺手了以后应该用 Mx copy-theme-options 把设置搬进自己的配置，然后关掉这个主题。
  • 自带 Org v9.8（Emacs 30.1 自带的是 9.7）。
  • 兼容终端里 xterm-mouse-mode 默认开启（NEWS 提醒：鼠标拖选会改写 Emacs 的复制/粘贴按键，想保持旧行为把 xterm-mouse-mode 定制为 nil）；新增次模式 delete-selection-local-mode（把 delete-selection-mode 按缓冲区局部地开关——注意它是新加的次模式，不是给谁改的新名字）；新增选项 kill-region-dwim（没有选区时 C-w 不再报错，而是删掉最后一个词）；IDLWAVE（IDL 的 IDE）搬到了 GNU ELPA。

4.5 Emacs 32：正在开发中

如果你拿到的是 32.0.50 这类开发快照（我本机就是），随它安装的 etc/NEWS 开头写的是 “This file is about changes in Emacs version 32.”，条目还很少。目前能看到的有：Kmscon 终端类型、新的 tty-cursor-movement-use-TAB 选项、query-replace-show-preview（查询替换时显示预览）、更多基于 Tree-sitter 的主模式、canvas 图像对象支持，以及Package-vc 可以从已有的 tarball 安装里复制本地改动。

顺便澄清一个容易被误传的消息：package-archives 不是 Emacs 32 才改的名。它是 Emacs 24.1 就有的名字（那次 ELPA 换了包管理器实现）；package-archive-alist 属于 Emacs 23 及更早。所以「升级到 32 所以包归档配置报 void-variable」这种说法是假的——真正会在 32 上炸的，是别的原因。

练习 8　行号选项 display-line-numbers 是在哪个 Emacs 大版本引入的？

Emacs 26.1（2018-05-28）。证据在 etc/NEWS.26：buffer-local variable 'display-line-numbers' to activate this optional display。Emacs 28 的 NEWS 里关于行号的唯一改动是 mode-line-position-column-format，跟这个功能无关。它在 Emacs 32.0.50 上的默认值是关闭（nil）。

练习 9　某篇文章说「Emacs 29 引入了 use-completion 选项，打开它就能用新式补全」。你在 Emacs 32 的配置里写了 (setq use-completion t)。会发生什么？

报错：Symbol's value as variable is void: use-completion。这个变量在 Emacs 32.0.50 上 (boundp 'use-completion) 返回 nil，在 NEWS.29、NEWS.30、NEWS.31、NEWS（32）里都搜不到，在 Emacs 30.2 与 31.0.91 的 emacs.info 里也搜不到。Emacs 29 真正引入的是 minibuffer 补全的交互改进（M↑/M↓ 选候选、completion-auto-select 等）和内置 Eglot。

练习 10　你升级到 Emacs 31.1 后，发现某个依赖 ctags 的跳转包不工作了。NEWS 说 Emacs 不再自带旧的 ctags 程序。该怎么办？

装 Universal Ctags（https://ctags.io/）。按 Emacs 31.1 的 NEWS，Emacs 自带的旧 ctags 不再被编译和安装；想临时保留旧行为可以跑 etags --ctags，或者在 PATH 前面放一个名为 ctags 的 shell 脚本包一层。

五、官方手册怎么用：Ch i 实战

原书反复说「Emacs 手册是最权威的信息源」，但没细说怎么用。这一节把它讲透。

Ch i 调起的是 Info 阅读器——Emacs 内置的、超链接风格的在线文档系统。Emacs 自己、以及几乎所有装了的包，文档都以 Info 节点的形式装在你的电脑上。它和网页最大的不同是：断网也能用，而且可以用 Cs 在整本手册里搜。

按 Ch i 之后，Emacs 会先问你输一个手册名，直接回车就进主目录页。主目录页列出了你这个 Emacs 上所有可读的文档。常用操作：

  • n（Info-next）进到下一个节点；Tab（Info-next-reference）把光标移到下一个交叉引用（正文里形如 *note Foo:: 的那种跳转标记），MTab（Info-prev-reference）往回移一个。移到哪一行都按 RET（Info-follow-nearest-node）跟过去。
  • g 后面跟节点名回车（Info-goto-node）直接跳到那个节点，例如 g refruge-> 是本手册的章回列表、g (emacs) 回 Emacs 手册首页；f 后面跟交叉引用名（Info-follow-reference）则是专门跟正文里的 *note 引用。注意：在 Info 缓冲里 Cx Cf 仍然是全局的 find-file（打开文件），不是 Info 的跳转命令——这一点很容易记错。
  • t（Info-top-node）回到这本手册的目录页；l（Info-history-back）回到上一个节点，L（Info-history）再前进。
  • Cs（isearch-forward）向后增量搜索，Cr（isearch-backward）向前搜；s（Info-search）则是 Info 自己的跨整本文件搜索。Ms 从 Emacs 29 起不再是「向前搜」：它变成了一个前缀键，按下后再按 w / _ / . 才是按词、按符号、按光标处的词搜。
  • 节点名后面带 : 是跳转指令（node predicate，节点谓词），不带 : 是普通链接。

Emacs 手册的顶层节点（下面这张表我是从本机 Emacs 32.0.50 的 emacs.info 目录页逐条核对过的）里，有几个是你从头到尾都会反复用的：

除了 emacs 这一本，Ch i 还能读到成套的ref 系列手册。这些是以 ref 开头的「参考手册」系列，命名规则是取 Emacs 社区的技术委员会缩写，格式是「REF 是什么」——读法是把缩写当首字母缩写来念。这些手册不是 API 文档，而是规范与规范解释，适合解决「Emacs 到底约定什么」的问题：

  • refcard — 速查卡，一页纸的 Emacs 快捷键总表
  • refuge — 键位绑定（key binding，把某个键序列接到某个命令上）和keymap（按键到命令的查找表）的规范
  • refract — 正则表达式（regular expression，一种描述字符串模式的记法）的规范。Emacs 里的正则和别的语言不一样，这一本解释为什么
  • refface — face（外观属性，比如字体、粗体、前景色、背景色的集合）的规范。理解 face 是理解主题的前提
  • refcard / reftex — reftex 是 TeX 的引用管理工具，和 Emacs 主题无关，只是名字撞车

Emacs 之外最重要的两本是 elisp（Emacs Lisp 手册，学写 Elisp 的官方教材，在 Ch i 里输 elisp）和 org（Org 手册）。写 Elisp 的时候 elisp 手册是唯一该反复翻的东西——它有完整的节点结构：Introduction（概览）、Evaluation（求值）、Functions、Data Types、Sequences、Hash Tables、Customization、Major Modes、Text、Processes、Nonlocal Exits、Error Handling。

技巧

读 Info 手册的最好方式不是在手册里从第一页读到最后，而是把它当字典用：遇到一个不懂的命令就 Ch f，或者直接 Ch F（Info-goto-emacs-command-node）一键跳到手册里讲这个命令的那一节。Ch F 是比 Ch f 更省事的一招——它把「查命令」和「跳到手册」合成了一步。

练习 11　你想打开 Emacs 手册的主页而不必在 Ch i 的提示符里打 emacs。用哪一组键？

Ch r（info-emacs-manual）。另外 Ch i 然后直接回车进的是 Info 的总目录页，两者不完全一样：C-h r 直接落在 Emacs 手册的首页。

练习 12　你在写 Elisp，用到一个不认识的函数，想直接跳到 Emacs 手册里讲它的那一节。用哪一组键？

Ch F（Info-goto-emacs-command-node），然后输入函数名。它会直接在 Info 里定位到对应的节点，而不是只弹一个描述窗口。

六、社区：去哪儿问、去哪儿读

原书列的社区清单大部分还活着，但重心变了。下面按「我想问一个问题」和「我想读点东西」分开。

6.1 提问的地方

  • Emacs StackExchange — https://emacs.stackexchange.com/。提问质量最高的地方，规矩是「问之前先自己查过」，答案通常带可运行的配置片段。想让别人认真回答你的配置问题，这里是首选。
  • Reddit r/emacs — r/emacs。日常讨论、发包链接、问「你们怎么配的」。氛围比 StackExchange 松，答案质量方差大，但翻历史能挖到很多东西。还有细分版块，比如 r/orgmode。
  • Emacs IRC / Matrix — 官方的 #emacs 频道（IRC 和 Matrix 都有）。适合问「这个问题该怎么问」这种元问题，以及被卡住时的实时救助。
要点

提一个好问题的模板几乎总是这三行：(1) 你的 Emacs 版本（Ch Ca 抄）；(2) 你的最小复现配置（从 init.el 里把相关的几行贴出来，隐去个人信息）；(3) 你期望什么、实际发生什么，最好有报错原文。少了版本号，对方给的答案有一半概率对你的 Emacs 不成立——这是 Emacs 社区问题里最常见的失败原因，也正是本书反复强调版本差异的原因。

6.2 读的地方

  • Emacs Wiki — https://www.emacswiki.org/。这是 Emacs 世界的维基，任何人可编辑。它的强项是「怎么用某项内置功能」的实用配方，弱项是没有版本标注（一个 2015 年的配方在 2026 年可能已经不成立），所以读的时候要交叉验证。
  • Planet Emacs — https://planet.emacslife.com/。Emacs 博客的 RSS 聚合器，一页看完社区所有活跃博客。原书推荐的几个博客大多能从这里读到。
  • 原书作者的博客 — https://www.masteringemacs.org/。Eli Spare 写的深度文章，IDDO 和 Eshell 那两块在书里只提了一句，细节在那儿。
  • 包的官方文档：任何第三方包，先 Ch P 看它有没有随包附带的 Info 手册。有手册的包和没手册的包，可靠程度差一个量级。
易错

读 Emacs 博客和社区帖子时养成一个习惯：看一眼这条内容的日期，以及它说的 Emacs 版本。Emacs 的社区内容衰减得比一般技术博客快得多——2020 年写「配置 vertico 和 consult」的帖子在 2026 年基本还成立（因为这些包还活着），但 2020 年写「配置 ido」或者「用 package-archive-alist」的帖子会直接把你带进沟里。这本书能做的最好的防护，就是在每个技术断言旁边标清版本。

练习 13　你在 StackExchange 上贴了一个配置片段求帮助，结果没人回。三条最该补充的信息是什么？

(1) 你的 Emacs 版本（Ch Ca 抄，注意要写 30.2 还是 31.1 这种小版本）；(2) 最小复现配置——把你 init.el 里跟问题相关的几行原样贴出来，隐去路径、邮箱、token；(3) 期望行为与实际行为的对照，有报错就把原文贴上。Emacs 的答案对版本极其敏感，缺了第一条，对面回的方案有一半可能在你这儿跑不通。

七、一条具体的四周学习路线

「读完这本书之后干什么」是个真问题。这里给一条能立刻执行的路线，每周一个主题，每周末有明确的验收标准。默认你已经有了一个能启动的 Emacs 和一份能用的 init.el（这是本书第 13 章的内容）。

第 1 周：把「问 Emacs」变成肌肉记忆

  1. 把 Ch k、Ch c、Ch f、Ch v、Ch m、Ch b 这六个键打印出来贴在显示器边上。
  2. 每天用 Emacs 写任何东西时，遇到一个不认识的键就立刻问，问完在纸上记一笔——一条笔记只需要三行：我按了什么 / 它跑了什么命令 / 这个命令干什么用。
  3. 周末验收：笔记满 30 条，而且你现在能不查任何资料说出 Cx s、Cx f、Cg、M- 各自干什么。

第 2 周：把官方手册变成日常工具

  1. 用 Ch r 打开 Emacs 手册，从目录页跳进 Help、Keys、M-x 三个节点，各读十分钟。
  2. 养成一个动作：任何时候 Ch f 看完描述之后，追加按一次 Ch F 跳到手册对应节点。多这一步，你会从「知道有这个命令」升级到「知道这个命令在什么场景下用、和哪些命令搭配」。
  3. 用 Ch n 读一遍你当前版本的 NEWS。重点看「Incompatible Changes」那一节——这一节列的就是会打破你现有配置的变化。
  4. 周末验收：能说出你当前版本相对上一个版本，有哪三条对你有影响。

第 3 周：补上生态的三个缺口

  1. 先补 Git。装 Magit（Mx package-install RET magit RET，装完重启 Emacs），在一个已经是 git 仓库的目录里按 Mx magit-status RET 打开状态面板（等价写法就三个字母 magit）。然后花一个小时只学这十个单字母键——注意全部是单字母、没有和弦，3.2 节那个易错框解释了为什么：

    • ?（magit-dispatch）——先学这一个。它是 Magit 的命令速查菜单，忘了别的键就按它，然后搜命令名。有了它，其余九个键就变成「慢慢记」而不是「必须背」。
    • g（magit-refresh）—— 刷新面板（在编辑器里改了文件之后必按）。
    • s（magit-stage-files）—— 把当前改动暂存（对应 Git 的 git add）。
    • u（magit-unstage-files）—— 取消暂存。取消暂存是 u，不是 k——老文章里那个 g k 在 Magit 4 上压根不存在。
    • c（magit-commit）—— 提交。
    • l（magit-log）—— 看提交历史（连按两下 l 是 magit-log-current，只看当前分支）。
    • b（magit-branch）—— 分支操作（切分支、建分支都在这儿）。
    • d（magit-diff）—— 看当前改动。
    • p（magit-push）—— 推送。
    • q（magit-mode-bury-buffer）—— 收起面板，回到编辑。

    这十个键加上 ?，覆盖日常绝大多数 Git 操作。只有一种情况才需要 Mx magit-init RET：你正处在一个还没 git init 的新目录里。它的文档字符串是 “Initialize a Git repository, then show its status.”——「建仓库」，不是「装 Magit」，也不是「初始化 Magit」，这是三件不同的事，别混。

  2. 再补语言服务。如果你写代码，配好 eglot-server-programs，然后用 M. 跳一次定义、用一次自动补全、故意打一个语法错误看诊断。
  3. 最后补弹出面。Magit 本身就是 transient 面板的最佳教材。Magit 熟了之后，你已经会用 transient 了；Magit 自己的 Info 手册（Ch i m a g i t）就是最好的教材。
  4. 周末验收：在一个真实项目里，完成「改代码 → 看诊断 → 跳定义 → git add → git commit」全程不离开 Emacs。

第 4 周：写你的第一段 Elisp

  1. 做一件小事：把一个你已经问过三次 Emacs 的问题，固化成一条配置。比如「我总是想在保存时自动删掉行尾空格」，就写：(setq-default show-trailing-whitespace t) 加一个 after-save-hook。或者「我总觉得光标太细」，就定制 cursor-type。
  2. 用 Ch i 打开 elisp 手册，只读 Introduction 和 Evaluation 两个节点。
  3. 学会检查自己写的 Elisp：M- checkdoc- 后面补全，选 checkdoc-current-buffer。它会检查文档字符串格式、参数顺序、文件尾换行这些风格问题——这些是 Emacs 社区评审 Elisp 的硬性要求。
  4. 周末验收：你写的那段配置，checkdoc 不报错，并且你能用一句话向别人解释它为什么这么写。
技巧

四周之后不要停。最好的下一步是：去读一个你正在用的第三方包的源码——不用全读，就读它的 ;;; Commentary: 段落和文件末尾的 ;;;###autoload 标记。看完你会发现，这些包的源码写得和 Emacs 官方代码一个风格，那份风格就是 Emacs 社区对 Elisp 的规范。写出符合规范的 Elisp，比写出「能跑」的 Elisp 重要得多，因为前者别人愿意读、愿意合并进你的配置。

练习 14　下面三个动作分别对应这条路线里的哪一周？（A）读一遍当前版本的 NEWS 的「Incompatible Changes」；（B）花一小时只学 Magit 的十个单字母键；（C）用 checkdoc-current-buffer 检查自己写的第一段 Elisp。

(A) 属于第 2 周（用 Ch n，前缀 Cu 可以缩小到某个版本）；(B) 属于第 3 周，装好 Magit 后在一个 git 仓库目录里用 Mx magit-status（或三个字母的 magit）打开状态面板；(C) 属于第 4 周，用 M- checkdoc- RET 调到 checkdoc-current-buffer。

结语

回到本章开头那个被引用的话：Emacs 是地面，我们在上面做各种事。这句话的准确含义是——你永远不会走到「已经学完了」那个点，因为地面本身一直在长。本书写的是截至原书出版时地面上的样子；今天你手上的 Emacs 30.2 或 31.1、Magit 4.x、Consult 3.x、Corfu、VertiCo，比原书那时候又长出了一大片。

但这恰恰是原书那句话最值得反复读的地方。地面在长，问路的方式没变。Ch k 在 Emacs 26 上是什么答案，今天在 Emacs 32 上还是什么答案——甚至更完整，因为 Emacs 31 会在 Ch v 的时候额外提醒你该用 setopt。二十多年过去，Emacs 唯一没变的是它对自己完全透明。

这就是本书真正的结尾：不是「你现在会 200 个按键了」，而是「你现在知道怎么让 Emacs 告诉你它会什么」。后者永远不会过期。
