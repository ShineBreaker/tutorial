八、编辑理论（三）：键盘宏、文本展开、缩进、排序对齐

前两章的编辑动作都是一次性的：这一次你按了十一次键，下一次还得再按十一次。这一章讲 Emacs 真正开始替你干活的地方。键盘宏让你把手工操作录下来、反复回放、绑键、最后改写成写进配置文件的 Elisp；文本展开（abbrev、hippie-expand、代码片段）让你少打字；缩进、排序、对齐把格式交给程序而不是手指。读完这一章，你手上有第一个属于自己的 Emacs 工具。

要点

本章的命令与默认值，除非特别标注，都是我在本机 Emacs 32.0.50（emacs-next 开发版）上用 emacs --batch -Q 实测绑定与变量值得到的。凡原书写错或今天的 Emacs 已改的地方，当场标出；凡我查不到的，也当场说明。

本章地图

  1. 键盘宏：F3 F4 起步，C-x C-k 前缀是控制室，M-x insert-kbd-macro 把宏变成 Elisp。
  2. 文本展开：abbrev、dabbrev、hippie-expand、YASnippet、skeleton、autoinsert。
  3. 缩进：TAB 到底做了什么，区域怎么缩进，制表符怎么换空格。
  4. 排序：sort.el 的七个命令，含处理 CSV 的 M-x sort-regexp-fields。
  5. 对齐：align.el 的五条命令，以及做数据表该用的 table.el 与矩形。
  6. 零碎但有用的命令：Mz（按字符删）、M$ 与 Flyspell（拼写）、C-q（字面插入控制字符）。

一、键盘宏：Emacs 的「录下来，再替你做」

1.1 这是什么，为什么它值钱

键盘宏（keyboard macro）就是把一串按键与命令记录下来、之后原样或带参数重复执行。先和 Elisp 宏（macro，一个求值时展开的 Lisp 模板）划清界限——两者除了名字像，毫无关系。Emacs 里它对应的函数基本都以 kmacro- 开头（kmacro = keyboard macro 的缩写）。

多数编辑器都有「录制宏」，Emacs 的特殊之处是几乎一切都能录：它记录的是「触发了哪个命令、修饰键与参数是什么」，不是死字符。所以你可以在录制中用 M-x 调任意命令、用 query-replace（第六章）做带确认的替换、甚至嵌套调用另一个宏——这是后文「把宏改写成 Elisp」的底气。

要点

Cg 在今天的 Emacs 里绑的命令叫 keyboard-quit，不是 quit。老手册（包括原书）写「C-g（quit）」——quit 这个命令在 32.0.50 上已经不存在，(fboundp 'quit) 返回 nil。这不影响使用：Cg 的作用没变，只是它现在跑的命令换了名字。

1.2 最小闭环

  1. 光标放到目标位置，按 F3。模式行（mode line，底部显示文件名与模式名的那一行）右侧出现 Def，表示正在定义宏。
  2. 像平时一样做你的编辑。
  3. 按 F4。宏被结束、存进宏环，并立刻在光标处执行一遍。
  4. 继续按 F4，每按一次执行一遍。

想知道宏被录成了什么？在 F4 之前执行 M-x edit-kbd-macro，它开一个临时 buffer，按「一行一个命令调用」的格式打印宏——例如 (forward-line 1)、(insert "foo")。

易错

录制中按 Cg 会中止录制；回放中任何错误（signal error）也会自动停止。最常见的误报是 Mg Mn / Mg Mp（next-error / previous-error，跳到下/上一个错误）——到了错误列表末尾就报错。这其实是特性：录一个调用 next-error 的宏，再反复回放，它会在列表走完时自己停下。

1.3 前缀参数：让同一个宏干不同的活

  • Cu F3：追加到上一个宏末尾。录到一半发现少一步时最舒服。
  • Cu F4：回放宏环里的第二个宏（内部调用 kmacro-call-ring-2nd）。我逐个版本核对过：Emacs 26.3、28.2、29.4、30.2 到 32.0.50 一路都是这个行为，从没变过。
  • Cx Ck Ct（kmacro-swap-ring）才是交换宏环头两个元素。没有哪个版本的 Cu F4 能做这件事。
  • M-3 F4：把宏执行 3 遍。
  • M-5 F3：开始录制并把计数器初值设为 5。
  • M-0 F4（或 Cu 0 F4）：一直重复到出错为止。跑到缓冲区末尾、或第一行不匹配时自动停。
技巧

「跑到出错为止」在批处理里极常用：先用 C-x r m（rgrep，跨文件递归 grep）找出待改文件，在 *grep* buffer 里录一个只改一行的宏，然后 M-0 F4 一次跑完整个列表。

1.4 宏环

Emacs 有好几样这样的环形历史：kill ring（第六章）、撤销历史、minibuffer 历史。宏环（macro ring）属于同一类——每录一个新宏，旧宏自动往后排，不会丢。环长由 kmacro-ring-max 控制，默认 8。环只活在内存里，退出 Emacs 就没有了；要长期保存见 1.8。

1.5 计数器：让宏自动编号

开始录制时计数器初始化为 0。录制中每次按 F3，插入当前值并加一；回放时每次都插入并递增同一个计数器。下面这个例子把「初值」和「增量」分开演示：

M-5 F3  x  M-2 F3  y  F4  F4  F4  F4
插入结果：  x5yx7yx9yx11y

读法：M-5 F3 设初值 5；输入 x；M-2 F3 插入 5 并把计数器 +2（变 7）；输入 y；F4 结束并执行，再按三次，每次插入当前值再 +2，于是得到 5、7、9、11。计数器只在两种情况下重置：你显式设置它，或开始录一个新宏；多次回放之间它是保持的。

  • Cx Ck Ca（kmacro-add-counter）：给计数器加一个数，给负数即减。
  • Cx Ck Cc（kmacro-set-counter）：直接设成某值，不是相对增减。
  • Cx Ck Ci（kmacro-insert-counter）：插入计数器并加一。
  • Cx Ck Cf（kmacro-set-format）：给计数器设格式串（format string，一种用 %d、%05d 描述输出形状的字符串，M-h f 看说明）。%05d 打成 00007，item-%d 打成 item-7。提示时不必自己加引号。
易错

原书写「C-x C-k TAB 插入计数器」，这是对的，但要知道原因：Emacs 键记法里 TAB 与 C-i 是同一个字符（ASCII 9），键表里实际登记的是 C-i 那一项，所以 M-x 查帮助显示的是 kmacro-insert-counter 挂在 Ci 上。两种敲法完全等价。

另一个坑：给 C-x C-k C-i 或 F3 加 C-u，插入的是上一次的数字且不递增，连续插入同一编号时用得上。

进阶：计数器与寄存器联动（Emacs 30 新增，极冷门）

原书成书时这批命令还没有，现在都在 kmacro-keymap 里（我读过 lisp/kmacro.el 的键表定义）：C-x C-k C-r s（kmacro-reg-save-counter，存进寄存器）、C-r l（kmacro-reg-load-counter，用寄存器设计数器）、C-r a = / < / >（kmacro-reg-add-counter-equal / -less / -greater，比较寄存器与计数器后按前缀增量相加）；C-q = / < / >（kmacro-quit-counter-equal / -less / -greater，比较计数器与前缀值，成立就终止宏，用来写「编号到 20 就停」的循环）。这两组是同一个版本进来的：我拉了 Emacs 29.4 与 30.2 的 lisp/kmacro.el 对比，29.4 里一个都没有，30.2 里八条齐全，都是 Emacs 30。

坦白说这些极少有人用，因为绝大多数需求用 C-u 0 F4（跑到出错为止）就够了。真需要按数值终止，直接写 Elisp 宏比记这些键划算。

1.7 查看与逐条编辑

录错了可以像改文本一样改宏。Emacs 把宏摊开在临时 buffer 里，每行一个「命令调用」，可增删改，最后 C-c C-c 提交。

  • C-x C-k e（kmacro-edit-macro-repeat）或 RET：编辑当前宏，连按可切换宏环里的宏。
  • C-x C-k SPC（kmacro-step-edit-macro）：逐条单步编辑——宏一步一步回放，每步停下来问你是保留还是跳过。调试「宏到底做了什么」的最佳工具。
  • C-x C-k l（kmacro-edit-lossage）：事后追认。Emacs 一直记着你最近 300 次按键（lossage），从这段历史挑一段直接做成宏，不必重新演示。原始列表按 C-h l（view-lossage）。
易错

lossage 记录你敲过的每一个字符，包括密码。执行 M-x open-dribble-file 会把全部击键原样写进文件，Emacs 不会替你过滤。

另外 lossage 显示的是「当时那个 buffer、那个模式下」的键义。同一个键在不同 major mode 里可能触发不同命令，脱离原环境查键位时别被骗。

1.8 命名、绑键、落盘：从「会用」到「会造工具」

要让宏活过重启，走三步：命名 → 生成代码 → 写进配置并重载。

  1. 命名：C-x C-k n（kmacro-name-last-macro），给它一个名字。必须先命名，下一步才能生成可读代码。
  2. 生成代码：把光标放进 Emacs 配置文件（Emacs 28 起默认 ~/.emacs；用 use-package 的现代配置通常在 init.el 或某个模块里），执行 M-x insert-kbd-macro，输入刚才的名字，它会插入一小段可执行的 Elisp。
  3. 重载：在配置里执行 M-x eval-buffer 或 M-x load-file，或重启 Emacs。
(fset 'my-insert-date
      (kmacro "..."))   ; insert-kbd-macro 生成的字符串
要点

(fset '名字 (kmacro "...")) 这个写法是 Emacs 29 起的：29 的 NEWS 写明键盘宏改成了 OClosure，新增构造器 kmacro（用 key-parse 语法），取代旧的 kmacro-lambda-form。你在 Emacs 29 及更新的版本里看到的就是上面这种；老文章里那种 (fset 'x (kmacro-lambda-form [...])) 不用再抄了。

易错

很多人（包括大量中文教程）会说「用 M-x kmacro-to-elisp 把宏转成 Elisp」。Emacs 里没有这个命令。我在本机 32.0.50 的完整 lisp 源码树与 loaddefs.el 里都 grep 不到 kmacro-to-elisp 这个符号，运行时 (fboundp 'kmacro-to-elisp) 也是 nil。正确的是上面两个：edit-kbd-macro（编辑并可交互回放）与 insert-kbd-macro（往当前 buffer 插入 (fset ... (kmacro ...))）。想存进寄存器用 C-x C-k x（kmacro-to-register）。

C-x C-k b（kmacro-bind-to-key）能把最近一个宏临时绑到一个键上，只在本次会话有效。想试手感用它，想长期用走命名那条路。

技巧

命名有讲究：起完名它就是一个真正的 Emacs 命令，会和其他命令一起出现在 M-x 补全面板里。Elisp 符号不能有空格，但几乎所有其他字符都行。原书作者用自己名字缩写打头（比如 mp-），以后按 C-h a 输入 mp- 就能列出自己造的全部命令。这个习惯值得抄。

1.9 询问点：让宏在关键处停下来问你

有些判断没法自动化。录制时按 C-x C-k q（等价键 C-x q，命令 kbd-macro-query）插入一个询问点。回放到这里宏会暂停，在 minibuffer（底部那行小输入区）问你。

本节按键：询问点的回答方式

按键含义在「反复回放」模式下的效果
y照常继续这一条按宏的既定步骤做完，然后跑下一条
n 或 DEL跳过本轮剩余部分回到宏开头，继续下一条
RET彻底停止整个宏与后续循环全部结束

这三个回答的语义要分清：在 M-0 F4 这种循环里，n 只跳过这一条并回到宏开头继续下一条，y 是「这一条就这么办」，RET 才让整个循环停下。

进阶：递归编辑——Emacs 最被低估的功能

递归编辑指：在某个正在执行的复杂命令（Isearch、query-replace、宏回放）中途按 C-r，把这个命令挂起，控制权交还给你。你此时可以像平时一样自由编辑，甚至再录一个宏；做完按 C-M-c 退出，Emacs 立刻弹回现场继续原命令。可以嵌套多层；身处其中时模式行的模式名会被方括号括起来；连按三次 ESC 强行退出所有层；C-g 不能退出递归编辑——这点跟它在别处都不一样。

实战价值：宏跑着跑着你发现某一行要手工大改。与其 C-g 掐了重来，不如 C-r 进去改完 C-M-c 出来。更妙的是 Emacs 允许你在递归编辑里录制和回放另一个宏——一个宏做大范围重排，另一个做精细收尾。minibuffer 本身也是 buffer，所以「在询问提示里递归编辑、改掉默认提示、再回来」同样可行。这正体现了 Emacs 的概念循环复用：同一个 buffer 抽象，既是文件，也是命令行输入框，也是递归编辑的暂存地。

1.10 实战组合

  1. 窗口布局：想每次按同一方式打开四个文件？先按 C-x 1（delete-other-windows）留出干净底子，然后开始录制，依次 C-x C-f 打开、C-x 3 分屏、C-x b 切 buffer，结束录制。以后按 F4 一键复原整套布局——这招能把「复杂的窗口编排」变成一个键，而编排本身不需要你会任何 Elisp。
  2. 批量改文件：M-x rgrep 找出待改文件 → 在 *grep* buffer 里开始录制 → M-g M-n 跳到第一条匹配 → 做替换 → 结束录制。之后每按一次 F4 处理一条。这个模式是通用的：occur、M-x compile 的错误列表，凡是产出「可用 M-g M-n 遍历的列表」的功能都能套。
  3. 对区域每一行做同一件事：选一块文本，C-x C-k r（apply-macro-to-region-lines）把宏对每行各跑一遍，比 M-0 F4 精确，不会跑过头。
  4. 用鼠标回放：默认 S-鼠标3（变量 kmacro-call-mouse-event）会在点击位置设置 point 并执行最近一个宏。
要点

Emacs 30 新增 M-x list-keyboard-macros（kmacro-menu-mode 的入口）：列出当前所有键盘宏，在那个 buffer 里可以重排宏环顺序、复制、删除，甚至编辑它们的计数器、格式与绑定键。想要「键盘宏仪表盘」，命令就是它。

练习 1　你录好一个「在当前行前面加 - [ ] 」的宏。现在想对选中的 40 行统一加前缀，用 C-x C-k 下的哪个命令？

Cx Ck r（apply-macro-to-region-lines）。它把宏对区域的每一行各执行一遍，比 M-0 F4 精确。

练习 2　想把录好的宏变成能写进 init.el 的 Elisp 代码，用哪个命令？（提示：不是 kmacro-to-elisp）

先 C-x C-k n 给宏命名，再执行 M-x insert-kbd-macro 并输入这个名字，它会插入 (fset '名字 (kmacro ...))。Emacs 里没有 kmacro-to-elisp——32.0.50 的 lisp 源码树与 loaddefs 里都 grep 不到它，(fboundp 'kmacro-to-elisp) 为 nil。

练习 3　录制宏时想在「这行有 FIXME 就停下来问我」的分支上插一个询问点，按哪组键？

Cx Ck q，等价键 Cx q，命令 kbd-macro-query。回放时宏停在这里，在 minibuffer 里等 y / n / RET。

练习 4　按 M-5 F3、输入 x、M-2 F3、输入 y，再按四次 F4，buffer 里会得到什么？

结果为 x5yx7yx9yx11y。M-5 F3 把计数器初值设为 5；M-2 F3 插入 5 并让计数器 +2（变 7）；之后每按一次 F4 插入当前值再 +2，依次 7、9、11。

练习 5　你刚才手打了一遍正确操作，现在想直接把它变成宏而不重录，用哪个命令？

C-x C-k l（kmacro-edit-lossage）。Emacs 一直记着最近 300 次按键，这个命令让你从历史里挑一段直接做成宏。原始列表按 C-h l 查看。

练习 6　宏带着询问点在 M-0 F4 的循环里跑。你想「这一条跳过、但继续跑剩下的」，按哪个键？想让整个循环停下呢？

跳过当前这一轮按 n（或 DEL）——宏回到开头做下一轮；y 是「这一条照常做」；RET 才会彻底停止整个宏与后续循环。

Emacs 里有好几套「输入固定文本」的机制，目标相同、打法不同。先建立坐标系，再逐个上手。

2.1 abbrev：安静、即时、也最容易惹祸

abbrev（abbreviation，缩写）是你输入某个短词后 Emacs 悄悄把它换成长词的机制。最大优点是安静——不弹窗、不出补全列表、没有视觉噪音，你多半注意不到它发生了。适合的场景是纠错和少量固定词替换：teh → the、recieve → receive、resume → résumé。

易错

abbrev 的定义方向非常反直觉，Emacs 老用户也常在这里卡住：用 C-x a g 时，Emacs 拿光标前面那个词当展开结果，让你输入的是触发词。所以想把 resume 变成 résumé，正确做法是先打出 résumé、把光标放到词尾，再按 C-x a g，输入 resume。之后每次敲 resume 再敲一个分隔符（空格、回车、) 等）就自动替换。

「反向」命令方向是顺着直觉的：先打出触发词 resume，按 C-x a i g，再输入展开结果 résumé。刚上手用反向命令，别用正向命令。

要用 abbrev 做代码补全，得先想清两笔账：

  • 按键开销：定义一条要花 C-x a g 加上输入缩写和结果；使用虽「免费」（自动展开），但你打字时不能真的打出那个词，否则会被提前展开。以 M-x 这类高频长词为例，省下的手指未必抵得上心智负担。
  • 全局污染：add-global-abbrev 的缩写在所有 buffer 生效，包括别人的文件、邮件、密码字段。用得太宽就会出现「我想打 as，结果变成 assert」这类事故。凡是跟代码词法相关的缩写，都用 C-x a l 限定在当前 major mode。

还有个隐形的坑：abbrev 的展开点会跟随光标移动。你打完触发词后往回改别处，Emacs 有时不会重新展开。所以 abbrev 只适合「打完就走」的短词，不要指望它像 hippie-expand 那样能来回试。

2.2 dabbrev 与 hippie-expand：M/ 的两种命运

dabbrev（动态缩写）扫描当前 buffer 里已经出现过的词，补全光标处那个词：M/（dabbrev-expand）补全一个候选，再按一次换下一个，按到头会绕回原词；C-M/（dabbrev-completion）先尽力补全最长的一段，仍有多个候选就把它们列出来让你选。局限很直白：只认当前 buffer、只认词——文件刚新建是空的，它什么也给不了。

hippie-expand 是 Emacs 内置的、功能强得多的替代品（hippie-exp.el）。它把一串「尝试函数」按顺序试一遍，谁先成功用谁；顺序由变量 hippie-expand-try-functions-list 决定，我在 32.0.50 上读到的默认值是：

(try-complete-file-name-partially try-complete-file-name
 try-expand-all-abbrevs try-expand-list try-expand-line
 try-expand-dabbrev try-expand-dabbrev-all-buffers
 try-expand-dabbrev-from-kill
 try-complete-lisp-symbol-partially try-complete-lisp-symbol)

换成白话：先试文件名 / 目录路径 → 试 abbrev → 试列表 → 试整行 → 再退回 dabbrev → 最后试 Elisp 符号。你只需打出前缀，Emacs 自己猜你在写什么。

技巧

hippie-expand 最被低估的是文件名补全：在文档、配置、注释里写路径时，打出前缀按 M/，它像 shell 的 TAB 一样把绝对/相对路径补完整。其次是整行补全：代码里写过一次的样板行，下次打头几个字就能整行拉回来。写 Elisp 时它还会认出符号并补全。替换默认做法的写法：

(global-set-key (kbd "M-/") #'hippie-expand)

保留两者共存也行，但抢同一个键位，二选一更省事。M/ 还有一个缺点：C-M/ 那个「列出候选」的变体只对 dabbrev 有效，hippie-expand 没有对应版本，候选列表只能在回显里逐个读。

想知道有哪些可用的尝试函数，两种办法：M-h f 描述 hippie-expand，Emacs 会告诉你在哪个库里，再 M-x find-library 读注释；或用 M-x apropos-function 按名字前缀搜。两种都做一遍最好——注释经常过期，按名字搜又要求你先知道大概叫什么。

2.3 YASnippet、skeleton、autoinsert：模板类工具

YASnippet 是第三方包（Emacs 的 GNU ELPA——也就是内置 package-archives 里的默认仓库——以及 MELPA、NONGNU 都有，维护者 Joao Távora，仓库 github.com/joaotavora/yasnippet）。M-x package-install yasnippet 之后执行 M-x yas-global-mode 启用。模型接近编辑器 TextMate 的 snippet：用简单的模板语言定义片段，用 tab 或空格触发，展开成带「跳板」的可编辑模板。写 C / Java / JS / Go 的人几乎人手一份。

skeleton 是内置（skeleton.el）的模板系统：M-x define-skeleton 能把一段填空式模板定义成一个命令。它二十多年来一直在 Emacs 里但用的人很少——因为要会一点 Elisp 才用得舒服，模板语法（&n、?\n、> 回跳）不直观。今天想走「Elisp 路线」可以试，想省时间就上 YASnippet。

auto-insert（autoinsert.el）解决另一个问题：新建文件时自动铺一段样板。开关是 M-x auto-insert-mode——注意命令名中间有连字符，autoinsert-mode 这样的写法不是 Emacs 的符号，会报 void-function。打开后，新建 foo.html 会在开头自动插上 <html>、<head> 那一堆。规则表由变量 auto-insert-alist 控制（按文件名后缀或 major mode 匹配，本机 32.0.50 上默认有 13 条）。另外两个变量分工要分清：auto-insert-query 的含义是「非 nil 就先问用户要不要插」，本机默认值是符号 function，意思是只在被非交互方式调用时才问（比如从 hook 里触发），你亲手 M-x auto-insert 则直接插；auto-insert 控制插完之后算不算「文件已被修改」，本机默认是 not-modified——样板插进去了，但保存时不会问你「文件已改变，是否保存」。

易错

网上（包括一些中文 Emacs 教程）推荐的两个东西，本书经查证要修正。

其一，text-skeleton-mode 不是 Emacs / Org 自带的命令。我在 Emacs 28.2、29.4、30.2、31.1 以及本机 32.0.50 的完整 lisp 源码树里 grep text-skeleton，结果都是零——skeleton.el、org.el、org-list.el 都没有这个符号，M-x text-skeleton-mode 会直接报 void-function。想要 Org 里的「填表式列表」体验，用 Org 自己的列表功能（命令是 M-x org-toggle-item，样式规则由 org-list-indent-offset、org-list-automatic-rules 这一组 org-list-* 变量控制）。

其二，expand-region-function 也不是 Emacs 的变量。32.0.50 里 (boundp 'expand-region-function) 是 nil，官方手册与 lisp/ 源码树里也找不到它（只有早年的第三方包会来设它）。「智能扩展选区」是一个独立的第三方包，名字就叫 expand-region（github.com/magnars/expand-region.el，作者 Magnar Sveen），GNU ELPA 与 MELPA 都收录了，装上之后不用设任何 Emacs 变量，直接把它的命令绑到你要的键上即可：

(global-set-key (kbd "C-=") #'er/expand-region)

（同一作者还给了 er/contract-region，按负的前缀参数 C-- C-= 收缩选区。）网上把作者写成 stenaro 的说法是张冠李戴。

三、缩进：Emacs 怎么知道该缩进多少

Emacs 的缩进不是「按一个键插入若干空格」，而是把判断权交给当前 major mode。每种语言、每个模式有自己的缩进引擎；Emacs 也提供几套通用引擎供新模式继承。

3.1 electric indentation（电缩进）

Emacs 24.4 起，回车就会自动缩进到与上一行相同的列，这叫 electric indentation，由 minor mode electric-indent-mode 控制，各语言模式默认开启（我在 emacs-lisp-mode 下读到它是 t）。官方手册的措辞是「This mode is enabled by default」；24.4 的 NEWS 记着「'electric-indent-mode' is now enabled by default」——它不是 Emacs 29 才开的开关，比那早得多，Elisp 24.1 就有了这个模式，24.4 开始默认打开。要按 buffer 单独开关用 M-x electric-indent-local-mode，要全局开关用 M-x electric-indent-mode。

3.2 TAB 到底做了什么

TAB 触发的是 indent-for-tab-command——一个通用代理命令：它自己不做缩进，而是把活派给当前模式注册的 indent-line-function。我实测的结果：text-mode 与 fundamental-mode（新建空 buffer 的默认模式）下它是 indent-relative（简单插一个制表符）；emacs-lisp-mode 下是 lisp-indent-line（真正按括号结构缩进）。

有些模式会覆盖 TAB，直接绑自己的缩进命令（C 语言的 c-mode 是典型）。所以 TAB 的行为随 buffer 变——同一个键，在 Markdown 里插一个 Tab，在 Lisp 里重排整个缩进层级。控制这个分歧的变量是 tab-always-indent，默认为 t；设为 nil 时，Emacs 判断「当前行已经缩进够了」就只插入一个真正的制表符，不再重排。

3.3 用空格还是制表符，以及缩进宽度

  • indent-tabs-mode：是否用真正的制表符字符缩进。本机 32.0.50 默认 t。想要空格就 M-x 后输入它回车切换。对语言文件通常需要设成 nil 并把 tab-width 设成 2 或 4。
  • tab-width：每个缩进层级占多少列，默认 8。即使关掉制表符，这个宽度仍决定缩进量。它只是「显示宽度」约定，不会把文件里的制表符改写成空格——真要把制表符批量转成空格（反之亦然），用 M-x untabify 与 M-x tabify，它们作用于选区（这两个命令在 tabify.el 里，注意名字里没有 -buffer）。
  • M-i 与 M-x edit-tab-stops：Emacs 支持传统行编辑器的「制表停止点」，edit-tab-stops 让你在行的合适位置插 :，之后 M-i 按这些点跳。今天基本只在你手写 Makefile 这类需要精确制表符对齐的文件时才有用。

3.4 区域缩进

单行缩进简单，区域缩进麻烦——有些语言的缩进有语义（Python 里缩进决定代码块，重缩进可能直接改变程序含义）。所以 Emacs 给了两条性质不同的路：

  • 智能路径：选一块文本按 C-M \（indent-region），Emacs 问当前模式「这段该怎么缩进」，对 HTML、C 等缩进无关语言效果好，对 Python 有风险。给它一个数字前缀，会把区域缩进到指定列，并尊重你的 fill prefix（fill-prefix，每行自动加的前缀，缩进式排版里很有用）。
  • 硬缩进路径：C-x TAB（indent-rigidly）只做纯粹的列平移，不管语言语义；正数右移、负数左移。
技巧

C-x TAB 不加任何参数会进入交互式缩进模式：之后用 S-left 和 S-right 一行行左右推区域，单独按 left / right 也能推，TAB 也被绑定成「整块右移一列」。注意这个模式没有「RET 确认、ESC 取消」这回事——indent-rigidly 的文档写的是「Typing any other key exits this mode, and this key is then acted upon as normally」：你按下的第一个「别的键」会先结束这个模式，然后照常执行。想干净地退出，按一个你不打算让它生效的键，或者按 ESC（它会以前缀键的身份把后续输入变成一条命令）。想手工把一段代码挪 2 列，带数字前缀最省事：M-2 然后 C-x TAB 右移两列，M--2 则左移。另外，选区存在时直接按 TAB，Emacs 会尝试用当前模式重排整个选区——但不要指望它在所有语言里都聪明，尤其 Python。

练习 10　同一个 Emacs 里，text-mode 和 emacs-lisp-mode 按 TAB 结果完全不同。决定这个差异的变量是哪个？

indent-line-function。TAB 触发的是通用代理命令 indent-for-tab-command，它把活派给这个变量指向的函数。我实测：text-mode 下是 indent-relative（只插一个制表符），emacs-lisp-mode 下是 lisp-indent-line（按括号重排）。

练习 11　选中一段 Python 代码，想把它整体右移两列（不改变缩进语义），用哪个命令？

C-x TAB（indent-rigidly），硬缩进只做列平移不管语言语义，负数左移。不要用 C-M \（indent-region）——它按模式规则重排，在 Python 里可能改变程序含义。

sort-fields 与 sort-numeric-fields 是这一节最容易敲错的前缀。sort-fields 的源码里交互规格写的是 (interactive "p\nr")（p = 原样取前缀数字），函数文档也写明「With a negative arg, sorts by the ARGth field counted from the right」——它拿前缀数字当列号用，从来不拿它当反向开关；它内部调用 sort-fields-1 时传给 sort-subr 的 reverse 参数写死是 nil（永远升序）。我实测 (sort-fields -2) 处理 a 3 / b 1 / c 2，输出原封不动。真要降序排字段，唯一办法是排完再用 M-x reverse-region 翻过来（官方手册也是这么建议的）。

另一个实用细节，跟常见说法相反：M-x sort-lines 不会去调用系统的 sort 程序，它一直在 Emacs 内部用 sort-subr 排。我拉了 Emacs 24.4、25.3、26.3、27.2、28.2、29.4、30.2 的 lisp/sort.el 逐个 grep，sort-buffer 这个外部-sort 入口一次都没出现过；原书与很多中文教程说的「非 Windows 上调用外部 sort」是老资料里的过时说法。真正会用外部 sort 的是 M-x sort-columns——它的文档写着「when possible, it uses the sort utility program, which doesn't understand tabs」，源码里是 (apply #'call-process-region beg1 end1 "sort" t t nil sort-args)；而且它会在两种情况下退回 Emacs 内部实现：系统是 windows-nt，或者区域里带非字体锁定的文本属性。sort-columns 还有一个硬限制：遇到制表符直接报错，让你先 M-x untabify。

4.1 字典序 vs 数值序：为什么 4 排在 23 后面

字典序就是逐字符比较字符编码，数字也一样比编码，于是 4（编码 52）大于 23 的首字符 2（编码 50）。要按真正的数值排，必须用 M-x sort-numeric-fields。

4.2 按字段排序：数字前缀选列

M-x sort-fields 与 M-x sort-numeric-fields 需要指定按第几列排序，列号从 1 开始，用数字前缀给出，例如按第三列排：M-3 然后 M-x sort-fields。列是按空白分隔的——一个或多个空格、制表符都算一个分隔符。给负数则改成从行尾往回数（M--1 = 按最后一个字段排）。列号只能给一个；想按多列排只有 M-x sort-columns：它不用列号，而是把 point 和 mark 放在你想比较的起止两个列位置上，从 point 所在行到 mark 所在行之间的所有行就按这段字符排序（注意它的「区域」定义很特殊：point 那一整行和 mark 那一整行都算在范围内）。

4.3 sort-regexp-fields：处理 CSV 与「部分排序」的坑

这个命令要你提供两个正则：Record（一条记录长什么样）和 Key（拿记录的哪部分当排序键）。Emacs 内置排序函数的心智模型是「键 vs 记录」——记录通常就是一整行，键是其中被挑出来比较的部分。Key 可以写 \1 / \2 直接引用 Record 里的第几个捕获组，也可以写 \& 表示「整条记录都当键」。处理下面这份 CSV：

Price,Product
$3.50,Cappuccino
$4.00,Caramel Latte
$2.00,Americano
$2.30,Macchiato

第一步，选中下面四行数据（从 $3.50 那一行起拖到文件末尾，不要把表头包进去），然后执行 M-x sort-regexp-fields，依次回答（注意 \( 是 Elisp 正则里的分组括号）：Record: ^\([^,]+\),.*$、Key: \1。Record 把每行定义成「一个不含逗号的捕获组 + 逗号 + 剩下随便什么」，Key 取第一个组（价格）来比较。32.0.50 上实测结果：

Price,Product
$2.00,Americano
$2.30,Macchiato
$3.50,Cappuccino
$4.00,Caramel Latte
易错

忘了选区、连表头一起排，会出两个意外。其一，表头 Price,Product 自己也是一条记录，它的键是 Price；而 $ 的字符编码是 36、P 是 80，所以表头会被排到最下面而不是留在顶部（我实测整个 buffer 直接排，得到的是 $2.00,Americano / $2.30,Macchiato / $3.50,Cappuccino / $4.00,Caramel Latte / Price,Product）。其二，原书给的 Record 正则 ^\([^,]+\),\([^,]+\)$ 在今天的 Emacs 上还会多插一个空行出来——所以这里我改用结尾是 .*$ 的写法，上面那段输出就是它的实测结果。

第二个坑更凶：部分排序会毁掉你的数据。如果你少写一个括号，只写 Record: ^\([^,]+\)，Record 只匹配逗号之前的前半段，行会被拆开重排，价格和商品名就散了。同样在原始的四行数据上实测：

$2.00,Cappuccino
$2.30,Caramel Latte
$3.50,Americano
$4.00,Macchiato

价格确实排对了，商品名的对应关系全乱了——每个商品名都往上错了一行。所以跑 sort-regexp-fields 之前先 Cx u 撤销点一下，或者干脆复制一份。

练习 12　一行数据里第二列是数字（name 23、name 4），要按第二列的数值升序排，按键怎么敲？

M-2 然后 M-x sort-numeric-fields。用 sort-fields 会按字典序排，4 会排在 23 后面——因为字符 4 的编码大于 2。

练习 13　sort-lines 默认升序，想改成降序，前缀怎么加？这个约定对所有排序命令都成立吗？

加 Cu（universal-argument），对 sort-lines、sort-paragraphs、sort-pages、sort-columns、sort-regexp-fields 成立。但 sort-fields 与 sort-numeric-fields 是例外：它们的前缀数字是列号，给负数表示「从行尾往回数第几个字段」，不会降序。要给字段降序，只能排完升序再 M-x reverse-region 翻过来。

练习 14　一份三列 CSV（价格、名称、数量）要以价格排序。执行 M-x sort-regexp-fields 前应该先做什么防护动作？为什么？

先 C-x u 撤销点一下，或复制一份。因为 sort-regexp-fields 可能只排到部分行：Record 正则写错（比如只写 ^\([^,]+\)）时行会被拆开重排，价格对了但名称的对应关系全散。命令出错时不会自我保护。

五、对齐：align.el 与 table.el

「缩进」和「对齐」是两件事。缩进是相对行首的整体位移，由语言规则决定；对齐是让某一列字符横着对齐——一堆赋值语句的等号对齐成一竖排，或表格的价格列对齐。对齐系统 align.el 与缩进系统完全独立。

5.1 align.el 的五条命令

本节命令：对齐（M-x 调用）

命令（均为 M-x 调用）作用要点与变体
align按对齐规则表对齐选区逐条试 align-rules-list，第一条整段匹配的规则胜出
align-current不选区，光标在哪一行就自动找 section 并对齐最常用的一条：内置规则能认出 Python 的 = 与 Lisp 的 alist 点
align-regexp自己给正则，指定对齐字符直接调用是新手模式（只问一次 Align regexp）；加 Cu 进复杂模式（问四个问题，可一行内反复对齐）

前两个命令按变量 align-rules-list（对齐规则表）逐条尝试，第一条整段都匹配的规则胜出。规则里可以限定 major mode 和要匹配的正则。section（段落块）是 align.el 特有的概念：一组连续的行，其中第一条命中的规则统辖它们。比如有一条规则对齐字符串里的 =，那么所有连续含 = 赋值的行就是一个 section。

两条免选区的命令很省事：M-x align-current 从光标所在行推出 section 并一起对齐；M-x align-entire 把整个选区当成一个 section。内置规则里，Python 会把赋值语句的 = 对齐，Clojure / Lisp 的 alist 里的点也能对齐——把光标放在其中一行执行 M-x align-current，Emacs 自己认。

易错

align-rules-list 里的规则需要读者相当熟悉正则才能看懂，而且每条都没有文档字符串——这是 Emacs 的一个老大难，也是原书作者吐槽的地方。想看懂某条规则会怎么改你的文本，用 M-x align-highlight-rule：它会把「这条规则会动到的空白」高亮出来，比读正则直观得多。

5.2 align-regexp：自己指定对齐字符

内置规则很少正好命中你的场景，这时用 M-x align-regexp（正则驱动的临时对齐规则）。它有新手模式（直接调用）和复杂模式（加 Cu 前缀）。

新手模式只问一个问题 Align regexp:。例如对齐 $：

Cappuccino $2.00
Caramel Latte $2.30
Americano $3.50
Macchiato $4.00

要在一行里对齐多处（比如三列 CSV 的所有逗号）必须进复杂模式。我读过 align-regexp 的交互规格，它依次问四件事：

  1. Complex align using regexp:——预填 \(\s-*\)，即「捕获已有的连续空白」。需要它是因为你可能刚对齐过一次、现在文本又乱了，得先匹配住现有空白再重排。这个空白捕获组即使在只支持单点时也存在，只是你看不到。
  2. Parenthesis group to modify (justify if negative):——改动第几个捕获组，默认 1；给负数表示「两端对齐」。
  3. Amount of spacing (or column if negative):——间距，默认取 align-default-spacing（用 Emacs 的制表位），一般保持默认；给负数表示对齐到第几列。
  4. Repeat throughout line?——是否沿整行反复对齐。处理三列 CSV 必须答 yes。

完整处理三列 CSV 的答案：

C-u M-x align-regexp
Complex align using regexp: ,\(\s-*\)
Parenthesis group to modify (justify if negative): 1
Amount of spacing (or column if negative): 1
Repeat throughout line? y

注意逗号放在正则开头还是结尾，结果完全不同：放前面（,\(\s-*\)）对齐的是逗号之后的列；放后面（\(\s-*\),）对齐的是逗号之前的列。结果：

Price, Product, Qty Sold
$2.00, Cappuccino, 289
$2.30, Caramel Latte, 109
$3.50, Americano, 530
$4.00, Macchiato, 20
技巧

「一行里要反复对齐两次以上」太常用了，把它录成键盘宏是最自然的选择——这正是 1.10 说的「用宏自动化你反复做的复杂命令」。不过老实说，只要数据是规整的多列文本，正确的答案往往是下一节的 table.el，而不是跟正则搏斗。

5.3 table.el：今天做数据对齐应该用它

如果处理的是真正的表格数据（列有明确含义、要反复增删行列），现代最佳实践不是 align.el，而是 Emacs 内置的 table.el（lisp/textmodes/table.el）。理由很简单：align.el 只是「在文本里插空白让某列对齐」，那些空格是文本本身的一部分；table.el 则把一块矩形区域识别成一个表格，之后光标被限制在单元格内，打字时单元格自动加宽 / 加高以容纳内容——这就是所谓 WYSIWYG（所见即所得）式的纯文本表格编辑。

  1. M-x table-insert，依次输入列数、行数、单元格宽、单元格高（默认值分别是 3、3、5、1）。
  2. Emacs 插入带边框的表格，光标落在第一格。
  3. 用 TAB 在单元格间移动、直接打字。字超出宽度时单元格自动变宽，同列其他单元格跟着一起变宽。

Number of rows: 2

Cell height: 1

+-------+--------------+------+

5.4 矩形（rectangle）：按列而不是按行操作

矩形指横跨多行、但只取每行某个列区间的选区。它的价值在于「给这三行的第 5 到第 12 列都填上同一个字符」这类操作——普通选区做不到，矩形一下就够。

矩形和 table.el 怎么配合？矩形用在纯文本还没成型的时候：批量加行号、批量补前缀、把带缩进的数据「压平」成一行、给多行统一加边框字符——它不认识「列」是什么，只知道字符位置。table.el用在数据成型之后：一旦你认定这是有行有列的表格，就交给它，之后插行插列、切分合并、单元格对齐、导出 HTML 全都顺手。典型流程：先用矩形把原始数据规整成等宽方块，再 M-x table-recognize 识别成表格，接着当表格编辑。

练习 17　想插入一个 4 列 3 行、每格宽 20 的可编辑表格，敲什么命令？

M-x table-insert，依次回答 4（列数）、3（行数）、20（单元格宽）、1（单元格高）。之后用 TAB 在格子间移动，打字超出宽度时单元格自动加宽。Emacs 里没有 M-x table-generate 这个命令；导出成 HTML / LaTeX 源码的命令叫 table-generate-source，在单元格里按 C^。

六、Zapping Characters：Mz 按字符删

第六章的 kill 命令（Cw、Mw 等）作用于语法单元——词、行、句子。但有时你只想「删到某个字符为止」，不想管中间是什么。zap 命令干的就是这件事。按 Mz（zap-to-char）之后，Emacs 在 minibuffer 里提示 Zap to char:，你把那个字符输入进去、回车，Emacs 就从光标处一直杀到那个字符为止，而且把那个字符也一起杀掉。

下面用 | 标出光标的位置（| 只是给你看的记号，不是真要敲的东西）：

删除前：http://www.example.com/|articles/?id=10
按 M-z，在 Zap to char: 后面输入 /，回车
删除后：http://www.example.com/|?id=10
              ↑ articles 没了，连那一个 / 也一起没了
易错

「含」还是「不含」是这一族命令唯一要记的差别。zap-to-char 的文档字符串原文是 “Kill up to and including ARGth occurrence of CHAR”，zap-up-to-char 是 “Kill up to, but not including ARGth occurrence of CHAR”。所以上面那个例子用 zap-to-char 会把斜杠吃掉；换成 zap-up-to-char 就留下 /，结果是 http://www.example.com/|/?id=10。如果你删完发现少了一个本该保留的字符，就要往另一条命令上换。

为什么是「输入字符」而不是「按下一个键」？这是版本变化的结果：zap-to-char 从 Emacs 27 起改用 read-char-from-minibuffer（可在 minibuffer 里输入、能用搜索历史），zap-up-to-char 从 Emacs 28 起跟上。老文章里写「按 Mz 然后直接按字符键」是 Emacs 26 及以前的用法，在今天的 Emacs 上照做会没反应。本书作者在 32.0.50 自带的 etc/NEWS.27 第 584–585 行和 etc/NEWS.28 第 1041 行查到了这两条原文。

因为它走 kill ring，可以像别的 kill 命令一样加前缀：M-3 Mz 连续 zap 三次（注意方向会翻转），负数字符串往回删。所以原书说「可以把它和 kill 命令、数字参数、负参数组合使用」是对的。

zap-up-to-char 是内置命令（定义在 misc.el 里），默认没有任何键位，所以表里写的是 M-x 加名字。原书建议自己绑一个，比如 (global-set-key (kbd "M-S-z") #'zap-up-to-char)。但更好的做法是替换而不是新增——多数人真正想要的是「含」与「不含」二选一：(global-set-key (kbd "M-z") #'zap-up-to-char)。

要点

版本差异，本书作者在本机 etc/NEWS.* 里逐条查到的原文：Emacs 27（NEWS.27 第 584–585 行）起 zap-to-char 改用 read-char-from-minibuffer，并且「会用你以前 zap 过的那些字符的历史」；Emacs 28（NEWS.28 第 1041 行）起 zap-up-to-char 也改用同一个函数；Emacs 29（NEWS.29 第 1258 行）起两者对大写字符区分大小写——也就是输 a 不会匹配 A 了。

一条作者没能核实的说法，这里说清楚：「zap-up-to-char 是从哪个版本才开始有的」——本书查遍 NEWS.20 到 NEWS.32 只找到上面那两条讲「改用 minibuffer」的记录，没有一条说它是哪个版本新加的命令。NEWS.28 那条说它「now uses」，措辞暗示它在那之前就已经存在。所以「Emacs 28 才加入」这个说法本书无法证实，不作为结论。你要在自己的 Emacs 上确认，用 Mx 输入 zap-up-to-char 看它认不认识；不认识就说明你的版本早于它被加进来的时间，照 M-x 查文档即可。

练习 18　把光标到下一个 /（含这个斜杠）之间的文本删掉用哪个键？「不含斜杠」的版本又用哪个？

含斜杠用 Mz（zap-to-char）；不含斜杠用 zap-up-to-char，它默认没键位，可以绑 MSz，或干脆 (global-set-key (kbd "M-z") #'zap-up-to-char) 把 Mz 变成「不含」的行为。

七、拼写检查：M$、Flyspell 与词典查询

反直觉但重要的一点：Emacs 自己不做拼写检查。真正干活的是外部程序——Linux 上通常是 aspell 或 ispell，Emacs 会优先用 aspell（更快也更现代）。Emacs 内部一律把「拼写检查」叫 ispell，哪怕底层跑的是 aspell 或 hunspell。

词典查询（Emacs 28 新增）

Emacs 28 加了 dictionary.el（lisp/net/dictionary.el），可以把光标处的词发到 dict.org 这类 RFC 2229 词典服务器去查。我读过它的选项：dictionary-server 默认是 nil，含义是「先试本机 localhost，不通就在征得同意后改用 dict.org」——不是默认就往外发数据，这点值得肯定。

  • M-x dictionary-lookup-definition：查光标处的词。
  • M-x dictionary-search：搜索你输入的词。
  • M-x dictionary-select-dictionary：选择查哪个词典（dict.org 支持很多语言）。
  • M-x dictionary：打开一个专门的查询 buffer。
  • M-x dictionary-tooltip-mode：鼠标悬停即查释义。

练习 19　开了 flyspell-mode 之后，想「直接采用第一个候选、不弹列表」地自动纠正光标处的词，按哪个键？原书给的 C-M-i 答案在今天的 Emacs 里对吗？

按 MTAB（flyspell-auto-correct-word）。原书的 C-M-i 需要修正：32.0.50 的 flyspell.el 里 flyspell-auto-correct-binding 默认是 C;（绑 flyspell-auto-correct-previous-word），而 C. 绑的是 flyspell-correct-word，它会弹候选列表，跟「不弹列表」正好相反。

八、Quoted Insert：字面插入控制字符

有时候你需要在文本里放一个真正的制表符、回车或 ASCII 控制码——比如你正在写一份讲 Emacs 的文档，正需要展示 C-q 这个键。quoted insert（字面插入）就是干这个的：按 C-q（quoted-insert）后接任意键，Emacs 把它原样插入，不解释成命令。

  • C-q TAB：插入一个字面的制表符。
  • C-q C-j：插入换行符（LINE FEED，ASCII 10）。
  • C-q RET：插入回车符（CARRIAGE RETURN，ASCII 13）。
  • C-q ESC：插入 ESCAPE 字符（ASCII 27）。
  • C-q C-q：插入 C-q 自己。
  • C-q C-u 8 RET：用八进制数直接插入任意字符。
要点

LF 与 CR 不是一回事。你敲 RET 产生的是 CARRIAGE RETURN，而 C-q C-j 产生的是 LINE FEED。绝大多数现代文本文件里行尾统一用 LF，所以「我明明按了 RET 为什么插进去的东西不一样」，答案就是这一条。

Emacs 还会用专门的 face（face，一组显示属性）escape-glyph 把控制字符显示成 ^[、^I 这种两字符记号，方便你在屏幕上找到它们。需要调整就 M-x customize-face。

练习 20　要在文档里插入一个「纯换行符」（LF），同时又要让读者看到你按下的是回车，分别怎么敲？

插入纯 LF 用 C-q C-j；插入回车（CR，ASCII 13）用 C-q RET。直接按 RET 产生的是 CR，两者不是同一个字符。

收尾：把这一章连起来看

键盘宏、片段展开、缩进、对齐，看起来是四个话题，其实是同一个观念的四次应用：Emacs 不替你猜，它替你算。宏替你重复，abbrev 替你写词，缩进引擎替你算列，对齐命令替你补空格，而 table.el 干脆把「算」封装成一个可以进出的矩形对象。

要点

这一章最值得你真花时间练熟的，是「录 → 改 → 命名 → 写进配置」这条完整链路。它是你从 Emacs 的使用者变成 Emacs 的主人的分水岭：一旦你意识到「任何我手动做过一遍的操作都可以变成一个我自己的命令」，Emacs 对你的意义就变了——它不再是一个要你适应它的编辑器，而是一个你每天都在往上加零件的工具。

具体路线：先在 *scratch*（C-x b 后输入 *scratch* 打开的临时 buffer，不会保存）里把三个最烦人的操作录成宏——比如「把当前行变成待办注释」「把下一行往上提」「在文件末尾追加一行带时间戳的注释」——然后命名、写进配置、重载。做完这一遍你会发现，写 Elisp 的门槛比想象中低得多。

练习 21　原书把 abbrev 列为文本展开的第一选择。按今天的实际情况，给新用户的推荐顺序是什么？至少说出两条理由。

先开 hippie-expand 替换 dabbrev（零成本）→ 写代码就装 YASnippet → 最后才用 abbrev，且只做拼写纠错、优先 mode-local 版本。理由：(1) abbrev 定义时要多按 C-x a g 并输入两遍，有按键开销；(2) add-global-abbrev 的缩写在所有 buffer 生效，容易污染别人的文件、邮件甚至密码字段；(3) 它只能做单词替换，多行模板能力被 YASnippet / skeleton 完全覆盖；(4) 展开点跟随光标，容易出意外。
