九、实用篇（一）：自助探索、项目管理、交叉引用

前面八章教你的都是「怎么做」：怎么移动、怎么编辑。这一章教你一件更根本的事——怎么自己找到答案。Emacs 的键位有上千个、命令有上万条，任何一本书都列不完；但 Ch 这一个键就能把整个 Emacs 的说明书摊开在你面前。读完这一节，你就能自己查清任何一个陌生功能，并把 Emacs 从「别人的工具」调成「你的工具」。这一章还会交代 Emacs 30/31/32 的现状：项目用 project.el，跳定义统一走 xref（背后多半是 Eglot 那个语言服务器），而 compilation-mode 虽然在「跳编译错误」这件事上被 Eglot 分走了一半，仍然是核心内建、仍然值得会；看日志则有一套专门的手法。

要点

本章的命令与键位全部在 GNU Emacs 32.0.50 上用 emacs --batch 实际查询过。凡是原书写错了或已经过时的，正文里会直接标出来。

一、自助探索：把 Emacs 当成搜索引擎

为什么这是全书最该反复强调的一件事

先说一个残酷的事实：Emacs 的功能你学不完。它的命令多到写一本书都写不完，而且核心内建的部分每年还在长（Emacs 30 往里塞了 which-key，Emacs 31 加了 project-root-find-file，Emacs 29.1 起 image-mode 换上了一套 image-transform-* 变换键）。如果你打算「背按键」来用 Emacs，这条路是走不通的。

Emacs 给出的另一条路是：你不需要记住按键，你需要学会查按键。这就是这一章第一部分的主题。原书作者说它是「Emacs 里的 alpha 和 omega（开端与终结）」，这不是夸张。

为什么这件事对初学者尤其重要？因为你一旦开始改配置——改个变量、重新绑定一个键、装一个包——你就会造出一个全世界只有你一个人有的 Emacs。别人的教程、别人的答案、别人的快捷键截图，对你可能全是错的。这时候，唯一可靠的信息来源就是 Emacs 自己。

技巧

养成一个习惯：每看到一个不认识的键位，先按 Ch k 问一句「你是谁」，比直接记在脑子里可靠得多。三十秒的查询，胜过三十天的困惑。

Ch 家族：Emacs 的搜索引擎

Ch 本身不是一个命令，而是一个前缀键。按住 Ch 再按一个字母，就会打开不同的「帮助窗口」。这些字母不是随便挑的，记住它们有个诀窍：字母就是你要查的东西的第一个字母。

  • f = function，查函数。
  • k = key，查键位。
  • m = mode，查模式。
  • v = variable，查变量。
  • i = info，进 Info 手册浏览器。
  • b = bindings，列出当前所有生效的键位绑定。

下面是 Emacs 32 里 Ch 家族的实际成员表。这一张表建议你打印出来贴在显示器边上，用一周就记住了。

易错

上面说的「别名」是 Emacs 内部的：F1 和 <help> 在键表里都指向同一个命令 help-command。但在终端里能不能真的按出来，取决于你的终端会不会把 F1 这个物理键发送成 Emacs 认识的 <f1>——很多老终端不会（常见的是发成 ESC [ A 或 ^[[11~，Emacs 收不到）。真按不出来就用 Ch，功能完全一样。

易错

很多人以为 Ch t 是「进 Info 手册」。不是。在 Emacs 32 里 Ch t 绑定的是 help-with-tutorial，它打开的是一份简短的交互式上手教程。进手册要用 Ch i（info），直接进 Emacs 手册要用 Ch r（info-emacs-manual）。这个误解流传很广，写在这里免得你去查。

逐个拆开：每一条都值得亲手敲一次

Ch f（describe-function）——已知函数名，查它是什么。Emacs 弹出的 *Help* 缓冲区里有几块内容，顺序是固定的（下面拿 C-x v v 举例，这是我在 Emacs 32 上 M-x describe-function vc-next-action RET 的真实输出）：

  1. 定性说明：vc-next-action is an autoloaded interactive Lisp function in ‘vc.el’.——顺便就把「autoloaded（延迟加载）」和「定义在哪个文件」一起交代了；
  2. 这个命令被绑定在哪些键上：It is bound to C-x v v.，以及有没有菜单入口；
  3. 函数签名：(vc-next-action VERBOSE)；
  4. Emacs 推断出的类型：Inferred type: (function (t) t)（纯给写 Elisp 的人看的，可跳过）；
  5. 最后是文档字符串，也就是真正讲它怎么用的那段文字。

文档字符串里夹着的高亮小方块是可点击的：REGEXP 这种高亮词点一下就会跳去解释它是什么。这种「文档里嵌链接」的设计在 Emacs 里到处都是，习惯之后查东西会非常快。

Ch k（describe-key）——已知键位，查它干什么。这个方向和 Ch f 相反，是「按键 → 命令」。它会把这个键当前生效的所有绑定一起列出来：局部绑定（来自 minor mode 或 major mode）和全局绑定都能看到，哪个在前哪个在后一目了然。

易错

Emacs 32 里 Ch k 不接受前缀参数——你按 Cu Ch k，它还是会按当前缓冲区（包括 minor mode 的局部覆盖）来回答，不是「只看全局绑定」。（describe-key 的 interactive 形式只有 (help--read-key-sequence)，文档里也没提前缀参数；老的 describe-global-key 命令也不存在了。）真想跳过 minor mode 只看全局绑定，用 M- 求值 (lookup-key global-map (kbd "C-x v v") t)——第三个参数 t 表示「没绑就返回 nil，别报错」。（别去搜 global-lookup-key，那个函数在 Emacs 32 里已经没有了。）

要点

原书作者提醒过一个小缺点，这里值得重复：Ch k 的读者对象其实是写 Elisp 的人。它的说明会带上一堆技术细节，比如 C-x v v 在 Emacs 32 的输出第一行就是 vc-next-action is an autoloaded interactive Lisp function in ‘vc.el’（这是一个定义在 vc.el 里的、延迟加载的交互式 Lisp 函数）。不要被这些词吓到——你只要越过前面几行，直接看最后那段文档字符串就够了，那段是用人话写的。

Ch m（describe-mode）——这是最被低估的一个。它显示当前缓冲区所有生效模式的文档：major mode（主模式，决定这个缓冲区的主要编辑行为，比如 emacs-lisp-mode、text-mode）和所有 minor mode（次模式，叠加在主模式上的小功能）。每个 minor mode 都会列出它自己额外提供的键位。

怎么用：当你走进一个陌生缓冲区，不知道能对它做什么的时候，按 Ch m。你会看到这个模式是谁、有哪些额外的键、以及每个键的完整说明。Emacs 32 的 describe-mode 输出是可点击的超链接界面，一路点下去就行。

Ch b（describe-bindings）——列出当前生效的全部键位，输出到一个 *Help* 缓冲区（help-mode，就是 Ch f 用的那个；Emacs 32 里已经没有叫 *Key Bindings* 的缓冲区了）。这是一张大表，可以边看边筛：在 *Help* 里按 Ms o 输一个前缀片段（比如 C-x v），只留匹配的行。什么时候用它？当你按一个键什么都没发生、或者发生了你不想要的事，你需要知道「现在谁占着这个键」的时候。

Ch a（apropos-command）与 Ch d（apropos-documentation）——这两个是搜索，不是查询。区别很重要：

  • Ch a 搜的是名字。你知道大概叫什么但记不准全名时用它。
  • Ch d 搜的是文档字符串——所有函数和变量的说明文字。名字完全不知道、只知道它大概是干什么的时候用它。

原书说 Ch d 是「最散乱的查找方式」，这话对但要理解为什么：文档是自由文本，没有统一格式，所以你会搜出一堆沾亲带故的东西。但它是覆盖面最广的一种搜法——只要 Emacs 里有任何地方提到过一个词，Ch d 就能找到它。所以「先宽后窄」的顺序才是对的：先用 Ch d 找到大致方向，再用 Ch a 拿到准确命令名，最后用 Ch f 看细节。

顺手提几个没有默认键位、但同属这一家的命令，用 Mx 调：apropos（搜符号名）、apropos-variable（搜变量名）、apropos-library（搜某个库文件里有什么）、info-apropos（在所有 Info 手册里搜关键词）。info-apropos 特别有用——手册不是每个功能都有专章，但 info-apropos 能把所有手册全文爬一遍。至于 apropos-mode：它在 Emacs 32 里还在（apropos.el 第 488 行的 define-derived-mode），但它是 *Apropos* 结果缓冲区用的那个大模式，不是搜索命令——搜命令的入口始终是上面那几个 apropos-* 命令，别搞混。

前缀键调查法：按一个不完整的序列，再按 Ch

这是本节最实用、也最少人知道的一招。

假如你记得 Emacs 里有个东西叫 VC（版本控制接口），你敲了 Cx v 出现了一个前缀键表，你不知道后面按什么。诀窍是：在敲完前缀之后，接着敲 Ch，Emacs 会把这个前缀下的全部绑定列出来。

这背后的命令叫 describe-prefix-bindings，它的文档字符串在 Emacs 32 里是这样写的：「Describe the bindings of the prefix used to reach this command. The prefix described consists of all but the last event of the key sequence that ran this command.」（描述「用来到达本命令的前缀」的绑定；这个前缀就是把你引到本命令的那串按键里除最后一个事件之外的部分。）所以机制是：你在 Cv 之后按了 Ch，Emacs 发现 Ch 没有绑定，于是拿前面那串前缀去查，列出它的全部子键。

这个功能在 Emacs 32 里依然有效（我自己查过：describe-prefix-bindings 存在，机制如描述）。Emacs 官方文档自己也在用这招：Emacs 28 的 NEWS 在介绍 C-x p 这个项目前缀键时专门写了一句「Type Cx p Ch to show the full list」；project.el 的 Commentary 里也留着同一句。

技巧

这一招还有个副作用很有用：它会把你想不到的功能翻出来。原书写得很准——你可能会看到「给当前修订打标签」这样的功能，你从来没想过 Emacs 有，但既然它在那儿，就说明有它存在的理由。

进阶：为什么「前缀 + C-h」比 C-h b 更好用

C-h b 会列出当前缓冲区的全部绑定，输出可能上千行，你得在里面翻找。而「前缀 + Ch」只列你关心的那一小段前缀下的绑定，输出通常不到二十行，噪声极小。

正确的用法顺序是：

  1. 你只知道一个模糊的印象——「好像是 Cx 开头的吧」。敲 Cx Ch，列出 C-x 下的全部绑定，扫描一遍找方向。
  2. 找到了感兴趣的前缀，比如 Cx v，再敲 Cx v Ch 收窄。
  3. 看到可疑的命令名后，用 Mx 加 Ch f 确认它是干什么的。

这三步是本章的核心工作流，后面 VC 那个完整案例就走的是这条路。

顺便一提，Emacs 内部用的键位查找变量叫 help-char，在 Emacs 32 里它的值就是 C-h。如果你好奇整条机制长什么样，Mx 描述一下 help-char 就有分晓。

which-key：Emacs 30 起已经内建

原书写于 which-key 还是个 MELPA 第三方包的时代，读者如果照着装是装得上的。但今天有变化，而且是好变化。

Emacs 30 起，which-key 已经是核心内建包，不需要装任何东西。本机 Emacs 32.0.50 的 etc/NEWS.30 里原文写着：「New package 'which-key'. The 'which-key' package from GNU ELPA is now included in Emacs. It implements the global minor mode 'which-key-mode' that displays a table of key bindings upon entering a partial key chord and waiting for a moment.」（新增 which-key 包，原本在 GNU ELPA 上的它现在被并入 Emacs。它实现了一个全局次模式 which-key-mode：你敲下一个不完整的前缀键并稍等片刻，它就会显示一张按键表。）

which-key（一个全局 minor mode）做的事是：当你敲下一个前缀键然后停下来，它自动弹出一张表，列出这个前缀后面可以跟什么。注意区分两件事：「表」出现在哪儿由 which-key-popup-type 决定（默认 side-window，也就是在屏幕侧边开一个小窗口），「你已经敲到哪了」这段前缀文字显示在哪儿才由 which-key-show-prefix 决定（默认 echo，也就是回显区）。它和「前缀 + Ch」的区别是：Ch 需要你主动多敲一下，which-key 只需要你停顿一下。

内建版本是 which-key 3.6.1，作者 Justin Burkett（bundled 版本头部的版权行是 2017–2026 Free Software Foundation）。默认的等待时间是 which-key-idle-delay，值为 1.0 秒——很多人嫌慢，调到 0.3 或 0.4 更好用。

打开它的最简写法，是在你的 Emacs 配置文件里加两行：

;; 在 init.el 里（或 early-init.el 里，更快）
(setq which-key-idle-delay 0.4)
(which-key-mode 1)

放在 early-init.el（Emacs 27.1 引入的启动早期配置文件；Emacs 27 的 NEWS 里那条标题就是「Emacs can now be configured using an early init file」）里比放在 init.el 里更好，因为这样它在包系统初始化之前就生效了，别的包绑的键也能被显示出来。

易错

开 which-key 有一个必须知道的代价：它会抢走前缀之后的 Ch，而那正是本书反复在教你的自省手法。因果链是这样的：前缀键之后按 Ch，Emacs 默认会跑 describe-prefix-bindings，列出这个前缀下的全部绑定——本书的「前缀 + Ch 列全部绑定」讲的就是它。而 which-key 默认把这个键接管了：前缀之后按 Ch 不再列绑定，而是变成「在 which-key 已经弹出的那张表里翻页」。

开关是 which-key-use-C-h-commands，默认值是 t（也就是「接管」），本书作者在 Emacs 32.0.50 的内建 which-key 上实测过 (default-value 'which-key-use-C-h-commands) 返回 t。既然你要跟着这本书学，开 which-key 之前就把它设成 nil：

;; 这一行要放在 (which-key-mode 1) 之前
(setq which-key-use-C-h-commands nil)
(which-key-mode 1)

顺序有讲究：设成 nil 必须在启用 which-key 之前，否则它自己已经把 Ch 抢过去了。这两行一起放进 early-init.el 最省事——本书第 13 章会讲 early-init.el 和 init.el 的分工。

另一个相关选项 which-key-show-early-on-C-h 默认是 nil；设成 t 之后，等 which-key 的计时器还没到就按下 Ch，也会立刻把表弹出来。但它同样会占掉这个键，设成 nil 之外的任何值都意味着你放弃了 describe-prefix-bindings。要哪个自己选，本书建议两个都保持默认、只关掉上面那一个接管项。

进阶：which-key 值得调的选项清单

这些变量在 Emacs 32 的内建 which-key 里都存在，都是 defcustom，可以用 Mx customize 里选 which-key 分组统一调整。

  • which-key-idle-delay（默认 1.0）：停顿多久弹出表。常用值 0.3–0.5。
  • which-key-show-prefix（默认 echo）：把「你已经敲到哪了」这段前缀文字显示在哪里。可选 left、top、bottom、echo、mode-line、nil。
  • which-key-popup-type（默认 side-window）：按键表本体弹在哪儿。可选 minibuffer、side-window、frame、custom。side-window 在终端里也照样能用（它就是一个普通窗口），只是要吃掉一截屏幕宽度；屏幕窄的终端可以改成 minibuffer。
  • which-key-max-description-length（默认 27）：描述文字最长显示多少字符，超了就截断。窗口窄的时候可以调小。
  • which-key-show-docstrings（默认 nil）：是否把命令的文档字符串也显示出来。设 t 信息量很大，但会占更多屏幕。
  • which-key-show-early-on-C-h（默认 nil）：见上面的「易错」。
  • which-key-sort-order（默认 which-key-key-order）和 which-key-sort-uppercase-first（默认 t）：排序方式。默认按键盘位置排，很符合直觉，一般不用动。
  • which-key-side-window-max-width（默认 0.333）、which-key-side-window-max-height（默认 0.25）：side window 模式下的尺寸上限。

内建版本自带几个一键切换的预设命令（都是 autoload 的交互命令，用 Mx 就能调）：which-key-setup-side-window-right、which-key-setup-side-window-right-bottom、which-key-setup-side-window-bottom、which-key-setup-minibuffer。不知道从哪儿调起的话，先跑一次这四个里最合你屏幕的那个，剩下的默认值它会顺手改好。

判断一个键后面还有没有后续，要看表里那一项是不是一个 prefix（前缀）——内建 which-key 会在续按键的前面加一个 + 号（比如 + f 表示 Cx f 后面还有东西）。which-key-prefix-prefix 这个变量就是控制这个 + 的，默认值就是 "+"。

MSx：只列出当前模式下真正有用的命令

原书提到了 Emacs 28 新增的 MSx，绑定到 execute-extended-command-for-buffer（为当前缓冲区执行扩展命令）。Emacs 28 的 NEWS.28 原文：「New command 'execute-extended-command-for-buffer'. This new command, bound to 'M-S-x', works like 'execute-extended-command', but limits the set of commands to the commands that have been determined to be particularly useful with the current mode.」

它和 Mx 的区别：Mx 列的是全部命令（几千条），MSx 列的是当前模式声明为有用的那几十条。走进一个陌生的模式，敲 MSx 而不是 Mx，噪声小一个数量级。

它的局限原书也点到了：效果依赖模式作者有没有配合。有些模式（尤其是第三方写的）没有提供任何「推荐命令」提示，那 MSx 给你的结果就跟 Mx 差不多，甚至更少。所以它适合当 Ch m 的补充，不适合当替代品。

万能入口 Mx

你从本书开始应该就知道，但这一章要专门强调：任何命令都有名字，任何命令都能用 Mx 调起来。Mx 后面那串可以只打前几个字母然后按 TAB 补全，比如 M-x comp RET 会调起 compile（编译当前目录）。

初学者常犯的错是「因为没有快捷键所以以为功能不存在」。Emacs 里有大量功能故意不绑键——因为快捷键有限，而这类功能要么用得少，要么每个项目的用法不同。这类功能的标准调用方式就是 Mx。反过来，你也可以给自己常用的 Mx 命令绑键，方法在配置那一章会讲。

走一遍：怎么从零调查一个陌生功能

下面是原书里那段 VC（VC，Emacs 内建的版本控制接口，vc.el，负责对接 Git、Mercurial 等各种版本控制系统）调查的完整流程。这个流程本身就是方法论，值得原样走一遍。

  1. 读手册。Ch i 进 Info 浏览器，选 Emacs 手册，然后 Cs 搜 version control，一路点进 Version Control 那一章。Emacs 32 里这一步更简单：直接 Ch r 就到了。

练习 1　你打开了一个从没见过的缓冲区（比如 *Messages*），完全不知道能对它做什么。应该按哪个键？

Ch m，即 describe-mode。它会列出当前缓冲区所有生效的 major mode 和 minor mode，以及每个模式额外提供的键位。

练习 2　要查 Emacs 官方手册里的某个功能，Ch t 对不对？该怎么按？

不对。Ch t 是 help-with-tutorial，打开的是交互式教程。正确做法：Ch i（info）进入 Info 浏览器自己找，或者 Ch r（info-emacs-manual）一步直达 Emacs 手册。

练习 3　你想找一个功能，隐约记得命令名里带 occ，但想不起全名。用哪个命令搜？

Ch a，即 apropos-command，它搜的是命令名。Ch d（apropos-documentation）搜的是文档文字，方向不对。

练习 4　你不知道任何命令名，只知道 Emacs 好像有「在多个文件里批量替换」的功能。用什么查？

Ch d，即 apropos-documentation，它搜索所有函数和变量的文档字符串。搜「across files」之类的关键词即可。因为是在搜自由文本，结果会掺杂无关条目，扫一遍标题就好。

练习 5　你敲了 Cx v 出现一串候选，但不知道后面按什么。补完这个操作该怎么敲？

在敲完前缀之后紧接着按 Ch，也就是 Cx v Ch。这会运行 describe-prefix-bindings，列出该前缀下的全部绑定。注意：若 which-key 开着且 which-key-use-C-h-commands 为 t（默认），这一下会被改成翻 which-key 的表；把它设成 nil 才能得到原本的行为。

练习 6　Mx 会弹出几千条命令，太吵。有没有一个只列「当前模式下真正有用」的命令的键？

MSx，Emacs 28 新增，绑定到 execute-extended-command-for-buffer。它依赖模式作者提供推荐命令，第三方模式可能什么都没有，所以适合当 Ch m 的补充而不是替代。

练习 7　想让 Emacs 在你敲下前缀键并停顿时自动显示候选表，原书说要从 MELPA 安装 which-key。2026 年还需要装吗？

不用装。Emacs 30 起 which-key 已是核心内建包（见 Emacs 30 的 NEWS.30：「The 'which-key' package from GNU ELPA is now included in Emacs」）。直接 (which-key-mode 1) 即可，建议连同 (setq which-key-idle-delay 0.4) 写在 early-init.el 里。

练习 8　你开了 which-key 之后，「前缀 + Ch 列出所有绑定」这个操作失灵了。改哪个变量？

把 which-key-use-C-h-commands 设为 nil。它默认为 t，此时 Ch 会被改成翻 which-key 弹窗的分页键。想恢复 describe-prefix-bindings 的原行为就把它关掉。

二、项目管理：project.el 及其今天的地位

Emacs 一贯「一个文件一个文件」地看世界

在讲具体命令之前，先说清楚为什么这件事存在。历史上 Emacs 一直把文件当作孤立的个体来编辑，从来不认为「这一堆文件属于同一个项目」。所以：多文件搜索替换要你自己想办法，编译要你自己敲命令，打开项目里的文件你得一个个 Cx Cf。

Emacs 早年有个 fileset（文件集，一组被归类到一起的文件，可以让一批命令同时作用其上）机制，从 2002 年就存在，但它太冷门了，连维护者自己都忘了——原书作者这句话说得很重，也确实是实话。（补一句今天的状态：fileset.el 本身已经从 Emacs 里移除了，我在 Emacs 32 的 lisp 目录下找不到这个文件。VC 那边还留着 fileset 这个词，指的是另一回事，不是这套机制。）除了它，Emacs 主要靠两样东西撑场面：一是 directory-local variables（目录局部变量，.dir-locals.el，Emacs 读到它时会求值里面的 Elisp，让某个目录下的文件自动带上某些设置），二是外部工具比如 Makefile。

这些都不够。开发者想编辑一个项目的五个文件，希望一条搜索能扫完整个项目，希望编译命令自动在项目根目录跑，希望能一键列出这个项目里所有打开的缓冲区。Emacs 后来意识到这是一个正经的内建功能，于是有了 project.el。

进阶：项目管理的三代历史（原书的来龙去脉）

原书用了一整段讲这段历史，因为它解释了为什么今天 Emacs 里会有好几套并存的方案。理一遍：

  1. EDE（Emacs Development Environment，Emacs 开发环境，Emacs 23 引入，来自 CEDET——CEDET 是 Emacs 的一整套语言分析与代码工具集，做语义分析、补全、代码生成、图表等；它的缩写展开是 Collection of Emacs Development Environment Tools，见《GNU Emacs 手册》的「GNU Emacs 致谢」一节）。EDE 只是 CEDET 的一个子集。CEDET 在 C/C++ 社区有一批拥趸，但在其他语言上一直没火起来。
  2. projectile 和它的同类（第三方，MELPA 有）。它们真正改变了「项目管理」这个概念：不再要求你先创建一个项目文件，而是从版本控制仓库反推——只要你在一个 Git 仓库里，它就知道哪些文件是相关的。这个思路对了，于是被官方吸收。
  3. project.el（2015 年才写进 Emacs 源码，随 Emacs 25.1 首次发布——Emacs 25 的 NEWS 里有一条「New package Project」；C-x p 前缀键是 Emacs 28 才加上的）。原书的评价很中肯：如果你没有强烈偏好，就用它——开箱体验对绝大多数用户都很好。

今天写在这里的补充：「build on ideas from third-party packages」这句话是原书作者的评论，不是 Emacs 源码里的原文（我 grep 过 lisp/progmodes/project.el，零命中）。源码能证实的是另一件事：project.el 的 Commentary 里写着 Any third-party code that wants to use this package should likewise target the public API. Use any of the built-in commands as the example.（想在这个包上做扩展的第三方代码，应该只依赖它的公共 API，并且拿内建命令当范例）——也就是说它从设计上就打算让第三方往上接。同一段 Commentary 还留了一句「Type Cx p Ch to see all available commands and bindings」，正好又教了上一节那招。

原书说「只要有一个 Git 或 Mercurial 仓库就能用」，这一点今天依然成立，而且更简单：project.el 会沿着目录往上找版本控制的根目录，找到就算一个项目。

project.el 的核心思想：先确定「项目」是什么

理解 project.el 的关键，是理解它怎么回答「当前这个文件属于哪个项目」。Emacs 32 的做法是：沿着当前文件所在目录逐级向上找，找到一个版本控制的根目录（比如有 .git 的那一层）就停。找到以后，这个根目录就是项目根，项目里「已知的文件」就是版本控制知道的那批文件。

这个设计比原书描述的还要多一层兜底：万一找不到项目怎么办？Emacs 32 的 project-current 文档字符串把这里的分寸讲得很清楚：project-current 的第二个参数叫 MAYBE-PROMPT，它不给（或者给 nil）时找不到项目就返回 nil；给了真值才会去问你要不要用当前目录当项目（问的方式由 project-prompter 决定），而你确认了却还是找不到版本控制根，它才返回一个「transient（临时）project」——一个以当前目录为根、包含该目录下所有文件（除了 vc-directory-exclusion-list 和 grep-find-ignored-files 里匹配的那些）的临时项目。

换句话说：只要你在一个目录里，C-x p 就能用。这一点对初学者很重要——你不需要先「创建一个项目」，不需要写任何配置文件，不需要装任何包。原因就在这里：下面那条 C-x p 命令几乎都是用 (project-current t) 调的（t 就是「找不到就问我」），你答了「就用这儿」，它就给你造一个临时项目继续干。

要点

Emacs 32 里，「怎么找项目」这套规则挂在钩子（hook，一个变量，里面装着一串函数；Emacs 触发某个事件时会挨个调用它们）project-find-functions 上：project-current 内部用 run-hook-with-args-until-success 逐个试，直到某个函数返回项目为止。第三方包可以往这个钩子里加自己的识别规则（比如按 package.json、pyproject.toml 认项目）。

易错

Emacs 26/27 时代的老配置里你会看到 (setq project-backends '(project-backend-vc project-backend-elisp project-backend-dumb)) 这样的写法。在 Emacs 32 里这些符号已经不存在了：project-backends 这个变量没有了，project-backend-vc 这个函数也没有了（我用 emacs --batch 查过，都返回 void）。所以网上老的配置片段不要照抄。同样地，project-elsewhere-prompt 也没了，现在控制「找不到项目时问什么」的是 project-prompter，默认值是 project-prompt-project-dir。

  • Emacs 28：加了 C-x p 这个前缀键表，也就是下面那张表；同时新增了 project-dired、project-vc-dir、project-shell、project-eshell 和 project-compile。
  • Emacs 29：新增命令 project-list-buffers，绑定在 Cx p C-b（就是下面表里那一行）；project-find-file 与 project-or-external-find-file 拿到前缀参数时可以「把项目外的文件也算进来」；project-kill-buffers 可以在关之前先列一份要关的清单（由 project-kill-buffers-display-buffer-list 控制）。还新增了 project-vc-extra-root-markers（额外认作版本控制根的标记目录）和 project-vc-include-untracked。
  • Emacs 31：新增了 project-root-find-file、project-customize-dirlocals（把 C-x p f 加进 .dir-locals.el 的 f 列表）、project-find-matching-buffer、project-list-exclude、project-prune-zombie-projects，以及 C-x p C-x s（project-save-some-buffers）——「只保存这个项目的缓冲区」。

技巧

新手最容易忽略的是 Cx p b 和 Cx p C-b 的区别。前者让你在输入框里敲缓冲区名继续补全，后者直接弹出一个本项目缓冲区的清单。刚开始用 Emacs 时，后者比你想的更有用——它回答了「我手头这堆窗口到底属于哪个项目」这个每天都要问的问题。

项目搜索的一个额外能力

原书说项目功能「内置枚举项目文件的支持，可以跨文件搜索替换」——这一点值得展开，因为它是 project.el 相对旧方案的核心优势：它知道哪些文件该跳过。版本控制忽略列表里的东西（.gitignore 之类）、二进制文件、巨大的生成物，都会被自动排除。你不需要维护一份自己的文件白名单。

命令行版本的对应物是 Emacs 内建的 rgrep（Mx rgrep，递归 grep），它也会参考 grep-find-ignored-files 和 grep-find-ignored-directories 这两个变量来过滤。两个变量在项目搜索和 dired 搜索里是共用的，值得知道。

练习 9　想打开当前项目里的某个文件，但希望候选列表里不要出现项目外的东西。用哪个键？

Cx p f，即 project-find-file。如果你确实偶尔需要列出项目外的文件，用大写的 Cx p F（project-or-external-find-file）。

练习 10　你在网上抄到一段老配置：(setq project-backends '(project-backend-vc ...))。把它放进 Emacs 32 的配置里会怎样？

会报 void-variable project-backends。Emacs 32 里这个变量和 project-backend-vc、project-backend-elisp、project-backend-dumb 这些函数都已经不存在了。识别规则现在挂在钩子 project-find-functions 上，而 你根本不需要配它——Emacs 默认就能沿目录向上找版本控制根目录。

练习 11　想在项目根目录开一个 shell，用 Cx p s 还是 Cx p e？

Cx p s 是 project-shell（系统 shell），Cx p e 是 project-eshell（Emacs 内建 shell，有补全、历史、跨会话持久）。初学者用 s 就够；熟了之后 eshell 更顺手。相关的还有 Cx p D（project-dired）和 Cx p v（project-vc-dir）。

三、编译与错误跳转：compilation-mode 今天的位置

先说结论：它没被取代，但角色变了

这一节要处理原书没怎么讲、但今天必须讲清楚的一件事。如果你用 Eglot，跳转编译错误这件事已经不用 compilation-mode 了——语言服务器会直接给你诊断、让你直接跳到出错的那一行。但 compilation-mode 本身仍然是 Emacs 核心的一部分，并没有过时。

它现在承担的角色可以这样理解：

  • 它不再是「跳转器」，而是「构建日志阅读器」。编译输出里有很多东西语言服务器不告诉你——测试框架的运行结果、链接器的完整报错、构建工具自己的警告。这些还得靠它。
  • 它仍然是「没有 LSP 时的退路」。不是每种语言都有成熟的语言服务器。
  • 它的能力被复用到内联诊断上。Emacs 26.1 起 Emacs 把 Flymake 整个重做过，现在它是一套内建诊断框架（作用是把「这个文件哪里有问题」直接标在缓冲区里，替代了当年「跑一次编译、跳一次错误」的循环），Eglot 启动时会自动把 Flymake 接上。也就是说，你看到的那条红色波浪线，很可能就来自编译输出，只是被重新整理了一遍。Emacs 29 只是给它补了 ShellCheck 后端和行尾提示灯，不是它诞生的版本。

原书写这一章的时候，compilation-mode 就是「跳到编译错误」的主力。这个机制今天在 Emacs Lisp 里还完好无损——你甚至能亲眼看到它的默认诊断后端。不开 Eglot 的时候，在 emacs-lisp-mode 缓冲区里查 flymake-diagnostic-functions，它的 buffer-local 值是：

(elisp-flymake-byte-compile elisp-flymake-checkdoc t)

也就是说，即便不开 Eglot，Emacs Lisp 文件也会被自动做字节编译检查和文档字符串检查。这些默认是从 elisp-mode.el 的 emacs-lisp-mode-hook 注册进去的（见 elisp-mode.el 第 774–776 行两处 add-hook）。注意一个反直觉的点：Eglot 一旦在这个项目里跑起来，它不是把这个列表追加，而是整个替换成 (eglot-flymake-backend)（eglot.el 第 2450 行）——所以你在用了 Eglot 的会话里查，看到的就只剩语言服务器这一条了。flymake-diagnostic-functions 本身是一个特殊钩子（special hook，一个「往里加一个函数，就等于加一条检查规则」的钩子）——它的文档字符串第一句就是 「Special hook of Flymake backends that check a buffer.」。想给别的语言加编译检查，往这个钩子里加函数就行。

怎么用

运行编译用 Mx compile，或者用项目版本 Cx p c（project-compile，在项目根目录跑）。Emacs 会问你要执行什么命令，默认填的是 compile-command 这个变量的值——Emacs 32 里默认是 make -k -j15 （末尾有个空格，是 Emacs 特意加的，别删）。

要点

compile 命令在 Emacs 32 里没有默认键位。我查过 where-is-internal，它只返回菜单栏入口 Tools > Compile，没有任何键盘绑定。所以用 Mx 调用，或者自己绑一个。

进阶：next-error 的「同一套机制」原理

next-error 不是一个功能，而是一套通用协议。任何缓冲区只要设置好 next-error-function 这个 buffer-local 变量，告诉 Emacs「我的第 N 条消息对应源文件的哪个位置」，next-error 就能在它里面跳。

今天内建的用户里，除了 compilation-mode，还有：

  • *Warnings* 缓冲区今天不走这套协议（这一点原书写的时候还不是这样，别照抄）。我在 Emacs 32 上实测：*Warnings* 只是个 special-mode 缓冲区，next-error-function 是 nil；当年的 Mx list-errors 命令也已经不存在——where-is-internal、apropos、整个 lisp 目录、Emacs 32 手册全文，四处都查不到这个符号。警告里带的位置跳转要靠警告自带的按钮，不能靠 Mn。
  • *Occur* 缓冲区——它的 next-error-function 是 occur-next-error，所以在 *Occur* 里也能用同一套 next-error 命令跳转，这正是上面那张表里 Cc Cf 的作用。
  • Elisp 的字节编译诊断（byte-compile-file 的输出缓冲区）——它用的 major mode 叫 emacs-lisp-compilation-mode，是从 compilation-mode 派生的。

理解了这一点，你就知道为什么 Emacs 里「跳到下一个错误」听起来像很多功能、其实是一个函数。第三方包想接入，只要实现同一个协议就自动兼容。

练习 12　想编译当前项目，Emacs 32 里用什么命令？它有默认键位吗？

用 Mx compile；在项目里用 Cx p c（project-compile）。compile 没有默认键位——我查过 where-is-internal，只有菜单栏入口 Tools > Compile。默认执行的命令来自 compile-command，Emacs 32 里是 make -k -j15 （末尾有空格）。

练习 13　编译卡住不动了，在编译缓冲区里按什么能停掉？编完之后想再跑一遍按什么？

停掉按 Cc Ck，即 kill-compilation。重跑按 g，即 recompile。注意别和 Mn 搞混——那个是「跳到下一条错误」，n 是「不离开当前缓冲区地看下一条错误」。

四、Xref：跳定义的统一前端

它解决的问题是什么

Xref（cross-reference，交叉引用）是一个「统一的前端」：不管你光标下那个标识符（identifier，代码里的名字：函数名、变量名、类型名）的定义在哪里，xref 都负责找到它、列给你、让你跳过去。

关键在于「统一」两个字。Emacs 里能回答「这个东西在哪定义」的东西有很多：TAGS、grep、语言服务器（LSP，Language Server Protocol，语言服务器协议，一套让编辑器跟「语言服务器」通信、由后者提供补全/跳转/重命名能力的工业标准）……每一家的后端都不一样。xref 不管后端是谁，它只提供一套键和一套界面。你要换后端，键不变。这在架构上叫「依赖倒置」，理解这一点，后面 Eglot 那部分就顺理成章了。

Emacs 32 里 xref-backend-functions 这个钩子有两层值：全局值是 (etags--xref-backend)（xref.el 第 247 行用 (add-hook 'xref-backend-functions #'etags--xref-backend t) 注册的 etags 后端），而在 Elisp 缓冲区里它会多出一条 buffer-local 的值 (elisp--xref-backend t)——elisp--xref-backend 由 elisp-mode.el 第 768 行和 help-fns.el 第 294 行注册。问题来了：那个 t 是什么？

要点

先把「钩子的两层值」这件事本身说清，你才能读懂 t。一个钩子变量可以同时有两份值：全局一份、当前 buffer 一份，默认只用全局那份。add-hook 的第三个参数是「要不要设成 buffer-local」：写成 t，Emacs 就只在当前 buffer 里加上这个函数，全局那份一动不动。

那么 buffer 里有自己的值之后，全局那份还跑不跑？默认不跑——buffer-local 值取代全局值。而 add-hook 干了一件很贴心的事：它在设成 buffer-local 的同时，顺手往那份 buffer-local 值里塞一个 t。这个 t 不是函数，它是一个标记，意思是「除了本地的这些，全局那些也要照跑」。跑到它的时候被跳过（因为它不是函数），但它代表的语义已经被执行了。

这正是 add-hook 文档字符串里的原话：This makes the hook buffer-local, and it makes t a member of the buffer-local value. That acts as a flag to run the hook functions of the global value as well as in the local value.

下面这几行是本书作者在本机 Emacs 32.0.50 上真跑出来的，你可以照着敲一遍验证：

M-: (setq my-hook '(my-a))
M-: (add-hook 'my-hook 'my-b nil t)       ; 第三个参数 t = 设成 buffer-local
M-: (list my-hook (default-value 'my-hook))
⇒ ((my-b t) (my-a))
      ↑ 本地值    ↑ 全局那份没被动过
M-: (run-hooks 'my-hook)                  ; 看它到底跑了谁
⇒ (b a)                                   ; 先跑本地的 my-b，再跑全局的 my-a

对照组：第三个参数不写 t
M-: (setq my-hook2 '(my-a))
M-: (add-hook 'my-hook2 'my-b)            ; 没写第三个参数
M-: (list my-hook2 (default-value 'my-hook2))
⇒ ((my-b my-a) (my-b my-a))               ; 两层都被改了，等于直接改全局

回到 xref-backend-functions：在一个 Elisp 缓冲区里，它的 buffer-local 值 (elisp--xref-backend t) 读作「先用 elisp--xref-backend，然后接着照样用全局那份 etags--xref-backend」——两个后端都在链上，Emacs 会挨个问「你能不能处理这个符号」。敲 M- 求值 (default-value 'xref-backend-functions) 就能看到全局值（本书作者实测返回 (etags--xref-backend)）；想看当前 buffer 的完整值，在任意缓冲区里求值 xref-backend-functions（不带 default-value）。

技巧

记住这一条就够了：add-hook 第三个参数写 t，意思是「只在当前 buffer 生效，但全局那套照旧保留、照旧执行」。第 13 章配置包时会大量用到它——比如让某个「只在项目里该关掉」的功能只影响项目缓冲区，而不动你个人的全局配置。

今天真正的答案：Eglot 接管了跳转

这一节要更新原书最明确。Emacs 29.1 起，Eglot（Emacs 内建的 LSP 客户端）已经随 Emacs 分发。版本关系的证据就写在 eglot.el 里——它把这张对应表挂在 customize-package-emacs-version-alist 上：(Eglot ("1.12" . "29.1") ("1.12" . "29.2") ("1.12" . "29.3") ("1.12.29" . "29.4") ("1.17.30" . "30.1") ("1.24.31" . "31.1"))，即 Eglot 1.12 从 Emacs 29.1 开始随发行版分发，到 Emacs 31.1 是 1.24（我查到的本机 Emacs 32.0.50 里内嵌的正是 1.24）。它一启动，就把 eglot-xref-backend 挂到 xref-backend-functions 钩子上（我读了 eglot.el 第 2442 行确认）。

所以真实情况是：你按的还是 M.，但背后干活的已经不是 xref 自带的后端，而是你的语言服务器。这才是「统一前端」设计的兑现——xref.el 在这里的角色和 LSP 出现之前完全一样。

还有一件值得知道的事：Eglot 用 project.el 来找项目根目录。它的源码里直接调用 project-root 来确定 LSP 的工作区。所以上一节那套 C-x p 体系不只是方便你自己浏览文件——它是 Eglot 能不能正常工作的地基。你在一个不是版本控制仓库的裸目录里打开代码，Eglot 就会去找「transient project」，行为可能不如预期。

还有一件事要提醒：Eglot 在 Emacs 32 里没有默认键位。我查过，where-is-internal 对 eglot、eglot-ensure、eglot-shutdown 全部返回 nil，eglot 只有一个菜单栏入口（Tools > Eglot）。另外提醒一句：老配置里常见的 eglot-mode 和 eglot-retake 在 Emacs 32 里已经不是命令了——(fboundp 'eglot-mode) 和 (fboundp 'eglot-retake) 都返回 nil。所以每个项目里你都得自己绑一个，比如：

;; 在项目配置里：打开 C/C++ 文件时自动起语言服务器
(add-hook 'c-mode-hook #'eglot-ensure)

;; 全局兜底：任何时候按 M-l 起一个 Eglot 会话
(global-set-key (kbd "M-l") #'eglot-ensure)

用 eglot-ensure 而不是 eglot，是因为它做了幂等处理——文档字符串写得很直接：「Start Eglot session for current buffer if there isn't one.」（如果当前缓冲区还没有会话，就起一个。）挂在 c-mode-hook 上时，如果 Eglot 已经在管这个项目里的文件，它什么也不做。

要点

想判断「当前缓冲区是不是已经被 Eglot 管着」，用公开函数 eglot-managed-p（文档字符串是 「Tell if current buffer is managed by Eglot.」）。注意别写成 eglot--managed-p——带双横线的那个名字在 Emacs 32 里并不存在，我实测是 void function（内部真正对应的是一个叫 eglot--managed-mode 的 minor mode，不是函数）。同理，老配置里常见的 eglot-workspace-fallback 在 Emacs 32 的 eglot 里也已经找不到了，别照抄。

易错

如果你在 C/C++ 项目里既开了 Eglot 又按 M. 得到「找不到定义」，多半是语言服务器没找到编译数据库（比如 compile_commands.json），或者项目根被认错了。该做的是检查 project.el 认出来的根目录对不对（Mx project-current 会告诉你），而不是回退到 xref 的老后端。诊断信息看 Mx eglot-list-connections；Eglot 1.24 起还可以用 Mx eglot-describe-connection 看详细的连接状态。

进阶：TAGS、即时搜索和 LSP 该怎么选

原书在 xref 那节末尾讨论了三条技术路线，这里把结论整理得更明确一些，因为今天的选择比原书简单得多。

  1. TAGS（旧学派的产物）。做法是：把所有源文件里的标识符和它们的行号抽出来，存成一个巨大的静态查找表（传统上叫 TAGS 文件）。Emacs 32 里自带 etags（Emacs 自己的标签生成器，etags 这个命令开箱可用）；更快的 ctags 是外部程序（现在的事实标准是 universal-ctags），得自己装，Emacs 不带。
  2. 即时搜索工具：grep、ack、ag、ripgrep。原书推荐 dumb-jump（第三方，MELPA 有）——它利用 ripgrep 之类的搜索器，按当前 major mode 的规则猜「什么才算定义」，然后跳过去。这个方案在大项目上比 TAGS 快得多，因为不需要预先建索引，也不需要在文件改动后重建索引。Emacs 32 里 ripgrep 快得离谱，原书说它在现代硬件上「快得不可测」（unfathomably fast），我同意这个判断。
  3. LSP：今天的事实标准。

选型建议：

  • 有语言服务器（几乎所有主流语言现在都有）→ 用 Eglot，它给出的不只是跳转，还有补全、悬停文档、重命名、诊断。
  • 没有语言服务器的小语言 / 配置语言 → dumb-jump，或者用 ripgrep 包提供的 Mx rg（注意：rg 本身不是内建的，来自第三方包 ripgrep，得先从 MELPA 装；同时你本机要有 rg 这个可执行文件）再配合 xref 的 grep / rgrep 兜底。
  • TAGS 在超大项目里仍有意义（原书说它「在天文数字般大的项目里表现良好」），但日常用不着。

无论选哪条，M. 这个键不变。这就是 xref 存在的全部意义。

Dired 里的 xref：一个需要更新的说法

原书写「Xref 在 Dired 里也能用：按 A 搜索，按 Q 搜索并替换被标记的文件」。

键位没有变——Emacs 32 里 A 确实还是 dired-do-find-regexp（在标记过的文件里查找匹配），Q 确实还是 dired-do-find-regexp-and-replace（在标记过的文件里交互式替换）。我查了 Emacs 32 的 dired-mode-map（dired.el 第 2424 行开始的绑定表）：A 在第 2437 行，Q 在第 2450 行。

但机制变了。这两个命令现在的文档字符串里写的是「REGEXP 应当使用你本地 grep 命令支持的构造」，还提到了 grep-find-ignored-files 和 grep-find-ignored-directories 这两个过滤变量——而在 Emacs 32 的 dired.el 里，xref 这个词一次都没出现过（我 grep 过整个文件，零命中）。所以今天这两条命令走的是 grep 后端，不是 xref 体系。

这不影响你使用它们。实际效果上，Q 在几百个文件上做替换依然是好用的工具。知道它是 grep 而不是 xref 的意义在于：它的正则语法受限于你本机 grep 的实现（GNU grep 和 BSD grep 有差异），遇到奇怪的正则会报「Invalid grep regex」。

练习 14　光标停在一个函数名上，想跳到它的定义。按哪个键？

M.，即 xref-find-definitions。如果你开着 Eglot，实际干活的是语言服务器（Eglot 会把 eglot-xref-backend 挂到 xref-backend-functions 上），但键和界面完全一样。

练习 15　按 M. 跳走了，想回到原处，按什么？原书里这个命令叫什么？

按 M,。Emacs 32 里它绑定的主命令叫 xref-go-back，原书写的 xref-pop-marker-stack 还在，但已从 Emacs 29.1 起被标成废弃别名（define-obsolete-function-alias）。另外 CM,（xref-go-forward）是「反悔」——撤销上一次返回，回到当初按 M, 时所在的位置。

练习 16　在 dired 缓冲区里按 Q 跨文件替换，这背后用的是 xref 还是 grep？

用 grep。A 和 Q 的绑定没变（dired-do-find-regexp / dired-do-find-regexp-and-replace），但 Emacs 32 的 dired.el 里已经没有 xref 相关代码了，这两个命令的文档字符串明确要求「正则要符合本机 grep 支持的语法」。

练习 17　在 Emacs 32 里 M-x eglot-ensure 有没有默认键位？没有的话你一般怎么起？

没有。我用 where-is-internal 查过 eglot、eglot-ensure、eglot-shutdown，全部返回 nil；eglot 只有菜单栏入口 Tools > Eglot。（顺带一提，老配置里的 eglot-mode、eglot-retake 在 Emacs 32 里已经不是命令了，fboundp 返回 nil。）常见做法是自己在项目的配置里绑一个全局键，比如 (global-set-key (kbd "M-l") #'eglot-ensure)，需要时按一下就起。

五、看日志文件：Emacs 的隐藏强项

为什么日志值得专门学

读日志、盯构建输出、翻线上错误——这是程序员每天都要干的事。原书说得很准：日志文件里那些长得几乎一模一样的行，是最容易「看漏」的文本。用眼睛扫一百行近乎重复的内容，人会本能地开始跳读，然后漏掉真正重要的那一行。

Emacs 在这件事上有几件专门的工具。掌握它们之后，你看日志的方式会从「读」变成「筛」。

第一步：以只读方式打开

原书提到一个小机制很实用：如果文件本身不可写，Emacs 会自动用 read-only-mode 打开它。很多日志文件靠 chmod 设成了只读，所以「打开就是只读」往往是自动的，你什么都不用做。

什么时候需要解除只读？原书的答案很明确：当你接下来要对缓冲区做破坏性操作的时候，比如下面要讲的 flush-lines。只读模式下你不能删行，而删行正是缩小日志视野的手段。

易错

日志文件如果真被 flush-lines 改动了而你按了保存，就把日志毁了。不要对正在写入的日志用 C-x s。你的目的是在缓冲区里看得清爽，不是改磁盘上的文件。

第二步：筛掉无关的行

occur（Ms o）是这一节的主力。它的行为是：按一个正则，把当前缓冲区里所有匹配的行抽出来，放进一个叫 *Occur* 的新缓冲区，每行前面标着它在原文件里的行号。原缓冲区完全不动。

Emacs 32 里 Ms o 绑定的就是 occur（isearch 模块加载后我核对过全局绑定）。有个变化值得知道：搜索进行中按的 Ms o 现在触发的是 isearch-occur，而老名字 isearch-other-buffer 在 Emacs 32 里已经没有这个函数了。

原书提了一句很多人不知道的事：你可以在 *Occur* 缓冲区里再按一次 Ms o，对已有的结果再筛一层。机制是 Occur 缓冲区记住了上一次的搜索参数——存在 occur-revert-arguments 这个 buffer-local 变量里（我实测它的值是 ("a" nil (#<buffer …>)) 这种「正则 + 标志 + 原缓冲区」的形状），而重放动作交给 *Occur* 缓冲区里的 buffer-local revert-buffer-function（它的值就是函数 occur-revert-function）。效果是：先 ERROR，再 timeout，你就得到了「超时导致的错误」列表。这才是 occur 真正强大的用法——单次筛选谁都会，多次叠加才能处理复杂日志。

第三步：给关键信息上色

highlight（高亮，用不同的 face 即「外观样式」把匹配的部分染上颜色或加粗，让眼睛能快速抓住）。Emacs 的高亮是叠加式的：同一行可以有多种不同颜色的高亮共存。

原书这里有一条建议非常实用，值得原样记住：就算你记不住这四个键也没关系，只要知道它们全叫 highlight- 开头，需要的时候用 Mx 就能调出来。Emacs 的命令命名是有规律的——同一族功能共享前缀，所以「猜名字」这件事本身就可靠。这和第一章说的「Emacs 的 Elisp 没有命名空间、靠前缀防撞车」是同一件事的两面。

顺带说清 highlight-phrase 和 highlight-regexp 到底差在哪。翻 Emacs 32 的 highlight-phrase 文档字符串，它其实也接受正则（参数名就叫 REGEXP），唯一的额外行为是：「Also set search-spaces-regexp to the value of search-whitespace-regexp.」（同时把「搜索一个空格」放宽成「匹配任意长度的空白」。）

这个差别在日志场景里极其有用。日志经常在窄终端上折行，connection refused 可能被断成 connection 和 refused 两行。用 highlight-regexp 你得写成 connection\s-+refused；用 highlight-phrase 你直接打 connection refused，那个普通空格就已经自动等价于 \s-+ 了。所以看日志首选 Ms h p，需要精细控制才换 Ms h r。

第四步：直接砍掉噪音（不推荐在活动日志上做）

  • Mx flush-lines：问一个正则，把所有匹配的行从缓冲区删掉。提示语是 Flush lines containing match for regexp，读的就是一个普通正则（跟 M% 一样，直接敲 DEBUG 即可）。缓冲区处在只读状态时它会直接报错拒绝执行——这就是为什么必须先 Cx Cq。
  • Mx keep-lines：反过来，只保留匹配的行，删掉其余全部。提示语是 Keep lines containing match for regexp。

这两个都是内建函数直接当命令用。它们威力很大，也很容易造成「缓冲区内容和磁盘不一致」的错觉，所以动手前先想清楚：你是要「看得清爽」还是「要改文件」。看日志永远只是前者，解掉只读只是手段，不是授权——按完 Cx s 就把磁盘上的日志改了。删掉的行嫌可惜，还有个折中办法：Mx kill-matching-lines，它同样删匹配行，但会把删掉的内容放进 kill ring，想找回来时按 Cy 就能贴回去。

第五步：让日志自己更新

日志是活的。原书讲了两种模式，Emacs 32 里都还在：

  • auto-revert-mode（很老的老内置模式了——Emacs 22 的 NEWS 就已经在讲它的「自动跳到末尾」行为，Emacs 27 的 NEWS 又整节讨论文件变更通知）——底层文件一变，整个缓冲区重新加载。适合更新不频繁的日志。
  • auto-revert-tail-mode——像 Unix 的 tail -f 一样，文件变化时把新增内容追加到缓冲区末尾，并自动滚到末尾。适合追踪正在跑的构建。

两者都用 Mx 开启（Emacs 32 里都没有默认键位，也没有全局开启——我查过 auto-revert-mode 和 auto-revert-tail-mode 都是默认值 nil，而且 get 查它们的 globalized-local 属性返回 nil，也就是说它们是普通的、非全局化的 minor mode）。

Emacs 底层用的是文件系统变更通知（inotify 这类机制，现代平台上都有），不支持通知的老系统会退化成轮询（auto-revert-interval 控制轮询间隔，默认 5 秒）。这对你意味着：只要 Emacs 跑着，变化就能被察觉到，你不用按任何键。另外，这两个模式在只读缓冲区里照样能用——read-only 限制的是你手动编辑，重载缓冲区不受这条限制（我用一个 chmod 400 的文件实测过）。

要点

还有一个相关的设置：revert-without-query。注意它不是布尔量——在 Emacs 32 里它的类型是「正则列表」（:type '(repeat regexp)），默认值 nil 表示空列表、也就是什么都不特殊处理。它的含义是：如果文件名匹配上列表里某个正则，并且你在这个缓冲区里没有未保存的修改，revert-buffer 就不再问你。看到的那句询问，在有改动时是 Discard edits and reread from %s?，没改动时是 Revert buffer from file %s?。所以对日志文件，正确的写法是按名字给正则，比如 (setq revert-without-query '("\\.log\\'" "syslog"))；千万别写成 (setq revert-without-query t)——那是个列表被塞了 t，Emacs 会拿它当序列遍历而出错。（另外顺带一提：缓冲区本来就没被改过时，Mx revert-buffer 根本不会问，所以你大多数时候根本不需要动这个变量。老版本的 auto-revert-check-unchanged 在 Emacs 32 里已经没有这个符号了。）

练习 18　日志里有几千行，你想先只看 ERROR 行，再在结果里只看含 timeout 的。怎么做？

在原日志里按 Ms o，正则输 ERROR；然后在 *Occur* 缓冲区里再按一次 Ms o，正则输 timeout。Occur 缓冲区记住了上次的参数，第二次是对已有结果再筛一层。定位到具体某一行按 RET 回原文件。

练习 19　想在日志里把所有出现的 connection refused 染成红色，不删除任何行。用什么？

Ms h p，即 highlight-phrase。它不改动文本，只叠加一层着色。特别适合日志的是：它会把「一个空格」放宽成任意长度空白，所以直接打 connection refused 就能同时命中被折行拆开的那几行。需要精确控制正则时再换 Ms h r（highlight-regexp）。取消单处高亮用 Ms h u。

练习 20　你在 tail 一个正在增长的构建日志，希望新增行自动出现并且视图停在末尾。开哪个模式？需要先解只读吗？

开 auto-revert-tail-mode，工作方式等同 Unix 的 tail -f：文件一变就把新增内容追加到缓冲区末尾并滚过去。不需要先 Cx Cq 解只读——「只读」限制的是你手动编辑，重载缓冲区不受它管；我实测一个 chmod 400 的日志文件，两个 auto-revert 模式都能正常打开并在文件增长时刷新。另一个 auto-revert-mode 是整份重新加载，适合更新不频繁的文件。两者在 Emacs 32 里都默认关闭，也没有默认键位。

练习 21　用 DocView 打开一个 PDF，翻页用哪两个键？

n 翻到下一页，p 翻回上一页（doc-view-next-page / doc-view-previous-page）。SPC 是「滚动一行，到顶了才翻页」。想看 PDF 里的纯文本用 Cc Ct。

练习 22　想在日志缓冲区里删掉所有 DEBUG 行好让它短一点，第一步该做什么？

先 Cx Cq 解除只读（read-only-mode）。然后 Mx flush-lines，正则输 DEBUG。删完千万不要按 Cx s——你只是想看得清爽，不是想改磁盘上的日志。觉得比 occur 粗暴的话，Mx keep-lines 是它的反面（只保留匹配行）。

要点

最后把这一章的线索收一下。探索给你的是「任何时候都不慌」的能力：Ch 加上 which-key，Emacs 的任何功能你都能在三分钟内查到。项目管理给你的是「多文件是常态」的观念：Cx p 这一组键会随 Emacs 版本持续变厚（Emacs 31 才加了 Cx p C-x s），值得偶尔用「前缀 + Ch」重新扫一遍。编译与 xref给你的是「分层」的观念：xref 是永远不变的界面，语言服务器是可换的引擎；compilation-mode 从「跳转器」退成「日志阅读器」，但仍然是核心。日志这一节给你的是「Emacs 会替你做减法」的能力：长文本交给 occur、交给高亮、交给自动刷新，你只负责给对的那一个正则。
