十七、附录：速查表与排障手册

这一章不做叙述，只做三件事：把全书出现过的按键收拢成一张可搜索、可折叠的总表；把出问题时该按哪几个键写成一张排障表；把会卡住你的术语列成中英对照表。此外还补两节：怎么把 Caps Lock 改成 Control（X11、Wayland、macOS、Windows 四套现行做法），以及前面每一章的练习该怎么用、怎么自测。表里的按键与命令名在本机 Emacs 32.0.50 上用 emacs --batch -Q 逐条查过绑定关系，版本归属则比对同一套 Emacs 自带的官方手册（emacs.info、elisp.info）与 NEWS.28/29/30/31；凡是本机实测不出来的（比如 macOS 的 hidutil、esc-delay 这类本机构建里就没有的变量），正文里会写明依据来自哪份官方文档，或者直接标注「本机查不到，请自己核实」。

要点

本章的命令名与变量名以 Emacs 32.0.50 为准。你手上的版本更老时，某些命令可能还不存在——照抄会报 Symbol's function definition is void。碰到这种报错，正文里凡是列了该命令的地方都已经标了「本机这套构建里查不到」，你自己确认的办法是 Ch d（apropos-documentation）按功能描述搜；第四节开头那段「排障表怎么用」里也写了完整的三步。

一、按键总表：Cx 前缀

二、按键总表：其余前缀

先解释几个记号，后面的表才读得顺：C 是 Control 键；M 在字母上指 Alt 键，在标点键上指 ESC 键；S 是 Shift；CM 表示两个修饰键同时按住（终端里通常是 ESC ESC）。前缀键指按下之后还要再按一个键才能确定具体命令的按键，Cx、Cc、M 都是。

易错

M%（query-replace，按字面量逐个替换）和 CM%（query-replace-regexp，按正则替换）在键盘上只差一个 C，作用却完全不同：前者的「%」表示「逐个处理」，后者才是正则。用正则替换时要按 CM%，按成 M% 时方括号 [ 会被当成字面量而不是字符类，行为和你想的完全不同，而且不会报错。

另外提醒一句：Ms r 不是正则替换——本机实测它在普通缓冲区里未绑定；它是搜索过程中才出现的 isearch-toggle-regexp，作用是「把当前这次搜索切换成正则」。

易错

Emacs 没有一个叫 redo 的交互命令——实测 Mx redo 报「未定义」（(fboundp 'redo) 为 nil）。但这不等于「Emacs 没有重做」，撤销本身就是双向的：Cx u（undo，等价键还有 C/ 和 C_）会连续往回撤，撤过头了再按一次就 redo 回来了。

另有两个相关命令要分清（本机实测都存在、都是 commandp）：undo-only「只往回撤、绝不 redo」，undo-redo「撤销之前那些撤销操作」，也就是真·重做。官方手册把它们列为 Mx 命令，出厂没有默认按键，所以「照着敲不出来」不是你的问题。同样，Cx z（repeat）是「重复上一个命令」，跟撤销/重做不是一回事，别混用。

四、常见故障排障表

这一节按症状组织，不是按命令。四列分别是：症状、你可能撞上的原因、怎么确认、以及怎么修。先说三句通用的话：

  1. Emacs 卡住了先按 Cg，它对应 keyboard-quit，是所有命令的中止按钮。原书推荐的 ESC ESC ESC（keyboard-escape-quit）在某些终端里被终端自己截走了，Cg 更可靠。
  2. 按了键没反应，先问 Emacs：Ch c（describe-key-briefly）然后按下那个键，三秒得到答案。三十秒得到答案，而且这个答案永远对应你手上这个版本。
  3. 想知道一个功能到底存不存在：Ch d（apropos-documentation）输入功能描述，比如「indent」，Emacs 会列出所有相关的命令和变量。这比翻书、翻网都快。
要点

下面这张表里，凡涉及「这条命令在这个版本里叫什么」的判断，都在 Emacs 32.0.50 上实测过。但有一点必须说清楚：本机那套 32.0.50 的 loaddefs.el 只有 2808 条 autoload 记录，比正常构建少得多，所以需要靠 autoload 才会加载的命令在这里验不出来——例如 profiler-stop、profiler-report、auto-save-file、recover-file 之外的 display-mode 等，在这一版 fboundp 均为假，但这不代表你的 Emacs 里没有。凡是本表列了而你按了没反应的，一律用 Ch d 现查。

易错

症状：Cc x 或 Cm x 没反应。

可能原因：这两个前缀是「模式专用」的，出厂状态下全局键位表里几乎是空的——Cc 自己叫 mode-specific-command-prefix，只带一个 Cc ^；Cm f、Cm q、Cm g 实测都未绑定。真正的填充命令是 Mq，设置填充宽度是 Cx f。

怎么查：Ch m 看当前模式的键位表。

怎么修：改用上表里对应的键，或者用 Mx 直接调命令名。

易错

症状：终端里 M 打出来是 ESC 前缀串，Mx 正常但 Mf 之类的没反应。

可能原因：终端的 meta 发送方式（Escape Sequence）和 ESC 前缀冲突。

怎么查：在 *scratch* 里按 Mx version，看回显区显示的是什么。

怎么修：把终端的 meta 发送方式改成 Escape Sequence（多数终端在「首选项 → 高级」里）。更彻底的做法是让终端发 CSI u（Kitty 键盘协议），但不是所有终端都支持。

网上常见的建议是在 init.el 里写 (setq esc-delay 0) 来「消除 ESC 延迟」。本机这套 32.0.50 里 esc-delay 根本查不到（(boundp 'esc-delay) 为 nil，两份官方手册里也没有它的条目），所以我们无法替你确认它在你的 Emacs 里存在、更无法确认它能解决这个问题。正确做法是先自查：Mx M-x，回显区打出 self-insert-command 就说明这个键没绑命令，确实需要去查键位；别把 esc-delay 当成已知有效的解法照抄。

易错

症状：中文或其他非 ASCII 字符显示成乱码、方块或问号。

可能原因：文件编码与 Emacs 内部编码不一致；或者终端本身不是 UTF-8。

怎么查：Ch L（describe-language-environment）看当前语言环境。

怎么修：按 Cx RET f 再输入编码名（UTF-8、gb18030…），或者用 Mx set-language-environment。终端那边另设。

易错

症状：Emacs 启动时刷一堆红色警告，或者干脆停在 *Error Messages* 里。

可能原因：init.el 里某行有语法错误，或者某个包没装。

怎么查：用命令行加 -Q 启动可以跳过配置：emacs -Q。能起来就说明问题在配置里。然后把 (setq debug-on-error t) 放在 init.el 最前面（实测本机 debug-on-error 默认值是 nil），下次出错会直接跳到出错的那一行。

怎么修：出错的行会显示成一个 *Backtrace* 缓冲区，从下往上第一条是真正出错的调用。

易错

症状：敲了几个字母没反应，只在回显区显示按键名（C-x C-f 之类）。

可能原因：Emacs 进入了「两键前缀」状态，等你补第二个键。这不是卡住。

怎么查：按 Cg 放弃当前序列。

怎么修：记住常用前缀是 Cx / Cc / Ch / M-；补一个 Cg 就能重来。

易错

症状：缓冲区被切成窄窄的一条，看不到一半内容；或者以为内容被删了。

可能原因：narrowing（窄化）生效了——文件其实一行都没少，只是 Emacs 让你只看见一部分。常见于你之前在同一个文件里按过 Cx n n 限定范围，又没按 Cx n w 恢复。

顺带澄清一个常见误解：*Occur* 缓冲区（Ms o 的结果）不是靠 narrow 实现窄化的——本机实测它的 buffer-narrowed-p 为 nil，buffer-file-name 为 nil，它是一个全新的独立缓冲区，里面只有匹配行的一份拷贝。真要编辑并写回原文件，要在 *Occur* 里按 e（occur-edit-mode），然后 Cc Cc 存回去。

怎么查：Ch m 里有 Narrowed to 字样就是。

怎么修：Cx n w（widen）。养成习惯：进 *Occur* 之前先记住这个键。

易错

症状：Emacs 变得很慢，一动就卡，尤其在大文件里。

可能原因：字体高亮（font-lock-mode，即 Emacs 的语法着色）在超大文件里要花很多时间；或者某个包里开了低效的正则。

怎么查：Cg 中断后按 Cg g 再看；或者关掉自动高亮再看。

怎么修：关掉 font-lock-mode（Mx font-lock-mode）对比一下。

顺带纠正一个流传很广的说法：现代 Emacs 默认就只对可见部分做高亮——官方手册写明「Emacs initially fontifies only the visible portion of a buffer」，机制叫 JIT Lock（Just-In-Time，按需高亮），由 jit-lock 这个 customization 组控制。所以你不需要（也不该）去设 font-lock-mode 为某个特殊数值；真要调，看 Mx customize-group RET jit-lock。真正适合自己写进 init.el 的是「超大文件直接不高亮」：

;; 大文件干脆关掉字体高亮，提升响应速度
(defun my-no-font-lock ()
  "大文件里关掉字体高亮，提升响应速度。"
  (when (and font-lock-mode (> buffer-size 500000))
    (font-lock-mode -1)))
(add-hook 'find-file-hook #'my-no-font-lock)

怎么修：先另存一份（Cx Cw）保住自己的改动，再 Mx revert-buffer 读回磁盘版本，然后手工合并。开了自动保存（auto-revert-mode）时会更频繁出现。

易错

症状：Cu 撤销不回去了，或者撤销过头把想要的内容也撤了。

可能原因：Cx u 是「连续撤销」，撤销过头只能靠再撤销把它带回来；Emacs 没有叫 redo 的键，但有 undo-redo 这个命令（见第二节的易错框）。

怎么查：Ch l（view-lossage）能回看你按过什么。

怎么修：撤销过头就再按几次 Cx u 往前redo；如果连按次数太多已经不可控，先 Cx s 存一份，再 Mx revert-buffer 从磁盘重来（会丢未保存改动）。

易错

症状：按 Cx Cs 存盘时 Emacs 报 fatal error：设备或资源忙。

可能原因：文件被锁住了。最常见的是同一个文件在两个 Emacs 进程里同时开着（Emacs 的文件锁保护机制）；也可能是 NFS/网络盘的问题。

怎么查：报错信息里会给出锁文件路径（通常是 .#file）。

怎么修：确认另一个 Emacs 是不是还开着那个文件；关掉它，锁自动消失。确实不需要锁时全局关掉：

(setq create-lockfiles nil)

代价是失去这一层保护——两个 Emacs 同时写一个文件会互相覆盖，所以只在明确知道自己在做什么时用。

易错

症状：按 Mx package-install 一直失败，或者报签名错误。

可能原因：没配好 package-archives；或者第三方源（NonGNU、MELPA）的签名密钥不在 gnupg 环里。

怎么查：Ch v（describe-variable）输入 package-archives，回显区会列出当前配了哪些源。

怎么修：至少要有 GNU ELPA（https://elpa.gnu.org/packages/，随 Emacs 自带）。要装第三方包再加 NonGNU（https://elpa.nongnu.org/nongnu/，实测该路径下的 archive-contents 返回 200，是可用地址）。配置片段：

;; 只用 GNU ELPA：Emacs 自带，不用额外配
;; 加 NonGNU ELPA（非 GNU 认可但自由软件的包）
(require 'package)
(add-to-list 'package-archives
             '("nongnu" . "https://elpa.nongnu.org/nongnu/") t)
(package-refresh-contents)

签名问题按 Emacs 提示的 package-check-signature 逐个接受即可。

易错

症状：滚动时窗口乱跳、行被拉散，或者觉得「Emacs 反应很钝」。

可能原因：滚动量参数与你的滚轮不匹配。本机实测默认 mouse-wheel-scroll-amount 是 (1 ((shift) . hscroll) ((meta)) ((control meta) . global-text-scale) ((control) . text-scale))，也就是滚轮一下滚一行，Shift+滚轮横向滚。

怎么查：Ch v mouse-wheel-scroll-amount。

怎么修：改成一次滚三行：

(setq mouse-wheel-scroll-amount '(3))

想让光标所在行永远可见，开 scroll-margin（官方手册有明确条目，本机实测默认值是 0）：

(setq scroll-margin 5)
易错

症状：明明定义了缩写，敲进去却不展开。

可能原因：缩写表是缓冲区局部的；只在某个特定模式里定义的缩写，换个文件就没了。

怎么查：Mx list-abbrevs 列出当前缓冲区已定义的所有缩写。

怎么修：想让缩写全局生效，把定义包在 define-global-abbrev 里：

(define-global-abbrev "btw" "(by the way) ")
(define-global-abbrev "wip" "work in progress ")
易错

症状：Cg 也按不动，Emacs 彻底没反应。

可能原因：某个命令在死循环，或者某个包在等一个模态对话框。

怎么查：从另一个终端 Cc 打断（Emacs 会进入交互式中断），或用 Cg Cg 连按两次。

怎么修：最狠的办法是 Cg Cg 回车（recover-session）；实在不行从另一个终端 kill 掉进程，然后用 Mx recover-file 找 #file~# 找回改动。

易错

症状：装完某个包，Emacs 启动时间明显变长。

可能原因：包的初始化代码在启动时做了重活（扫整个目录、建索引、连网络）。

怎么查：Mx profiler-start 回车（选 CPU），干半天活之后 Mx profiler-report，它会按耗时排序列出函数。

怎么修：把该包的初始化推迟到真用到时再加载，或者干脆不开这个包。（本机这套构建的 autoload 表不完整，profiler-report 在这里 fboundp 为假，但这是构建裁剪造成的，你的 Emacs 上应该有。）

六、把 Caps Lock 改成 Control

原书把这一节放在讲按键之后，理由很简单：Emacs 里 C（Control）出现的频率远高于任何其他键位，右手小拇指要频繁在 A 和左 Ctrl 之间来回搬，长期下来很累。把 Caps Lock 映射成 Control，等于在右手拇指下多放一个 Control，很大一部分人试过之后就回不去了。

下面四套做法按操作系统分。请只做你现在这台机器上那一套，不要把四种混着设——同时设置会互相打架，你会分不清是哪个在起作用。

易错

先讲清楚三条必须知道的代价，再动手：

  • 改完之后打不出大写字母了。Caps Lock 不再是大写锁定。需要临时打大写，用 Shift 加字母（这是绝大多数情况唯一需要的），或按两次 Shift（Caps Lock 的临时替代）。
  • 这影响的是整台机器，不只是 Emacs。终端里 Cu（行首删除）、Ca、Cc 都会跟着变——这通常是好事，但如果有脚本依赖大写锁定就可能出问题。
  • Emacs 里的 CM（Control-Meta）在某些终端上需要连按两个 ESC。官方手册的说法是：终端没有真正的 Meta 键时，CMf 就是「ESC 然后 Cf」。（顺带澄清一个常见误会：Emacs 31 确实新增了 tty-cursor-movement-use-TAB-BS，但它管的是终端上光标移动的显示优化、为屏幕阅读器让路，和 CM 怎么发完全无关，别指望它解决这件事。）

6.1 Linux / Wayland：keyd

Wayland 桌面（GNOME、KDE Plasma、Sway、Hyprland 等）上，只有内核层方案是可靠的。X11 的 xmodmap 那一套在 Wayland 下要么根本不生效，要么每个终端各自为政、结果不一致。

keyd 是一个 Linux 下的按键重映射守护进程，GitHub 仓库 rvaiya/keyd（MIT 许可，写稿时实测 6013 星，最近提交 2026-06-01，正式版 v2.6.0 发布于 2025-12-19）。它工作在 evdev/uinput 内核输入层，所以对 X11、Wayland、纯终端（tty）一视同仁——这是它相对 xmodmap 的核心优势。

# 从源码安装（README 给出的官方步骤）
git clone https://github.com/rvaiya/keyd
cd keyd
make && sudo make install
sudo systemctl enable --now keyd

配置文件放在 /etc/keyd/default.conf。README 里给出的「Caps Lock 按下是 Control、点按是 Escape」这段：

[ids]

*

[main]

# 按住时是 control，点一下是 esc
capslock = overload(control, esc)

# 把 esc 挪回原位
esc = capslock

然后 sudo keyd reload 让配置生效。改完按 Caps 试一下。

如果配置文件写坏了导致键盘完全没反应，keyd 的 man page 记了一条逃生序列：连按 Backspace + Escape + Enter 会强制让 keyd 退出，这样你还能用键盘操作终端修配置。

进阶：keyd 还能做什么，以及「其他键也一起改」的正确写法

keyd 的 overload 只解决「同一个键两种行为」。更常见的诉求是「Caps Lock 当 Control，同时 Shift+Caps Lock 还是原来的大写锁定」，keyd 用 layer（层）表达。注意层名就是括号里那个名字，不是「层名+修饰键」——man page 的写法是 [capslock]，[capslock:C] 这种形式不存在。它给的示例之一是：

[main]

capslock = layer(capslock)

[capslock:C]

[capslock+shift]

h = left

man page 说：这段配置会让 Shift+Caps+h 得到 ←，同时 Caps 和 Shift 单独按下时保持各自原来的功能。它还有一条硬性规则：复合层（用 + 组合的层）必须定义在它所依赖的那些层之后——顺序写成 [layer1]、[layer2]、[layer1+layer2] 是对的，反过来无效。

如果你的设备「一个 id 对应多种类型」，配置里 [ids] 段可以用 k: 前缀只匹配键盘、m: 前缀只匹配鼠标（例：m:046d:b01d）；用 - 前缀排除某个 id。man page 有三条提醒值得记住：通配符 * 只会匹配被 keyd 识别成键盘的设备，鼠标必须显式列出 id；鼠标支持目前是实验性的，主要面向传统鼠标/触控板；某些鼠标（man page 举例 Logitech MX Master）会被误认成键盘，需要手动拉黑。另外同一配置文件里的所有键盘共享同一状态，这是用来把多个输入设备联动（比如脚蹬）的好办法。

用 keyd monitor 可以打印实时按键事件，用来查设备 id 和键名。注意 keyd 跑着时看到的是 keyd 处理之后的结果；要看原始事件得先停掉 keyd。

6.2 Linux / X11：xmodmap 与 xbindkeys

如果你还在 X11（不是 Wayland），最轻量的做法是 xmodmap。它把 Caps Lock 重新定义成 Control，同时把 Escape「借」给 Caps Lock——这样原来的大写锁定不会彻底消失，而是变成一个不占地方的备用键：

# 立即生效（只影响当前 X 会话）
xmodmap -e 'keycode 37 = Control_L'
# 或者把 Caps Lock 换成 Escape
xmodmap -e 'keycode 9 = Escape'

# 写进 ~/.Xmodmap 让它每次登录都生效
xmodmap -e 'keycode 37 = Control_L' >> ~/.Xmodmap
xmodmap -e 'keycode 9 = Escape' >> ~/.Xmodmap

这里的 37 是标准 PC 键盘上 Caps Lock 的 keycode，9 是 Escape 的。你的键盘如果不是标准布局，用 xev（按 Caps，看输出里 Keycode 那一行）查实际编号。

易错

xmodmap 有两个已知局限：一是只对 X 会话生效——切到 tty（Ctrl+Alt+F）、或者 XWayland 下的原生 Wayland 应用，都可能不跟随；二是要等会话启动脚本跑，有时会和其他改键位的工具冲突。如果你在 Wayland 上，正文 6.1 的 keyd 才是应该选的方案。另外，某些终端（比如 GNOME Terminal）有自己的「发送 Escape 序列」设置，可能覆盖这一层。

另一个更灵活的选择是 xbindkeys，它用配置文件声明「某个按键组合 → 执行某命令」，适合把 Caps+某键做成一整套新层。代价是它也是 X11 专用、要装守护进程，而且配置语法比 xmodmap 啰嗦。只想换 Caps Lock 的话不值得；想做 Vim 风格的 home row mod 之类才值得。

6.3 macOS：hidutil 与 Karabiner-Elements

macOS 从 10.12（Sierra）起改变了按键重映射机制，Apple 为此专门写了技术文档 TN2450。

先说结论：macOS 上最省事的是系统自带的「修饰键」设置面板。它是图形界面、改完立即生效、重启后依然有效，也不依赖任何第三方软件。要找的是系统设置 → 键盘 → 键盘快捷键 → 修饰键，在「Caps Lock 键」的下拉里选「Control」。

它的局限是：Caps Lock 变成 Control 后，大写锁定功能就没有入口了。

如果你需要「按一下 Caps Lock 是 Escape，按住是 Control」这种双重行为，系统设置做不到，得用下面两个方案之一。

方案 A：hidutil（系统自带命令行工具）。Apple 技术文档 TN2450 给出的用法是 hidutil property --set 后面跟一段 JSON 描述「源按键 → 目标按键」的映射，键码是 0x700000000 或上 USB HID 键盘/键垫页的 usage ID。该文档明确说了三件事，值得逐字记住：

  • 重映射适用于所有用户，只要有活动的键盘服务就一直有效；
  • 系统重启后失效，或者拔掉最后一个键盘后失效；
  • 不需要任何特权（不用 sudo）。

TN2450 的键表里 Keyboard Caps Lock 的 usage ID 是 0x39，Keyboard Escape 是 0x29，Keyboard Left Control 是 0xE0。所以最基本的「Caps Lock 变成 Control」是：

hidutil property --set '{"UserKeyMapping":[{"HIDKeyboardModifierMappingSrc":0x700000039,"HIDKeyboardModifierMappingDst":0x7000000e0}]}'

查询当前状态用 hidutil property --get "UserKeyMapping"，返回 (null) 表示没有任何映射生效。因为重启会丢，要持久化就放进登录项里跑一次。这条路我只找到 Apple 官方文档层面的依据，hidutil 在你手上的 macOS 版本上是否接受上面这组具体键码，请先用 --get 和 man hidutil 核对一遍。

方案 B：Karabiner-Elements。这是 macOS 上功能最全的重映射工具，GitHub 仓库 pqrs-org/karabiner-elements（Unlicense，写稿时实测 22903 星，最近提交 2026-09-28，正式版 v16.3.0 发布于 2026-09-06）。README 明确列出的支持系统是 macOS 13 Ventura 到 macOS 27，Intel 与 Apple Silicon 均可。安装走官网或 brew install --cask karabiner-elements。

它用一个 JSON 文件描述规则。Karabiner-Elements 的规则体系叫 complex modification，基本结构是「from（什么条件下）+ to（要发出什么）」。要实现「按住是 Control、点一下是 Escape」这种双重行为，靠的是 to 数组里两个条目的先后顺序——先处理「按住」，再处理「单独点按」，Karabiner 自己会按这个顺序解释它们（源码里对应的两个概念是 to_if_held_down 和 to_if_alone，另外还有可调的 to_if_alone_timeout_milliseconds、to_if_held_down_threshold_milliseconds）：

{
  "complex_modifications": {
    "rules": [
      {
        "description": "Caps Lock 单按 = Escape，按住 = Control",
        "manipulators": [
          {
            "type": "basic",
            "from": {
              "key_code": "caps_lock",
              "modifiers": { "optional": ["any"] }
            },
            "to": [
              { "key_code": "left_control", "modifiers": ["left_control"] },
              { "key_code": "escape" }
            ]
          }
        ]
      }
    ]
  }
}

这段 JSON 我没有在真实 macOS 上跑过（本机是 Linux）；「按住在前、点按在后」这个顺序依据的是 Karabiner-Elements 官方文档与仓库源码里的 to_if_held_down / to_if_alone 机制。落到你自己的配置前，请照官方文档（karabiner-elements.pqrs.org/docs/）核对字段名——JSON 里字段拼错不会报错，只会静默不生效。

6.4 Windows：PowerToys Keyboard Manager

Windows 上别再用老的注册表改键或者 AutoHotkey 脚本了——那类方案在新版本 Windows 上经常失效，而且会破坏系统快捷键。官方工具是 PowerToys（GitHub 仓库 microsoft/PowerToys，MIT 许可，写稿时实测 139167 星，最近提交 2026-10-02，即前一天），其中的 Keyboard Manager 专门做重映射。

微软官方文档里和「把一个键变成组合键」相关的规则，写得比大多数第三方教程清楚：

  • 要重映射的是 Select 那一列（输入键），目标填在 To send 列；
  • 目标可以是单个键、一个快捷键组合、或者一段 Unicode 文本。文档给的例子是「按 Ctrl 发出 ⊞ Win ←」，也就是把一个键映射成组合键——正是 Caps Lock → Control 要的能力；
  • 重映射只在 PowerToys 运行时生效。退出 PowerToys 就恢复原样。
易错

文档里有两条限制要记住：⊞ Win + L 和 Ctrl + Alt + Del 是操作系统保留的，不能重映射；Fn 键通常也不能。另外——这条对 Caps Lock 特别关键——文档里有个行为说明：重映射在「按下」时就执行，不是「松开」时，所以被重映射的键即使出现在别的组合键里也会先生效。

6.5 还有一条只在 Emacs 里做的路：keyboard-translate-table

最后一种做法是不动系统，只在 Emacs 内部翻译按键。Emacs 31 把这项功能做成了交互式的：NEWS.31 的「Editing Changes in Emacs 31.1」里明写，key-translate 现在是交互命令，会依次问你「把哪个键翻译成哪个键」并设置 keyboard-translate-table；同时新增了 key-translate-remove 用于撤销。本机实测这两个命令都存在。

;; 最省事：走交互命令，两次询问就设好了
;;   M-x key-translate RET 问 FROM，再问 TO
;; 要撤销就 M-x key-translate-remove RET 问 FROM
;;
;; 写成一行也行。官方手册的示例长这样（本机实测可用）：
(key-translate "C-x" "<control-x>")
(key-translate "C-c" "<control-c>")
(key-translate "C-v" "<control-v>")
(keymap-global-set "<control-x>" 'kill-region)
(keymap-global-set "<control-c>" 'kill-ring-save)
(keymap-global-set "<control-v>" 'yank)

这里有个容易踩的坑：keyboard-translate-table 要的是一张字符表（char-table），翻译的是「终端读进来的字符」，不是键序列。所以参数得用 kbd 记法之外的形式——手册给的 (key-translate "C-x" "<control-x>") 里两端都是字符串，表示「把字符 C-x 翻译成控制字符」。网上常见的 (make-sparse-keymap) + define-key 写法是错的：那是给 keymap 变量用的，放进 keyboard-translate-table 类型对不上。还有一点：翻译发生在输入法之前，中文/日文等输入法的候选过程不受它影响。

至于「把 Caps Lock 翻译成 Control」这种需求：keyboard-translate-table 面对 GUI 终端时要终端支持扩展 ASCII 输入才行，在纯终端里意义有限——所以这一节真正推荐的还是前面 6.1 到 6.4 的系统层方案。

这条路的代价和收益都很明确：收益是零系统风险、随时能撤；代价是你在终端里还是打不出 Cc、Cd 这些 Emacs 之外的常用 Ctrl 组合，而且符号输入、Emacs 自己的快捷键定义（比如 define-key 写 C-c）不会跟着翻译。什么时候不该用它：如果你本来就打算让终端里的 Cu、Ck 也工作，系统层方案（keyd / hidutil / PowerToys）才是对的选择。

最后一句提醒：改完之后用 Ch k 在 Emacs 里验一下——按一下你以为现在是 Control 的那个键，看 Emacs 是不是认出它为 C- 开头的按键。系统层改错了、Caps Lock 还是大写锁定的情况下，这一步会立刻暴露问题。

七、前面各章的练习：怎么用、怎么自测

本书每一章末尾都有一个带「显示答案」按钮的练习块。这一节说明它们是怎么设计的、你应该怎么用，以及——如果答案和你的理解不一致——怎么判断是书错了还是你错了。

练习块的三个组成部分

按键命令作用
（无按键）data-answer 属性标准答案的纯文本，网页脚本用它做自测判分。它只认你写的答案里「包含」这段文本，不认同义改写——所以写 C-x C-f 就别写「打开文件的快捷键」
（无按键）显示答案 按钮点一下展开答案，按钮文案变成「隐藏答案」。展开状态存在浏览器的 localStorage 里，下次打开还在
（无按键）自测模式 开关开启后所有答案默认折叠，并且练习之间串上「上一题 / 下一题」按钮，适合一段一段刷
（无按键）div.keys 折叠块本附录所有按键表在手机上默认折叠，点标题才展开

三类练习，三种做法

练习分成三类，做法完全不同，别用同一种方式对待。

  1. 认键类（「Cx Cf 干什么？」）——查表能过，但没意义。这类题的意义是让你在真机上按一遍确认「我手上的版本确实是这样」。做法：打开 Emacs，按那个键，看结果对不对。
  2. 动作类（「怎么把整行往上移一行？」）——这是真正需要练熟的。做法：在 *scratch* 里真的敲一遍。练到不用想为止。
  3. 概念类（「什么叫 killing 和 deleting 的区别？」）——背没用，要能举例。做法：随便找个文件，用命令实际演示一遍，然后用自己的话复述。
技巧

最有效的自测方式不是看答案，而是合上书去 *scratch* 里做。打开一个空缓冲区（Cx b 然后输入 *scratch*），敲几行字，把这一章的键位全部试一遍。*scratch* 的内容不会保存到任何文件，放心折腾。

易错

答案和你的 Emacs 对不上怎么办？按顺序做三件事：

  1. 按 Ch Ca（about-emacs）看自己的版本号，然后对照本书第 16 章的版本差异表。
  2. 按 Ch k 问 Emacs 那个键现在到底是什么。有些按键在 Emacs 29→30→31 之间换过归属，本书写的是它写稿时的版本。
  3. 如果 Ch k 也说「未绑定」，那就是你装了什么包改过键位（比如 evil-mode、hydra、paredit）。用 Ch b 看当前模式的完整键位表。
要点

这一章（第十七章）的练习全部围绕查询能力，而不是记忆能力。下面十道题没有一道需要你背，任何一道都能用前面几节的表或 Ch 系列查出来——这正是这一章想传达的意思：Emacs 的正确用法是随时能问，不是全记住。

练习 1　你按了一个键，什么也没发生，也没有任何提示。用一组键问 Emacs「这个键到底是什么」，要拿到完整说明（含它绑定在哪个文件里）。

按住那个键，再补 Ch k，然后松开。命令是 describe-key。想只要一行短答案就按 Ch c（describe-key-briefly）。

练习 2　你不知道 Emacs 有什么命令能做到「重新缩进选中的区域」，也记不住命令名。用哪一组键按功能描述去搜？

Ch d（apropos-documentation），然后输入 indent。它搜的是文档内容而不是命令名，所以就算你完全不知道命令叫什么，也能找到 indent-region。配套的 Ch a（apropos-command）才是按命令名搜。

练习 3　你想知道命令 save-some-buffers 现在被绑在哪些键上。用哪个命令？

Ch w（where-is），然后输入命令名。它会列出当前所有绑着这个命令的按键——这是查「我的配置改了哪些键」最直接的办法。

练习 4　你在 Python 文件里按 Cc Cc 想缩进，结果整个文件被发去执行了。用哪个命令能立刻看清「这个键在这个模式下到底是什么」？

Ch m（describe-mode）。它会列出当前模式（这里是 python-mode）以及该模式下所有可用键位和命令名。更快的办法是只问一个键：Ch k 然后按 Cc Cc。

练习 5　你之前在某个文件里把范围限定过，现在打开它只看得到一小段，其余部分像是「不见了」。用哪一组键把整个文件重新显示出来？（注意：文件内容其实一个字节都没丢）

Cx n w（widen）。这是 narrowing（窄化）的逆操作：Cx n n 把可见范围限定住，Cx n w 再放开，文件本身从头到尾一个字节都没改。判断方法：Ch m 里会写明 Narrowed to。

顺便纠一个常见误解：*Occur* 缓冲区（Ms o）不是靠 narrow 实现的，它是独立缓冲区，只装匹配行的拷贝；想改并写回原文件，要在里面按 e 进 occur-edit-mode。

练习 6　你要把一段排得参差不齐的文字补齐到每行 70 列。用哪个按键？注意：不是 Cm q，那个键在 Emacs 32 上未绑定。

Mq（fill-paragraph）。想改宽度按 Cx f（set-fill-column），因为本机实测 fill-column 默认就是 70。另外在 Lisp / Python 这类语言模式下 Mq 换成了 prog-fill-reindent-defun，重排的是整个函数。

练习 7　你改了文件，但 Cx Cs 之后磁盘上的文件没变，模式行上有个奇怪的小标记。用哪一组键切换它？

标记是只读状态的提示。按 Cx Cq（read-only-mode）切换可写/只读。要确认是不是这个原因，按 Ch m 看 read-only-mode 的值。

练习 8　你在 Emacs 里打开着一个文件，但磁盘上的那个文件被别的程序改过了（git checkout、另一个编辑器）。你决定放弃 Emacs 里的版本、读回磁盘上的。用哪个命令？这个操作会丢改动，Emacs 会先问你。

Mx revert-buffer。想先保住自己的改动就 Cx Cw 另存一份，或者先 Cx Cs 存了再说。

练习 9　你刚才那次「重新缩进整个文件」做错了，想撤回。注意：Emacs 没有叫 redo 的交互命令。用哪一组键？连续按会发生什么？

Cx u（undo），笔记本键盘上也可以按 C/ 或 C_。连按会连续一步步往回撤；撤过头了就再按它，redo 也就回来了——因为 Emacs 的「撤销」本身就是双向的，不需要另设一个 redo 键。真想显式重做，可以用 Mx undo-redo（它出厂没有按键）。

练习 10　你按下 Cx 之后什么都没发生（回显区显示 C-x 在等你补第二个键），又误按了几个键，现在想重来。用哪个键？

Cg（keyboard-quit）。它会放弃当前的按键序列和正在执行的命令。原书推荐的 ESC ESC ESC（keyboard-escape-quit）也能退出，但在某些终端里会被终端自己截走，Cg 更可靠。

要点

十道题做下来，你会发现它们全都用到了同一件事：让 Emacs 回答。这就是原书结尾那句话的意思——掌握 Emacs 的办法不是背下所有键位，而是学会向它问正确的问题。带着这本附录你还会继续往后查；不带它，你也已经会查了。
