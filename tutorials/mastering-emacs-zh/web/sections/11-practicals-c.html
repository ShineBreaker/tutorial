十一、实用篇（三）：Dired、编译与 Shell

这一章讲 Emacs 的第三重身份：如果 C-x C-f 打开的是文件，C-x d 打开的就是整个文件系统。你会学会在 Dired 缓冲区里标记、成批重命名、批量删除、跨目录操作，然后用 M-!、M-x compile 和三种内置 shell 把 Emacs 接到命令行上。读完你能把 90% 的 ls / mv / make / grep 杂活从终端搬进 Emacs，并且知道今天该选 shell、eshell 还是 vterm。

要点

本章所有键位与命令名，都在本机 GNU Emacs 32.0.50 上用 emacs --batch -Q --eval 逐条查过。跟原文（写作于 Emacs 26–30 时代）不一致的地方，我都会单独标出来并说明「从哪个版本开始是这样」。凡是第三方包，会写明包名与安装源。

一、Dired 是什么：Emacs 的「增强」模型

Dired（读作「迪瑞德」，全称 Directory Editor，目录编辑器）是 Emacs 自带的目录浏览器。它把一个目录下的文件列成一个可编辑的文本缓冲区，你在里面看到的每一行就是一个文件或子目录。

关键的心智模型是 augmentation（增强）：Emacs 并不自己实现「列目录」这件事，它调用外部命令 ls -al，把命令的标准输出原样塞进缓冲区，再对这个缓冲区做后处理——给文件加上字体高亮、给它加上「按下 RET 就能打开」的超链接属性、把权限字符串 -rw-r--r-- 标成灰色、把目录名标成蓝色。Emacs 内部管这套机制叫一个 major mode（主模式）——dired 缓冲区的主模式就叫 dired-mode。

这个模型的价值在于：结果本身就是文本。所以 Dired 缓冲区里的所有移动命令（C-s / C-r 增量搜索、C-n、鼠标、书签、寄存器）全都免费可用；你也可以像对待任何文本一样选中几行、按 M-w 复制出去，粘到邮件或聊天窗口里。同一套机制也是 M-x grep、M-x compile 的工作方式——这正是原书反复强调的「Emacs 的 buffer 范式」在实践中最漂亮的一次体现。

要点

Windows 上没有 ls 怎么办？不用担心。Emacs 32 内置了一套用 Elisp 写的 ls 模拟层，直接调用操作系统接口取文件列表，不调用外部进程。所以 Windows、macOS、Linux 上的 Dired 界面完全一致。换句话说，Dired 在跨平台这一点上比「真的去跑 ls」更稳。

打开 Dired 的四种方式

  1. C-x d —— 全局键，绑定到命令 dired。按下后 Emacs 在 minibuffer（屏幕底部那行迷你输入行）里问你要目录名，默认值是当前缓冲区所在的目录（变量 default-directory）。直接按 RET 就能看到当前文件所在目录的全部文件。
  2. C-x 4 d —— 命令 dired-other-window，在另一个窗口（Emacs 把一块屏幕区域叫做窗口，window，和操作系统窗口不是一回事）里打开，不打断你正在看的文件。
  3. C-x 5 d —— 命令 dired-other-frame，在另一个 Emacs 框架（frame，Emacs 里的顶层窗口，类比 VS Code 的多窗口）里打开。
  4. C-d —— 「在 C-x C-f 找文件的过程中按 C-d 跳到该文件所在目录的 Dired」这个技巧，是 ido（Emacs 自带的 IDO 模式）提供的，不是默认行为：它的命令叫 ido-magic-delete-char（ido.el 里叫「Magic C-d」），只有在光标已经位于输入行末尾、且你输入的词正好匹配一个已存在的文件或目录时才触发（源码注释原文是「C-x C-f ... C-d enter dired on current directory」）；用 FIDO（第三方包，IDO 的改进版）同样有效。不用 IDO / FIDO 的话，Emacs 默认的 minibuffer 键位里根本没有 C-d 这一条——想达到同样效果，用 C-x d 或者 M-x dired-jump（光标所在文件的目录）就行。

当然，任何命令都可以用 M-x（Emacs 的「万能前缀键」，按下后输入命令名再按 RET）调用，比如 M-x dired、M-x dired-jump。

技巧

Tramp 联动。如果你在上一章学会了 Tramp（在 Emacs 里编辑远程机器上的文件），那么在 /ssh:server:/home/me/src 这类远程路径上执行 C-x d，Emacs 会自动弹出一个 Dired 缓冲区列出远程目录。所有标记、重命名、删除命令在远程目录上一样能用。这一条是 Dired 相对文件管理器最大的隐藏优势——你可以在远端机器上用 M-x dired + R 批量改文件名，不用 ssh 上去敲 mv。

二、导航：Dired 就是一个普通缓冲区

因为 Dired 缓冲区本质是文本，所以它继承了 Emacs 全部的移动与搜索能力。增量搜索（C-s / C-r）、方向键、鼠标点击，在 Dired 里都照常工作。除此之外，Dired 自己额外提供了一批导航键——也包括一组专门在文件之间跳转的搜索键（M-s a C-s、M-s f C-s，见第四节）。

三、标记与取消标记：一次操作一批文件

mark（标记）和 flag（删除旗标）是 Dired 里两个必须分清的概念。原文特别强调了这一点，我再强调一遍：

  • 标记 *（命令 dired-mark，键 m）：这是「选中」的泛称。标记过的行左边会显示一个星号 *。之后你敲的大写字母批量操作命令（复制、重命名、改权限……）作用在所有被标记的文件上。标记不会导致任何文件被删除。
  • 删除旗标 D（命令 dired-flag-file-deletion，键 d）：在行前面插一个字母 D。只有 x 这条命令会去删「被打了 D 旗标」的文件。

两者的区别在实践中非常有用：你可以先打一堆 * 标记，选中一批要做某件事的文件；也可以打一堆 D 旗标，表示「这批待会儿要删」。它们互不干扰。原书写得很准确：「mark 永远不会被删除命令影响，flag 也永远不会被其它操作命令影响，只有一条命令会连标记的一起删。」

要点

m 和 d 执行完都会自动把光标移到下一项（相当于替你按了一次 C-n），所以你可以一路连按 m m m 一路标下去。嫌快就按住 M-3 m——负数参数会让操作反向，即「标记当前项和往上两项」。C-u m 同理，往回标。

* 前缀键：批量标记的瑞士军刀

单独的 m 只能一次标一个。*（星号）是一个前缀键，按下去会进入一个专门做批量标记的子映射——它不是一个独立命名的小键位表：dired.el 里直接写的是 (define-key dired-mode-map "*" (make-sparse-keymap " *")) 这样的匿名稀疏键位表，Emacs 里不存在 dired-subdir-mode-map 这个变量（本机 32.0.50 实测 boundp 返回 nil，本机整个 lisp 目录里也搜不到这个名字；我又查了上游 emacs-23.7 / 24.5 / 25.1 / 29.1 的 dired.el，同样一次都没出现过）。要临时改它的键，得自己重建这个匿名键位表。下面都是本机 Emacs 32.0.50 lookup-key 实测的结果：

四、批量操作：把 mv / cp / chmod 搬进缓冲区

这是 Dired 的核心价值所在。所有大写字母的批量操作命令遵循同一条规则：如果缓冲区里有被标记（*）的文件，就作用于全部标记文件并弹出确认清单；否则只作用于光标所在的这一行。

技巧

标记一个目录 = 递归处理它整棵树。这是个很多人不知道的福利：A、Q 的文档里都写着「如果被标记的是目录，会递归处理其中所有文件」（被 grep-find-ignored-files 和 grep-find-ignored-directories 匹配掉的除外）。也就是说，* /（标记所有目录）之后直接 Q，就能对整棵目录树做一次跨文件正则替换——以前这活儿是 grep -rl 加 xargs sed 的组合。

易错

D 和 x 别搞混。原文专门提醒过：D 删的是打星号选中的文件，x 删的是打 D 旗标的文件。如果你在 m 标记了一批之后手滑按了 D，那一批就真的被删了。安全习惯：用 d 打旗标 → 检查一遍 → x 统一删除。D 还有个容易被忽略的细节：它删的是「被标记的、但没被旗标」的文件（菜单里那一条就叫「Delete Marked (Not Flagged) Files」）——所以已经打过 D 旗标的行再按 D 反而删不掉。删除前 Emacs 会弹出一个名为 *Deletions* 的窗口，把待删文件列成清单，再问一句 y/n；你按 n 取消的话回显区会显示 (No deletions performed)，只有真的失败的文件才会被列成报告（现代 Emacs 不再有「Deleted N files」这句提示）。注意这个清单是只读的展示窗口，不是 Dired 缓冲区——你没法在里面改标记；而且待删文件只有一个时 Emacs 干脆不弹窗口，直接问 y/n。

Tree Dired 与 image-dired。把多个目录用 i 插进同一个缓冲区之后，C-M-d（dired-tree-down）在光标处建一棵子树、C-M-u（dired-tree-up）把整棵子树删掉、C-M-n / C-M-p（dired-next-subdir / dired-prev-subdir）在子目录节点间跳、M-G（dired-goto-subdir）跳到指定子目录。核心 dired 还绑了一组 image-dired（Emacs 自带的图片浏览器）的键：C-t d 显示缩略图、C-t t 给选中图片打标记、C-t j 在缩略图缓冲区里跳转——只在你有一堆图片要过一遍时才有用。

五、跨目录：Dired 还能把一棵树塞进一个缓冲区

这是原文特别强调、但大多数人都没用过的能力。

按 RET 进入子目录会开一个新的 Dired 缓冲区；而把光标放在某个目录行上按 i，命令 dired-maybe-insert-subdir 会把这个子目录的内容直接插入到当前缓冲区里，成为一棵嵌套的目录树。反复这么干几次，你就能在一个缓冲区里同时看到五六个目录。

这么做的意义是：标记和操作命令会跨越所有出现在同一缓冲区里的目录。也就是说，你可以「顶层选 3 个文件 + lib/ 里选 2 个 + docs/ 里选 1 个」，然后按一次 R 把这 6 个文件一起改名/移动。命令会自动补全出它们的相对路径，你根本不需要管它们在不同目录。

配套的折叠键是 $（折叠/展开光标处的子目录）、M-$（全折叠/全展开）、C-M-n / C-M-p（在子目录节点之间跳转）、M-G（dired-goto-subdir，跳到指定子目录）。折叠起来的子目录里所有命令都不生效——所以删之前先按 $ 折起来，等于给自己加了一道保险。

递归：不用 find + xargs

手工按 i 插目录显然不递归。Emacs 为此准备了一组 find 包装命令：它们调用系统的 find，但把结果做成一个 Dired 缓冲区，所有 Dired 命令照常可用。

本节按键：find 系列命令（用 M-x 调用）

按键命令作用
M-xfind-dired最通用的一条：先问目录，再让你写完整的 find 表达式（例如 -name "*.py"）。它实际执行的是 find . \( ARGS \) -ls（结尾的 -ls 由变量 find-ls-option 决定），结果进 *Find* 缓冲区；因为结尾是 -ls，输出的列才能对齐成 Dired 列表

技巧

M-x find-name-dired 然后输入 *.py，接着 m m m 标记三个文件、Q 做一次跨文件正则替换（逐条确认 y / n）、再 C-x s 存盘——这一串动作在终端里对应的是 find + sed + 一堆管道，在 Emacs 里就是一串按键，而且每一步都看得见、可撤销。

六、版本现状：dired-x 在 Emacs 32 里还剩什么

原文写于 dired-x 尚不可替代的年代，只说了一句「Emacs 29 把 dired-x 的几个功能搬进了核心 dired，但装 dired-x 太省事了，建议直接加上 (require 'dired-x)」。这句话今天需要修订：回迁不是「几个功能」，而是早在 Emacs 25 就基本完成了。

我把上游 Emacs 各分支的 dired.el（emacs-mirror 仓库的 emacs-25.1 到 emacs-31.1 标签）逐个抓下来对比过：本章第三节、第四节表格里的绝大多数命令——硬链接 H、符号链接 S、相对链接 Y、T touch、L load、B 字节编译、I info、N man、P print、Z 压缩、W 浏览器打开、k 删行、o 他窗打开、v 只读查看、w 复制文件名、y 文件类型、= 比较、~ 备份文件旗标、# 自动保存文件旗标、( 隐藏细节模式，以及整个 % 正则子映射和 dired-guess-shell-* 规则表——在 Emacs 25.1 的核心 dired.el 里就已经全部存在，并不是「Emacs 29 才有」，更不是「Emacs 32 才回迁」。今天唯一的版本增量是 E → dired-do-open，那是 Emacs 30 新增的（etc/NEWS.30：「New command dired-do-open. This command is bound to E」），在此之前它属于 dired-x。

那 dired-x 今天还剩下什么？我在加载前后把 dired-mode-map 逐键 diff 了一遍：真正只属于 dired-x 的只有两个单字符键和三个子映射键——F（dired-do-find-marked-files，一次打开所有标记文件）、V（dired-do-run-mail，用 mail 打开标记文件）、以及 * .、* O、* (。此外 dired-x 还独有 dired-virtual（「虚拟 Dired」：把一条命令的 ls -lR 风格输出当成 Dired 缓冲区来操作——比如 M-x dired-virtual 然后运行 ls -lR /usr/share/doc，就能在结果上按 R 批量重命名）和 dired-virtual-revert（把虚拟 Dired 缓冲区重新抓一遍）。最后是一整套「隐藏垃圾文件」机制，由两个变量控制：dired-omit-files（文件名正则，默认值是 "\`[.]?#\|\`[.][.]?\'"，只藏 .、.. 和 Emacs 的 #自动保存# 文件）和 dired-omit-extensions（扩展名与目录名列表，默认值已经把 .pyc .pyo .elc .o .so .class 以及 .git/ .svn/ CVS/ 等包了个遍）。两者都只在 dired-omit-mode 打开时生效，而它们都定义在 dired-x.el 里——这就是本节开头那行 (require 'dired-x) 今天仍然值得写的原因。

要点

那还要不要 (require 'dired-x)？要，但理由和原文不同。Emacs 32 依然把 dired-x.el 随发行版一起安装（我在本机 locate-library 找到了它），只是不再自动加载，而 F 和 dired-virtual 依然只有它有。成本只是一行配置，收益是多两个命令 + 隐藏垃圾文件 + 虚拟 Dired，值得。

;; 放进 init.el（Emacs 启动时自动读取的配置文件）。
;; 如何重载：M-x eval-buffer RET，然后选 y；或者重启 Emacs。
(require 'dired-x)
进阶：猜命令规则表与 dired-jump 的版本细节

猜命令规则表换了文件。变量 dired-guess-shell-alist-default 及其配套的 -optional、-user 在 Emacs 32 里定义在 dired-aux.el（早期版本在 dired.el 或 dired-x.el）。它定义的是「! 什么也没标记时，Emacs 根据文件名猜一条命令来问你要不要执行」的规则，本机 32.0.50 上这张表有 39 条，比如：碰到 .zip 问要不要 unzip；碰到 .patch 问要不要 cat * | patch（在 git 仓库里则是 cat * | git apply）；碰到 .tar.gz / .tgz 问要不要 gunzip -qc * | tar xvf -；碰到 .tar.Z 问要不要 zcat * | tar xvf -。想加自己的规则就往 dired-guess-shell-alist-user 里加。这个功能属于核心 dired，不需要 dired-x（dired-aux 也会在运行 Dired 时自动加载，本机实测 (dired DIR) 之后 (featurep 'dired-aux) 已经是 t），只是那张表换了文件——原文说的「在变量 dired-guess-shell-alist-default 里」，名字今天仍然对，位置变了。另外 dired-guess-shell-alist-optional（播放器、阅读器这类「可选的」外部程序）是 Emacs 30 才拆出来的，早期和默认表混在一起。

M-x dired-jump 是核心命令。它在当前缓冲区所属的目录开一个 Dired 缓冲区。Emacs 32 里它的 repeat-mode（「按一次 C-x C-j 就能重复上一个命令」的键位映射表）从 j 改成了 C-j——我 dump 出来的 dired-jump-map 现在只有 C-j 一项，Emacs 的 NEWS（32.1 部分）里写着「'repeat-mode' 键 j 已从 dired-jump-map 移除」。

八、编译与测试：M-x compile 才是长任务的正路

compile（编译）这个功能在 Emacs 里的范围比「编译」大得多：它就是「跑一条会输出很多行的命令，然后把输出里的错误变成可跳转的条目」的通用引擎。跑 make、跑单元测试、跑 npm test、跑 cargo test、跑 eslint，全都用同一套机制。

它背后有一个正则引擎：Emacs 内置了几十种工具的错误输出格式（compilation-error-regexp-alist，本机 Emacs 32.0.50 里有 72 条），从 gcc 到 cargo 到 pytest 到 ESLint 都能识别。识别出来之后，每条错误在 *compilation* 缓冲区里变成一个可以按 RET 跳到源文件对应行的链接。

发起编译：M-x compile。Emacs 会在 minibuffer 里预填变量 compile-command 的值——本机 Emacs 32.0.50 的默认值是字符串 "make -k -j15 "（-k 是「继续编译其余目标」，-j15 是并行 15 路）。你完全可以把它改成 cargo test、npm test、pytest，Emacs 一样能解析输出。

易错

原文在这一节提到 C-x p c「在当前项目里编译」。我逐版本查了：GNU Emacs 从 29 到 32 都不存在 compile-project 这个命令（本机 fboundp 返回 nil，etc/NEWS 里也从未提到过它——如果你在别处看到「Emacs 31 引入了 compile-project」的说法，那是错的）。C-x p c 在 Emacs 32 里真正绑定的是 project-compile，来自核心的 project.el（项目系统，Emacs 内置的「猜测你当前在哪个项目根目录」的机制）。它会先定位项目根目录，再在那里跑编译命令。你在 init.el 里设一次 project-default-directory，之后 C-x p c 就能在任何文件里一键编译正确目录。

同一套 C-x p 前缀下还有几个很实用的（全部实测确认）：C-x p d（project-find-dir，直接在项目根目录开 Dired）、C-x p f（在项目内找文件）、C-x p e（在项目根目录开一个 eshell）、C-x p !（project-shell-command，在项目根目录执行一条 shell 命令，输出插入缓冲区）。

技巧

如果项目用 git，那编译这整节你可以只记一条：M-x magit。Magit（MELPA / NELPA 里的第三方包，Jonas Bernoulli 写的）把 git 的所有操作变成了 Emacs 缓冲区里的按键。按当前 magit-mode-map（我核对的版本）最常用的几条是：g 刷新状态缓冲区（不是 M——M 是 magit-remote，管远程仓库的）、s 暂存改动、c 提交、l 看提交日志、d 看 diff、F 拉取（f 只是 fetch 到本地，P 推送；p 是「往前翻一屏」，不是拉取）、! 跑一条命令。改完代码顺手就能 g 刷新、d 确认 diff、c 提交。装了 Magit 之后，M-x compile 依然有用（跑测试很方便），但日常 git 流程完全不必碰命令行。

C-c C-e / C-c C-r 分别是 comint-show-maximum-output（把上条命令的输出折叠到一行）和 comint-show-output（展开）。跑了个输出几万行的命令之后按一下 C-c C-e，缓冲区立刻清爽，比 C-c C-o 直接删掉更安全，因为内容还在，随时能展开。这两条不是新键位：我拉了 emacs-24.5、25.1、26.1、27.1、28.1、29.1 六个分支的 comint.el 逐一比对，C-c C-e → comint-show-maximum-output、C-c C-r → comint-show-output 在 Emacs 24.5 就已经是这个绑定了（连命令本身都更早，Emacs 19 的 NEWS 里就提到过 comint-show-maximum-output）。

C-c M-r / C-c M-s 是 comint-previous-matching-input-from-input / comint-next-matching-input-from-input：在历史里找和你当前正在输入的这行开头相同的上一条 / 下一条命令。比 M-p 一路往回翻快得多——先敲命令的前几个词，再按 C-c M-r 即可。

技巧

M-p / M-n 和 C-↑ / C-↓ 是真的在缓冲区里移动光标，不是在终端里「回显一条旧命令」。这个区别让不习惯 shell 模式的人很困惑：你按 M-p 之后看到光标跳到了缓冲区中间某一行，那行就是上一条命令。想立刻改这条命令？直接改就行，不用先按 ↑ 再乱按一通。

9.2 M-x eshell：Emacs 自己的 shell

eshell 是一个完全用 Elisp 实现的 shell。它的实现方式是：你输入的每一个词，先过 Eshell 的命令层（匹配内建命令或外部程序），再过 Emacs 自己的交互命令层（比如把 find-file todo.org 直接解释成 Emacs 的 find-file），最后才考虑 $PATH 里的外部程序。所以在 eshell 里可以直接敲 dired . 打开当前目录的 Dired 缓冲区，或者 find-file todo.org 在 Emacs 里打开文件——这在真正的 bash 里当然是不行的。

它的强项很实在：跨平台一致（Windows 上也有同样的体验）、能配合 TrAMP 直接给远程命令开一个 eshell、以及 把命令输出重定向进 Emacs 缓冲区极其自然。它内置了一批 GNU coreutils 的 Elisp 实现（ls、cp、mv、rm、find、grep 等），所以就算系统上没有这些命令也能用。

它的弱项原文说得很准，而且今天依然成立：不支持全屏交互程序（htop 之类），而当你真的敲了这样一个命令，eshell 会很贴心地自动开一个 ansi-term 缓冲区给你跑它；命令历史解析非常脆弱——eshell 靠正则从缓冲区文本里「猜」历史命令，一旦你手改了那一行、或者命令里有引号和管道符，它经常认不出来，C-p 就开始乱跳。Emacs 32.1 的 NEWS 里给了 eshell 一个「Lisp 管道」：可以直接把命令管道进一个 Elisp 函数，比如 echo hi | #'upcase。但原文提到的 eshell-clear 命令在今天的 Emacs 32.0.50 里并不存在（fboundp 返回 nil，eshell.el 里也搜不到这个名字），别照着敲。

要点

原书作者的建议今天依然成立：日常用 shell 模式。原因很简单：shell 跑的是真的 bash，你的肌肉记忆（管道、`&&`、引号、`grep -r`）100% 有效；eshell 的收益（跨平台、命令落进 Emacs）只在特定场景才值它的解析脆弱性。

9.3 M-x ansi-term：真终端

如果你要跑 htop、vim、emacs（套娃）、ssh 进另一台机器跑 tmux，就需要真正的终端模拟器。Emacs 自带两个入口，而且它们都住在同一个文件 term.el 里——早就没有一个叫 ansi-term.el 的独立文件了（我查了 emacs-mirror 的 emacs-24.5 及其之后的每一个分支，lisp/ansi-term.el 一路都是 404，ansi-term 是 term.el 里的一个函数）：M-x term（复用同一个 *terminal* 缓冲区反复开 shell）和 M-x ansi-term（每次调用都开一个新缓冲区，缓冲区名默认 *ansi-term*，能同时开好几个；它还把 C-x 也设成了转义字符，方便把 C-x 组成的函数键发给远端）。原文只讲了 ansi-term，因为它更常用。

它有两种模式，这个切换是使用 ansi-term 最大的心智负担：

  • 字符模式（character mode，默认）：像真正的终端一样，几乎所有按键——包括普通的字母和 Emacs 命令键——都绕过 Emacs 直接发给子进程。此时 Emacs 命令（C-x C-f 之类）全部失效。
  • 行模式（line mode）：像一个普通的 Emacs 缓冲区，可以移动、搜索、复制。

切换靠 C-c 前缀。但 C-c 本身被 Emacs 拦下来当转义字符用，所以想给子进程发一个真正的 C-c，必须连按两次 C-c C-c。这是新用户最常踩的坑——「我明明按了 C-c 为什么程序不停」。一个精确化的说明：第二次 C-c 触发的是命令 term-interrupt-subjob，它给前台进程组发 SIGINT；对绝大多数命令行程序来说效果跟在终端里按 C-c 一样，但它并不是「把 C-c 这个字节写进 pty」。

9.4 M-x vterm：今天在 Emacs 里跑真终端的更好选择

vterm 是第三方包（在 MELPA 里，仓库是 akermu/emacs-libvterm）。它的关键差异是：核心不是 Elisp，而是一个 C 动态模块——它把 Neovim 用的终端模拟库 libvterm 编译成 Emacs 的动态模块加载进来。

所以它比 term / ansi-term 强在两点，而且都是压倒性的：速度（大段输出不会卡）和兼容性（几乎所有终端程序都能跑，因为底层就是标准的 VT100/xterm 模拟器）。代价有三条：

  1. 需要支持动态模块的 Emacs 构建。检查方法：M-x eval-expression 输入 module-file-suffix，返回值不是 nil 才行。从源码编译的 Emacs、多数 Linux 发行版的包、Homebrew 的版本都有；Windows 原生构建通常没有。
  2. 需要 CMake、libtool 和 libvterm 库，首次运行时 vterm 会自动编译模块。
  3. 和 Emacs 的整合没那么紧：按键直接发给子进程，evil-mode 这类改动按键方案的包用不了（项目 README 里直接点名了这个限制）。另外作者在 README 里自评当前处于 alpha 阶段，接口可能变。

安装（MELPA 路线，README 里的推荐做法）：在 init.el 里加 (use-package vterm :ensure t)，然后 M-x package-install 输入 vterm 回车即可。

;; init.el：装 vterm
(use-package vterm
  :ensure t)

;; 顺手把两个最常用的命令绑上全局键。
;; 注意 s- 在 kbd 里是 Super 修饰键，不是「shift」也不是什么前缀简写：
;; (kbd "s-C-c t") 实测得到 [8388611 116]，也就是 Super-C-c 然后 t，
;; 跟上面那行绑的 C-c t 完全是两回事（不会互相覆盖）——但这个序列
;; 实际上没人敲得出来，等于白绑。所以这里换一个正常键。
(global-set-key (kbd "C-c t") #'vterm)
(global-set-key (kbd "C-c M-t") #'vterm-other-window)

;; 在 vterm 终端缓冲区里按 C-c C-t 是 vterm-copy-mode：
;; 打开后这个终端就变成一个只读文本缓冲区，可以搜索、可以正常复制，
;; 这解决了「在终端里用鼠标精确选字」的老大难。

另有两个相关包值得知道：vterm-toggle（MELPA）让你在「普通文件缓冲区」和「vterm 终端」之间反复切换，特别适合「在项目目录里 npm start 然后切回去改代码」这种循环；eedit（同一作者）是一个 eshell 与 comint 的混合体，介于 eshell 和 shell 模式之间。如果你今天就想用 Emacs 里的真终端，装 vterm；如果 Emacs 没有模块支持，就老实用 shell 模式跑命令、需要交互式程序时切到系统终端。

十二、练习

练习 1　你正在编辑 ~/project/src/main.py，想看看 src 目录里还有哪些文件。最快的按键是什么？如果想在新窗口里看呢？

C-x d 打开当前缓冲区所在目录的 Dired；C-x 4 d 在另一个窗口打开（命令 dired-other-window）。默认值来自变量 default-directory，所以不需要输入任何路径，直接 RET 就行。

练习 2　你在 Dired 里用 m 标记了三个文件，现在想删掉它们。用 D 和用 x 分别会删掉哪一批？哪一个更安全，为什么？

D（dired-do-delete）删掉打星号标记的那三个；x（dired-do-flagged-delete）删掉打了 D 旗标的文件。更安全的是 x，因为标记是快速连按出来的、容易多标，而旗标需要逐个用 d 确认，Emacs 也会在删除前列出完整清单让你核对。

练习 3　你选中了 200 行可能重复的配置项，想就地排序去重、并且让结果替换掉原来选中的内容。敲哪两个键、输入什么命令？

C-u M| 然后输入 sort -u。前缀 C-u 让 shell-command-on-region 用命令输出替换选区；不加 C-u 的话输出会另外显示，原始选区保持不变。

练习 4　你用 M-x compile 跑了构建，在 *compilation* 缓冲区里。现在回到源码文件想跳到第一条错误处。至少按哪一组键？g 必须先按吗？

只要按 M-g M-n（next-error）就够了——这两个是全局键，在源码缓冲区里也能直接用，会跳到最近一次编译输出的第一条错误；M-g M-p 跳回上一个。g（recompile）只在你想重新跑一遍编译时才需要——如果刚才那次编译已经跑完、结果还在，跳之前先按 g 反而会白等一次。所以「先 g 再 M-g M-n」只有在你刚才没看结果、想边看新结果边跳的时候才对。

练习 5　在 M-x ansi-term 开的终端里，你按了一次 C-c 但里面跑的 tail -f 停不下来。应该怎么把真正的 C-c 发过去？Emacs 32 里这组键实际绑的是哪个命令？

连按两次：C-c C-c。Emacs 截获第一个 C-c 当作自己的转义前缀，第二个才触发命令。注意 Emacs 32 里 C-c C-c 绑的是 term-interrupt-subjob，它给前台进程组发 SIGINT；对 tail -f 这类程序效果和真按 C-c 一样，但它不是「把 C-c 这个字节写进 pty」。

练习 6　今天要在 Emacs 里跑日常命令行命令，候选是 M-x shell、M-x eshell、M-x vterm。给出你的选择和一句话理由。

选 M-x shell。它跑的是真的 bash，你的管道、引号、grep -r 全部照常工作，心智成本为零；同时因为输出是 Emacs 文本，你还能自由移动、搜索、复制。eshell 的历史解析脆弱、vterm 需要模块支持和编译、而且按键直接发给子进程导致 Emacs 命令用不了。

练习 7　你想一次性标记 Dired 列表里从第 3 行到第 8 行的所有项。怎么做？

三步，全程都在 Dired 缓冲区里做：① 把光标放到第 3 行的行首，按 CSPC（set-mark-command，就是这一个键，Emacs 没有「C- 配合 SPC」这种两键写法）；② 移动到第 8 行的行尾，此时这一段是激活选区；③ 按 * 然后 m（dired-mark），区域内的每一项都会被标记。

为什么第 ③ 步会作用于整个区域？dired-mark 的文档字符串写着 “Mark the file at point… only in the region if ‘dired-mark-region’ is non-nil.”——也就是它平时只标记光标那一项，只有在有激活选区、而且变量 dired-mark-region 不是 nil 时才扩展到整个区域。这个变量的默认值本书作者在 Emacs 32.0.50 上实测是 file（不是 nil），所以区域标记默认是开着的，你不用配任何东西。

反过来取消标记按 * u（dired-unmark）。另外记两个同一族里常用的：* %（dired-mark-files-regexp）按正则批量标记，比如 * % 输 \.py$ 选中所有 Python 文件；* * 切换「标记显示模式」。

练习 8　你想在一个大仓库里找出所有 *.org 文件并按大小排序后再批量处理。用哪个命令？

M-x find-name-dired，输入 *.org。它生成的缓冲区是完整的 Dired 缓冲区，所以 s（切换排序）、m（标记）、R（批量移动）全部可用。Windows 上没有 find 的话改用 find-lisp-find-dired（纯 Elisp，但用 Emacs 正则而非 shell 通配符）。

练习 9　Dired 缓冲区里已经有一个子目录展开了（用 i 插进来的）。现在要在另一个目录里再放一个子目录，敲哪个键？插进来的子目录内容会被 C 和 R 影响吗？

敲 i（命令 dired-maybe-insert-subdir），光标要放在目录行上。会——同一个缓冲区里的所有行（包括插进来的子目录）都在标记和操作的作用范围内，C / R 一样生效，Emacs 会自动加上正确的相对路径。用 $ 可以把子目录折叠起来暂时排除在外。

练习 10　在 M-x shell 的缓冲区里，M-p 和 M-r 有什么区别？哪个更适合「找三个月前敲过的那条很长的命令」？

M-p（comint-previous-input，等价于 C-↑）是在历史里逐条往回翻，得按很多次。M-r（comint-history-isearch-backward-regexp）是反向增量搜索：按 M-r 后输入几个字符片段，Emacs 实时匹配历史里含该片段的命令，RET 选中。找特定长命令应该用 M-r。

练习 11　你误按了 D，Emacs 弹出一个列出待删文件的窗口问你「是否删除这 N 个文件」。你发现清单里混进了一个不该删的文件。接下来该怎么做才能既安全又不用全部重来？

在提示处按 n 取消，然后回到 Dired 缓冲区把那一项的标记去掉，再重新按 D。n 是完全可逆的——这个确认由 dired-deletion-confirmer（默认就是 yes-or-no-p）负责，回显区会告诉你 (No deletions performed)，一个文件都没动。要注意那个列出待删文件的 *Deletions* 窗口只是给你看的，不能在里面编辑：它由 dired-mark-pop-up 用 completion--insert-strings 生成，里面不是 dired-mode，所以你按不了 d、也按不了 * ! 去改标记（那两条只在真正的 Dired 缓冲区里有效）；而且待删文件只有一个时 Emacs 干脆不弹窗口，直接问 y/n。不要因为看到确认弹窗就条件反射按 y——这个弹窗的用处正是让你检查清单，看完按 n 也不丢东西。

练习 12　你嫌 Dired 列表太长，想去掉「属主 / 属组」那几列。改哪个变量、改成什么？改完怎么让它生效？

改 dired-listing-switches，把 -al 里的 l 去掉即可，比如 (setq dired-listing-switches "-a")（-a = 全部条目含隐藏文件，-l = 长格式即那些列）。改完按 g（revert-buffer）刷新现有 Dired 缓冲区，或者在 init.el 里改完用 M-x eval-buffer RET 选 y 重载。

练习 13　在 Dired 里想用系统的默认程序打开一个 PDF（不是用 Emacs 内置的 PDF 查看器）。按哪个键？这个键是哪个 Emacs 版本新增的？

E，命令 dired-do-open，Emacs 30 新增（此前要 dired-x）。Emacs 32 把它内置进了核心 dired，本机实测不需要 dired-x 就能用。

练习 14　你在 Dired 里标记了 10 个 .py 文件，想把里面所有的 foo 批量替换成 bar。按键序列是什么？Q 执行的过程中你还会看到什么交互？做完之后还必须做哪一步？

标记这 10 个文件（m 连按或 * %），然后按 Q（dired-do-find-regexp-and-replace），输入 foo 和 bar。它会先把这些文件交给 grep 搜出全部命中，再像 query-replace 一样逐条问你要不要替换（y 换 / n 跳过 / SPC 也换 / DEL 也跳），改完的文件被开成缓冲区。必须再按 C-x s（save-some-buffers，本机实测 C-x s 绑的就是它）存盘——Q 改的是 Emacs 缓冲区，磁盘上的文件还是旧的。这一步漏了是最常见的翻车点。

练习 15　在 vterm 终端里想用鼠标精确选中一段输出复制，但 vterm 默认把鼠标事件发给远端程序。有什么办法？

按 C-c C-t 进入 vterm-copy-mode。这个模式下终端缓冲区变成一个普通的只读文本缓冲区，可以用全部 Emacs 移动命令、Isearch、M-w 复制；选中一段后按 RET 复制并退出该模式（没选中则复制当前整行，变量 vterm-copy-exclude-prompt 控制是否带上提示符）。

练习 16　某篇文章说「Emacs 31 引入了 compile-project 命令，按 C-x p c 就能在项目根目录编译」。这句话哪里对、哪里错？

按键和用途是对的，命令名是错的。我在 Emacs 32.0.50 上实测：compile-project 的 fboundp 返回 nil；我又拉了上游 emacs-29.1 / 30.1 / 31.1 的 lisp/progmodes/compile.el 逐个搜，defun compile-project 一次都没出现过；全部 etc/NEWS* 里也从来没有提到过这个名字。C-x p c 真正绑定的是核心 project.el 提供的 project-compile。

练习 17　你的 Emacs 里 term 和 ansi-term 跑 htop 时画面对不齐、输出量大就卡。给出两个改进方向，并说明怎么判断你的 Emacs 能不能用第一个方案。

第一，装 vterm（MELPA，akermu/emacs-libvterm），它基于 C 的 libvterm，速度和兼容性都远超 Elisp 写的 term。前提是 Emacs 支持动态模块：M-x eval-expression 输入 module-file-suffix，返回值不是 nil 才行；还要有 CMake / libtool / libvterm。第二，Windows 或无模块支持时，只能改用系统自带的真终端，Emacs 里的 ansi-term 兼容性不足是已知短板，不建议硬扛。

练习 18　你在 Dired 里光标停在一个 foo.patch 上按了 !，Emacs 提示你「是否对 foo.patch 执行 patch」。这个「猜命令」的规则表在 Emacs 32 里放在哪个文件？需要装 dired-x 吗？

规则表是 dired-guess-shell-alist-default（及相关 -optional、-user 两个变量），Emacs 32 里它们搬到了 dired-aux.el（早期版本在 dired.el / dired-x.el）。不需要 dired-x，猜命令的逻辑已经属于核心 dired。
