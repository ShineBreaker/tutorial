七、编辑理论（二）：替换、大小写、计数、文本操作

上一章讲了怎么「安全地删」。这一章讲怎么「批量地改」：把一处改动同步到全文件、按条件筛行、在表格里对齐着批量编辑。光靠单键操作写不出这些东西，但只要学会本章的替换、过滤和矩形编辑，Emacs 就能替代掉你平时随手开的那些文本处理小工具。

读完你应该能：熟练使用 query-replace（交互式替换，逐条确认）并说清它每一键的含义；写出符合 Emacs 方言的正则表达式，知道它比 PCRE 少什么、多什么；在正写的过程中用三个 M 键改大小写；用 keep-lines / flush-lines 筛行；用矩形命令批量处理对齐好的表格。本章覆盖原书第 209–234 页（Search and Replace、Changing Case、Counting、Text Manipulation）。

本章的每一条键位、命令名和默认值，都在 Emacs 32.0.50 上用 (key-binding …) 和 (fboundp …) 实测核对过；与原书写成书时的 Emacs 26–30 不一致的地方，正文会单独标出「今天的做法」。

一、搜索与替换：Emacs 最有生产力的一个命令

1.1 两个家族：交互式与非交互式

Emacs 的替换命令分两族，区别只有一条：要不要逐条问你。

搜索与替换命令

按键命令作用
CM%query-replace-regexp交互式正则替换：每找到一个就问你要不要换
M%query-replace交互式字面量替换（模式按纯文本处理）
Mx replace-regexpreplace-regexp非交互式正则替换，不问，全部换掉
Mx replace-stringreplace-string非交互式字面量替换，不问，全部换掉

名字里的 query 就是「提问」的意思：query-replace 会把每一处匹配高亮出来，然后停下来等一个键。replace-string / replace-regexp 是它们的「闷头干活」版本，一次跑完，不能撤销单次替换，只能整体 C- 撤销。所以除非你写 Elisp 脚本，日常请一律用 M% 和 CM%。

易错

replace-regexp 改坏了整个缓冲区之后想反悔？Cx u 能把缓冲区整个恢复到替换前的状态——因为整批替换在 undo 列表里属于同一个命令的一组记录，中间没有撤销边界（本机实测：替换 5 处之后 buffer-undo-list 里是 5 条连续的删除记录 ("a" 10) ("a" 8) ("a" 6) ("a" 4) ("a" 2)，它们之间没有 nil 边界，所以一次 Cx u 全退）。但只要你紧接着敲了别的编辑命令，这组记录就整体失效了。这不是 Emacs 特意为难你，而是「一步撤销一整批修改」和「随时插入别的操作」在数据结构上无法同时成立。养成习惯：先想清楚再敲，敲错了立刻 C-。

用 query-replace 时，顺序是：先问搜索串，再问替换串，最后才开始逐条确认。按 CM% 时，本机源码 replace.el 给出的第一个提示串是 Query replace regexp（小输入框自动补上 : ）；回车后第二个提示由 (format "%s %s with: " prompt (query-replace-descr from)) 拼出来，实际长这样：Query replace regexp Hello with: ——你刚搜的内容就夹在中间，而且会被预填成初值，所以直接按 RET 等于「用同样的东西替换」（这不是 bug，敲 e 就能回去改它）。填完替换串才进入 Replace this occurrence? 的循环。两个输入框之间可以用 Ms t 来回横跳（命令 query-replace-read-transpose-from-to，本机实测确认它绑在 query-replace-read-map 上）。

易错

在 query-replace 的提问界面里按 e 是「编辑替换串」，不是别的东西。本章第五节讲 occur 模式时也有一个 e，含义是「进入可编辑模式」——两个完全无关的功能在 Emacs 里各占一个 e，很容易记混。不过「记法」那条要更正一下：现代 Emacs 里 occur 并不住在 occur.el，那个文件早就不存在了（本机实测 (require 'occur) 直接报 Cannot open load file，整个 lisp/ 目录里也搜不到 occur.el），occur 现在和 query-replace 同住在 replace.el 里。真正能记的只有一句：e = occur-edit-mode。

1.4 大小写折叠：Emacs 最贴心的一处设计

先看一个具体现象。假设缓冲区里有这么几行：

HELLO_WORLD = "Hello, World!"
function hello() {
    print(HELLO_WORLD)
}

现在用 CM% 把 hello 换成 goodbye。Emacs 的结果不是你可能预期的「全部小写」或「全部原样」，而是逐处沿用被匹配文本的大小写形状：

GOODBYE_WORLD = "Goodbye, World!"
function goodbye() {
    print(GOODBYE_WORLD)
}

这不是原书的举例需要，是 Emacs 的默认行为，我在本机 Emacs 32.0.50 上实跑验证过：缓冲区内容为 hello HELLO Hello，默认设置下执行 (replace-regexp "hello" "goodbye")，结果是 goodbye GOODBYE Goodbye；而把 case-replace 设成 nil 之后，结果变成 goodbye goodbye goodbye。

这个行为由两个变量控制，它们都在「Emacs 自己的实际源码 / 文档字符串」里定义：

  • case-fold-search（默认 t）：搜索时忽略大小写。
  • case-replace（默认 t）：替换时沿用匹配文本的大小写。设成 nil 就是「一律按你输入的替换串原样插入」。

但「忽略大小写」有一条重要的例外：如果你的搜索串里含有大写字母，Emacs 会自动把它当成「大小写敏感」来搜。这一点由第三个变量 search-upper-case 控制，默认值是 not-yanks，文档字符串原文是：

If non-nil, upper case chars disable case fold searching.
That is, upper and lower case chars must match exactly.

实测印证：默认设置下 (replace-regexp "HELLO" "goodbye") 在 hello HELLO Hello 上只替换了中间那一个，结果 hello goodbye Hello。所以原书那句「如果你搜的是 Hello 或 HELLO，Emacs 只会替换字面吻合的那些」是对的，但要说清它依赖的是这个默认变量，而不是「永远大小写敏感」。

同一条规则在 replace-regexp 的文档字符串里被写得更死（原文：“Preserve case in each match if case-replace and case-fold-search are non-nil and REGEXP has no uppercase letters.”）——注意是 REGEXP，也就是搜索串，不是替换串。

技巧

在输入搜索串的小输入框里，按 Ms c 可以临时切换这一次的「大小写折叠」开关（命令 read-regexp-toggle-case-fold，提示「Case folding is now on/off」；本机实测该键绑在 read-regexp-map 上，而源码里 read-regexp-map 是用 :parent query-replace-read-map 定义的——它是 query-replace-read-map 的子表，所以那张表上原有的 Ms s（翻历史）和 Ms t（在两个输入框之间横跳）它全都继承。这个键是 Emacs 29 新增的——本机 etc/NEWS.29:3552 原文：“Ms c in read-regexp now toggles case folding.”Emacs 28 及更早的输入框里没这个键，遇到时改用 1.4 节说的「把 search-upper-case 设成 nil」的办法即可）。想「无视大小写地替换所有 HELLO」，就用它把折叠打开。

1.5 替换文本里的特殊字符：本章最容易踩坑的地方

替换串不是「原样插入的文本」，它有一套自己的转义规则。这套规则的确切清单，Emacs 32.0.50 的 query-replace 文档字符串（源码 replace.el）是这么写的：

替换串里的转义（M% / CM% 的第二个输入框）

写法命令 / 来源作用
\&replace-match插入整个匹配文本
\1 … \9replace-match插入第 N 个 \(…\) 捕获组匹配到的文本（从 1 开始数）
\\replace-match插入一个字面的反斜杠
\?query-replace-regexp在输入框的这个位置停下来，让你手改这一次要插入的内容
\,(表达式)query-replace-compile-replacement每替换一处就 Elisp 求值一次，用结果当替换文本
\#同上已替换的次数，从 0 开始（第一条是 0，第二条是 1……）
\#& / \#N同上整个匹配 / 第 N 组，经 string-to-number 转成整数——只能在 \, 表达式内部用
易错

替换串里写 \n 是会报错的，错误信息是 “Invalid use of ‘\’ in replacement text”。这不是我保守推测——Emacs 32.0.50 的 replace-match 文档字符串最后一句白纸黑字写着：“Any other character following ‘\’ signals an error.”（反斜杠后面跟任何其他字符都会报错。）我也在本机实跑过 (replace-regexp-in-string "b" "a\\nb" "abcb")，确实抛这个错误。同理 \t、\d 之类也都不行。

要插入换行，请用 \, 表达式。容易困惑的是：在 \,(…) 的内部，你写的是一段 Elisp，Elisp 自己的字符串里 "\n" 是合法的换行——所以这条能用：

\,(concat "第" \# "行\n")

本机实测它编译成 (replace-eval-replacement replace-quote (concat "第" replace-count "行<换行>"))，完全正常。区别只在于换行发生在哪一层：替换串自己的 \n 是 Emacs 替换语法的转义（不认识，报错）；\,(…) 内部 Elisp 字符串的 "\n" 是 Elisp 语法（认识，是换行）。

另外注意方向别搞反：在搜索串（第一个输入框）里，Emacs 会专门检测你写的 \n 或 \t（这条检查只在正则模式下生效，也就是 CM% / Cs；源码里的条件是 regexp-flag），然后在回显区提醒你「Note: `\n' here doesn't match a newline; to do that, type C-q C-j instead」或「Note: `\t' here doesn't match a tab; to do that, just type TAB」——在搜索串里要匹配真正的换行，得按 Cq Cj（quoted-insert，插入一个控制字符）。搜索串、替换串、Elisp 字符串是三套转义规则，别指望它们一致。（顺便：这条只是提醒、并不拒绝输入，所以你按了 Cq Cj 之后看到的搜索串里会是一段控制字符显示。）

还有一条方向容易搞反的规则，我专门实测确认过：

实测：\& 和 & 不是一回事

替换串输入 abcb、模式 b 的结果说明
a&baa&bca&b& 是普通字符，原样输出
a\&baabbcabb\& 才代表「整个匹配」，这里匹配到的 b 被插进去了

记住这条就够了：Emacs 里 \&（带反斜杠）才是「整个匹配」，单独的 & 就是个和字。这跟 Perl / PCRE 习惯的 $&（裸 & 才是整段）正好相反，写惯了 Perl 的人第一次一定会在此翻车。

用 \? 做「逐条确认替换内容」也很实用。比如你有一批 foo 要换成不同的东西，替换串写 \?替换成什么，Emacs 每处理一处就会停下来等你输入，输入 RET 继续。命令源码 replace.el 原文：“\? lets you edit the replacement text in the minibuffer at the given position for each replacement.”

1.6 在替换里调用 Elisp

\,(表达式) 是本章最强大也最容易把人吓到的功能：替换串的每一处都会现场执行一段 Elisp，用返回值当替换文本。

在表达式内部，匹配到的内容以字符串形式暴露出来：\& 是整个匹配的字符串，\1 是第 1 组的字符串，\#& 和 \#N 是把对应内容用 string-to-number 转成数字，\# 是已替换次数。源码里那句注释是 “\#& and \#N the respective numeric values from string-to-number”。

一个把「数字加上千分位」的实用例子（把 1234567 变成 1,234,567）：

\,,(format "%,d" \#&)

我不需要你懂 Elisp 也能用——先记住两条规矩就够了：

  1. 捕获组是字符串，不是数字。要参与算术必须显式转换，源码文档字符串对 \#N 的说明就是「the numeric values from string-to-number」。
  2. 一个 \, 只能放一个表达式。要调多个函数，用 \,(concat …) 把它们的结果拼起来。
易错

如果 \, 后面跟的是一个标识符（比如 \,upcase），而紧接着的下一个字符又是字母，Emacs 会把那个字母也当成标识符的一部分——本机实测 (query-replace-compile-replacement "\\,upcaseX" t) 编译出来是 (replace-eval-replacement replace-quote upcaseX)，X 被吞进去了。文档字符串给的正式解法是在标识符后面补一个空格，那个空格会被自动吃掉（实测 \,upcase 编译成 upcase）。包一层写成 \,(or \#) 同样有效（实测编译成 (or replace-count)）。另外，如果替换串里的下一个字符本来就该是数字，你可以直接写 \# 而不必套 \,。

要点

原书作者对 \, 的评价很中肯，值得原样传达：Emacs 内部那些「能干活的」函数绝大多数操作的是缓冲区而不是字符串，所以 \, 这个功能虽然很强，实际用起来限制不少。真要搞复杂的多步文本变换，原书建议改用 键盘宏（本系列第八章）——这个建议是对的，键盘宏在这类场景下通常比硬凑 \, 表达式更省事。

二、Emacs 的正则表达式：跟 PCRE 长得不一样

2.1 一句话总结

如果你用过 PCRE（Perl、JavaScript、Python 里那套正则），最需要重新适应的一条是：在 Emacs 里 ( 和 ) 是普通字符，不是分组括号。要写分组必须转义成 \( 和 \)。这个差异会一路影响到搜索串和捕获组引用两边，务必先记住。

Emacs 的正则引擎本身是 GNU 风格的，年代非常早，语法上比 PCRE「少」不少东西，但也有 PCRE 没有的语法类功能（见 2.3）。原书对它的评价很不客气，原文是 “It's old, weathered and too entrenched – and heavily modified to suit Emacs's peculiar needs – to be easily replaced.”（老、磨损过度、根深蒂固，又为了迁就 Emacs 的特殊需求被改得面目全非，很难替换掉了。）这是作者本人的判断，本章不对社区态度下断言；但下面这些差异你必须知道。

必须转义才能用的元字符

Emacs 写法命令 / 术语PCRE 里对应
\( \)捕获组( )
\|交替（or）|
\{n,m\}重复次数{n,m}
\(.\+?\)非贪婪重复(.+?)
\(.*?\)非贪婪的 *(.*?)

非贪婪那条特别容易忘：Emacs 里 * 和 + 本身就是贪婪的，想改成非贪婪必须紧跟一个问号，而且这个问号要写在 \(…\) 捕获组内部。本机实测：string-match-p "\\(.*?\\)" "aXbXc" 返回 0、"\\(.+?\\)" 也返回 0，两个都匹配成功。（顺便一提，\(?:…\) 这种「不捕获的分组」Emacs 是有的，本机实测 string-match-p "\\(?:ab\\)" "ab" 返回 0；但 PCRE 的 (?:ab) 写法不行，实测返回 nil，会被当成普通字符去找字面量 (?:ab)。）

2.2 Emacs 没有的东西

这几条是原书明确点出、我在本机也逐一验证过的：Emacs 正则不支持任何形式的前后向断言（look-ahead / look-behind），也没有分支重置组（branch reset group）之类的花活。

  • 没有 (?=…)、(?!…)、(?<=…)、(?<!…)。本机实测这四个在 string-match-p 下全部返回 nil（不匹配），不会被当成 PCRE 语法解析。
  • 没有 \d 这个数字类简写。本机实测 string-match-p "\\d" "a1" 返回 nil——它不会匹配到 1。想匹配数字必须写 [0-9]，或者用字符类 [[:digit:]]。
  • 没有 PCRE 的内联修饰符，比如 (?i)。本机实测 string-match-p "(?i)foo" "FOO" 返回 nil。要忽略大小写靠的是 1.4 节讲的 case-fold-search，不是模式里的标志。

对绝大多数文本编辑场景，这些缺失并不致命——用 CM% 做重构时，「匹配后面跟着冒号的那个词」这种需求，实践中往往写成「先匹配词、替换时人工确认」，比硬凑一个 look-ahead 省事。

2.3 Emacs 独有的东西：语法类

这是 Emacs 正则真正发光的地方。它不只认「字符」，还认字符在当前 major mode 语法表里的类别——也就是「这是不是个空白」「这是不是个单词成分」。

Emacs 独有的正则构造

构造命令 / 术语作用
\< \>词边界匹配「词」的开始和结束
\_< _>符号边界匹配「符号」的开始和结束（\_< 与 \> 之间的空格是必须的）
\s代码语法类匹配匹配语法表代码为 代码 的任何字符

易错

原书那句「它不会移动你的光标」——放在负数参数那一版上是对的，放到正参数上就是错的。本机实测：缓冲区 hello world、光标在 hello 中间（第 3 个字符），敲 Mu 之后光标从第 3 位移到了第 6 位；Mc 同样会移（结果 heLlo world，光标停在 6）。upcase-word 和 capitalize-word 的文档字符串第一句都写着 “…moving over.”，只有带负参数时才是 “but do not move”。所以准确的说法是：正参数版会跳到词尾，负参数版才原地不动。

还有一个更要命的细节，文档字符串接着写：“If point is in the middle of a word, the part of that word before point is ignored when moving forward.”——光标在词中间时，词在你光标前面的那部分不会被改。实测：hello world 的光标在第 3 个字符，敲 Mu 得到的是 heLLO world，不是 HELLO world。所以要改整个词，光标得先落在词的开头。

原书真正该被记住的观察是：这三个键会把整个词跳掉，所以你可以一边写一边随手改——写完 How 想让它大写，直接 Mu，光标已经落在词尾，你接着往下敲就行。

Mu 往前改，M- Mu 就往回改上一个词。命令文档字符串写得很清楚：“With negative argument, convert previous words but do not move.”（带负参数时转换之前的词，且不移动光标。）本机实测确认这条说明与代码一致。

易错

原书最后建议「忘了就看看 Cx r Ch」——这个键位是错的。它没有被绑定（本机实测 (key-binding (kbd "C-x r C-h")) 返回 nil）。Cx r 这张键表里确实有几个键被别的命令占了，但占掉它们的是 point-to-register，而它绑在 SPC / CSPC / C@ 上，不是 Ch（本机 bindings.el 的 ctl-x-r-map 里逐条查过）。正确做法：Ch f Cx r 然后输入命令名去查单个命令；想一次看全部矩形命令，用 Mx apropos-command RET rectangle RET。另外 Cx r 这个前缀后面还有很多普通寄存器命令，不只是矩形命令（本机 bindings.el 里的 ctl-x-r-map 键表）：s / x 是 copy-to-register，i / g 是 insert-register，j 是 jump-to-register，n 是 number-to-register，+ 是 increment-register，w / f / F / B 分别是窗口配置、框架集、文件、缓冲区的存取。敲 Cx r SPC 或 Cx r C@ 则是 point-to-register（把当前 point 存进寄存器）——注意被占掉的是这三个键，不是 Ch。这也是 Emacs 里少数几个「C@ 有实际用处」的地方之一。

一个完整的矩形编辑例子

假设你有一张对齐好的表，想把第二列整体往右挪一格（给左边补一个空格）：

name        value   unit
alpha       1.20    ms
beta        330     ms
gamma       42.0    s

操作：
1. 光标移到 value 那一列的开头（第一行）
2. C-x SPC              矩形标记模式开关，mark 落在光标处
3. M-n  M-n            连按两下，矩形向下各扩一整行（共 3 行）
4. C-x r t             替换成一个空格（也可以用模式里的 C-t，同一个命令）

结果：
name         value   unit
alpha          1.20  ms
beta           330   ms
gamma          42.0  s

这里有个关键点：第 3 步结束时矩形是「零宽」的（mark 和 point 在同一列），所以第 4 步的 string-rectangle 实际上起的是插入作用——官方文档说得很宽松：“The length of STRING need not be the same as the rectangle width.”，宽度为 0 时就是往每行里插一个字符。另注意第 4 步不能写成 Cx r SPC：那个键是 point-to-register（见上面的提示框），不是替换。

这个例子里三个环节缺一不可：mark（矩形的一个角）、point（对角），以及中间那条命令。mark 从哪来？原书这节讲得很好，值得保留：任何「会把光标带走」的命令都会顺手设标记——最常见的是 Cs / Cr 搜索（Isearch 开始时会在起点设标记）。所以实用套路是：先移动到矩形一角，敲 Cx SPC 把标记钉在那一瞬间（如果当时没有选区，Emacs 会显示 “Mark set (rectangle mode)” 并帮你设好），再移动到对角，敲矩形命令。想确认矩形到底圈了什么，可以在敲命令前按 Cx Cx 交换 point 和 mark 看一眼高亮。

原书给出他本人最常用的三个是 Cx r t、Cx r k、Cx r y，并称之为「插入文本、杀死、取回矩形」这一实用三件套（原书用词是 practical trifecta）。这个建议可以照搬。

M^ 的键位上绑的命令是 delete-indentation，不是 join-line。本机实测 (key-binding (kbd "M-^")) 返回 delete-indentation，其文档字符串第一句是 “Join this line to previous and fix up whitespace at join.”（把本行并到上一行并整理连接处的空白）。而且这个名字里完全没有「join」的意思——它说的是「删掉本行开头的缩进」，缩进一删，行自然就和上面那行并到一起了，纯属历史遗留。另外注意 M^ 和 M- 长得极像，两个是完全不同的键，别敲错。

Co 和 CMo 的区别最好用原书的例子看：

起点：All the world's a stage, █and all the …

按 C-o 之后（光标留在原位，█ 不动）：
All the world's a stage, █
and all the …

按 C-M-o 之后（后面的文字保持原来的列对齐，█ 也不动）：
All the world's a stage, █
                  and all the …

两个命令光标都不移动——本机实测确认：把光标放在上面第 27 位，分别执行 open-line 和 split-line，两次 point 都停在原处没动，变的只有缓冲区内容。这是它们相对于 RET 的全部意义：RET 敲完光标就跳到下一行了，而 Co / CMo 让你能把一个段落拆成两段、或者把一个长函数调用拆成多行，而光标仍留在原位等你接着写。

还有个 fill prefix（填充前缀，Emacs 用来自动在续行开头插入同样缩进的机制，本系列第六章讲过）的交互：CMo 的文档字符串说，如果当前行以 fill prefix 开头，新行也会自动带上 fill prefix；反过来 M^ 合并时会把续行的 fill prefix 去掉。原书这段描述经核对准确。

Cx Co 的三条规则，本机实测确认与文档字符串完全一致（原文：“On blank line, delete all surrounding blank lines, leaving just one. On isolated blank line, delete that one. On nonblank line, delete any immediately following blank lines.”）：

  1. 光标在空行上：把周围所有空行删掉，只留一个。所以在一堆空行里反复敲它，最后总会剩下一个空行——这正好用来统一段落间距。
  2. 光标在孤立的空行上：把这个空行本身删掉。
  3. 光标在非空行上：删掉它后面紧挨着的空行，而且全删（不像规则 1 会留一个）。

第 3 条还覆盖了「只含空格和制表符的行」——这种行也会被当空行删掉，所以它对清理代码里那些看不见的空行特别好用。

M^ 合并时会自动修剪空白：并入一个空行时把所有空白都清掉，并入一个有内容的行时保留恰好一个空格。这也是它比「手动 C- SPC 删掉换行」省事的地方。

cycle-spacing 比 just-one-space 多了这些设计，本机源码 simple.el 确认：

  • 可以自定义动作和顺序：改变量 cycle-spacing-actions，它是个动作列表（Emacs 29 新增这个可定制性，见 NEWS.29:1255-1256）。预定义的动作有五个（本机 simple.el:1193 的 defcustom 文档原文列的）：just-one-space（只留 N 个，N 是前缀参数）、delete-space-after（只留点后面的 N 个）、delete-space-before（只留点前面的 N 个）、delete-all-space（前后全删）、restore（恢复成最初的空白）。但这个列表并不封闭——同一段文档接着说，“In addition to the predefined actions listed above, any function which accepts one argument is allowed. 六、练习

练习 1　把当前缓冲区里所有 foo_bar 换成 fooBar，每处都要亲自确认，不想误伤别的行，用哪个键？

CM%（query-replace-regexp）。回车输入搜索模式，再回车输入替换串，然后每处按 SPC 确认、n 跳过。如果确定全都要换，按 ! 一次搞定。

练习 2　你有一个列表 a b c，想用 CM% 把每个元素用尖括号包起来，得到 <a> <b> <c>。替换串该怎么写？

模式填 \sw，替换串填 <\&>——也就是一个字面的 <、一个 \&、一个字面的 >，中间只有一个反斜杠。\&（带反斜杠）才代表「整个匹配」，裸的 & 是个普通字符，会原样输出——这是从 Perl 过来的人最常栽的地方。还要小心一个连带陷阱：尖括号不要写成 \<，本机实测 (replace-regexp-in-string "\\sw" "\\<\\&\\>" "a b c") 直接报 “Invalid use of ‘\’ in replacement text”——替换串里反斜杠只认 \&、\N、\\、\?、\,、\# 这几个，\< 不在其列。

练习 3　M^ 的命令名到底是什么？join-line 算正确答案吗？

delete-indentation（本机 (key-binding (kbd "M-^")) 实测确认）。两点澄清：一，原书其实只是用一句英文描述它的行为，并没有把它写成命令名 join-line；二，join-line 这个名字确实存在，但它和 delete-indentation 是同一个函数（实测 (symbol-function 'join-line) 返回 delete-indentation，文档字符串完全相同），不是方向相反的另一条命令。delete-indentation 这个名字说的是「把本行开头的缩进删掉」——缩进一删，行自然就和上一行并到一起了。

练习 4　想给矩形的每一行前面加上字符串 #，但不能覆盖原有的内容。用哪个命令？

Mx string-insert-rectangle（无默认键位），不是 Cx r t。后者 string-rectangle 的文档字符串写的是 “Replace rectangle contents”，会覆盖原内容；前者才是 “does not delete or overwrite any existing text”，它把原文字右移。

练习 5　打开矩形标记模式的键位是什么？CSPC 行不行？

是 Cx SPC（rectangle-mark-mode）。CSPC 不是——本机实测 (lookup-key global-map (kbd "C-SPC")) 返回 set-mark-command（设置标记），图形界面下也是它。point-to-register 绑的是 Cx r SPC，不是裸的 CSPC。Emacs 源码 bindings.el 附近还留着一句历史注释：“Many people are used to typing C-SPC and getting C-@.”

练习 6　想删掉当前文件里所有含 FIXME 的行，但只处理「打开时就有的那一大段」，不想连你刚敲的笔记也删掉。怎么做？

先 Cx h 全选（mark-whole-buffer），再 Mx flush-lines，输入 FIXME。flush-lines 的范围由选区决定：选区激活时只处理选区，没激活时从光标处理到缓冲区末尾——所以想整缓冲区过一遍就先 Cx h，想只处理某一段就先 Cx r d 圈定。想反过来（只保留匹配的行）用 keep-lines（注意它的选区是「整行都在选区里才算数」）。

练习 7　delete-duplicate-lines 默认保留重复行的第一份还是最后一份？想要最后一份怎么敲？

默认保留第一份（从前往后扫）。要保留最后一份，加一个纯前缀参数 Cu，命令会改为从后往前扫。另外 Cu Cu 变成「只删相邻的重复行」，Cu Cu Cu 变成「保留重复空行」——三条都是本机文档字符串里明确写的。

练习 8　在 CM% 的替换串里写 \n 想插入换行，会发生什么？

会报错：“Invalid use of ‘\’ in replacement text”。Emacs 32.0.50 的 replace-match 文档字符串最后一句是 “Any other character following ‘\’ signals an error.” 替换串只认 \&、\N、\\、\?、\,(…)、\# 这几个。要换行请用 \, 表达式。注意方向反了：在搜索串里写 \n 不会匹配换行，Emacs 会提示你改按 Cq Cj。

练习 9　想知道选中的一段有多少行、多少词、多少字符，最快的键是什么？Mx count-lines-region 对吗？

按 M=（count-words-region），一次报出行数、句数、词数、字符数四项。count-lines-region 这个命令不存在——本机实测 (fboundp 'count-lines-region) 返回 nil。真正存在的是 count-lines，但它是个编程函数，交互调用不打印任何东西。

练习 10　你刚写完 print(greeting_string)，光标在右括号前，想把 greeting_string 改成全大写。用什么键序列？

M- M2 Mu。要退 2 个而不是 1 个，因为 _ 在多数 major mode 里属于标点或符号成分、不是单词成分，Emacs 认为 greeting_string 是三个语法单位。Emacs 怎么切分「一个词」由语法表说了算——在 Ch v 里看 syntax-table 可以查当前 buffer 的切分规则。

进阶：为什么 Emacs 的正则不能向前看

Emacs 的正则引擎写于 1980 年代，是 GNU 风格的老引擎。它的设计目标是「在编辑缓冲区时够用且极快」，而不是「表达力最强」。

没有 look-ahead 意味着你不能直接表达「匹配一个后面跟着冒号的词」。实践中人们用两个绕法：

  1. 把上下文也匹配进去，然后在替换时丢掉。要找「后面跟冒号的词」，写成 \(\sw\+\):，替换串写 \1:——冒号被重新插回去，等于没变。
  2. 用两轮替换。先用一个宽泛的模式改掉全部，再回头修边角。

Emacs 确实有硬编码的特殊断言（原书提到「except specific, hard coded constructs」），数量很有限，而且全都是零宽的——它们只看「我此刻站在哪」，从不往前／往后读字符，所以仍然不是 look-ahead：\`（只匹配缓冲区开头）、\'（只匹配缓冲区末尾）、\=（只匹配光标当前位置）、\b（词首或词尾）、\B（词首词尾之外）、以及 \< \> / \_< \_> 这两组词与符号边界。本机实测：缓冲区内容为 foo\nbar 时，re-search-forward 扫 \`、\'、\= 分别命中第 1、8、1 位，而 Perl 习惯的 `、'（不带反斜杠）和 \G 一个都匹配不到——它们在 Emacs 里只是普通字面字符。行首行尾的锚点是 ^ 和 $（不带反斜杠），这一点和 PCRE 正好相反，是本章最容易记混的地方之一。

另一类 Emacs 特有构造带双下划线前缀（\_<、\_>、\s-、\sw …），那不是断言，而是语法类匹配——见 2.3 节。

反过来说，Emacs 独有的语法类（\s-、\sw、\s_、\s"、\s( …）是 PCRE 完全没有的，而且直接绑定到 Emacs 的语法表——「在当前语言的语境里理解文本」这件事，Emacs 正则比 PCRE 强。这才是它当年被选中的原因。

进阶：\, 求值为什么有这么多限制

源码里 query-replace-compile-replacement 的实现揭示了原因：Emacs 会在你按下 RET 的瞬间把替换串编译成一个 Elisp 表达式，然后每次替换时求值它一次。

所以：

  • 它只能出现在交互式调用里。非交互调用（比如从 Elisp 里写 (query-replace-regexp "a" "\\,(upcase \\&)")）不会触发编译，你会拿到 “Invalid use of ‘\’ in replacement text” 这个错误——我本机实测确认了这一点，因为编译步骤发生在读小输入框的那一步。
  • 编译的粒度是「每替换一处求值一次」，所以表达式里可以引用 replace-count 这类逐次变化的状态。
  • 正因为每次都真跑一遍 Elisp，写错的代价是真的：表达式报错会让整个替换中断。

实际建议和原书一致：\, 适合「格式转换」这种一两行能说清的需求；超过这个复杂度就上键盘宏，或者直接写一小段 Elisp——那种代码还能存下来反复用，比每次手敲 \, 表达式划算。
