五、移动理论（三）：搜索与索引

这一章讲 Emacs 里两类跳跃：在缓冲区里找文本的 Isearch 增量搜索，在整个机器上找代码的 grep 递归搜索；再加上把匹配汇总成清单的 occur、把当前文件编成索引的 imenu。本章还有一大节要处理一件原书写错了时代的事：书里推荐的 Helm 和 IDO 已不是今天的主流，今天该装的是 vertico / consult 一族；顺手还有一个很多人不知道的事实——内置的 fido-mode 不需要装包。读完能独立完成三件事：熟练用 Cs 在缓冲区里高速移动；用 occur 和 grep 把散落的匹配点汇成一份可编辑的清单；知道该往配置里写哪一套补全。

这一章在全书里的位置

前三章处理的「基本移动命令」（elemental movement commands，Emacs 里只看文本语法结构、不需要你事先知道要找什么的那一类命令）能按行、按段、按函数、按括号跳。但现实中你常常只知道要找「什么字」，不知道它在哪儿。这时候要换一套工具：搜索（search，在文本里找字符串）和索引（index，把一个缓冲区或目录里「有意思的位置」预先编号，让你能按名字跳）。这一章讲的就是这两件事，分两大块：缓冲区内（Isearch、occur、imenu）和文件系统上（grep）。

要点

Emacs 的搜索之所以特别好用，不只是因为有正则，而是它把搜索当成移动做：搜索界面不弹窗、不遮挡、不抢焦点，就在回显区（echo area，底部显示状态和正在输入内容的那一行）里敲键盘，「边想词边移动」的手感完全不被打断。从 Vim 过来的人第一次都会不适应，适应之后基本没人愿意回头。

Isearch：Emacs 的默认搜索引擎

Isearch（incremental search，增量搜索：随你敲键盘实时收窄结果）是 Emacs 里用得最多的搜索功能。它的工作方式：按 Cs 后，Emacs 在底部开一个迷你缓冲区（minibuffer，Emacs 专用于读取单行输入的小窗口，长按 Cx 时那条窄缝就是它），提示符显示 I-search:；你每敲一个字符，它立刻重新搜一遍，把当前匹配用 isearch 这个 face（face 是 Emacs 决定文字长什么样的「样式」）高亮，光标跳到匹配之后。「增量」的意思就在这里：不是敲完整串再回车。

四个入口键

默认绑定四个键（完整列表见本节末尾的按键表）。前两个是普通搜索，搜索串按字面匹配，提示符分别是 I-search: 和 I-search backward:；后两个是正则搜索，搜索串按正则表达式匹配——一种用 *、+、?、[] 描述「一类字符串」的小语言，绝大多数程序设计语言的正则都兼容它。

「向前」在 Emacs 里指光标之后（往文件末尾方向），「向后」指光标之前。这点和很多编辑器相反，记住就行。

五个动作：输入、浏览、环绕、失败、退出

  1. 选方向开始。 Cs 向前，Cr 向后。
  2. 输入即搜索。 每敲一个字符重定位一次；同时缓冲区内其他匹配也会被点亮，用 lazy-highlight 这个 face（Emacs 28 起叫「懒惰高亮」：你停顿一下它才去扫全缓冲区，扫完持续高亮到你离开搜索）。想关掉把 isearch-lazy-highlight（Emacs 28 引入，默认 t）设成 nil。
  3. 浏览匹配。 搜索中再按一次 Cs 跳到下一个匹配（isearch-repeat-forward），Cr 跳到上一个（isearch-repeat-backward）。想反方向就按另一个方向键，搜索串不变。数字前缀也认：M3 Cs 一次跳 3 个。
  4. 环绕（wrapping）。 搜到末尾再按方向键，Emacs 从另一头继续，提示符多出 Wrapped；越过出发点则变成 Overwrapped。所以「搜不到」永远不会真的搜不到。
  5. 失败反馈。 搜不到时提示符变 Failing I-Search，并把没匹配上的那部分用 isearch-fail face 标红。搜 FOOT 而缓冲区只有 FOOL，你会看到光标停在 FOO 后，只有 T 是红的。
技巧

Cs Cs 是最省事的一招：第一次开始搜索，第二次把上一次的搜索串取出来直接开搜（isearch-repeat-forward）。Cr Cr 同理向后。这是 Emacs 里性价比最高的肌肉记忆之一。

两个出口：RET 与 Cg

  • RET（isearch-exit）接受匹配：停在找到的位置，同时在出发点上放一个标记（mark，一种随时可用 Cu CSPC 跳回去的记号）。「搜过去 → RET → 忘了要干嘛 → Cu CSPC 跳回来」是完整的一套。
  • Cg（isearch-abort）放弃搜索：直接回出发位置。快捷键里的 Cg 叫取消键，Emacs 里几乎所有「我不要了」都归它管。

Cg 还有一个中间状态：搜索已经失败时，第一次 Cg 只把没匹配上的字符从搜索串里删掉（留下匹配上的部分，搜索转为成功），第二次才真正取消。这个两级行为第一次遇到会吓一跳，但很合理：你打的 FOOT 里 T 多余，Emacs 先帮你去掉。

易错

别把 Isearch 里的 Cg 当成「关掉一个小窗」。它不是关窗，是回退操作——回退到上一个还能匹配的状态。这和 VS Code 里 Esc 的直觉不同，需要适应。

大小写折叠（case folding）

Isearch 默认不区分大小写。这是特意设计的大小写折叠（case folding）：敲小写 foo 会同时匹配 foo、Foo、FOO；但只要搜索串里出现大写字母，Emacs 自动切成区分大小写。直觉是：你敲 foo 时多半不确定它在文件里长什么样，所以宽松点；你特意敲了 Foo，说明你就是要找这个名字，一个字都不能差。

想把整个默认行为关掉：

(setq case-fold-search nil)

case-fold-search（变量：控制搜索时是否折叠大小写，默认 t）同时影响 Isearch、query-replace 等等。规则本身来自 search-upper-case（默认 not-yanks）。有个细节：用 Cw 之类从光标捞进来的文字，若当前搜索忽略大小写会被自动转成小写，以保证折叠仍生效。

搜索历史（search ring）

Emacs 把最近的搜索串存进 search ring（搜索环），条数由 search-ring-max 控制，默认 16。在 Isearch 过程中：

  • Mp — isearch-ring-retreat，往旧的方向翻，取上一条到输入框里（可继续改）。
  • Mn — isearch-ring-advance，往新的方向翻。
  • MTAB 或 CMi —— 两者是同一个命令 isearch-complete，用 search ring 里的字符串补全当前搜索串。原书写的是 CMi，那是对的。很多窗口管理器会抢走 MTAB（切换窗口），抢了就换 CMi，行为完全一样，不会少任何功能。本书作者在 32.0.50 上实测过这个等价关系：(lookup-key isearch-mode-map (kbd "M-TAB")) 和 (lookup-key isearch-mode-map (kbd "C-M-i")) 都返回 isearch-complete。

把光标处的文字捞进搜索串

最常见的情况是光标正停在一个你不确定拼写的词上——报错信息里的函数名、日志里的 URL、刚改过的标识符。手打一遍纯属浪费。Isearch 为此准备了一组「捞字」命令（命令名见按键表）。其中三个值得当面说清：

  • Cw（isearch-yank-word-or-char）追加光标处下一个词，连按多次逐词追加。绝大多数时候你只需要这一个。
  • CMw（isearch-yank-symbol-or-char）追加整个符号，一个整块标识单元，如 C 语言的 foo->bar。原书把 CMy（isearch-yank-char，只追加一个字符）写成「取符号」，按 Emacs 32 的实际绑定，CMw 才是这个语义；原书说 CMy 对多数人价值边际，编辑大量非拉丁文字时可以试试。
  • Ms Ce（isearch-yank-line）追加光标处整行剩下的内容，找日志里那条完整的一行很顺手。CMz（isearch-yank-until-char）追加到下一个指定字符为止的内容，写正则替换规则时好用；Cy 把剪贴板（Emacs 里叫 kill ring）内容追加进来，紧接 My 可在多条剪切记录间换；CMd 删搜索串末尾一个字符，而 DEL（isearch-delete-char）删的是整个上一次输入动作。

七个开关（toggle）

Isearch 里最强大的一块。用 Ms 加一个键临时改变搜索规则，这些开关只影响当前这一次搜索，搜完就恢复——所以可以放心随手切。命令名见按键表，这里说三个要点：

  • Ms c 和 Ms r 分别切换大小写敏感和正则模式，两者都有单键等价物 Mc / Mr。正则开关的价值在于：你可以先用普通搜索敲个大概，再切过去继续写。
  • Ms w（词模式）开启后，像 .、- 这类分隔符可互相替代：搜 hyphenated string 能匹配 this-is-a-hyphenated-string。写代码时非常有用，搜 foo bar 能匹配 foo->bar = 42; 里的那两段。Ms _（符号模式）更严格：按当前主模式（major mode，为一类文件定制的编辑模式）认定的符号边界匹配，符号指语言里的一个完整标识单元。
  • Ms '（字符折叠）让搜 a 也匹配 á、å 等一整族等价字符；想让它常开，把 search-default-mode（变量：搜索的默认模式，默认 nil，可设成 char-fold-to-regexp 或 word-search-regexp）设成 char-fold-to-regexp。Ms i 切换是否搜「隐藏文本」——隐藏文本指被 overlay（覆盖层：贴在某段文本上的额外标记，不改原文）折叠起来的内容，如折叠大纲（outline）时收起的部分。

跳过一屏：Ms M< 与 Ms M>

这段原书和今天的 Emacs 有出入，值得单独讲。

Emacs 28 起新增了两个 Isearch 命令：Ms M<（isearch-beginning-of-buffer，跳到搜索串在整个缓冲区里第一次出现的位置）和 Ms M>（isearch-end-of-buffer，跳到最后一次）。它们默认可用，不需要任何配置，带数字前缀时跳到第 N 次出现的位置。

原书推荐的 M< / M> 走的是另一条路：它把 beginning-of-buffer（回到文件开头）这两个命令在 Isearch 里重新定义成「跳到首个 / 末个匹配」，而这个行为默认是关的，必须先开变量：

(setq isearch-allow-motion t)

isearch-allow-motion（变量：Emacs 28 引入，默认 nil）打开后，M< 和 M> 在 Isearch 里跳首 / 末匹配，Cv 和 Mv 则跳到当前窗口还没显示的上一个 / 下一个匹配——每按一次滚一屏，适合在长文件里粗略扫一遍所有匹配大致分布在哪儿。原书专门表扬了这个「跳不可见匹配」的能力，我同意，它是唯一能做到这件事的钥匙。

技巧

今天的建议：把 isearch-allow-motion 打开，两个不同键干不同的事反而更清楚：Ms M< 管「第一次在哪」（全局、默认可用），Cv / Mv 管「按屏跳」（没有替代品）。

一组相关开关，顺带交代清楚，免得在别处看到时不知道。isearch-allow-scroll（默认 nil）设成非 nil 后，滚动命令在 Isearch 里不退出搜索，设成符号 unlimited 时连「不让当前匹配滚出视野」的限制也去掉。isearch-yank-on-move（默认 nil）设成 shift 后，Isearch 里按住 S 再按光标移动键会把经过的那段文字追加进搜索串——shift 方向键是搜索，这是把 Emacs 变成「搜索就是导航」的关键技巧。isearch-motion-changes-direction 决定 motion 后方向是否跟着翻；isearch-repeat-on-direction-change（默认 nil）设 t 后按另一方向键立刻跳到另一个匹配，而不只是把光标挪到当前匹配另一端。isearch-allow-prefix（默认 t）允许在 Isearch 里直接敲数字前缀。isearch-wrap-pause（默认 t）控制搜到头时的行为：t 暂停报错等你决定，no / no-ding 立刻环绕，nil 干脆不环绕。

把搜索变成高亮，把高亮变成替换

  • Ms o — isearch-occur：用当前搜索串执行 occur（把所有匹配行汇成清单）。见下一节。缓冲区内任意位置按 Ms o 则绑到 occur，主动发起一次正则搜索。
  • M% — isearch-query-replace：用当前搜索串作为「查找」内容直接进入 query-replace（交互式替换：Emacs 逐个问你要不要替换）。负数前缀参数（M- M%）表示向后替换。这是「我搜到了，接下来批量改」的最短路径。
  • CM% — isearch-query-replace-regexp：同上，但把搜索串当正则。
  • Ms h r — isearch-highlight-regexp：退出搜索但把缓冲区里所有匹配永久高亮（hi-lock 机制，原书成书时 Emacs 才有，值得单独一提）。Ms h l 高亮整行，Ms h u 取消高亮。这套键是全局的，不在 Isearch 里也能用。

进阶：Isearch 里还有这些（很少用到，但知道就不慌）

原书写于 Emacs 26/27 时代，这几年 Isearch 又加了一些东西，都是「知道了不算本事，用到了能救命」级别：

  • 按名字搜非 ASCII 字符。 Cx 8 RET（isearch-char-by-name）输入 Unicode 名字或十六进制码点；Cx 8 e RET（isearch-emoji-by-name）输入 Emoji 名字，如 smiling face。想不起名字可以先 Cx 8 e l（emoji-list）列出全部 Emoji，或 Cx 8 e d（emoji-describe）描述当前字符。
  • 搜控制字符。 Cq（isearch-quote-char）后跟一个非图形字符或八进制数字。搜换行则是在搜索串里按 Cj。
  • 输入方法。 当前缓冲区开了输入法（input method，用来打非 ASCII 字符的方案，如拼音、日文假名）的，Isearch 里也自动可用；C\（isearch-toggle-input-method）切换，C^（isearch-toggle-specified-input-method）换指定的一种，Cx \（isearch-transient-input-method）临时用一下就关。提示符会显示 I-search [IM]:。
  • 把不认识的字符并入搜索串。 search-exit-option 设成 append 后，搜索中按 Ca 这类「本来会退出搜索」的键不再退出，而是当成搜索串的一部分。
  • 在 Isearch 里查帮助。 Ch Ch 进入 isearch-help-map，再按 b 就是 isearch-describe-bindings，列出 Isearch 全部键位及命令说明。这条命令任何模式下都能按，所以哪怕你把 Isearch 键位改乱了也能自救。
  • 非增量搜索。 搜索串为空时直接按 RET，Emacs 切到非增量搜索（isearch-nonincremental）：先输入完整搜索串，回车才搜一次，提示符显示 search:。适合搜索串含控制字符、需要精确控制的情况。
  • 取消的硬核写法。 ESC ESC ESC（isearch-cancel）无条件取消；Cg Cg 是连按两次取消。搜索串编辑则用 Me（isearch-edit-string）在迷你缓冲区里改，此时 Cf / → 可把光标处后续字符追加进搜索串。

练习 1　光标停在一个你不确定拼写的函数名上，想用它作为搜索串去找其他定义。开始向前搜索后，第一下应该按什么键？

Cw，即 isearch-yank-word-or-char：它把光标处下一个词追加进搜索串，连按多次会一个个词往下追加。想一次取整个符号（像 foo->bar）用 CMw；要整行则用 Ms Ce。

练习 2　缓冲区里有 foo->bar = 42;，你用 Cs 搜 foo bar 搜不到。按哪个开关能让它匹配上？命令名叫什么？开关默认状态如何？

按 Ms w，命令是 isearch-toggle-word（词模式）。它把 .、- 视为可互换，于是 foo bar 能匹配 foo->bar。开关默认关闭，只在当前这次搜索里生效。更严格的版本是 Ms _（isearch-toggle-symbol，按语言认定的符号边界匹配）。

练习 3　想在当前搜索过程中直接跳到该字符串在整个缓冲区里第一次出现的位置。用哪个键？需要先改配置吗？

用 Ms M<，命令是 isearch-beginning-of-buffer，Emacs 28 起默认可用，不需要改配置。跳到最后一个用 Ms M>（isearch-end-of-buffer）。原书说的 M< / M> 是另一条路：靠 isearch-allow-motion（默认 nil）开启才生效；开启后 Cv / Mv 还能按屏跳过当前不可见的匹配。

练习 4　你从文件开头搜到了第 400 行，想在那里接着做事；但十分钟后你意识到其实想先看看第 400 行有没有我要的字。用哪个键结束搜索？结束后怎么跳回第 400 行？

用 RET（isearch-exit）接受匹配，它同时会在你出发位置放一个标记。之后按 Cu CSPC（set-mark-command 配前缀参数）就能跳回第 400 行。Cg（isearch-abort）也能回原位，但它不给你留标记，是「取消」而不是「完成」。

Thing at Point：光标处的那块「东西」

Cw 的思路可以再推一步：与其手工告诉 Emacs「我要找的是词还是符号」，不如让它自己判断光标处最可能是个什么东西。Emacs 内核里有个 thing at point（光标处的东西）机制，thing-at-point（函数：按类型取出光标处那块文本，类型可以是 word、symbol、url、sexp 等）是总入口。搜索里有两个现成的用户界面：

  • Ms . — isearch-forward-symbol-at-point，取光标处的符号直接开始向前搜索。符号的边界由主模式决定，但 Emacs 通常很聪明，能自己判断符号从哪里开始到哪里结束。这个键是全局的，不在 Isearch 里也能按。
  • Ms M. — isearch-forward-thing-at-point，取光标处的「东西」直接开始搜索。取什么由变量 isearch-forward-thing-at-point（默认 '(region url symbol sexp)）决定：按这个顺序依次尝试——有激活的选区就用选区文本，否则试 URL，再试符号，再试 S 表达式（sexp，用括号平衡切出的一段代码）。

这个「按顺序试」恰好覆盖日常最常见的三种情况：选中一段文字想找同样的文字、停在一个 URL 上想搜它、停在一个函数调用上想找它的定义。这套机制还被 M(（mark-sexp）、M-（mark-symbol）、Mw（mark-word）复用——它们本质都是「把 thing at point 选出来当区域」。

进阶：包作者如何扩展 thing at point——以及一个常见误解

thing at point 是一套可扩展机制：任何包都能注册自己认得的「东西」。这在 Emacs 30 之后有了正式、可查的写法。

Emacs 30 之前，包作者用 define-thing-at-point（宏：定义一个新的 thing 类型）注册。但在 Emacs 32（以及 30/31）里这个宏已经从内核中移除了——我在这台 Emacs 32.0.50 上实测 (fboundp 'define-thing-at-point) 返回 nil，本机 Emacs 32 的 Elisp 手册里也查不到这个词条。如果你在网上（多半是 2018–2022 年的文章）看到它，那是旧写法。

Emacs 30 起的正规接口是三个 provider 列表变量，写在 thingatpt.el 里：thing-at-point-provider-alist（提供 thing-at-point 的取值方式）、forward-thing-provider-alist（提供 forward-thing，从 thing 跳到下一个）、bounds-of-thing-at-point-provider-alist（算出 thing 的起止位置）。Emacs 30 还加了两个便利函数 thing-at-point-for-char-property 和 bounds-of-thing-at-point-for-char-property 帮写基于文本属性的 provider，并让 bug-reference-mode 支持了 thing at point（在 bug 引用上取 url 得到这个 bug 的 URL）。

作为使用者你不需要碰这些。但知道「thing at point 是可扩展的」有实际价值：遇到 Ms M. 在某个模式下取错了东西（比如你的 Org 文件里它取了 sexp 而不是你想要的标题），那大概是这个包注册的方式不对，不是你用错了。

Occur：把匹配行汇成一张清单

Occur 是 Emacs 内置的类 grep 工具。和 grep 相比它功能少得多，默认也只搜当前这一个缓冲区，但有两个 grep 没有的优势：速度快，而且不需要调用外部进程（grep 得把文件交给操作系统上的 grep 可执行程序，occur 全在 Emacs 内部完成）。它还会保留语法高亮——匹配结果里代码还是彩色的，grep 输出则是纯文本。

Isearch 是「一个一个走过匹配」，occur 是「把所有匹配行抄到一个新缓冲区里」。这个新缓冲区叫 *Occur*（名字两侧星号表示 Emacs 自动生成的临时缓冲区，不用保存），每行以行号开头，就是一个超链接：鼠标点它或光标停在上面按 RET，立刻跳回原缓冲区那一行。

下面这段是本书作者在本机 Emacs 32.0.50 上真跑出来的：源缓冲区名叫 *temp*，里面三行文字，在 (point-min) 处执行 (occur "gamma")，*Occur* 缓冲区里就是这三行（下面 | 标记是给你看的说明，不是真的输出）：

源缓冲区 *temp*：                 *Occur* 缓冲区：
  1  alpha beta                  2 matches for "gamma" in buffer: *temp*
  2  delta gamma        →              2:delta gamma
  3  zeta epsilon gamma beta           3:zeta epsilon gamma beta
要点

这个输出里有三个数字，含义各不相同，混起来读是最常见的困惑来源：

  • 最前面的 2 matches for "gamma" —— 一共匹配到几行。它是统计，跟 *temp* 是两回事。
  • in buffer: *temp* —— 被搜的那个缓冲区叫什么。occur 默认只搜当前这一个，所以这里出现的不是你的文件名，而是你碰巧正待着的那个缓冲区名。如果你在一个叫 notes.txt 的文件里按 Ms o，这里就会写 notes.txt。
  • 每行行首那个 2: 和 3: —— 这一行在源缓冲区里是第几行。2:delta gamma 的意思是「源缓冲区第 2 行，内容是 delta gamma」。把这个行号和左边源缓冲区对照着看：源缓冲区第 1 行 alpha beta 不含 gamma，所以没出现在清单里；第 2、3 行含了，于是清单里就是它们的行号。

所以「为什么不是我的文件名」和「为什么不是全部行」这两个问题，答案都在上面第三条里。

接下来才是这一节的重点：清单本身可以当索引用。光标停在 2:delta gamma 这一行，按 RET（occur-mode-goto-occurrence），Emacs 就跳回 *temp* 的第 2 行；按 o（occur-mode-goto-occurrence-other-window）则在另开一个窗口显示那一行，本窗口继续留在清单上，好让你一条条往下过。

怎么用

  • Ms o（occur）—— 在缓冲区任意位置按，Emacs 问一个正则表达式，把当前缓冲区所有含匹配的行汇总到 *Occur*。注意 occur 只接受正则、不接受「字面字符串」模式，但正则里普通字符就是字面意思，通常没区别。
  • Ms o 在 Isearch 过程中按（isearch-occur）—— 直接用当前搜索串，不用重新输入。同一按键在两种场合绑到不同命令，因为 Isearch 里键位先由 isearch-mode-map（Isearch 自己的键位表）解释。
  • M-x multi-occur-in-matching-buffers —— 跨多个缓冲区。第一个参数是匹配缓冲区名字的正则，比如 \.py$ 表示「所有名字以 .py 结尾的缓冲区」；第二个参数是要搜的内容。例如输入 \.py$ RET def parse RET。
  • M-x multi-occur —— 同上，但让你逐个手挑缓冲区。更精确，也更啰嗦。

两种 multi-occur 产生的也是 *Occur* 缓冲区（内部走同一个 occur-1），里面可以正常用下面那张表里的所有键。想看匹配行的上下文（前后几行），改变量 list-matching-lines-default-context-lines（默认 0）：负数表示只在匹配行之前带 N 行，正数表示前后各带 N 行。

(setq list-matching-lines-default-context-lines 2)
易错

旧资料里 occur 的老名字 list-matching-lines 在 Emacs 32 里仍然存在，但它是 occur 的别名（alias），官方文档已不再收录。新写配置请一律用 occur。

*Occur* 缓冲区里的按键

下表是我在 Emacs 32.0.50 上实际执行一次 occur 之后逐键查出来的结果，和原书有出入的地方已经标出。三点值得当面说清：

  • Mn / Mp 在清单内移动光标（不跳回源文件），n / p 同样在清单内移动但不跳转窗口——后者原书没提。
  • g（revert-buffer）重跑一遍搜索刷新清单。Emacs 里 g 是极强的惯例：几乎所有「刷新当前视图」的模式都把它绑到 revert-buffer，值得当成通用习惯记住。r 会把缓冲区改名成 *Occur: 源文件名，跨多文件搜索时很方便区分。
  • Cc Cc —— 在不同模式下含义不同：普通 occur-mode 里它是「跳到源行」（原书没说）；在按过 e 之后的 occur-edit-mode 里，它才是「提交修改并返回 occur-mode」（occur-cease-edit）。这是原书那一行最容易让人踩坑的地方。

occur-edit-mode：在清单里直接改源文件

在 *Occur* 里按 e，只读属性被去掉，你可以像编辑普通文本一样直接改这些匹配行；改完按 Cc Cc（occur-cease-edit），改动会同步写回原来的缓冲区。

这个功能的价值不在于「改几行字」，而在于你能一边看着全局清单一边批量修改。比如一个配置错误出现在 30 个不同文件里，你在 *Occur* 里逐个跳过去改、改完提交，全程不用在 30 个窗口之间来回切。再配合键盘宏（第 8 章）或 query-replace（第 7 章）威力更大。

技巧

在 *Occur* 里按 Cc Cf 打开 next-error-follow-minor-mode，之后每次用 Mg Mn 在匹配间跳时，另一窗口会跟着实时显示对应行的上下文——这样你连 *Occur* 都不用看，直接在源文件窗口里审阅。

next-error：occur / grep / compile 共用的一套跳转

Emacs 有个通用命令 next-error（Mg Mn）和 previous-error（Mg Mp）。名字里带「error」纯属历史遗留——它们和报错没关系。

机制是：每当你运行一个「产出一份匹配清单」的命令（occur、grep、compile……），Emacs 把那份清单登记成「上一次错误列表」，Mg Mn 就自动变成「跳到上一次那类操作的第 N 个匹配」。你只需要记这一对键，它就能用在编译错误、grep 结果、occur 清单上，而且还能跨缓冲区：文件没打开就自动打开，已经打开了就切过去。这是 Emacs「一切都是缓冲区」这个设计最漂亮的地方之一。

练习 5　你跑了一次 occur，在 *Occur* 里看着清单很满意。现在的问题是：清单在右边窗口，你在左边的源文件里来回跳太累。用哪一对键可以在两边之间自动来回，不需要鼠标？

Mg Mn（next-error）跳到下一个，Mg Mp（previous-error）跳到上一个。occur 执行完会把清单登记成「上一次错误列表」，所以这对键直接生效，而且它们对 grep 和 compile 的结果同样有效——记住这一对就够了。想让它在移动时另一窗口实时显示上下文，在 *Occur* 里按 Cc Cf。

练习 6　当前缓冲区有三万行，你想看所有包含 timeout 的整行，而不是一行行跳过去。Emacs 里怎么做？如果此刻你正在 Isearch 过程中呢？

在缓冲区任意位置按 Ms o（命令 occur），输入正则 timeout RET，Emacs 生成 *Occur* 缓冲区列出所有匹配行，每行可跳转。如果已经在 Isearch 过程中，同一个键 Ms o 走的是 isearch-occur，直接拿当前搜索串用，不用重新输入。想让每行带上前后 2 行上下文，把 list-matching-lines-default-context-lines 设成 2。

练习 7　你在 *Occur* 清单里发现 12 行的拼写都错了，想直接改掉。按哪个键进入可编辑状态？改完按哪个键提交？请特别说明：如果还没按第一个键就按了提交键，会发生什么？

按 e（occur-edit-mode）进入编辑状态，改完按 Cc Cc（occur-cease-edit）提交，改动会写回源缓冲区。陷阱：在还没按 e 的普通 occur-mode 里，Cc Cc 绑的是 occur-mode-goto-occurrence，意思是「跳到源行」——按了会跳走而什么都没改。补一句：*Occur* 缓冲区默认只读，不按 e 根本改不动。

Imenu：跳到定义

Imenu 是一个索引框架：主模式的作者写一小段 Elisp，生成一份「名字 → 位置」的列表，你调 imenu 就能从列表里按名字跳过去。编程模式里最典型的「兴趣点」是函数定义和类定义；邮件模式、结构化文本模式（Markdown、reStructuredText）的标题层级也能用。不是所有主模式都支持，但编程模式绝大多数支持。

键位现状（原书说对了，值得强调）：Emacs 29 起 imenu 才有全局键 Mg i；在此之前它没有任何全局键位，只能 M-x 调用。原书说「20 年老用户也不知道 imenu 有全局键」，指的就是这件事。Emacs 28 及更早的用户可以自己绑：

(global-set-key (kbd "M-i") 'imenu)

但今天不建议这么做。Mi 默认是 tab-to-tab-stop（跳到下一个制表位，一个打字机时代的概念），绑走它没什么损失，但也没必要——Mg i 已经够好记，而且 consult 生态正是把 consult-imenu 挂在 Mg i 上的。

还有一个版本差异：Emacs 30 新增了 imenu-flatten 变量（控制是否把 imenu 层级拍平成一维列表及如何显示），还允许用 completion-category-overrides 自定义 imenu 补全的排序。所以 Emacs 30+ 上，深层嵌套的代码里 imenu 会变得很好用。

要点

什么时候用 imenu，什么时候用 Isearch？原书这个判断很准，值得照抄：当你不确定某个东西在文件的哪儿（你知道有个 handleRequest 方法但不知道在哪个文件哪一行），用 imenu；当你能看见想要的东西（屏幕上就有个词），用 Cs，更快。

进阶：给不支持 imenu 的模式手写一份索引

接口是 imenu--make-index-alist（函数：根据一个「匹配规则列表」生成索引），最常用的两条规则由 imenu-generic-expression（变量：通用的 imenu 匹配表达式，默认 '((nil . "^\\(defun\\|defmacro\\|defsubst\\|defadvice\\|define-compilation-error\\|define-on-demand-widget\\|define-derived-mode\\|define-generic-mode\\|define-minor-mode\\)")）和 imenu-create-index-function 提供。规则种类有：:submenu（带标题的子菜单，用于嵌套结构）、形如 ("标题正则" . 正则)（按正则匹配标题）、形如 (名字 . 位置) 的直接指定项。

例如给一个 CSV 模式做「按列名索引」：

(defun my-csv-imenu ()
  "Build an imenu index from the header line of the current buffer."
  (let ((headers (split-string (car (split-string (buffer-substring-no-properties
                                                   (point-min) (line-beginning-position 2))
                                                  "\t")) "\t")))
    (mapcar (lambda (hdr) (cons hdr (list (point-min) hdr))) headers)))

(add-hook 'csv-mode-hook
          (lambda ()
            (setq-local imenu-create-index-function 'my-csv-imenu)))

写完在缓冲区里按 Mg i 就能挑列名跳转。这不是通用模板，但说明了接口长什么样：返回一个「名字 . 位置」列表就行，位置可以是一个数字，也可以是 (点 . 缓冲) 这样的列表。

说实话，绝大多数情况下你更该考虑装 consult（它自带的 consult-imenu 体验好得多），或者装对应主模式的增强包。先写 Elisp 是最后一步。

补全的谱系：Emacs 这三十年换了几代方案

到这里为止讲的全是内置搜索。下一节是本章的时代重点，也是原书和今天差距最大的地方。

补全到底是什么

补全（completion）指：在 Emacs 底部的迷你缓冲区里输入一段文字（文件名、buffer 名、命令名……），Emacs 实时列出所有「以你输入内容开头」的候选，你挑一个填进去。迷你缓冲区被用来读一行输入，几乎每个会问「哪个文件」「哪个 buffer」「哪条命令」的交互最后都落到它上面——Cx Cf（find-file）、Cx b（switch-to-buffer）、Mx（execute-extended-command，按名字执行命令）、Isearch 的搜索串——全是它。所以「换一个补全方案」实际效果是你每天用几十次的那个输入框换了一副面孔。

第一代：默认的前缀补全

Emacs 最早也最老实的方案是按 TAB 补全：在 M-x 里打 re 然后 TAB，Emacs 把 recenter-top-bottom、rectangle 等所有以 re 开头的候选列出来，再按 TAB 补全成唯一那个。实现由 completion-styles（变量：补全算法列表，默认 '(basic partial-completion emacs22)）控制。它永远是 TAB 驱动、先补全再让你看候选——你必须先按 TAB 才「有反应」，这对追求实时反馈的人是致命的。

Emacs 29 起新增了 partial-completion 风格（默认已包含），还有 flex 风格（flex matching，弹性匹配：fb 匹配 foo-bar、f-b 匹配 foobar，代价是变慢）。

易错

我在 Emacs 32.0.50 上实测过：原书和大量中文教程还在讲的 use-completion（Emacs 29 引入的新式补全总开关）在 Emacs 32 里已经不存在了——(fboundp 'use-completion) 返回 nil，本机 Emacs 32 的 Elisp 手册里也查不到这个词。看到讲 use-completion 的文章，请先确认它的 Emacs 版本。

第二代：ido 与 helm（原书的主角）

IDO（Interactive DO Things）是 Emacs 内置的小型补全系统，专门优化了「打开文件」和「切换 buffer」。思路是：不做候选列表，直接在迷你缓冲区里就地把匹配上的那个名字填进去，你继续打字它就继续补。极其高效——手指不用离开主键区，眼睛不用看别处，打 Cx b 然后 wc 就直接变成 widgets.c。原书说 IDO「注意不到干扰、目标感明确」，说的就是这个。

Helm 走相反路子：它是一个通用的边打字边筛选（filter-as-you-type）框架，会弹出一个候选缓冲区列出所有匹配项，你上下移动挑一个。视觉信息量最大，适合「我不完全确定要找什么」。原书在这一章花了整整五页讲 Helm 并建议「装上它，你会体验大幅提升」——今天读到这里需要打个问号。

第三代：ivy/counsel → consult（今天的主流）

  • ivy（通用补全框架）+ counsel（一批用 ivy 重写的常用命令）+ swiper（Isearch 的增强版）——三者同属一个仓库（abo-abo/swiper）。ivy 从 GNU ELPA 或 MELPA 都能装。
  • consult（作者 Daniel Mendler）—— 新一代方案，目标是不做补全引擎，只做命令。它的命令全部建立在 Emacs 标准 API completing-read（Elisp 手册 Minibuffer Completion 一节那个标准函数）之上，因此可以跟在 Emacs 自带的默认补全、vertico、mct、Icomplete 任意一种配合工作。

一条本书作者没能亲手核实的关键事实，你要知道它的证据强度。consult 和 vertico 进入了 GNU ELPA（Emacs 自带的官方包仓库，MELPA 上也有）这件事，本书的依据是这两个项目自己的 README 文档——consult 的 README 里明写着 “Consult can be installed from ELPA or MELPA via the Emacs built-in package manager”，两个仓库首页也挂着 ELPA 徽章。本书作者写这一章时网络被拦，没能直连 elpa.gnu.org 去核对包索引，所以这是「文档说的」，不是「作者看着包索引说的」。当年 Helm 就一直没进 ELPA，这也是同一来源。

技巧

所以装包之前，你自己花 20 秒核实一下，别信任何二手结论（包括本书）。按 Mx 输入 package-archives 回车——Emacs 默认的 GNU ELPA archive 那一项就是官方仓库；然后按 Mx package-list-packages RET，在 *Package List* 缓冲区里直接输入包名筛选，能看到 consult / vertico 就说明确实在官方仓库里。这一步只依赖你能连上网络——如果连不上，你连装包都做不到，问题自动变成「先解决网络」，而不是「是不是包名错了」。

万一 M-x package-install 报「找不到该包」，不要以为装不了就退回 Helm 那一套。那通常是默认的 GNU ELPA archive 没配好、或者网络不通。解法是先把 MELPA 加进去（https://melpa.org/packages/），第 0 章 0.3 节给了添加仓库地址和验证方法。加完 MELPA 之后 consult、vertico、corfu、cape、orderless 都能装到——这几个项目在 MELPA 上是确定存在的。

配套家族（除 vertico 和 compat 外都在 MELPA）：

  • vertico（VERTical Interactive COmpletion）—— 把候选竖着列出来，只改界面不改逻辑，因此和 Emacs 内核补全机制完全兼容。主要代码只有约 600 行，非常小。
  • marginalia —— 在候选旁边加边注（annotation）：文件大小、Git 状态、函数文档、时钟时长等。
  • embark —— 给当前候选提供局部动作（相当于上下文菜单）：选文件时提供「删除这个文件」等；还可以 embark-export 把候选导出成 Occur 或 Dired 缓冲区。
  • orderless —— 让匹配不依赖字符顺序（fbb 匹配 foo-bar-baz）。
  • compat —— consult 的依赖，提供对旧版 Emacs 的兼容层。

今天的三条路线，你该选哪条

  1. 什么都不装，先用默认补全。 自带的 TAB 补全在 Emacs 30/31/32 上足够用两三个月。好处是你不会因为「必须先装包才能正常用 Emacs」而卡住。
  2. 一行配置：内置的 fido-mode 或 vertico-mode。 性价比最高的一档，见下。
  3. 全套：vertico + consult（可选 marginalia + embark）。 今天社区的事实标准，值得花一个下午配置。README 给的最小配置只有五行：
(package-initialize)
(require 'consult)
(require 'vertico)
(vertico-mode)
(setq completion-styles '(substring basic))

substring 是一种子串匹配风格：输入 wgt 也能匹配 widgets.c（不要求从头开始）；basic 是传统前缀匹配。两个一起开，行为最接近原书描述的「随心输入」手感。

consult 自己不提供任何模式，也不绑定任何键——它只提供命令，绑定留给你（那是第 13 章的内容）。它官方推荐的键位里和本章直接相关的几个，我照抄并标注了各自替换掉哪个内置键：

  • Cx b → consult-buffer，替换 switch-to-buffer。可切换 buffer、最近打开的文件、书签、其它来源的类 buffer 候选。
  • Cx Cf → consult-find，替换 find-file。
  • Mg i → consult-imenu，替换 imenu。它把 imenu 层级拍平成一维列表，还带实时预览和分组。
  • Mg Mg、Mg g → consult-goto-line，替换 goto-line。
  • Ms d → consult-find（按名字找文件）；Ms c → consult-locate；Ms g → consult-grep；Ms G → consult-git-grep；Ms r → consult-ripgrep。
  • Ms l → consult-line：在当前缓冲区里按行内容搜，可选中所有匹配行并编辑（导出会变成一个 Occur 缓冲区）。和 occur 互补：occur 是只读清单，consult-line 是能直接改的。
  • Mg e → consult-compile-error；Mg r → consult-grep-match。
  • Isearch 集成（最漂亮的一招）：把 consult-line 绑到 isearch-mode-map 的 Ms l，这样你在 Isearch 中就能调用它——把 Isearch 的「找到」直接变成「批量选中并编辑」。

还有一个 future history（未来历史）特性：在 consult 任何提示符下按 Mn，它会「猜」你想输入什么，比如把光标处的符号、URL、文件路径直接填进去；大部分命令还会把最近的 Isearch 字符串塞进这个猜测里。知道这点能省掉很多手打。

进阶：ivy/counsel/swiper 现在算什么地位？

它的仓库还在活跃维护（我查到最近一次推送是 2026 年 9 月），README 依然完整，但已经不是新项目的推荐起点了。README 里有一句很坦白的说明：consult 的排错清单明确写着 selectrum-mode、ivy-mode、helm-mode、ido-mode 和 ido-ubiquitous-mode 都属于「不支持」的模式，遇到 bug 必须先关掉它们——也就是说 consult 作者自己承认这些是替代关系而不是共存关系。

什么时候还该考虑 counsel：你的配置里已经装好了 counsel + swiper，不折腾；你需要 swiper——Isearch 的增强替代品，能给匹配点分组显示，这是 counsel 这一族里 consult 暂时没有对位的东西；或者你依赖某个只在 counsel 生态里的包（比如 ivy-rich）。新项目不要以它为起点。

Helm 今天的处境

先说事实：Helm 没有死。我查了它的 GitHub 仓库，最近一次推送是 2026 年 10 月 1 日，还在活跃维护，README 上挂着 MELPA 和 MELPA Stable 徽章——但没有 ELPA 徽章，而 consult、vertico、ivy 都进了 GNU ELPA。这是官方包仓库对一个项目成熟度的背书差距。

技术处境：Helm 的核心机制是自己接管迷你缓冲区，并且替换（而不是扩展）Emacs 的补全机制。它的架构和 consult 走的「只做命令 + 用标准 completing-read」路线在哲学上就冲突：Helm 强调视觉化的候选窗口，而 Emacs 30 以后社区更倾向于让命令在不同补全 UI 下都能工作。

要点

「替换」具体替换了什么，读者最需要知道这一点，因为它决定了你该怎么排查。指的是迷你缓冲区（minibuffer）的行为：Helm 自己接管它，于是 M-x RET、C-x Cf、M-x 这些本来要弹出一个输入框的动作，全都会先弹出 Helm 那个大候选窗口。Emacs 自己的补全引擎（completion-styles、vertico-mode）被绕过了，不是被增强。

而 consult 不会碰 CMi、MTAB、Cs、Mg Mn 这些内置键。本书作者在本机 Emacs 32.0.50 上把装好的 consult 3.6 整个目录 grep -rl "C-M-i" 过一遍，零命中——也就是说 consult 作者根本没碰过这个键。所以「被窗口管理器抢了 MTAB 就换 CMi」和「会不会和 consult 打架」是两个不相干的问题：前者是键盘硬件问题，后者是包之间的问题，CMi 两边都不沾。

真正会互相干扰的，是 helm-mode、ivy-mode、selectrum-mode、ido-mode、ido-ubiquitous-mode 这几个——consult 的 README 在排错清单里明确把这几个列为「遇到 bug 必须先关掉」。也就是说：consult 和这些是替代关系，和 CMi 这种内置键位不是。

建议：不要新装 Helm——照着原书 p.170–175 装，你会得到一个能用、但会跟现代 Emacs 的其他部分持续摩擦的方案。已经装了也不必恐慌，它不跟内置功能冲突，只是你得记住它那一整套键位和命令名（下面折叠区里完整保留了）。

IDO 今天的处境，以及内置的 fido-mode

IDO 只对「文件和 buffer 名」这一类补全做了深度优化，其他地方用不上；它是 2000 年代初的作品，Emacs 后来十几年的补全架构改进它基本没享受到。

今天如果你还想要「就地补全」那种手感，Emacs 自带了一个：fido-mode。

这是个很多人不知道的事实：fido-mode 是 Emacs 内置的，不需要装任何包。我在 Emacs 32.0.50 上查到它的定义在 icomplete.el 里，文档字符串原文是「An enhanced icomplete-mode that emulates ido-mode」——一个模仿 ido-mode 的增强版 icomplete-mode。fido-vertical-mode（竖直列表版）是 Emacs 28 新增的（NEWS.28 明确记录了「New minor modes icomplete-vertical-mode and fido-vertical-mode」）。所以原书第 180 页推荐你「去装第三方 FIDO 包」，今天只需要：

(fido-mode 1)

放进初始化文件（或 M-x fido-mode 临时开）就行。它会自动启用 icomplete-mode（所以不用另外开 icomplete-mode），把候选就地填进迷你缓冲区，并自动使用 flex 匹配风格。

易错

fido-mode 和 vertico-mode 不要同时开。 两者都想接管迷你缓冲区的呈现，会互相打架。要竖直下拉列表用 vertico-mode，要就地补全用 fido-mode，二选一。

IDO 本身的键位（如果你已经用了 (ido-mode 1)）：Emacs 32 的 ido.el 里有四张键位表。ido-common-completion-map（所有 IDO 命令共有）里常用的是 Cs / Cr（ido-next-match / ido-prev-match）、TAB（ido-complete，回到传统 TAB 补全）、SPC（ido-complete-space，补全并吃掉一个空格，这是 IDO 最好用的键）、RET（ido-exit-minibuffer，接受当前匹配）、Cd（ido-magic-delete-char，智能删除）、MSPC（ido-take-first-match，直接选第一个匹配）、?（ido-completion-help，列出全部键位）。文件那张 ido-file-dir-completion-map 里 DEL 和 Backspace 都是 ido-delete-backward-updir、Cl 是 ido-reread-directory、Mf 是 ido-wide-find-file-or-pop-dir。buffer 那张 ido-buffer-completion-map 里 Ck 是 ido-kill-buffer-at-head、Co 是 ido-toggle-virtual-buffers。

要点

原书 p.178 给的 IDO 文件/目录键位表里有三条在今天的 Emacs 32 里已经不成立：Cd（原书写「在当前目录打开 Dired」，现在这个键是 ido-magic-delete-char，开 Dired 改成了 Cx Cd）、//（原书写「跳到根目录」）、~/（原书写「跳到家目录」）——这三个在 ido.el 里已经没有对应绑定了。Cs / Cr 和 TAB 在文件与 buffer 两张表里都有，含义与原书一致；RET 两表都是接受匹配。原书表格之外的 Ck、Co、Cx Cf（ido-enter-find-file）也是原书没提的。

从 Helm / IDO 迁到 consult：一份可执行清单

原则是一次只换一层，不要同时改键位和引擎：

  1. 先关 IDO。 把配置里的 (ido-mode 1)、(setq ido-everywhere t)、(setq ido-enable-flex-matching t) 删掉或注释掉。ido-everywhere 在 Emacs 32 里已是一个 minor mode（原书让你 setq，今天写 (ido-everywhere 1) 效果一样），不关掉它才会到处劫持读文件名的入口。
  2. 装 vertico 和 consult。 M-x package-install RET vertico RET、M-x package-install RET consult RET。不要同时保留 helm。装之前重启 Emacs 让 package 系统生效。如果提示找不到这个包，说明你的 GNU ELPA archive 没配好或者网络不通——用上面那段「技巧」里的 package-list-packages 核实一遍，必要时先把 MELPA 加进去（https://melpa.org/packages/，第 0 章 0.3 节有方法），这两个包在 MELPA 上是确定有的。
  3. 先只开 vertico。 写 (vertico-mode 1) 和 (setq completion-styles '(substring basic))，重启。这一阶段所有迷你缓冲区都会变成竖直候选列表，但命令还是原来的内置命令。
  4. 用一周，只把三个键绑到 consult。 建议从 Cx b → consult-buffer、Cx Cf → consult-find、Mg i → consult-imenu 开始，因为最常用、替换后收益最明显。用顺手了再逐个加。
  5. 加 Isearch 集成（可选，推荐）。 把 consult-line 绑到 isearch-mode-map 的 Ms l，consult-line-multi 绑到 Ms L。这是 consult 体验的分水岭：搜完之后能直接进入「选中所有匹配行」的编辑状态，而不只是跳转。
  6. 卸载 Helm（可选，也是全清单里唯一不可逆的一步）。 确认已不再需要任何 Cx c 开头的命令之后，再 M-x package-delete RET helm RET。「先看清楚会删掉什么」具体是哪几个键：M-x package-menu RET 打开 *Package Menu* 缓冲区，光标停在某个包上时，缓冲区顶部会列出它的依赖；按 RET 展开这个包的详情，看清 Installed by 和 Version 两行；确定要删了按 d，Emacs 会问「这些依赖也要一起删吗」，逐个看清楚再答 y。如果不确定就按 q 退出，什么都没发生——这才是「不要跳过确认」的真正含义。
  7. 删错了怎么办。 package-delete 只删 elpa/ 目录里那个包的目录，不碰你的 init.el，所以配置不会因为删包而报错，只是那些命令变成 void-function。回滚很简单：重新 M-x package-install RET helm RET 装回来，然后重启 Emacs。真正删不回来的只有「当初没装的」那部分。
  8. 加 marginalia / embark（以后再说）。 这两个是纯增强，关掉也不会坏。

如果你不想装任何东西，第 2–6 步全部跳过，只做第 1 步（关掉 IDO），然后把 (fido-mode 1) 写进去。这是今天「零依赖但仍有就地补全」的最小方案。

进阶：Helm 的完整键位表（原书 p.171–175，今天仅供已装 Helm 的读者查阅）

以下原样保留自原书，供已经装了 Helm 的读者查键位。新读者请跳过本框。Helm 是第三方包（不在 Emacs 里，也不在 GNU ELPA），安装方式是 M-x package-install 后输入 helm 回车，重启 Emacs。

所有 Helm 命令共享前缀键 Cx c。原书对这个前缀键的批评我同意一半：它离 Cx Cc（退出 Emacs）太近，后续键位（如 Cx c Cc g）也确实拗口——但你在用 Helm，这些键已经生效了，记下来就行。

Helm 通用键位：RET 执行主要动作（通常是跳转、打开、显示）；Ce 执行次要动作——有个容易被误会的细节，Ce 原本是「移到行尾」这个基本移动命令，在 Helm 里如果光标还不在行尾它仍然移到行尾，只有在行尾时才触发次要动作；Cj 执行第三动作；TAB 切换到动作选择器，同样支持边打字边筛选；Cn / Cp 下一个 / 上一个候选；Cv / Mv 向下 / 向上翻页；M< / M> 跳到列表开头 / 结尾；Cg 是退出 Helm 的万能键。

Helm 的主要补全引擎（都带 Cx c 前缀）：Cx c b 继续上一次的 Helm 命令（helm-resume）；Cx c / 在当前目录跑 find 命令行工具（helm-find-files）；Cx c a 是 M-x apropos 的补全版（helm-apropos，看 Commands 分组就好，Functions 是内部函数）；Cx c m 是 man page 的补全（helm-man）；Cx c i 是来自 imenu 或 Semantic 的补全（helm-imenu）；Cx c r 是交互式正则构造器（helm-regexp-builder）；Cx c h r 在 Emacs Info 里搜主题（helm-info-emacs）；Cx c Mx 是 M-x 的补全（helm-M-x）；Cx c Ms o 用 Helm 匹配 occur 的模式（helm-occur）；Cx c Cc g 是 Google Suggest 搜索建议（helm-google-suggest），原书很喜欢这个功能，选中结果按 RET 就用默认浏览器搜索，键位拗口是事实，可以用 remap-key 改掉。

怎么发现 Helm 自己的命令？原书这段思路适用于任何 Emacs 功能，值得保留：Emacs Lisp 没有命名空间，所以包作者习惯给自己的命令统一加包名前缀（helm-）。于是 M-x apropos-command（Ch a）输 ^helm- 就能列出所有以 helm- 开头的命令，M-x apropos-variable 输 ^helm- 列变量。想查前缀键绑了谁，用 describe-key：敲完前缀再敲 Ch，即 Cx c Ch。两个方法问的其实是不同问题（一个问「有什么命令」，一个问「这个键按下去会怎样」），所以两个都做。Helm 还有自己的 apropos 引擎 M-x helm-apropos。

练习 8　你在网上读到一篇文章说包作者用 define-thing-at-point 注册新的 thing 类型。这个说法在 Emacs 32 上还成立吗？如果不成立，该用什么代替？

不成立。我在本机 Emacs 32.0.50 上实测 (fboundp 'define-thing-at-point) 返回 nil，本机 Emacs 32 的 Elisp 手册里也查不到这个词条——这个宏已经从内核移除了。Emacs 30 开始的正规接口是三个 provider 列表变量：thing-at-point-provider-alist、forward-thing-provider-alist、bounds-of-thing-at-point-provider-alist。作为使用者你不需要碰这些，只需要知道「thing at point 是可扩展的」，这样遇到 Ms M. 取错东西时能判断是包的问题而不是自己的问题。

练习 9　你已经按原书装好了 Helm，并且配置了 (ido-mode 1)、(setq ido-everywhere t)、(setq ido-enable-flex-matching t)。今天要迁到主流方案，正确顺序是什么？迁移前最先要做的一件事是什么？另外，「零依赖」方案又是什么？

最先做的是关掉 IDO：删掉 (ido-mode 1)、(setq ido-everywhere t)、(setq ido-enable-flex-matching t)（ido-everywhere 在 Emacs 32 里已是 minor mode，写 (ido-everywhere 1) 等价）。然后 M-x package-install 装 vertico 和 consult（两者都已进 GNU ELPA，MELPA 也有），不要同时保留 helm；先只开 (vertico-mode 1) 加 (setq completion-styles '(substring basic))，用一周，再逐步把 Cx b、Cx Cf、Mg i 换成 consult 版本；确认不用了才卸载 helm（M-x package-menu 里选中包 → 看顶部依赖 → RET 看详情 → d 删除 → y 确认；删错了重新 package-install 装回来即可，init.el 不受影响）。零依赖方案是只做第一步，然后写 (fido-mode 1)——fido-mode 是 Emacs 内置的，在 icomplete.el 里，不需要装包。但注意 fido-mode 与 vertico-mode 只能二选一。

Grep：在 Emacs 里搜索文件系统

isearch 和 occur 都只管一个缓冲区。真正常见的任务是「这个标识符在整个项目里出现在哪些文件」，这需要 grep——操作系统上的一个外部程序，遍历目录树把匹配行打印出来。Emacs 有一整族命令去调用它，并把结果变成可跳转、可编辑的缓冲区。

要点

Emacs 里用 grep 和在终端里用是两种体验。你不需要退出编辑器、不需要 tmux、不需要重新 Cx Cf 打开文件：Emacs 调完 grep 会开一个 *grep* 缓冲区，每一行匹配都是超链接，回车就跳到源文件那一行，源文件没开就自动打开。很多 Vim 用户切换到 Emacs 后最先感受到的效率提升就在这里。

grep 这一族命令没有任何一个默认绑定按键，全部要用 M-x 调用，用顺手了再自己绑键。理解它们的关键是分两大类：

  • 低层——你自己给完整命令行。M-x grep（grep）给你一条建议好的 grep 命令串，你补上搜索模式和额外选项；M-x grep-find（grep-find）同上但用 find 递下去找文件，命令串由变量 grep-find-command 提供。原书用得少，理由是它们太底层：你想搜「一组文件里的某个模式」时太麻烦。只有当你要传特定选项（比如 -i、-A 5）时才有必要。
  • 高层——只问几个问题：搜什么内容、搜哪些文件、从哪儿开始搜。M-x lgrep（lgrep）给定搜索模式和 glob 模式（一种通配符写法，如 *.c）；M-x rgrep（rgrep）再问你从哪个目录开始，递归搜子目录，这是最常用的那条命令；M-x rzgrep（rzgrep）像 rgrep 但搜 gzip 压缩过的文件。它们把命令行完全藏起来，还会聪明地猜：按当前缓冲区的文件类型推断该搜什么扩展名，并把光标处的符号作为搜索串的建议值。但「猜」出来的目录默认值未必是你要的——所以正停在一个标识符上时，M-x rgrep 之后第一个提示先别急着回车，看一眼 Base directory: 那一行对不对（下一小节专门讲这个）。

「递归」是 rgrep 的价值所在——现代项目动辄几千个文件，逐个打开搜索是不可能的。

M-x rgrep 到底在哪个目录搜：必须搞清的一件事

上面说 rgrep 「问两个问题」，这是简化说法，会害你。实际它问三个问题，而且第一个问题的默认值不是项目根，是当前缓冲区所在的那个目录。本书作者在本机 Emacs 32.0.50 上查了 grep.el 里 rgrep 的交互规格，它实际是这么走的：

照着这个顺序，一个具体的例子。假设你的项目叫 myproject，里面有 src/api/user.py、src/api/auth.py、tests/test_user.py、README.md 四个文件，而你当前打开的是 src/api/user.py，光标停在函数名 parse_config 上。此时按 Mx 输 rgrep 回车：

三个默认值分别意味着：只搜 src/api/ 及其子目录（auth.py 会被搜到，tests/test_user.py 和 README.md 不会）；搜的是 parse_config 这一个词；只有 .py 文件算数。一路 RET 下去得到的就是「src/api/ 里的 .py 文件中出现 parse_config 的所有行」。

易错

三个默认值各有一个坑，踩哪个都会让「搜不到」变成一件很费时间的事。

  • 目录：默认是 src/api/，不是项目根。想搜整个仓库，就在 Base directory: 那里把路径改成 /home/you/myproject（末尾加不加 / 都行）。改目录和保留 glob 是两个独立的选择——目录决定「从哪儿往下走」，glob 决定「哪些文件算数」。
  • glob：默认只按当前文件类型推断。在 .py 文件里搜 *.py，就搜不到 README.md 里的引用、也搜不到 Makefile 和 .yml。这一格的默认值有优先顺序：先按当前文件的扩展名去匹配一张内置别名表，匹配上就用那一组（比如在 .h 文件里默认给的是 *.h）；匹配不上就直接用 *.<扩展名>。所以你在 .cc 文件里会看到 *.cc *.cxx *.cpp *.C *.CC *.c++ 这样一串——这一格本来就接受多个用空格隔开的模式，内置别名表里 cc、cchh 这些多模式条目就是证据。想要更多可以直接写：*.py *.md *.yml。
  • 搜索串：预填的是光标处的那一个符号。光标不在标识符上时预填的是空的，得自己打。

「搜不到」的三种可能，按这个顺序排查：① 目录对不对（看 Base directory: 那一行）；② glob 把你想搜的文件类型排除掉了；③ 搜索串大小写不对——grep 默认区分大小写，搜 parse_config 找不到 Parse_Config。

技巧

第三格按 TAB 就能省掉手打。Emacs 内置了一张文件名通配符别名表，本书作者在 Emacs 32.0.50 上查到的默认值是（grep-files-aliases）：all 对应 * .*（全都要）、el 对应 *.el、ch 对应 *.[ch]、c 对应 *.c、cc 对应 *.cc *.cxx *.cpp *.C *.CC *.c++、m 对应 [Mm]akefile*、tex 对应 *.tex，等等。所以「想搜整个项目所有文件」有一个现成答案：在那一格输入 all 再按 TAB，它会展开成 * .*——注意 * 和 .* 之间有一个空格，那是 Emacs 自己生成的写法（分隔文件通配与内容通配），不要手打漏掉。想改这张表用 Mx customize 搜 grep-files-aliases。

要点

自动排除的是哪些目录？不是「Emacs 拍脑袋决定的」，是直接取自版本控制系统的排除名单。grep.el 里 grep-find-ignored-directories（rgrep 不再递归进去的目录）的默认值就是变量 vc-directory-exclusion-list 的值，本书作者在 Emacs 32.0.50 的 vc-hooks.el 第 129–132 行查到它长这样：

"SCCS" "RCS" "CVS" "MCVS" ".src" ".svn" ".git" ".hg" ".bzr"
"_MTN" "_darcs" "{arch}" ".repo" ".jj"

另外还有 grep-find-ignored-files 管文件级排除，它的默认值是从 completion-ignored-extensions 推出来的（.elc、.pyc、.o、~ 结尾的备份、.class 这类都算，本书作者在 32.0.50 上打印过那个变量的完整值）。两个变量都能用 Mx customize 改；觉得默认排得不够（比如想连 node_modules 也排掉），改 grep-find-ignored-directories 加一条即可。

本书作者在 32.0.50 上实测过：Emacs 内核没有 ripgrep 支持——(fboundp 'ripgrep-any-handler) 返回 nil，rg 也不在 Emacs 32 里。所以 rgrep 底下跑的还是系统上的 grep / find，想要 ripgrep 的速度要自己接（见下面的折叠块）。

grep-mode 缓冲区

Emacs 里做任何事最后结果都是一个缓冲区，grep 也不例外：Emacs 把 grep 进程的输出管道（pipe，一个进程把输出直接接到另一个进程的输入）进一个叫 *grep* 的缓冲区，用 grep-mode（主模式）显示它。这个模式给每行匹配加高亮并做成指向「文件名 + 行号」的超链接。

原书有个很值得学的观察：*grep* 缓冲区里的文本长得和终端里 grep 的输出一模一样，因为 Emacs 用的就是原始输出，只是加了超链接和高亮。你可以自己验证：新建一个空缓冲区（Cx b 然后输一个没被占用的名字），敲进去一行 my_file.txt:10:This does not exist!，然后按 M-x grep-mode，Emacs 会把 10 高亮成超链接。Emacs 大量采用这种「把外部命令的原始输出灌进缓冲区再解释它」的低技术但极其有效的做法，你以后还会遇到很多次。

在 grep 结果里跳转

Mg Mn（next-error）跳到下一个匹配，Mg Mp（previous-error）跳到上一个——跟 occur 那节是同一套机制。Emacs 会自动打开还没打开的文件、跳到对应行；已经打开的就直接切过去。这就是为什么你只需要记住一对键。审阅结果时按 Cc Cf 打开 next-error-follow-minor-mode，另一窗口会跟着 Mg Mn 的节奏实时显示上下文。

怎么配置 grep

原书建议你 M-x customize-group grep 去配置，这一招今天依然有效（customize 是 Emacs 内置的配置界面）。这里说两件 grep 命令在背后「猜」的事：跨平台一致——Emacs 要在各种平台上表现一致，有些平台没有 xargs（把 find 的输出喂给另一个命令的工具），Emacs 会检测并改用 find 自己的 -exec 开关，而且各种 shell 的引号和转义规则不同，Emacs 会相应处理；自动排除无意义的目录——Emacs 会自动把版本控制目录（.git）、回收站等从搜索范围里排除，省得你搜出一堆噪音。

进阶：Windows 上的 grep / find，以及用 ripgrep 加速

Windows 的坑（原书 p.180–183 讲的是真问题，今天仍然存在，只是解法变了）：Windows 没有和 Unix grep 对等的工具，自带的 findstr 也不被 Emacs 默认调用；更麻烦的是 Windows 上有个老的 find 命令（搜文件名用的那个），Emacs 默认会拿它当 Unix 的 find 用，结果完全不对。原书给的解法是安装 GNU Coreutils（核心工具集，含 grep/find 的 Windows 移植版）并把它的 bin 目录加进 PATH：

(setenv "PATH" (concat "C:\\gnuwin32\\bin\\"
                      path-separator
                      (getenv "PATH")))

把路径换成你的 GNU 工具实际安装目录后重启 Emacs。这个做法今天依然有效，只是路径示例该用 MSYS2 之类工具链的真实路径。注意：如果用 WSL（Windows 子系统）里的 Emacs，或用 Scoop / winget 装了 ripgrep，这个问题通常自动消失。

ripgrep（rg）：今天的实际答案。ripgrep 是 Rust 写的 grep 替代品，默认忽略 .gitignore、多线程、支持 -t rust 之类的文件类型过滤，比 GNU grep 快一个数量级。Emacs 内核没有内置支持——我实测 (fboundp 'ripgrep-any-handler) 返回 nil，rg 不在 Emacs 32 里。两条路：一是用 consult 的 consult-ripgrep（官方推荐绑在 Ms r），最省事；二是 M-x grep 后把命令行手写成 rg --line-number --with-filename --context=3 PATTERN，rg 默认输出格式（文件:行号:内容）恰好和 Emacs 的 grep-mode 兼容，所以高亮和跳转都能正常工作。

补一条纠正：consult README 里提到「Emacs 31 上有 grep-edit-mode」可以在 grep 缓冲区里直接改源码。我在本机 Emacs 32.0.50 上核对过，这个命令目前并不存在（(fboundp 'grep-edit-mode) 为 nil，本机 NEWS.31 里也查不到），别照抄。真要在 grep 结果里改代码，现在的方案是第三方包 wgrep，或经由 embark 导出到 Occur 缓冲区（支持 e 直接编辑）。

零散的移动命令

原书在搜索之后附了一组「其它移动命令」，日常使用频率不高但每个都有明确用途，值得在第 3、4 章的基本移动之外补进工具箱。

  • Mr 与 Cl 功能相近：前者先把光标移到行首再在窗口顶部 / 中部 / 底部循环，后者滚动窗口让光标所在行重新居中到这三个位置。原书说他天天用 Cl：这是让缓冲区视野跟着阅读位置移动的最快办法，比如你正在读文件末尾 200 行，按几下让前面的内容露出来。CMl 更聪明：它会智能滚动，让光标所在的注释块或定义块完整可见。
  • Cx Cn 设置目标列。默认上下移动时 Emacs 尽量保持你的水平位置；设了目标列后它会强制让光标落在目标列那一格。取消用前缀参数 Cu Cx Cn——这是同一个命令加前缀参数，不是另一个命令。原书说它对多数人兴趣有限，我同意，但知道它存在能省掉一些「怎么让缩进对齐」的困惑。
  • Mg Mg 跳到指定行，Mg g 是同一命令的别名形式（goto-map 里 Mg ESC g 也一样）。数字前缀可直接跳：M55 Mg Mg 到第 55 行。数字前缀一律用 M 加数字而不是 C 加数字，手不用换到控制键上。Mg TAB（move-to-column）跳到指定列，Mg c（goto-char）跳到从缓冲区开头算起的第 N 个字符，如 M42 Mg c 跳到第 42 个字符；后两个的命令名原书没提，这里补上。

原书在结论里提了两个比命令本身更重要的建议：

  1. 把 Caps Lock 重映射成 Control。 如果你用标准键盘，Control 键在主键区左下角，距离太远。换成 Control 之后，C 前缀的所有命令（Cs、Cx、Ca）手感会彻底改变，原书说他「离开 Emacs 也离不开」。这一步在操作系统层面做（macOS：系统设置 → 键盘 → 修饰键；Linux/Windows：键盘驱动或 xcape 之类工具；机械键盘则在固件里改）。
  2. 一次只改一个习惯。 如果你刚接触 Emacs，继续用方向键完全没问题。等基本移动练熟了，你会自己开始觉得「右手离开主键区去够方向键」变慢了——这个转变应该由你自己的身体反馈触发，而不是被人告知。

练习 11　一个 5000 行的文件里有 200 处待办标记，你想快速看清它们大致分布在哪些区域（不是逐个看内容）。用什么组合？需要改配置吗？

先 (setq isearch-allow-motion t)（Emacs 28 引入，默认 nil）。然后 Cs 搜那个标记，反复按 Cv（scroll-up-command，在 Isearch 中被重定义为「跳到当前窗口还没显示的下一个匹配」）和 Mv 往回跳，每按一次滚一屏，200 个匹配十几屏就能扫完分布。补充一点：isearch-allow-motion 还会让 M< / M> 在 Isearch 里变成「跳到首 / 末匹配」；但跳首末匹配不需要这个开关，直接用 Ms M< / Ms M> 即可（Emacs 28+，默认可用）。

练习 12　你用 Cs 搜小写 error，结果里混进了 ERROR 和 Error；但你搜 Error 时只匹配到了 Error。这个行为叫什么、由哪个变量控制？如果想连这个「小写时宽松」的默认也关掉，写什么？

这叫大小写折叠（case folding），由 case-fold-search 控制（默认 t）。规则来自 search-upper-case（默认 not-yanks）：搜索串里出现大写字母时自动转为区分大小写。想整个关掉就写 (setq case-fold-search nil)，之后搜 error 就只匹配全小写的。想只在某一次搜索里临时区分大小写而全局不动，按 Ms c（isearch-toggle-case-fold，或等价的 Mc），开关只影响当前这次搜索。

练习 13　M-g i 是哪个命令的默认全局键位？这个键位从哪个 Emacs 版本才开始有？在更早的版本里怎么调用同一个功能？Emacs 30 又给它加了什么新选项？

M-g i 是 imenu 的默认全局键位，Emacs 29 起才有（我在本机 Emacs 32.0.50 上实测 (key-binding (kbd "M-g i")) 返回 imenu）。Emacs 28 及更早只能 M-x imenu 调用，或自己写 (global-set-key (kbd "M-i") 'imenu)——但 M-i 默认是 tab-to-tab-stop，今天不推荐再绑，改用 consult 生态挂在 Mg i 上的 consult-imenu。Emacs 30 新增了 imenu-flatten 变量（控制是否把 imenu 层级拍平成一维列表），还允许通过 completion-category-overrides 自定义 imenu 补全的排序。

练习 14　你光标停在一个 URL 中间，希望用「这段 URL」直接开始搜索，不需要手打。按哪个键？Emacs 按什么顺序决定要搜哪一块文字？

按 Ms M.，命令是 isearch-forward-thing-at-point。取哪一块由变量 isearch-forward-thing-at-point 决定，默认值 '(region url symbol sexp) 就是一个按顺序尝试的列表：有激活的选区就用选区文本，否则试 URL，再试符号，最后试 S 表达式（用括号平衡切出的一段代码）。所以它恰好覆盖三种常见情况：选中一段文字、停在一个 URL 上、停在一个函数调用上。想只要符号、不做这一串尝试，用 Ms .（isearch-forward-symbol-at-point）。

本章小结

三个层次，从轻到重：

  1. 缓冲区内的跳跃——Cs / Cr 的 Isearch，加上一整组开关（大小写、正则、词、符号、字符折叠、隐藏文本）、一组「从光标处取材」的键（Cw、Ms Ce）、以及 Ms o / M% 两个「搜索结束即行动」的出口。
  2. 缓冲区内 / 间的汇总——occur 把匹配行汇成一张可跳转、可原地编辑的清单；imenu 把当前文件编成一份索引；Mg Mn / Mg Mp 是贯穿 occur、grep、compile 的通用跳转键。
  3. 文件系统上的跳跃——rgrep 加 *grep* 缓冲区；补全方案的选择（今天建议 vertico + consult，或零依赖的 fido-mode）。

原书结尾那段我认为是整本书最好的话，意思是：记不住命令名和按键绑定完全没关系，重要的是你知道去哪查——M-x apropos-command 按名字找命令，C-h f 查一个函数，C-h k 查一个键，敲完前缀再敲 Ch 列出该前缀下的全部命令。看懂 Emacs 的源码和 Info 文档，比背下五百个键位有用得多。
