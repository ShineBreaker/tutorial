# 写作纲要：中文版 Emacs 精读本

## 我们在做什么

把 Eli Spare 的《Mastering Emacs》（第 5 版，326 页）改写成一本**中文精读本**，最终形态是一个**单文件、移动端优先、交互式**的 HTML 网页。

原书是英文的，写作年代横跨 Emacs 26 到 30 之间。它讲的是 Emacs 的肌肉记忆——按键、移动、编辑——这些内核知识至今没有过时，但**周边生态已经变了很多**（原书成书时没有 `consult`、没有 `eglot`、`vertico` 还是新东西、Emacs 29 引入了 `use-completion` 新式补全、Emacs 30 重写了若干默认行为与主题、`emacs 31` 已进入开发序列）。所以最终产物 = **原书的内核 + 当代 Emacs 的正确做法**。

## 读者画像

- 中文母语程序员，用过 VS Code / Vim / JetBrains 中至少一个，**完全没用过 Emacs**。
- 目标：读完能自己装好 Emacs、配好一套能用的配置、熟练完成日常编辑、看得懂并写出 Elisp、知道现代 Emacs 生态该选什么。
- 阅读场景：**手机上通勤时读**为主，电脑上精读为辅。这意味着句子不能太长，不能依赖横向滚动，不能假设读者能立刻敲键盘验证。

## 铁律

1. **正确性高于完整性。** 任何一条技术性断言（快捷键、命令名、变量名、包名、默认行为）在写下来之前都要有把握。不确定就去查，不要猜。查证途径优先级：GNU Emacs 官方手册 <https://www.gnu.org/software/emacs/manual/> → 该功能/包的官方文档与仓库 → Emacs Wiki <https://www.emacswiki.org/> → 你的既有知识（此时必须在正文里标注这是经验性说法）。
2. **标注版本差异。** 凡是行为在 Emacs 26/27/28/29/30/31 之间有变化的，必须说清楚「哪个版本开始是这样」「今天（30/31）该怎么用」。读者照着敲如果因为版本不同而失败，这本书就没做好。
3. **区分内置与第三方。** 大量初学者最大的困惑是「这个功能到底是 Emacs 自带的还是要装包」。凡是第三方功能，必须写明包名、是否 MELPA/ELPA 内置、是否有官方文档。
4. **术语就地解释。** 第一次出现的术语用 `**术语**（一句话白话解释）` 的形式当场解释，不要留到附录。初学者中途卡住是最大的失败。
5. **不留知识断层。** 讲到「用 `M-x` 调用」时要顺带说明 `M-x` 是什么；讲到 Elisp 函数要说明去哪儿执行；讲到配置文件要说明在哪儿改、怎么重载。宁可啰嗦。
6. **命令名、变量名、包名一律保留英文原名**，并给一句中文解释，不要意译。
7. **不要用「当然很简单」「众所周知」这类口气。** 读者是真的不会。
8. **不要写占位符。** 写不出来就整条略过，绝不留下 `TODO`、`待补充`、空壳标题。

## 文风

- 简体中文，短句，具体。凡是抽象原则都必须配一个「怎么做」的具体例子。
- 命令与快捷键的呈现格式以 `web/CONTRACT.md` 为准。
- 不写营销腔，不写「Emacs 是世界上最强的编辑器」这类空话——只在能指出它为什么强、代价是什么时才写。
- 主动写出 Emacs 的真实代价（配置门槛、启动时间、包质量参差、离 Vim 心智模型远），诚实比吹嘘有用。

## 原书章节文本的坑

`Emacs/mastering-emacs-zh/text/*.md` 是从 PDF 提取的纯文本：

- 快捷键记号在正文里是 `C-x C-f`、`M-x` 这种写法，和 CONTRACT 要求的 `<kbd>` 结构不同，需要你转换。
- 排版有断行连字（如 `migrat-ing`），个别符号可能丢失。遇到明显乱码，**回到原始 PDF 的对应页核对**：
  `/home/brokenshine/.zcode/cli/pdf-cache/sess_bbd46521-e33f-4dd4-8674-2398230987e7/pdf-9b193467a55b35d2815d095b544b249b.pdf`
  （`text/` 下每个文件的页码标记 `[p.86]` 与 PDF 实际页码一一对应。）
- 原书的**内容要点是可靠的**，语言和周边生态需要你更新。
